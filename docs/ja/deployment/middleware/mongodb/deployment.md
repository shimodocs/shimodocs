# で展開 MongoDB

[← ShimoDocs Suite デプロイメント文書](../../README.md)

この記事では、組み込み機能を無効にする方法を紹介します MongoDB インストーラー内の ShimoDocs 顧客自身の設定方法について説明します MongoDB サードパーティとして MongoDB ドキュメントデータベース。構成後、インストーラーは MongoDB ネットワーク接続や接続、認証などの権限をチェックします。チェックが通過すると、展開を続行できます。 

# 1. 設定前の準備 
開始する前に、以下を確認してください: 
- MongoDB サーバーがインストールされており、正常に稼働していること。 
- 展開ノードが、ホストとポートにアクセスできること MongoDB サーバー。 
- 接続情報および PASSWORD 認証用の MongoDB サーバーが準備されています。 

> [!TIP] 
> 
> この記事のIP、ポート、およびアカウントは例です。設定には実際の環境情報を使用し、実際の PASSWORD を公開文書やスクリーンショットに記録しないでください。 
> 

# 2. 高度な構成を入力する 
インストーラーの「構成」ステップでは、ネットワーク、ターゲット環境、およびノード情報の構成完了後、ページ下部の「詳細構成」を展開します。 

# 3. 組み込み MongoDB
「ミドルウェアサービス」エリアでチェックを外します MongoDB

チェックを外すと、インストーラーは組み込みインストールを行わなくなります MongoDBのインストールをキャンセルし、代わりに外部で準備された MongoDB を使用します。他のミドルウェアについては、組み込みサービスを使用するかどうかは実際の導入計画に従って選択してください。

# 4. サードパーティミドルウェアの設定を開く
「サードパーティミドルウェア」エリアで、「設定」をクリックします。

# 5. 設定 MongoDB ドキュメントデータベース
1. 左側で「MongoDB 左側の「ドキュメントデータベース」を選択します。
2. 「サードパーティのメッセージキューを使用」を有効にします。 MongoDB 「ドキュメントデータベース」
3. ホスト、ポート、 USERNAME, PASSWORD接続文字列の上書きを入力します。
4. 確認して保存してください

> [!WARNING]
>
> 注意: サードパーティの MongoDB がアプリケーション専用のアカウントを作成し、「最小権限の原則」に従う場合、アカウントは指定されたデータベースにアクセスする権限のみを持つようにしてください。それぞれのビジネスデータベースに対してユーザーと PASSWORD を割り当てる必要があります。

# 6. 確認結果の確認
インストーラーは次の内容をチェックします：
- ログイン: アカウントは正常に認証できます。
- 接続性：デプロイ環境がアクセス可能か MongoDB
- 権限: アカウントには接続、認証、コマンド実行などの権限があります。

すべてのチェック項目が「成功」と表示されたら、設定ウィンドウを閉じ、インストーラーの「設定」ページに戻ります。

もし障害が発生した場合は、ページの指示に従って確認してください：
- ホストとポートが正しく入力されているか
- デプロイメントノードと...の間のネットワークが MongoDB サーバーが接続されています。
- かどうか USERNAME および PASSWORD 正しいかどうか
- アカウントが必要な権限（接続および認証、コマンド権限など）を持っているかどうか。

# 7. デプロイの初期化を続行
「設定」ページに戻ったら、確認してください MongoDB 未確認の場合は、「デプロイの初期化」をクリックして、デプロイの概要、チェック、実行手順を完了してください。

> [!TIP]
>
> デプロイを初期化する前に、もう一度確認してください。 MongoDB 構成が保存され、すべての検証項目に合格しました。
