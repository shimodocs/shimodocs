# で展開 Kafka

[← ShimoDocs Suite デプロイメント文書](../../README.md)

この記事では、組み込みインストーラーを無効にし、 Kafka インストーラー内の ShimoDocs 顧客自身の設定方法について説明します Kafka をサードパーティのメッセージキューとして使用します。設定後、インストーラーは Kafkaのネットワーク接続とトピック作成の権限を確認します。確認が完了すると、デプロイを続行できます。 

# 1. 設定前の準備 
開始する前に、以下を確認してください: 
- Kafka サーバーがインストールされており、正常に稼働していること。 
- デプロイノードが Kafka サーバーホストおよびポートにアクセスできること。 
- 認証用ユーザー情報を準備し、 PASSWORD 接続先 Kafka サーバートピック（外部の場合） Kafka クラスタで安全な認証が有効になっています。 
- 認証されたアカウントは管理者ユーザーを使用し、トピックの作成、削除、認可、および読み書きの権限を持っている必要があります（外部の場合） Kafka クラスタで安全な認証が有効になっています。 

> [!TIP]
>
> この記事のIP、ポート、アカウントは例です。実際の環境情報を使って設定してください。実際のものを記録しないでください。 PASSWORD 。 
>

# 2. 高度な構成を入力する 
インストーラーの「構成」ステップで、ネットワーク、ターゲット環境、ノード情報の構成を完了した後、ページ下部の「高度な構成」セクションを展開します。 

# 3. 組み込みのインストールをキャンセルする Kafka
「ミドルウェアサービス」エリアでチェックを外します Kafka.

チェックを外すと、インストーラーは組み込みインストールを行わなくなります Kafka、および外部 Kafka 準備されたものは後で使用されます。他のミドルウェアについては、組み込みサービスを使用するかどうかは、実際のデプロイ計画に従って選択してください。

# 4. サードパーティミドルウェアの設定を開く
「サードパーティミドルウェア」エリアで、「設定」をクリックします。

# 5. 設定 Kafka メッセージングミドルウェア
## Kafka サーバー SASL 認証未有効
1. 左側で「Kafka 左側の「メッセージキュー」
2. 「サードパーティのメッセージキューを使用」を有効にします。 Kafka 「サードパーティのメッセージキューを使用」を有効にします。
3. 入力してください Kafka サーバー接続情報。
5. 確認して保存してください

## 有効化 SASL サーバーでの認証に Kafka サーバー 
もし Kafka 認証が有効になっている場合、Web UIでも同時に有効にする必要があります：ブローカーが認証アクセスを必要とする場合のみ有効にするボタン SASL 認証を有効にします 
1. 認証を有効にします SASL 認証 
2. チェック機構 
3. 入力してください USERNAME および PASSWORD 
4. 確認して保存してください 

# 6. 確認結果の確認
インストーラーは次の内容をチェックします：
- ログイン：アカウントが正常に認証できるか（有効な場合 SASL 有効です）。
- 接続性：デプロイ環境がアクセス可能か Kafka.
- トピック作成権限：アカウントがトピックを作成し、認可し、読み書きする権限を持っているか。

すべてのチェック項目が「成功」と表示されたら、設定ウィンドウを閉じ、インストーラーの「設定」ページに戻ります。

もし障害が発生した場合は、ページの指示に従って確認してください：
- ホストとポートが正しく入力されているか
- デプロイメントノードと...の間のネットワークが Kafka サーバーが接続されています。
- かどうか USERNAME および PASSWORD は正しいです（Kafka サーバーが有効になっています SASL 認証)。
- アカウントに必要な権限があるかどうか (Kafka 認証が有効になっている場合、Web UIでも同時に有効にする必要があります：ブローカーが認証アクセスを必要とする場合のみ有効にするボタン SASL 認証有効)。

# 7. デプロイの初期化を続行
「設定」ページに戻ったら、確認してください Kafka 未確認の場合は、「デプロイの初期化」をクリックして、デプロイの概要、確認、および実行手順を続行してください。

> [!TIP]
>
> デプロイを初期化する前に、もう一度確認してください。 Kafka 設定が保存され、すべての確認項目が合格しました。
