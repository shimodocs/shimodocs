# Kafka 構成

[← ShimoDocs Suite デプロイメント文書](../../README.md)

このドキュメントは、実装、運用、または統合担当者が完了するためのガイドを提供することを目的としています ShimoDocs 外部メッセージミドルウェアとの統合 Kafka 非同期タスク処理、メッセージ通知、データ同期、監査ログ配送などのシナリオにおいて、ステップバイステップで。 


## 1. 操作前の確認 

## Kafka インスタンス要件 


| ミドルウェア | 推奨バージョン | ユーザー数が3000未満の場合 | ユーザー数が3000以上の場合 | 
| --- | --- | --- | --- | 
| Kafka | Kafka 3.5 | 2C 4G 300G SSD | 4C 8G 300G SSD | 


## 構成要件 
- ブローカー >= 3 
- レプリケーション係数: デフォルトのレプリカ数は3であり、本番環境では高可用性を確保するために ≥ 3 が必須 
- メッセージ保持期間: 72時間（ビジネスニーズに応じて調整可能） 
- トピックごとの最大メッセージサイズ: 10 MB 
- 認証: 対応 SASL 暗号化アクセス（PLAIN, SCRAM-SHA-256, SCRAM-SHA-512) 





## ネットワーク接続 

アクセス用ポート Kafka ビジネスクラスターからのインスタンスへの K8s 接続は開放されている必要があります 

```js
telnet IP 9092
```



## その他の要件
- イントラネット RTT の遅延は < 5ms を推奨。データセンター間/リージョン間は < 20ms を推奨。
- 帯域幅はピークスループットを満たす必要があり、ネットワーク飽和によるメッセージ遅延を回避するために十分であること。
- 次を確保してください Kafka ブローカーと ShimoDocs アプリケーションサーバーの時間は同期しています（NTP）、時間のずれはメッセージの順序や TTL 計算に影響を与える可能性があります。
