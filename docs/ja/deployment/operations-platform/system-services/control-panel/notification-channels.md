# 通知チャネル

[← ShimoDocs Suite デプロイメント文書](../../../README.md)

## 機能概要

通知チャネルは、システムアラートメッセージの受信方法を集中管理するために使用され、ミドルウェアの検査やその他の機能が障害および回復通知を送信できるようにします。

現在サポートされているチャネルには、WeCom、DingTalk、Feishu、およびカスタムWebhooksがあります。

## ページへのアクセス

管理コンソールにログインした後、選択してください。 **通知チャネル** を選択してページにアクセスします。

通知チャネルは管理者のみ利用可能です。このメニューが表示されない場合は、アカウントの権限を確認するためにシステム管理者にお問い合わせください。

## 新しい通知チャネルの作成

クリック **チャネル作成**チャネル名を入力し、チャネルタイプを選択します：

- **WeCom**: ロボットのWebhookキーを入力してください。
- **DingTalk**: 完全なWebhookを入力してください。 URL必要に応じて、ロボットの設定に従って署名Secretを入力してください。
- **Feishu**: 完全なWebhookを入力してください。 URL必要に応じて、ロボットの設定に従って署名Secretを入力してください。
- **カスタムWebhook**: リクエスト方法を入力し、本文テンプレートを入力してください。 URL, HTTP 

チャネルを有効にするかどうかを確認し、その後クリックします。 **保存**.

## カスタムWebhook

カスタムWebhookの本文テンプレートは、以下の変数をサポートしています： 

```text
{{title}}
{{body}}
{{level}}
```

デフォルトテンプレートの例： 

```json
{"title":"{{title}}","body":"{{body}}","level":"{{level}}"}
```

システムが通知を送信すると、変数は実際のタイトル、内容、およびアラートレベルに置き換えられます。 

## テストチャンネル 

保存後、クリックしてください **テスト** チャンネルの右側にある。システムは、Webhookアドレス、署名、ネットワーク接続が正しいかどうかを確認するためにテストメッセージを送信します。 

チャネルを作成または変更した後は、ミドルウェア検査やその他の業務機能にバインドする前に、すぐにテストすることをお勧めします。 

## 有効化、編集、および削除 

- **有効/無効**: チャンネルを編集する際に有効状態を調整します。無効にすると、チャンネルはビジネス通知を受信しません。 
- **編集**: チャンネル名、種類、およびWebhookの設定を変更できます。 
- **削除**: もう使用しないチャンネルを削除します。ミドルウェアの検査で参照されているチャンネルは、削除する前にバインドを解除する必要があります。 

## 一般的な状況

- **送信テスト失敗**: Webhookのアドレス、キー、シークレットを確認してください。 HTTP メソッド、およびネットワークアクセス権限。
- **保存に失敗しました**: すべての必須項目が記入されており、Webhook URL 形式が正しいことを確認してください。
- **ビジネスアラートが受信されていません**: チャンネルが有効化されており、対応するビジネスページで選択されていることを確認してください。
- **チャンネルを削除できません**: このチャンネルはまだミドルウェアの検査で使用されている可能性があります。まず関連付けを削除し、検査設定を保存してください。
- **カスタムWebhook受信コンテンツの形式が正しくありません**: ボディテンプレートが対象システムの要件を満たしているか確認してください。

> Webhookアドレスおよび署名Secretは機密情報です。アクセスを制限し、スクリーンショット、ログ、チャットツールを通じて公開しないでください。
