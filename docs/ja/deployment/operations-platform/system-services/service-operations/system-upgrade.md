# システムアップグレード

[← ShimoDocs Suite デプロイメント文書](../../../README.md)

## 機能概要

システムアップグレードは、新しいものをアップロードして適用するために使用されます MDP インストールパッケージ。正式なアップグレードの前に、システムは自動的にアップグレードパッケージと現在の環境をチェックし、このアップグレードに関連する構成とサービスの変更を表示して、バージョンアップグレードまたは通常のメンテナンスの完了を支援します。

このページはアップグレード履歴も保持しており、過去のアップグレード記録、実行状況、および関連ログを簡単に確認できます。

**注意**: メジャーバージョンのアップグレードではデータベーススキーマが更新される場合があります。アップグレードには設定変更、サービスの再起動、機能インターフェースの変更が伴い、ユーザー体験に影響を与える可能性があります。ピーク時間外に実施することを推奨します。

## ページに入る

管理バックエンドにログイン後、左側ナビゲーションで **システムアップグレード** 左側のナビゲーションでページに入ります。

システムのアップグレードは管理者のみ利用可能です。このメニューが表示されない場合は、現在のアカウントの権限を確認するためにシステム管理者に連絡してください。

## アップグレード前の準備

アップグレードを開始する前に、以下の項目を確認することを推奨します:

- 現在の製品タイプと展開方法に一致する公式提供のアップグレードパッケージを使用してください。
- アップグレードパッケージは `.tar.gz` 形式です。パッケージ内のファイルを抽出または変更しないでください。
- 業務の閑散時間またはメンテナンスウィンドウ中にアップグレードを行うことを推奨します。
- 現在のサービスが正常に稼働していることを確認し、関係するユーザーに事前に通知してください。
- アップグレードにライセンスの変更が含まれる場合は、事前に新しいライセンス内容を準備してください。

## アップグレード手順

### 1. アップグレードパッケージをアップロード

システムアップグレードページのアップロードエリアをクリックするか、アップグレードパッケージをアップロードエリアにドラッグしてください。アップロードが完了すると、システムは自動的にアップグレードパッケージを解析し、検証します。

検証には主に以下が含まれます:

- インストールパッケージの形式および内容の完全性。
- インストールパッケージの署名が有効かどうか。
- アップグレードパッケージのバージョンおよびアップグレード計画。
- 製品タイプおよび展開アーキテクチャが一致するか。
- 現在のライセンスがこのアップグレードをサポートしているか。

検証結果は以下のステータスに分類されます:

- **合格**: 検証は正常で、続行できます。
- **変更**: このアップグレードには予想される変更があります。続行する前に内容を確認してください。
- **不一致**: アップグレードを妨げる問題があります。アップグレードパッケージを置き換えるか、再アップロード前に関連する設定を処理してください。

### 2. ライセンスを入力

システムがこのアップグレードに更新されたライセンスが必要であると判断した場合、ページには更新が必要な製品が表示され、現在のサーバーマシンコードなどの情報が表示されます。

新しいライセンスの内容を貼り付けた後、 **[検証して一時保存]をクリックします。**ライセンスが正常に検証されて初めて、アップグレードを続行できます。一時的に保存されたライセンスは、アップデートが正常に適用された後に自動的に有効になります。ライセンスに関する詳細は、[ライセンス管理]を参照してください。

ページにライセンスの更新が不要と表示されている場合は、直接次のステップに進むことができます。

### 3. アップグレードパッケージの内容を確認する

ページには、アップグレードパッケージ内の構成ファイルとサービスリソースが表示されます。特定のファイルを選択して内容を確認し、アップグレードパッケージが現在のアップグレード対象と一致していることを確認できます。

### 4. 変更点を確認する

システムは現在の環境とアップグレードパッケージを比較し、このアップグレードで追加、変更、削除、または再起動されるリソースを表示します。

特に注意して確認してください: 

- 予期しないリソース削除があるかどうか。 
- 重要なサービスを再起動する必要があるかどうか。 
- 設定ファイルの変更が期待通りであるかどうか。 

### 5. アップデートの適用 

上記の情報が正しいことを確認した後、クリックしてください **更新開始を確認**。システムはアップグレード前のスナップショットを作成し、アップデートパッケージの適用を開始します。 

アップグレード中、ページにはリソースの更新、サービスの再起動、実行状況の確認などの情報を含む実行ログが継続的に表示されます。 一部のコンポーネントが再起動すると、管理ページに一時的にアクセスできない場合があります。 少し待ってからページを再度開き、進行状況を確認してください。 

実行が失敗した場合、ログに従って問題を対処し、その後クリックできます **再適用**. 

### 6. アップグレードの完了 

アップグレードタスクが正常に実行された後、クリックしてください **完了** このアップグレードプロセスを終了します。 

アップグレード完了ページにはアップグレードパッケージの名前とバージョンが表示され、以下の操作が提供されます： 

- **実行ログの表示**: このアップグレードの全プロセスを表示します。 
- **アップグレード前のバージョンにロールバック**: アップグレード前のスナップショットに入り、ページの指示に従ってロールバックを行います。 
- **アプリケーション更新に戻る**: システムアップグレードのホームページに戻ります。 

## アップグレード履歴 

システムアップグレードのホームページ下部には、アップグレードパッケージ名、バージョン、作成時間、実行ステータスを含むアップグレードの履歴が表示されます。 

アップグレード記録をクリックすると、対応するプロセスに再度入り、アップグレードの進行状況や過去の実行結果を確認できます。

## 一般的な状況

- **アップグレードパッケージの検証に失敗しました**: アップグレードパッケージの出所、ファイルの完全性、製品タイプ、展開アーキテクチャが正しいことを確認してください。
- **バージョン不一致**: 現在のシステムバージョンとアップグレードパッケージバージョンを確認し、正しいアップグレードパスが使用されていることを確認してください。
- **ライセンス更新が必要**: 対象バージョンおよび現在の実行環境に適した新しいライセンスを取得し、検証してから一時的に保存し、続行してください。
- **アップグレードプロセスページは一時的に利用できません**: サービス MDP サービスは更新中または再起動中の可能性があります。しばらくお待ちの上、ページを更新してください。
- **アップグレードタスクに失敗しました**: 原因を特定するには実行ログを確認してください。問題を解決した後、使用してください **再適用**.
- **アップグレード後のサービス異常**: まず実行ログとサービスの状態を確認してください。復旧が必要な場合は、アップグレード前のスナップショットを使用してロールバックできます。

> システムのアップグレードはサービスの設定を変更し、サービスの再起動を引き起こす可能性があります。アップグレードパッケージと変更内容を確認した後にのみ進めてください。
