# 監査ログ

[← ShimoDocs Suite デプロイメント文書](../../../README.md)

## 機能概要

操作ログは、システム内のユーザー管理操作を表示・追跡するために使用され、トラブルシューティング、セキュリティ監査、変更追跡に役立ちます。

このページは読み取り専用であり、ログレコードの変更や削除はサポートされていません。

## ページへのアクセス

管理バックエンドにログイン後、左側ナビゲーションで **操作ログ** を選択してページにアクセスします。

## ログのフィルタリング

以下の条件の組み合わせでクエリを実行できます:

- **イベントソース**: 例として、コントロールパネル、アプリケーション構成センター、アップデーター、 Kubernetes リソース管理、またはユーザー管理センターがあります。
- **操作タイプ**: イベントソースに基づいて対応する操作を表示します。例えば、設定更新、バージョンアップグレード、サービスの再起動、またはユーザー管理操作などです。
- **操作ユーザー**: 特定のユーザーによって生成されたレコードをフィルタリングします。

イベントソースを選択すると、操作タイプのリストが自動的に調整されます。クリック **検索** してフィルター条件を適用するか、リセットボタンをクリックして条件をクリアします。

## ログリストの表示

リストには主に以下が表示されます:

- ログID。
- イベントソースおよび操作タイプ。
- 操作ユーザー。
- 操作対象のタイプ、名前、ID。
- 操作時間。 

ログの総数はページの上部に表示され、リストはページネーションおよびページごとの表示件数の調整をサポートしています。 

## ログ詳細の表示 

クリック **詳細** 記録の右側の詳細をクリックして、以下を含む完全な情報を表示します: 

- ソースおよび操作タイプの名前と内部識別子。 
- 操作を行うユーザーとユーザーID。 
- 操作時間。 
- オブジェクトタイプ、オブジェクトID、およびオブジェクト名。 
- イベントメタデータ。 

アプリケーション構成センターの変更について、詳細は構成の変更内容、自動再起動がリリース後に発生するかどうか、再起動されたワークロードを表示することもあります。

## 一般的な使用例

- 特定の構成変更を実行したユーザーを確認します。
- システムアップグレード、サービス再起動、またはスケーリング操作の時間を確認します。
- オブジェクト名に基づいて関連する変更を追跡します。
- イベントメタデータを使用して構成の差異や実行結果を確認します。
- 誤操作や予期しない管理上の変更を調査します。

## 一般的な状況

- **記録が見つかりません**: フィルター条件をクリアするか、選択したソース、操作タイプ、およびユーザーが一致しているか確認してください。
- **操作タイプの一覧は空です**: まずイベントソースを選択するか、最新の列挙を取得するためにページを再読み込みしてください。
- **オブジェクト情報は空です**: 一部のシステムイベントは特定のオブジェクトに関連付けられていない場合がありますが、これは正常です。
- **メタデータはフォーマットされた内容ではありません**: 一部の過去のイベントはプレーンテキストとして保存される場合があり、ページには元の内容が表示されます。
- **ログの数量が予想と一致しません**: ログはシステムで監査された操作のみを記録し、環境の保持ポリシーの影響を受ける場合があります。

> 操作ログには、ユーザー、オブジェクト識別子、設定変更情報が含まれる場合があり、許可された担当者のみがアクセスすべきです。
