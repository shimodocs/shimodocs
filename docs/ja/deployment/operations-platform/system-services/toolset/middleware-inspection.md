# ミドルウェア検査

[← ShimoDocs Suite デプロイメント文書](../../../README.md)

## 機能概要 

ミドルウェア検査はシステム依存の MySQL, Redis, Elasticsearch, S3, MongoDB、および Kafka が正常に接続および読み書きできるかを確認するために使用され、基盤となるサービスの異常をタイムリーに検出するのに役立ちます。 

このページは、即時検査、スケジュール検査、最近の可用性傾向、履歴記録、および障害と復旧の通知に対応しています。 

## ページに入る 

管理バックエンドにログイン後、左側ナビゲーションで **ミドルウェア検査** ページに入るには、左側のナビゲーションを使用します。 

ミドルウェア検査は管理者のみ開放されています。このメニューが表示されない場合は、システム管理者に連絡してアカウント権限を確認してください。 

## 即時検査 

ページで、 **概要** ページで、クリック **即時検査**を選択すると、システムは保存されたチェック対象に従って検査を実行します。 

検査結果には以下のステータスが含まれる場合があります： 

- **正常**: コンポーネントの接続および検査操作が成功しました。 
- **失敗**: コンポーネントに接続できない、読み書きに失敗した、または応答が異常です。 
- **スキップ**: 現在の環境でコンポーネントが設定されていないか、検査条件が満たされていません。 

コンポーネント結果をクリックすると、対象アドレス、応答時間、およびエラーの詳細を表示できます。 

## 可用性の傾向を表示 

概要ページでは、過去の検査結果に基づき各コンポーネントの最近の可用性を表示します。過去1時間、6時間、24時間、3日、7日、14日、または30日のステータス変化を確認できます。 

期間上にマウスを移動すると、その期間中の検査回数、平均応答時間、最近のエラーなどの情報を表示できます。 

## 定期検査の設定 

ページで、 **スケジューリングとアラート** ページで以下を設定できます： 

- **定期検査を有効にする**: 有効にすると、システムは設定した間隔で自動的に実行します。 
- **検査間隔**: 1〜1440分に対応しています。 
- **履歴保持日数**: 7日から365日をサポートします。 `0` に設定すると自動クリーンアップは行われません。 
- **検査対象**: 検査するミドルウェアを選択します。 
- **通知チャネル**: 検査通知を受け取るチャネルを選択します。 
- **障害時に通知**: 全体のステータスが正常から異常に変わったときに通知を送信します。 
- **復旧時に通知**: 異常ステータスが正常に戻ったときに通知を送信します。 

変更は、 **保存**をクリックして適用する必要があります。まだ通知チャネルがない場合は、まず **通知チャネル** ページに移動してチャネルを作成および有効にしてください。

## 検査履歴の表示

ページで、 **履歴** ページでは、検査時間、トリガー方法、実行時間、および最終ステータスを確認できます。

トリガー方法には手動検査およびスケジュール検査があります。各記録をクリックすると、この検査における各コンポーネントの詳細結果を表示できます。 

## 一般的な状況

- **検査記録がありません**: まず **今すぐ検査**をクリックするか、スケジュール検査を有効にしてください。
- **コンポーネントはスキップされました**: 対応するミドルウェアがシステムに設定され、有効になっていることを確認してください。
- **検査に失敗しました**: エラーの詳細に従って、ネットワーク、アカウント、接続先アドレス、およびミドルウェアのサービス状況を確認してください。
- **通知が届かない**: 通知チャネルが選択され有効になっていることを確認し、通知失敗や復旧のスイッチを確認してください。
- **プロンプトに検査が実行中と表示される**: 同時に実行できる検査タスクは1つだけです。現在のタスクが終了するまで待ってから、もう一度実行してください。

> 検査はミドルウェアへの軽量接続または読み書きのチェックを実行します。環境の規模に応じて合理的な検査間隔を設定することを推奨します。
