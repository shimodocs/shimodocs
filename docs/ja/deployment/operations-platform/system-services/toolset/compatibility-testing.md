# 互換性テスト

[← ShimoDocs Suite デプロイメント文書](../../../README.md)

## 1. ページ概要

互換性テストページは、オブジェクトストレージの構成、接続性、アップロード互換性、およびアップロード性能を確認するために使用されます。ページは以下に分かれています:

1. ストレージ構成;
2. 互換性テスト;
3. 性能テスト.

## 2. ストレージ構成 

### 2.1 設定項目の説明 

| 構成項目 | 機能 |
| --- | --- |
| アクセスキー | オブジェクトストレージアクセスID識別子、すなわちAK |
| シークレットキー | AKに付随するアクセスキー、すなわちSK |
| エンドポイント | オブジェクトストレージサービスアドレス |
| バケット名 | 検出対象のバケット |
| リージョン | ストレージバケットのロケーションエリア |
| パブリックエンドポイント | ブラウザがオブジェクトストレージにアクセスする際に使用する公開ドメイン、任意 |
| パススタイル | 'endpoint/bucket/object'形式でオブジェクトにアクセスする場合、通常は MinIO 有効化が必要 |

### 2.2 設定を記入 
1. 必要に応じて「添付バケットを埋める」または「コンテンツバケットを埋める」をクリックします。 
2. システムは現在の環境に対応するAK、SK、エンドポイント、バケット、リージョンなどの設定を自動で埋めます。 
3. 自動入力を使用しない場合は、すべての設定を手動で入力することもできます。 
4. エンドポイントに正しいプロトコルとポートが含まれているか確認します。 
5. バケット名が今回検出するバケットであるか確認します。 
6. リージョンがオブジェクトストレージの実際のリージョンと一致するか確認します。
7. ブラウザから直接オブジェクトストレージにアクセスさせる場合は、パブリックエンドポイントを記入します。
8. オブジェクトストレージの種類に応じて、パススタイルを有効にするかどうかを決定します。

今回、Attachments バケットを自動入力した後:

- バケット: `shimo-attachments`;
- エンドポイント: システムにより自動入力されます;
- リージョン: `cn-north-1`;
- パブリックエンドポイント: システムにより自動入力されます;
- パススタイル: 有効

「Contents バケットを埋める」をクリックすると、バケットは自動的に切り替わることがあります `file-contents`.

> シークレットキーは機密情報です。スクリーンショット、チャット、チケットで平文で表示しないでください。

## 3. 互換性テスト

互換性テストは、バックエンドアップロード、ブラウザ直接アップロード、マルチパートアップロードを順番にチェックします。

### 3.1 テスト開始

1. ストレージ構成を完了します。
2. 「互換性テスト」タブをクリックします。
3. バケット、エンドポイント、リージョン、パブリックエンドポイント、パススタイルの構成が正しいことをもう一度確認します。
4. 「互換性テスト開始」をクリックします。
5. ページに「互換性テスト完了」と表示されるまで待ちます。
6. ページの概要ステータスが「すべて合格」かどうかを確認します。
7. 3つのテストのステータス、所要時間、結果情報をそれぞれ確認してください。

### 3.2 バックエンドアップロードテスト

このテストは、バックエンドサービスからオブジェクトストレージへのネットワーク接続および書き込み権限を確認するために使用されます。

1. バックエンドはテスト用テキストファイルを生成します。
2. バックエンドはファイルをターゲットバケットに書き込みます。
3. ページにはアップロード時間とテストオブジェクトのパスが表示されます。
4. 緑色の成功ステータスは、バックエンドのネットワークおよび書き込み権限が正常であることを示します。

現在の結果：アップロード成功、所要時間 `157 ms`.

### 3.3 ブラウザ直接アップロードテスト

このテストは、ブラウザがPostPolicyを介してオブジェクトストレージに直接アップロードできるリンクを確認するために使用されます。

1. ページは、直接アップロードに必要なPostPolicyをバックエンドからリクエストします。
2. ブラウザはパブリックエンドポイントを使用してファイルをオブジェクトストレージに直接アップロードします。
3. ページはオブジェクトストレージから返された HTTP ステータスコードを確認します。
4. HTTP 204は、ブラウザ直接アップロードが成功したことを示します。

今回の結果：ブラウザ直接アップロード成功、所要時間 `61 ms`、ステータスコード `204`.

### 3.4 マルチパートアップロードテスト

このテストは、大きなファイルのマルチパートアップロードの全プロセスを検証するために使用されます。

1. マルチパートアップロードタスクを初期化します。
2. テストファイルを複数のパートに分割します。
3. 各パートを順番にアップロードします。
4. オブジェクト作成を完了するためにマージインターフェースを呼び出します。
5. ページには `multipart upload succeeded`が表示され、全プロセスが成功したことを示します。

今回の結果: マルチパートアップロード成功、所要時間 `1746 ms`.

### 3.5 テストオブジェクトの説明

互換性テストでは、ターゲットバケットに実際の書き込みを行い、バックエンドテストオブジェクトのパスは通常次のようになります:

```text
compatibility-tests/<RANDOM UUID>.txt
```

1. テストを実行する前に、ターゲットバケットが正しいことを確認してください。
2. 誤った本番バケットで無差別にテストを実行しないでください。
3. テスト後、環境のクリーンアップポリシーに従ってテストオブジェクトを確認・削除できます。

## 4. パフォーマンステスト

パフォーマンステストは、異なるファイルサイズのアップロード時間とスループットを測定するために使用されます。

### 4.1 パフォーマンステストの設定

1. 「パフォーマンステスト」タブをクリックします。
2. テストモードを選択します。ページはデフォルトで「ブラウザ直接」を使用します。
3. Content-Type を選択します。使用することができます。 `application/octet-stream` デフォルトで。
4. テストしたいファイルサイズを選びます。
5. ページは 1、5、8、10、12、15、20、25 MB に対応しています。
6. テスト環境では、まず 1 MB を選択して簡単に検証することができます。
7. 正式な性能比較では、複数のファイルサイズを選択してテストします。

### 4.2 パフォーマンステスト開始

1. ストレージの設定が正しいか確認します。
2. 少なくとも1つのファイルサイズが選択されていることを確認します。
3. 「パフォーマンステスト開始」をクリックします。
4. すべてのファイルのアップロードが完了するまで待ちます。
5. 平均スループット、最短時間、最長時間を確認します。
6. 各ファイルサイズのステータス、経過時間、スループット、エラーメッセージを確認します。
7. 失敗が発生した場合は、まずブラウザネットワーク、パブリックエンドポイント、クロスオリジン設定、オブジェクトストレージの状態を確認します。

### 4.3 本テストの結果

このテストでは 1 MB のファイルのみを使用し、軽量なフロントエンド直接アップロードテストを行います。

| メトリック | 結果 |
| --- | ---: |
| ファイルサイズ | 1.0 MB |
| ステータス | 成功 |
| 時間 | 874 ms |
| スループット | 1.14 MB/s |
| エラーメッセージ | なし |

実際の結果: アップロードは成功し、ページは経過時間およびスループットの指標を正しく生成できます。

> パフォーマンス結果は、ブラウザのネットワーク、クラスターの負荷、プロキシリンク、およびオブジェクトストレージの負荷によって影響を受ける可能性があります。単一のテストは機能の可用性を確認するだけであり、正式なパフォーマンス受け入れは同一環境で繰り返しテストし、統計および失敗率を記録する必要があります。 P50, P95失敗率を記録する必要があります。

## 5. 注意事項
1. テストを実行する前に対象のバケットを確認し、誤ったストレージバケットにテストファイルを書き込まないようにしてください。
2. ドキュメントやスクリーンショットにシークレットキーを平文で表示しないでください。
3. ブラウザの直接アップロードは、パブリックエンドポイントおよびクロスオリジンの設定に依存します。
4. S3-互換サービスのような MinIO 通常、パススタイルを有効にする必要があります。
5. パフォーマンステストは実際のネットワークトラフィックおよびストレージ書き込みを発生させます。大きなファイルをテストする前に環境への影響を評価してください。
6. 正式なパフォーマンス受け入れは複数ラウンドで実施する必要があります。単一のブラウザテスト結果だけでは不十分です。
