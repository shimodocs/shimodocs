# AI 구성

[← ShimoDocs Suite 배포 문서](../../README.md)

AI 구성은 ShimoDocs Suite 기본 모델, 이미지 모델, 온라인 검색 및 임베딩 서비스와 연결하는 데 사용됩니다. 구성을 완료한 후 ShimoDocs Suite 에서 AI 대화, 콘텐츠 생성, 이미지 처리 및 지식 검색과 같은 기능이 해당 서비스에 접근할 수 있습니다. 

## 1. 구성을 시작하기 전에 네 가지 유형의 기능을 이해합니다. 

네 가지 구성 유형의 목적은 서로 다르며, 모든 구성을 반드시 설정할 필요는 없습니다. 사용하려는 ShimoDocs Suite 기능에 따라 선택하십시오. 

| 구성 유형 | 목적 | 설정 필요 여부 | 
| --- | --- | --- |
| 기본 모델 | 대화, 글쓰기, 요약, 재작성, Q&A 및 기타 텍스트 또는 멀티모달 작업을 처리합니다. | AI 기능을 사용할 때 일반적으로 필요합니다. |
| 이미지 모델 | 이미지를 생성하거나 편집합니다. | 이미지 생성 또는 편집 기능을 사용할 때만 필요합니다. |
| 온라인 검색 | 모델 참조를 보완하기 위해 외부 검색 서비스에서 정보를 가져옵니다 | 온라인 검색 기능을 사용할 때만 필요합니다 |
| 임베딩 | 지식 기반 검색, 의미 검색 및 유사한 기능을 위해 텍스트를 벡터로 변환합니다 | 지식 검색 또는 벡터 검색 기능을 사용할 때만 필요합니다 |

> [!TIP]
>
> 온라인 검색은 일반적으로 독립적인 검색 서비스이며, 기본 모델에 내장된 온라인 기능과는 다릅니다. 

## 2. AI 설정 접근 

1. 운영 플랫폼에 로그인하고, **MDP 운영 플랫폼**. 
2. 상단에서 선택 **ShimoDocs Suite**.
3. 왼쪽 사이드바에서 선택 **테넌트 관리**.
4. 다음을 찾습니다 **AI 구성** 카드.
5. 카드를 클릭하여 'AI 모델 및 검색 구성' 페이지로 이동합니다.

## 3. 먼저 연결할 모델 서비스 제공업체를 선택합니다

사용하려는 모델 서비스를 먼저 확인한 후, 해당 섹션에서 구성합니다.

| 모델 유형 | 서비스 제공업체 |
| --- | --- |
| 기본 모델 | OpenAI 응답 프로토콜과 호환되는 제공업체 |
| 이미지 모델 | OpenAI 이미지 프로토콜과 호환되는 제공업체 |
| 인터넷 검색 엔진 모델 | 현재 Volcengine만 지원합니다 |
| 임베딩 모델 | OpenAI 임베딩 프로토콜과 호환되는 제공자 |

## 4. AI 모델 구성

이 섹션은 구성하는 데 사용됩니다 GPT관련 서비스. 요청 주소와 모델 ID는 연결 방식에 따라 달라질 수 있으므로 엔지니어링 팀에 OpenAI 공식 서비스, Azure OpenAI, 프록시 서비스 또는 기타 호환 인터페이스 사용 여부를 확인해 주세요.

| 구성 항목 | 예제 값 | 설명 |

| 요청 URL / 기본 URL | https://myai.com/v1 | OpenAI 응답 프로토콜과 호환되는 본인 AI 게이트웨이 주소 선택 |

>
> 여기에 구성된 모델 제공자는 스트리밍 모드를 지원해야 합니다. ShimoDocs 클라이언트로서 AI는 항상 모델 제공자로부터 요청할 때 `stream: true` 스트리밍 모드를 지원하지 않으면 요청이 실패합니다.

## 5. 각 구성 항목의 비즈니스 의미

이 섹션에서는 페이지의 각 구성 항목 목적에 대한 통일된 설명을 제공합니다. 처음 설정할 때는 앞서 언급한 벤더 템플릿에 따라 작성한 후, 이 섹션으로 돌아와 각 필드가 실제 비즈니스 요구사항을 충족하는지 확인할 수 있습니다.

### 5.1 기본 모델 제공자 구성 항목

| 구성 항목 | 비즈니스 의미 | 잘못 입력했을 경우 일반적인 영향 | 필수 |
| --- | --- | --- | --- |
| 공급자 | 시스템에 어떤 모델 적응 방식을 사용할지 지정합니다. 두 서비스가 유사한 인터페이스와 호환되더라도 제공자 옵션에 따라 요청 형식, 인증 방법, 결과 파싱 방식이 결정될 수 있습니다. | 저장 실패, 요청 형식 불일치 또는 응답을 파싱할 수 없음이 발생할 수 있습니다. | 예 |
| 요청 URL / 기본 URL | 입력 주소 ShimoDocs Suite 모델 서비스에 요청을 보낼 때 접근하는 주소 | 주소가 잘못되면 모델에 연결할 수 없습니다; 경로 수준이 잘못되면 인터페이스가 존재하지 않는 것처럼 보일 수 있습니다. | 예 |
| API 키 | 호출자를 식별하고 권한을 확인하기 위해 모델 서비스에서 사용하는 자격 증명. | 잘못되었거나 만료되었거나 권한이 충분하지 않으면 일반적으로 인증 실패를 안내합니다. | 예 |
| 기본 모델 | 비즈니스 기능에서 명시적으로 모델을 지정하지 않을 경우 시스템이 우선 호출하는 모델. | 설정되지 않았거나 사용 불가능한 모델로 설정된 경우 일부 AI 기능을 사용할 수 없습니다. | 예 |

### 5.2 기본 모델 구성 항목

| 구성 항목 | 비즈니스 의미 | 잘못 입력했을 경우 일반적인 영향 | 필수 |
| --- | --- | --- | --- |
| 상태 | 모델 호출 허용 여부를 제어합니다. ShimoDocs Suite종료 후에도 구성은 유지될 수 있지만, 비즈니스는 일반적으로 모델 사용을 계속할 수 없습니다. | 모델 구성이 올바르더라도 상태가 종료인 경우, 비즈니스에서 사용 불가능으로 표시될 수 있습니다. | 예 |
| 모델 ID | 모델 서비스 인터페이스에서 인식하는 모델 이름 또는 고유 식별자. | 서버 이름과 일치하지 않으면 일반적으로 모델이 존재하지 않는다는 메시지를 표시합니다. | 예 |
| 모델 이름 | 관리자가 운영 플랫폼에서 서로 다른 모델을 구별하는 데 도움이 되도록 표시되는 이름. | 이름이 중복되거나 불분명하면 잘못된 모델을 선택하기 쉽습니다; 실제 요청에 참여하는지 여부는 엔지니어링에서 확인합니다. | 예 |
| 컨텍스트 창 | 모델이 단일 요청에서 처리할 수 있는 정보의 총량으로, 보통 입력 텍스트의 길이, 대화 기록, 출력 공간에 영향을 줍니다. | 모델의 실제 용량보다 크게 설정하면 요청 실패가 발생할 수 있고, 너무 작게 설정하면 내용이 잘리거나 제출할 수 없게 될 수 있습니다. | 예 |
| 텍스트 입력 | 모델이 텍스트 내용을 받을 수 있는지 여부를 나타냅니다. | 잘못해서 꺼짐으로 설정하면 텍스트 관련 기능에서 이 모델을 선택하거나 호출할 수 없을 수 있습니다. | 예 |
| 이미지 입력 | 기본 모델이 사용자가 업로드한 이미지를 이해할 수 있는지 여부를 나타냅니다; 이는 멀티모달 입력 기능이며 이미지 생성과는 다릅니다. | 이미지를 지원하지 않는 모델에 대해 활성화하면 요청 실패가 발생할 수 있으며, 꺼짐으로 설정하면 이미지 이해 기능을 사용할 수 없습니다. | 예 |

| 기능 | 모델이 지원하는 이미지 기능을 선언합니다. 예: 이미지 생성, 이미지 편집 등. | 모델이 지원하지 않는 기능을 구성하면, 비즈니스 항목은 표시되지만 호출은 실패할 수 있습니다. | 예 |

### 5.5 임베딩 구성

임베딩 모델은 반드시 활성화할 필요는 없지만, 활성화하지 않으면 문서 내용을 벡터화할 수 없으며, 따라서 시스템이 사용자의 지식 기반과 관련된 질문을 처리할 수 없습니다.

| 구성 항목 | 비즈니스 의미 | 잘못 작성했을 때 일반적인 결과 | 필수 여부 |

| 기본 URL | 텍스트 벡터화 요청에 전송되는 서비스 주소. 주소가 잘못되면 벡터 데이터를 생성하거나 업데이트할 수 없습니다. 아니요 |

| 임베딩 모델 | 텍스트를 벡터로 변환할 실제 모델 ID. 모델이 존재하지 않거나 일치하지 않으면 벡터를 생성할 수 없습니다. 아니요 |
| 차원 | 각 텍스트 라인에서 생성되는 최종 벡터 길이는 모델의 실제 출력 및 벡터 저장 구성과 일치해야 합니다. | 차원이 일치하지 않으면 보통 쓰기 또는 검색이 불가능하며, 차원을 변경한 후 기존 벡터를 다시 생성해야 할 수 있습니다. 아니요 |

중복을 줄이기 위해 다음 순서에 따라 구성하는 것이 권장됩니다:

## Q&A

1. 구성이 효과적인지 어떻게 확인하나요?

구성을 완료한 후, 편집기의 사이드바로 가서 AI 세션을 열어 기능이 작동하는지 확인할 수 있습니다:

- 메시지가 정상적으로 응답되어야 합니다
- 이미지 모델이 구성된 경우, 'Xxx 이미지 생성'과 같은 명령을 보내고 명령이 제대로 실행되는지 확인할 수 있습니다
- 온라인 검색이 구성된 경우, '오늘 베이징 날씨 검색'과 같은 명령을 보내고 결과가 기대에 부합하는지 확인할 수 있습니다

2. /chat/completions 인터페이스를 지원하나요?

현재는 지원되지 않습니다. 현재는 OpenAI Responses만 지원합니다 API 프로토콜이 지원됩니다. Deepseek / Xiaomi-Mimo 같은 공식 API가 이 프로토콜을 지원하는 것으로 알려져 있습니다. vLLM 및 Ollama와 같은 로컬 배포 솔루션도 Responses 프로토콜을 지원합니다.
