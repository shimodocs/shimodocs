# 시스템 구성

[← ShimoDocs Suite 배포 문서](../../../README.md)

## 1. 지침

이 매뉴얼은 "시스템 구성(System Configuration)" 기능을 소개하며, ShimoDocs Suite이 기능을 처음 사용하는 시스템 관리자 및 구현자를 대상으로 합니다. 본 문서의 단계를 따라 구성 항목을 찾고, 구성을 수정하며, 변경 사항이 적용되는지 확인하고, 필요 시 원래 설정으로 복원할 수 있습니다.

> [!TIP]
>
> 구성 항목의 의미나 영향이 확실하지 않은 경우, 변경을 수행하기 전에 ShimoDocs 기술 지원 팀에 확인해 주십시오.

**가장 중요한 범위 규칙** Enterprise ID가 비어 있는 경우 조회 및 수정은 글로벌 구성에 적용되며, Enterprise ID가 선택된 경우 조회 및 수정은 선택된 기업의 구성에 적용됩니다. 글로벌 구성을 수정하면 여러 기업에 영향을 줄 수 있으므로, 저장 전에 구성 범위를 다시 확인하십시오.

### 1.1 접근 경로

관리자 백엔드 > ShimoDocs Suite > 구성 관리 > 시스템 구성

### 1.2 사용 전 준비

- 로그인 계정이 시스템 구성에 대한 조회 및 편집 권한을 가지고 있는지 확인하십시오. ShimoDocs Suite 
- 대상 범위가 글로벌인지 특정 기업인지 먼저 확인하고, 정확한 기업 ID를 확보합니다.
- 설정 요구 사항이나 부록 A에서 구성 키 이름을 확인합니다. 구성 키 이름은 고유 식별자이므로 중국어 이름만으로 추측하지 마십시오.
- 수정 전 소스, 상태 및 유효 값을 기록하고, 중요한 구성의 경우 롤백 값도 준비합니다.
- 영향이 큰 글로벌 구성은 업무가 적은 기간에 수정해야 하며, 관련 인원에게 사전에 알립니다.

## 2. 구성 범위 및 우선순위

시스템 구성은 글로벌 범위와 엔터프라이즈 범위를 모두 지원합니다. 수정을 하기 전에 페이지 하단의 엔터프라이즈 ID 필드와 범위 프롬프트를 확인해야 합니다.

| **기능 영역** | **글로벌 범위** | **엔터프라이즈 범위** | **페이지 식별 신호** |
| --- | --- | --- | --- |
| 시스템 구성 | 엔터프라이즈 ID 비우기 | 엔터프라이즈 ID 선택 | 하단 프롬프트 “글로벌 버전 재정의” 또는 “엔터프라이즈 최종 유효 결과” |

*그림 1  시스템 구성에서 엔터프라이즈 ID를 선택하는 위치*

### 2.1 글로벌 구성

- 엔터프라이즈 ID를 선택하지 않은 상태로 둡니다.
- 페이지에는 현재 쿼리 및 수정이 '글로벌 버전 재정의'를 위한 것임을 알립니다.
- 글로벌 값은 엔터프라이즈 재정의가 설정되지 않았을 때 사용하는 기본 값이며, 이를 수정하면 여러 엔터프라이즈에 영향을 미칠 수 있습니다.
- 저장하기 전에 엔터프라이즈 ID 필드가 실제로 비어 있는지 최소한 한 번 더 확인하세요.

### 2.2 엔터프라이즈 수준 구성

- 엔터프라이즈 ID 드롭다운에서 대상 엔터프라이즈를 선택합니다.
- 페이지에는 기본 값과 현재 엔터프라이즈의 사용자 정의 구성을 병합한 후 최종 유효 결과가 표시됩니다.
- 엔터프라이즈 수준 구성은 선택한 엔터프라이즈에만 영향을 미치며 다른 엔터프라이즈의 구성을 직접 변경하지 않습니다.
- 동일 항목에 대해 엔터프라이즈 수준 구성이 존재할 경우, 엔터프라이즈의 최종 유효값이 글로벌 값보다 우선합니다.

### 2.3 재정의, 상속 및 복원

- 현재 엔터프라이즈에 재정의가 없는 경우, 전역 구성 또는 시스템 기본값이 사용됩니다.
- '시스템 기본값 복원'과 같은 작업이나 현재 재정의 삭제는 일반적으로 현재 범위의 재정의를 제거하고 상위 수준 값을 다시 상속받는 것을 의미합니다.
- '시스템 기본값', '전역 버전 재정의', '엔터프라이즈 최종 유효 결과'와 같은 페이지의 안내 문구를 통해 현재 값이 어떤 계층에서 오는지 확인할 수 있습니다.
- 복원 또는 삭제를 수행하기 전에 현재 값을 기록하고 상속된 결과가 기대에 부합하는지 확인하십시오.

**위험 경고** 엔터프라이즈 범위를 확인하지 않고 바로 저장하지 마십시오. 엔터프라이즈 ID가 비어 있으면, 작업이 전역 재정의를 작성하고 여러 엔터프라이즈에 영향을 줄 수 있습니다.

## 3. 시스템 구성

시스템 구성은 일반 기능, 할당량 및 운영 매개변수를 확인하고 조정하는 데 사용됩니다. ShimoDocs Suite.

### 3.1 검색 방법 1: 정확 검색

- 엔터프라이즈 ID: 전역의 경우 비워 두고, 엔터프라이즈 수준 구성을 위해 엔터프라이즈 ID를 선택하십시오.
- 검색 기준: 필요에 따라 유형, 값 유형, 유효 종료를 선택합니다; 확실하지 않은 경우 "전체"를 유지합니다.
- 키 이름: 구성 키 이름을 입력합니다; 키당 한 줄씩 입력하거나 여러 키는 쉼표로 구분합니다.
- "검색"을 클릭하여 결과에서 이름, 키, 소스, 상태 및 현재 값을 확인합니다.
- 대상 행의 가장 오른쪽에 있는 "편집"을 클릭하여 수정 팝업을 엽니다.

*그림 2  시스템 구성 정밀 검색 영역*

*그림 3  구성 키 이름으로 정밀 검색 후 단일 결과*

**범위 힌트** 페이지 하단에 "기업이 선택되지 않은 경우 현재 조회 및 수정은 글로벌 버전 재정의를 위한 것입니다"가 나타나면 현재 범위가 글로벌임을 나타냅니다. 기업을 선택한 후 페이지는 기본 값과 현재 기업의 사용자 정의 구성을 결합한 최종 유효 결과를 표시합니다.

### 3.2 두 번째 검색 방법: 목록에서 직접 찾기

- 기업 범위와 필터 조건을 올바르게 유지하고, 목록을 탐색할 때 페이지 스크롤을 사용하세요.
- '이름(Name)' 또는 '키 이름(Key Name)'으로 대상 구성을 확인하고, 현재 값만으로 판단하지 마세요.
- 같은 행에서 유형, 유효 종료, 현재 값, 출처, 상태를 확인하세요.
- 가장 오른쪽의 '편집(Edit)'을 클릭하세요. 작업 열이 보이지 않으면 테이블을 수평으로 스크롤하거나 브라우저 화면을 확대하세요.

### 3.3 다양한 유형의 시스템 구성 편집

#### 3.3.1 키-값(Key-Value) 유형

편집 팝업 상단에는 키 이름, 이름, 설명, 유형, 유효 종료 등 읽기 전용 메타데이터가 표시됩니다. 활성화되어 있을 때, '문자열 값(String Value)'과 같은 입력 상자에 값을 입력하고 저장하세요. 문자열에 포함된 경우 JSON, URL, 경로(path), 또는 목록(list)은 원래 형식을 유지해야 합니다.

*그림 4  시스템 구성 키-값 유형 편집 팝업*

#### 3.3.2 할당량(Quota) 유형

쿼터 팝업에는 일반적으로 상태(Status), 최소값(Minimum Value), 최대값(Maximum Value), 그리고 '검증 안 함(No Validation)' 스위치가 포함됩니다. 설정을 활성화한 후, 비즈니스 요구사항에 따라 범위를 입력하십시오; '검증 안 함'을 켜면 시스템이 입력한 범위에 따라 제한 검사를 수행하지 않습니다. 값은 '개', 'MB' 등과 같은 팝업 단위와 일치해야 합니다.

*그림 5 시스템 설정 쿼터 유형 편집 팝업*

#### 3.3.3 기능 유형

기능 유형은 주로 상태 토글을 기반으로 합니다. 켜짐은 현재 범위에서 구성 항목이 활성화됨을 의미하고, 꺼짐은 비활성화되었거나 활성화되지 않았음을 의미합니다. 일부 키는 반대 의미를 가질 수 있으며, 구성 항목 이름과 설명에 따라 판단해야 합니다. 예를 들어, 이름에 'unsupport' 또는 'disable'이 포함된 키는 켜질 경우 '지원되지 않음' 또는 '비활성화됨'을 의미할 수 있습니다.

### 3.4 저장, 삭제 및 복원

- 저장하기 전에, 기업 범위, 키 이름, 유형, 단위 및 수정된 값을 다시 확인하십시오.
- 저장한 후, 동일한 구성 항목을 다시 검색하여 소스, 상태 및 유효 값이 변경되었는지 확인합니다.
- 현재 범위에 오버라이드가 있는 경우 '삭제' 작업을 사용할 수 있으며; 오버라이드를 삭제하면 이전 수준에서 상속된 값으로 되돌아갑니다.
- 롤백이 필요한 경우, 먼저 원래 기록된 값을 다시 작성하거나 상속 관계를 확인한 후 현재 오버라이드를 삭제합니다.
- '삭제'를 구성 항목 자체를 삭제하는 것으로 이해하지 마십시오; 페이지에서의 삭제는 일반적으로 현재 범위의 오버라이드 기록에만 적용됩니다.

## 4. 유효성 검증 및 롤백

### 4.1 저장 후 검증

- 시스템 구성 페이지에서 동일한 기업 범위와 동일한 구성 항목을 다시 조회하여 소스, 상태 및 유효 값을 확인합니다.
- 이 구성을 실제로 사용하는 기능 페이지로 이동하여 기능의 성능을 확인하고, 단순히 구성 백엔드를 보는 것에 그치지 않습니다.
- 글로벌 구성의 경우, 기업 수준 구성이 없는 최소 한 개의 회사를 샘플 검사해야 합니다; 기업 수준 구성은 대상 회사에 대해서만 검증됩니다.
- 계정, 권한 또는 캐시 관련 설정의 경우, 필요시 페이지를 새로 고치거나 다시 로그인하거나 캐시가 업데이트될 때까지 기다립니다.
- 수정 시간, 작업자, 기업 범위, 키 이름, 수정 전후 값 및 검증 결과를 기록합니다.

### 4.2 롤백

- 확실한 원래 값이 있는 경우: 원래 값을 다시 편집하여 작성합니다.
- 현재 범위 오버라이드만 제거하면 됩니다: '시스템 기본값 복원'을 사용하거나 현재 오버라이드를 삭제합니다.
- 롤백 후, 소스 값과 유효 값을 다시 조회하고, 비즈니스 페이지에 다시 들어가 검증합니다.
- 글로벌 변경으로 광범위한 이상이 발생하면, 우선 글로벌 적용 범위를 복원하고, 이후 개별 기업 간 적용 범위 차이를 조사합니다.

**중요 사항** 페이지에서의 삭제는 일반적으로 현재 범위 내의 오버라이드 레코드에 적용되며, 구성 항목 자체는 여전히 존재합니다. 삭제 전에 상속된 값이 기대치에 맞는지 확인할 필요가 있습니다.

## 5. 자주 묻는 질문

| **질문** | **처리 방법** |
| --- | --- |
| 편집 또는 작업 버튼을 찾을 수 없음 | 테이블이 넓을 경우, 오른쪽 끝까지 가로로 스크롤하세요; 브라우저의 표시 영역을 확대할 수도 있습니다. |
| 정확한 검색 결과가 없음 | 키 이름의 대소문자 및 밑줄을 확인; 기업 ID 범위를 확인; 지나치게 엄격한 유형, 값 유형 또는 유효 종료 필터를 해제합니다. |
| 저장 후 비즈니스 페이지에 변경 사항이 없음 | 잘못된 기업 범위가 선택되었는지, 소스가 기업에 의해 덮어쓰여지고 있는지, 새로 고침 또는 재로그인이 필요한지 확인하고 구성 항목이 현재 기능에 적용 가능한지 확인합니다. |
| 시스템 기본값 복원 버튼 사용 불가 | 현재 범위에는 오버라이드가 없으며, 현재 상속 값 또는 시스템 기본값을 사용하고 있습니다. |
| JSON 또는 URL 구성 오류 | 유효하게 유지 JSON 또는 URL 형식, 따옴표, 쉼표 또는 프로토콜을 생략하지 마십시오; 먼저 테스트 엔터프라이즈에서 확인하십시오. |
| 엔터프라이즈 최종 유효 값이 전역 값과 다릅니다. | 현재 엔터프라이즈에 재정의가 있을 수 있습니다. 엔터프라이즈 차이를 유지할지 상속을 복원할지 확인하려면 소스 및 재정의 기록을 확인하십시오. |
