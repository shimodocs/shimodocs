# 편집기 구성

[← ShimoDocs Suite 배포 문서](../../../README.md)

## 1. 매뉴얼 사용 방법

이 매뉴얼은 시스템 관리자 및 처음으로 이 기능을 사용하는 수행자를 위해 '에디터 구성(Editor Configuration)' 기능을 소개합니다. ShimoDocs Suite이 문서의 단계를 따라 구성 항목을 찾고, 기능 스위치 또는 쿼터를 수정하며, 적용 여부를 확인하고, 필요 시 원래 설정으로 복원할 수 있습니다.

**가장 중요한 범위 규칙** 팀 ID가 비어 있는 경우 기본 애플리케이션 구성을 조회 및 수정하며, 팀 ID를 입력하면 해당 팀의 구성을 조회 및 수정합니다. 기본 애플리케이션 구성을 수정하면 여러 팀에 영향을 줄 수 있으므로 저장하기 전에 구성 범위를 다시 확인하십시오.

### 1.1 접근 경로

관리자 백엔드 > ShimoDocs Suite > 구성 관리 > 에디터 구성

### 1.2 사용 전 준비 사항

- 로그인 계정이 ShimoDocs Suite 에디터 구성을 보기 및 수정할 권한이 있는지 확인하십시오.
- 먼저 대상 범위가 기본 애플리케이션인지 특정 팀인지 확인하고, 정확한 팀 ID를 확인하십시오.
- 설정 요구 사항 또는 부록 A에서 구성 항목 이름을 확인하십시오. 구성 항목 이름은 고유 식별자이므로, 중국어 기능 이름만을 보고 추측하지 마십시오.
- 수정 전에 소스, 유효 값, 제한 상태를 기록하십시오. 중요한 구성의 경우, 롤백 값도 준비하십시오.
- 기본 애플리케이션 구성은 영향 범위가 넓으므로, 업무가 적은 시간대에 수정하고 관련 책임자에게 사전에 통보하는 것이 좋습니다.

## 2. 구성 범위 및 우선순위

편집기 구성은 두 가지 범위를 지원합니다: 앱 기본(App Default)과 팀(Team). 변경하기 전에 페이지 상단의 팀 ID와 '현재 차원(Current Dimension)'을 꼭 확인해야 합니다.

| **기능 영역** | **앱 기본 범위** | **팀 범위** | **페이지 인식 표시기** |
| --- | --- | --- | --- |
| 편집기 구성 | 팀 ID를 비워두기 | 양의 정수 팀 ID 입력 | 현재 차원에는 '앱 기본(App Default)' 또는 '팀(Team)'이 표시됩니다 |

*그림 1 팀 ID와 현재 차원의 대응 관계*

### 2.1 애플리케이션 기본 범위

- 팀 ID를 비워 둡니다.
- 페이지 상단에 '현재 차원: 애플리케이션 기본'이 표시됩니다.
- 애플리케이션 기본 값은 팀 오버라이드가 설정되지 않았을 때의 기본값입니다. 이를 수정하면 여러 팀에 영향을 줄 수 있습니다.
- 저장하기 전에 팀 ID가 실제로 비어 있는지 다시 확인하여 팀 요구 사항이 실수로 애플리케이션 기본 설정으로 저장되지 않도록 합니다.

### 2.2 팀 범위

- 팀 ID 필드에 대상 팀의 양의 정수 ID를 입력한 후 '조회'를 클릭합니다.
- 페이지 상단에 '현재 차원: 팀'이 표시됩니다.
- 팀 수준 구성은 입력된 팀 ID에 해당하는 팀에만 영향을 미치며, 다른 팀의 구성은 직접 변경하지 않습니다.
- 구성 항목에 팀 수준 설정이 있는 경우, 팀 유효 값이 애플리케이션 기본 값을 우선합니다.

### 2.3 오버라이드, 상속 및 복원

- 현재 팀에 사용자 정의 재정의가 없는 경우, 애플리케이션 기본 구성 또는 시스템 기본 값이 사용됩니다.
- 목록의 "출처(Source)"는 현재 값이 시스템 기본값, 애플리케이션 재정의, 또는 팀 재정의에서 나오는지 확인하는 데 도움이 됩니다.
- 현재 레이어 재정의를 삭제한 후에는 구성은 일반적으로 상위 레벨 값을 다시 상속합니다. 삭제 전에 상속 후 결과를 확인하십시오.
- 수정 또는 복원 후 동일한 팀 ID와 구성 항목을 다시 조회하여 출처 및 유효 값이 예상과 일치하는지 확인하십시오.

**위험 경고** 현재 차원을 확인하지 않고 직접 저장하지 마십시오. 팀 ID가 비어 있는 경우, 작업이 애플리케이션 기본 범위에 기록되어 여러 팀에 영향을 줄 수 있습니다. 

## 3. 편집기 구성 

편집기 구성은 기능 스위치, 사용 할당량 및 편집기의 구조화된 구성을 조회하고 조정하는 데 사용됩니다. ShimoDocs Suite 타입별로 필터링하거나 "고급 필터(Advanced Filter)"를 확장하고 "이름 화이트리스트(Name Whitelist)"에 구성 항목 이름을 입력하여 정확히 검색할 수 있습니다. 

### 3.1 페이지 필드 

| **필드** | **설명** | 
| --- | --- | 
| 앱 ID | 현재 ShimoDocs Suite 애플리케이션 식별자, 컨텍스트 확인용으로만 사용됨. | 
| 현재 차원 | 팀 ID가 비어있을 때 '애플리케이션 기본값'; 팀 ID 입력 후 '팀'. | 
| 팀 ID | 팀 식별자; 양의 정수만 허용. | 
| 유형 | 옵션: 전체, 기능, 단일 값 쿼터, 범위 쿼터 또는 구성. JSON 구성 | 
| 고급 필터 | 구성 항목 이름 입력란 확장. | 
| 이름 허용 목록 | 구성 항목 이름 입력; 한 줄에 하나씩 또는 영어 쉼표로 구분 가능. | 
| 출처 | 현재 값이 시스템 기본값, 애플리케이션 재정의, 또는 팀 재정의에서 나왔는지 표시. | 
| 유효 값 | 현재 범위에서 사용되는 실제 스위치, 쿼터 또는 구조화된 구성. | 
| 액션 | 편집용 연필 아이콘; 현재 레이어 재정의를 제거하는 삭제 아이콘. | 

*그림 2 편집기 구성 조회 영역, 결과 목록 및 액션 열*

### 3.2 정밀 검색

1. 구성 범위에 따라 팀 ID를 입력할지 결정합니다: 애플리케이션의 기본 범위를 사용하려면 비워 두고, 해당 팀에 대해 입력하려면 값을 채우십시오.
2. 필요에 따라 "유형"을 선택합니다; 유형이 확실하지 않으면 "전체"로 두십시오.
3. "고급 필터"를 클릭하여 "이름 허용 목록"을 확장합니다.
4. 전체 구성 항목 이름을 입력합니다. 여러 이름을 입력할 경우, 한 줄에 하나씩 입력하거나 쉼표로 구분하십시오.
5. "조회"를 클릭하여 결과에서 이름, 유형, 출처 및 유효 값을 확인합니다.
6. 대상 행의 가장 오른쪽 연필 아이콘을 클릭하여 편집 팝업을 엽니다.

*그림 3 '고급 필터' 클릭 후 이름 허용 목록 입력*

*그림 4 편집을 위해 정확히 검색한 후 단일 결과_제한_모시트_크기*

**작업 팁** 작업 아이콘이 보이지 않으면 리스트를 수평으로 오른쪽 끝까지 스크롤하거나 브라우저의 표시 영역을 확대하십시오.

### 3.3 리스트에서 직접 검색

- 먼저 팀 ID와 유형 필터가 올바른지 확인한 후, 쿼리 결과를 스크롤하세요.
- 대상 구성을 확인할 때 '이름'과 '유형'을 모두 사용하세요; 현재 값만 의존하지 마세요.
- 페이지에 표시되는 레코드 수는 배포 버전과 현재 애플리케이션에서 지원하는 구성 항목에 따라 달라질 수 있습니다.
- 대상 행을 찾은 후, 가장 오른쪽의 연필 아이콘을 클릭하여 편집 모드로 들어갑니다.

### 3.4 구성 편집

#### 3.4.1 기능

기능 유형은 특정 기능의 사용 가능 여부를 제어하는 데 사용됩니다. 편집 팝업을 연 후, 페이지에서 제공하는 상태(예: '지원' 또는 '숨김')를 '유효 값' 드롭다운에서 선택한 다음, '저장'을 클릭합니다. 일부 구성 항목 이름에는 '미지원' 또는 '비활성'과 같이 반대 의미가 포함될 수 있으므로, 항목 이름과 설명을 기반으로 실제 의미를 판단하시기 바랍니다.

*그림 5 기능 유형 구성 항목의 유효 값 설정*

#### 3.4.2 단일 값 할당

단일 값 할당량에는 일반적으로 "제한 확인" 스위치와 "최대 값"이 포함됩니다. 제한 확인이 활성화되어 있으면 시스템은 최대 값에 따라 검증을 수행하며, 비활성화되어 있으면 일반적으로 "무제한"으로 표시됩니다. 최대 값은 매개변수의 허용 범위 내에 있어야 하며, MB, GB, 페이지, 항목 또는 문자와 같이 매개변수 이름에 있는 단위와 일치해야 합니다.

*그림 6 단일 값 할당량 검증 및 최대 값 설정*

#### 3.4.3 범위 할당량

- 범위 할당량에는 일반적으로 최소값과 최대값이 모두 제공됩니다.
- 최소값은 최대값보다 클 수 없으며, 입력 값은 페이지 또는 부록에 제공된 허용 범위 내에 있어야 합니다.
- 페이지에서 "검증 없음" 또는 "제한 없음" 옵션을 제공하는 경우, 먼저 현재 기능이 이 설정을 지원하는지 확인하십시오.
- 저장 후 실제 비즈니스 기능에서 경계 값을 확인하여 구성 백엔드에서 표시만 확인하는 것을 피하십시오.

#### 3.4.4 JSON 구성

- JSON 구성은 쌍을 이루는 따옴표, 쉼표, 괄호 및 올바른 데이터 유형을 포함하여 유효한 구조를 유지해야 합니다.
- 변경하기 전에 전체 원본 값을 저장하십시오; 한 필드만 기록하지 마십시오.
- 필드 의미가 불분명할 경우, 필드를 임의로 추가, 삭제 또는 이름 변경하지 마십시오.

### 3.5 저장 및 삭제

- 저장하기 전에 현재 차원, 팀 ID, 구성 항목 이름, 유형, 단위 및 새 값을 다시 확인하십시오.
- 저장 후 동일 범위 및 동일 구성 항목을 다시 조회하여 원본 값과 유효 값이 업데이트되었는지 확인하십시오.
- 삭제 아이콘은 일반적으로 구성 항목 자체를 삭제하는 것이 아니라 현재 범위의 오버라이드 기록을 제거하는 데 사용됩니다.
- 이 매뉴얼에는 현재 페이지에서 조회 및 수정할 수 있는 구성 항목만 나열되어 있으며, 실제 표시 항목은 배포 버전 및 현재 애플리케이션 지원 기능에 따라 다를 수 있습니다.

### 3.6 구성 항목 설명

부록 A에는 현재 페이지에서 조회 및 수정할 수 있는 편집기 구성 항목만 포함됩니다. 구체적인 표시 범위는 현재 배포 버전과 페이지의 실제 표시 상태에 따라 달라질 수 있습니다.

## 4. 효과 검증 및 롤백

### 4.1 저장 후 검증

- 편집기 구성 페이지에서 동일한 팀 ID와 동일한 구성 항목을 다시 조회하여 출처, 유효 값 및 제한 상태를 확인합니다.
- 실제로 이 구성을 사용하는 편집기 또는 기능 페이지에 들어가 기능이 표시되는지, 쿼터가 적용되는지, 제한이 해제되었는지 확인합니다.
- 기본 구성을 적용할 때 팀 수준 구성이 설정되지 않은 최소 한 팀 이상으로 확인하며, 팀 수준 구성의 경우 대상 팀 ID만 검증합니다.
- 필요한 경우 페이지를 새로 고치거나, 편집기를 다시 열거나, 다시 로그인하거나, 캐시 업데이트를 기다립니다.
- 수정 시간, 작업자, 구성 범위, 팀 ID, 구성 항목 이름, 수정 전후 값 및 검증 결과를 기록합니다.

### 4.2 롤백

- 원래 값이 기록되어 있는 경우, 다시 편집하여 원래 값을 다시 작성합니다.
- 현재 범위 오버라이드만 제거해야 하는 경우, 삭제 아이콘을 사용하고 삭제 후 상위 레벨에서 상속된 값을 확인합니다.
- 롤백 후, 소스와 유효 값을 다시 조회하고 비즈니스 페이지에 들어가서 다시 확인합니다.
- 기본 구성 수정 적용 시 이상이 발생하면 먼저 기본 값을 복원한 후, 어떤 팀이 독립적인 오버라이드를 가지고 있는지 확인합니다.

**중요 사항** 현재 오버라이드를 삭제하면 페이지에 즉시 상속된 값이 나타날 수 있습니다. 삭제 전에 상위 레벨 구성이 기대에 부합하는지 확인하고, 수정 전 상태를 기록으로 남겨야 합니다.

## 5. 자주 묻는 질문

| **문제** | **해결 방법** |
| --- | --- |
| 구성 항목 이름 입력 상자를 찾을 수 없음 | "고급 필터"를 클릭하여 "이름 허용 목록"을 확장합니다. |
| 편집 또는 삭제 아이콘을 찾을 수 없음 | 목록을 가로로 끝까지 스크롤하거나 브라우저 뷰포트를 확장합니다. |

| 단일 값 할당량 | 최대 값과 선택적 제한 검증 스위치 |
