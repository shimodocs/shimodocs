# RDB 도구

[← ShimoDocs Suite 배포 문서](../../../README.md)

> [!TIP]
>
> RDB 작업 운영 플랫폼에서 관계형 데이터베이스 데이터를 보고 문제를 해결하는 데 사용되며, 일반적으로 비즈니스 기록, 구성 기록, 작업 상태, 운영 로그 및 기타 구조화된 데이터를 확인하는 데 사용됩니다.
>
> 사용하기 전에 현재 계정이 미들웨어 도구 권한을 가지고 있는지, 올바른 배포 환경이 선택되었는지 확인하십시오.

> 사용자는 RDB 도구는 데이터베이스 데이터를 직접 액세스합니다. 쿼리를 실행하기 전에, 높은 비용의 쿼리를 실행하거나 운영 데이터가 잘못 조작되지 않도록 테이블과 필터 조건을 확인하십시오.

## 1. 접근 RDB

1. <서비스 이름>에 로그인 **MDP 운영 플랫폼**.
2. 선택 **시스템 서비스** 상단에 있습니다.
3. 확장 **미들웨어 도구** 왼쪽 탐색 패널에서.
4. 선택 **RDB**.

페이지에는 일반적으로 데이터베이스 연결, 테이블 선택, SQL 입력 및 쿼리 결과 영역이 포함됩니다.

## 2. 데이터베이스 연결 선택

1. 페이지에서, RDB 액세스해야 하는 데이터베이스 인스턴스를 선택하십시오.
2. 인스턴스 이름, 데이터베이스 주소 또는 환경 식별자가 현재 문제 해결 대상과 일치하는지 확인합니다.
3. 대상 데이터베이스를 선택합니다.
4. 테이블 목록을 확장하고 대상 테이블이 존재하는지 확인합니다.

> 데이터베이스 인스턴스가 비어 있거나 연결에 실패하면, 먼저 미들웨어 구성, 계정 권한 및 네트워크 연결을 확인하십시오.

## 3. 테이블 구조 보기

1. 왼쪽의 테이블 목록에서 대상 테이블을 선택합니다.
2. 필드 이름, 필드 유형, 기본 키 및 인덱스 정보를 확인합니다.
3. 필드 의미를 기반으로 이후 쿼리 조건을 확인합니다.

다음 정보를 중심으로 확인하는 것이 좋습니다:

| 정보 | 설명 |
| --- | --- |
| 기본 키 | 단일 레코드를 정확하게 조회하는 데 사용됩니다. |
| 비즈니스 ID | 예: 테넌트 ID, 사용자 ID, 작업 ID, 파일 ID. |
| 상태 필드 | 비즈니스의 현재 흐름 상태를 확인하는 데 사용됩니다. |
| 시간 필드 | 쿼리 시간 범위를 제한하는 데 사용됩니다. |
| 인덱스된 필드 | 전체 테이블 스캔을 줄이기 위해 가능한 한 쿼리 필터로 사용하는 것이 좋습니다. |

## 4. 공용 사용하기 SQL

'공용' SQL'공용'은 미리 설정된 쿼리를 빠르게 실행할 때 사용되며, 증명서, 신청서, 파일, 사용자 등 빈번한 확인 시나리오에 적합합니다.

1. 클릭 **공용 SQL** 편집기 위에 SQL 드롭다운 목록에서 사용해야 합니다.
2. 선택 SQL 선택합니다.
3. 먼저 문장 내용을 확인해야 하는 경우, 클릭합니다 **미리보기** 해당 항목 옆의 SQL.
4. 설명, 데이터베이스, 테이블 이름 및 내용 SQL 미리보기 창에서 확인합니다.
5. 모든 것이 올바른 것을 확인한 후, 클릭합니다 **실행**.

자주 사용되는 SQL 자리 표시자가 포함될 수 있습니다:

| 자리 표시자 | 매개변수 유형 | 예시 |
| --- | --- | --- |
| `%s` | 문자열 | 앱 ID, 제공자 파일 ID, 히스토리 GUID, 제공자 사용자 ID |
| `%d` | 숫자 | 내부 사용자 ID |

해당 SQL 자리 표시자가 포함되어 있으면, **입력 SQL 매개변수** 실행 시 창이 나타납니다.

1. 프롬프트에 따라 각 매개변수를 채웁니다.
2. 문자열 매개변수의 경우, 추가 따옴표 없이 전체 ID를 입력합니다.
3. 숫자 매개변수는 순수 숫자로 입력합니다.
4. 클릭 **쿼리 실행**.

일반적으로 사용되는 SQL 현재 주로 다음 시나리오를 포함합니다:

| 시나리오 | 설명 |
| --- | --- |
| 인증서 조회 | 애플리케이션 인증서 및 애플리케이션 ID 조회 |
| 지정된 appid로 조회 | 애플리케이션 ID로 애플리케이션 세부 정보 조회 |
| 지정된 고객 파일 guid로 조회 | 파일 세부 정보 조회 `provider_file_id`. |
| 지정된 내부 파일 guid로 조회 | 파일 세부 정보 조회 `history_guid`. |
| 지정된 내부 사용자 id로 조회 | 내부 사용자 ID로 사용자 세부 정보 조회 |
| 지정된 고객 사용자 id로 조회 | 사용자 세부 정보 조회 `provider_user_id`. |

> 일반적으로 사용되는 것을 사용하기 이전에도 SQL대상 환경과 매개변수 값을 확인할 필요가 있습니다. 일반적으로 SQL 사용되는 것은 수동 작성 비용을 줄이기 위한 것이며, 쿼리 결과가 이 조사 목적에 부합할 것이라는 보장은 없습니다.

## 5. 쿼리 실행

1. 입력 영역에 쿼리 문을 작성합니다. SQL 
2. 쿼리를 사용하는 것을 선호하며 삽입, 갱신 또는 삭제 문은 실행하지 마십시오. `SELECT` 
3. 기본 쿼리 LIMIT 는 10이며 수동으로 조정할 수 있습니다.
4. 클릭 **쿼리 실행**.
5.  EXPLAIN, 및 **쿼리를 시작하기 전에 실행 확인을 수행하는 것이 좋습니다.** 

예:

```sql
SELECT *
FROM example_table
WHERE id = 'example-id';
```

## 6. 쿼리 결과 보기

1. 결과 영역에서 반환된 레코드를 확인합니다.
2. 키 필드가 예상과 일치하는지 확인합니다.
3. 결과가 비어 있으면, 데이터베이스, 테이블 이름, 쿼리 조건 및 시간 범위를 확인합니다.
4. 결과가 너무 많으면, 더 정확한 필터링 조건을 추가하고 다시 쿼리합니다.

## 7. 쿼리 기록 사용

'쿼리 기록'은 현재 페이지에서 실행된 SQL 문장을 확인하는 데 사용되며, 문제 해결용 문장을 다시 사용하거나, 실행 결과를 검증하고, 복사하는 데 편리합니다. SQL."

> [!NOTE]
>
> 쿼리 기록은 현재 브라우저에 로컬로 저장되며 지속적으로 저장되지 않습니다. 각 데이터베이스/테이블 단위는 최근 100개의 기록까지 유지하며, 현재 자동 시간 기반 만료는 없습니다. 브라우저 사이트 데이터를 삭제하거나, 브라우저를 변경하거나, 장치를 바꾸거나, 다른 데이터베이스/테이블로 전환하면 다른 기록이 표시됩니다.

1. 결과 영역에서 **쿼리 기록** 으로 전환합니다.
2. 실행 상태, 시간, 데이터베이스, 테이블을 확인합니다. SQL, 히스토리 기록에서 반환된 행 수 및 경과 시간.
3. 실행하려면 SQL 문장을 다시 실행하려면 클릭 **해당 기록의 작업 열에서 '편집기에 삽입 후 실행'** .
4. 문장만 재사용하려면 클릭 **복사 SQL**.

쿼리 히스토리 필드 설명:

| 필드 | 설명 |
| --- | --- |
| 상태 | 실행 여부 SQL 성공적으로 실행되었는지; 실패하면 오류 메시지와 함께 문제를 해결하십시오. |
| 시간 | 현재 쿼리의 실행 시간. |
| 데이터베이스 | 실행 중 선택된 데이터베이스. SQL 실행 중 선택된 데이터베이스. |
| 테이블 | 연관된 테이블. SQL 실행 중 선택된 데이터베이스. |
| SQL | 실제로 실행된 쿼리 문. |
| 반환되는 행 수 | 이 쿼리에서 반환된 데이터 행 수. |
| 소요 시간 | SQL 실행에 소요된 시간으로, 느린 쿼리 위험 여부를 판단하는 데 사용될 수 있음. |
| 작업 | 재삽입 및 실행 또는 복사 지원. SQL. |

쿼리 히스토리 문제 해결 시 다음 항목에 집중하는 것이 좋습니다: 

| 상황 | 처리 방법 제안 |
| --- | --- |
| 상태 실패 | 먼저 다음을 확인하십시오. SQL 구문, 데이터베이스-테이블 존재 여부, 필드가 올바른지 여부. |
| 시간이 오래 걸립니다 | 필터 조건을 추가하거나 먼저 테이블 구조와 인덱스 필드를 확인하세요. |
| 너무 많은 행을 반환합니다 | 'WHERE' 조건과 'LIMIT'. |
| 여러 쿼리 결과가 일치하지 않습니다 | 데이터베이스, 테이블 또는 환경이 변경되었는지 확인하세요. |

> 쿼리 기록은 현재 문제 해결 과정을 검토하는 데 도움이 됩니다. 역사적 쿼리를 다시 실행하기 전에 SQL내용, 대상 데이터베이스 및 현재 환경을 반드시 확인해야 합니다. SQL  

## 8. 일반적인 문제 해결 시나리오

| 시나리오 | 운영 제안 |
| --- | --- |
| 비즈니스 기록이 존재하는지 확인하세요 | 정확한 쿼리를 위해 비즈니스 ID를 사용하세요. |
| 작업 상태 확인 | 작업 ID로 상태 필드와 업데이트 시간을 조회하세요. |
| 효과 없는 설정 문제 해결 | 설정 테이블에서 현재 값과 업데이트 시간을 조회하세요. |
| 최근 변경 사항을 확인하세요 | 시간 필드를 기준으로 내림차순 조회하고 반환 항목 수를 제한하세요. |
| 애플리케이션 또는 인증서 정보를 조회하세요 | "일반"에서 인증서 쿼리나 앱 ID 쿼리 사용을 권장합니다 SQL”. |
| 문제 해결 문장 재사용 | 복사 SQL “쿼리 히스토리”에서, 파라미터를 확인하고 다시 실행하십시오. |

## 9. 주의사항

1. 운영 환경에서 대형 테이블에 대한 무조건 쿼리는 금지되어 있습니다.
2. 영향에 확신이 없는 경우, SQL 먼저 위험이 낮은 환경에서 확인하십시오.
3. 명확한 변경 계획과 승인 없이 도구를 통해 비즈니스 데이터를 직접 수정하지 마십시오. RDB 
4. 공통 파라미터는 SQL 환경 간 잘못된 쿼리를 피하기 위해 현재 환경의 실제 값으로 채워야 합니다.
5. SQL 쿼리 히스토리 내에는 민감한 ID가 포함될 수 있으므로, 복사하거나 전달하기 전에 범위를 확인하십시오.
6. 쿼리 결과에 민감한 정보가 포함된 경우, 전체 스크린샷이나 평문 데이터를 외부에 공유하지 마십시오.
