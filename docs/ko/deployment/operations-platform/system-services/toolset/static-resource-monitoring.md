# 정적 리소스 모니터링

[← ShimoDocs Suite 배포 문서](../../../README.md)

정적 리소스 모니터링은 웹 페이지에서 참조하는 JS 및 CSS 리소스를 확인하는 데 사용되며, 리소스 접근 상태, 전송 프로토콜, 캐시 구성 및 CDN 사용 현황을 이해하는 데 도움이 됩니다.

> 시스템 페이지에서 기능 이름은 '정적 리소스 감지'입니다.

## 1. 사용 방법

관리 플랫폼에 로그인하고 선택 **시스템 서비스** 상단에서 선택한 후 **도구 모음 > 정적 리소스 감지 선택** 왼쪽 탐색 막대에 있습니다.

이 기능은 관리자만 사용할 수 있습니다. 항목이 보이지 않으면 계정 권한과 현재 제품 버전을 확인하십시오.

1. 전체 페이지 입력 URL예를 들어 `https://example.com/recent`.
2. 페이지에 로그인이 필요하면 '사용자 정의 요청 헤더'를 확장하고 필요한 정보 입력 `Cookie` 그리고 `Authorization`.
3. '감지 시작'을 클릭하고 결과가 반환될 때까지 기다리십시오.

> 요청 헤더는 페이지에서 참조된 정적 리소스에 접근하는 데에도 사용됩니다. 임시 자격 증명만 사용하고, 교차 출처 리소스의 도메인이 신뢰할 수 있는지 확인하십시오. 페이지 주소, 요청 헤더 및 최신 감지 결과가 현재 브라우저에 저장됩니다.

## 2. 감지 범위

시스템은 JS 및 CSS 페이지에서 직접 참조된 것을 식별합니다 HTML이미지, 폰트, 인라인 코드 또는 스크립트 실행 후 동적으로 로드된 리소스는 감지하지 않습니다.

- 각 도메인에 대해 최대 3개의 동일 도메인 JS 및 CSS 파일이 감지됩니다;
- 한 번에 최대 50개의 교차 도메인 리소스를 감지할 수 있습니다;
- 중복 URL은 한 번만 계산됩니다.

감지되지 않은 동일 도메인 리소스는 '동일 도메인 샘플링 생략'으로 표시되며, 이는 리소스 오류를 의미하지 않습니다.

## 3. 결과 보기

감지가 완료된 후 페이지에 다음이 표시됩니다:

- **요약 정보**: 개수 HTML 자원 수, 감지된 수, 문제 수, 캐시 사용, CDN, 및 HTTP/2;
- **페이지 응답**: 대상 페이지의 상태 코드, 프로토콜 및 캐시 정보;
- **자원 목록**: URL, 상태 코드, 프로토콜, 캐시, CDN, 각 리소스의 문제 및 응답 헤더.

리소스 목록은 '감지됨', '전체', '문제 있음'으로 필터링을 지원합니다. 

시스템은 주로 다음 문제를 나타냅니다: 

- HTTP 4xx/5xx; 
- 유효한 캐시가 감지되지 않음; 
- HTTP/2 사용되지 않음; 
- 교차 출처 리소스는 특성을 표시하지 않음; CDN ; 
- 요청 시간 초과 또는 도메인 이름 확인 실패. 

## 4. 일반적인 문제 

### 페이지 감지 실패 

페이지를 확인하십시오 URL, 네트워크 연결, HTTPS 인증서 및 로그인 상태. 감지 서비스는 브라우저의 로그인 정보를 자동으로 재사용하지 않으므로, 필요할 경우 맞춤 요청 헤더를 제공해 주세요. 

### 리소스를 인식하지 못함 

페이지가 정상적으로 반환되는지 확인해 주세요 HTML. 스크립트에 의해 동적으로 로드된 리소스는 인식되지 않습니다.

## 5. 참고 사항 

- 감지 결과는 이 요청 중 관리 플랫폼의 네트워크에서 관찰된 내용을 반영하며, 실제 사용자 경험과 다를 수 있습니다. 
- CDN, 캐시 및 문제 상태는 자동으로 결정된 결과이며 보조 진단용으로만 사용됩니다. 
- '문제 없음'은 페이지가 전체 성능, 보안 또는 사용성 평가를 통과했음을 의미하지 않습니다. 
- 페이지가 게시된 후 CDN 가 새로 고쳐지거나 네트워크 환경이 변경되면, 재검사가 권장됩니다.
