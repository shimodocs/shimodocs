# 컨테이너 패킷 캡처

[← ShimoDocs Suite 배포 문서](../../../README.md)

## 기능 개요 

컨테이너 패킷 캡처는 실행 중인 파드에서 네트워크 데이터를 수집하는 데 사용됩니다 Kubernetes 환경, 연결 실패, 요청 시간 초과와 같은 문제를 분석하는 데 도움을 줍니다, TCP 재전송 및 네트워크 혼잡. 

캡처가 완료되면 다운로드할 수 있습니다 PCAP 파일을 열고 Wireshark와 같은 네트워크 분석 도구를 사용하여 추가로 검사합니다. 

## 페이지 접근 

관리 콘솔에 로그인한 후, 선택 **컨테이너 패킷 캡처** 왼쪽 탐색에서 페이지에 들어갑니다. 

컨테이너 패킷 캡처는 다음에서만 적용됩니다 Kubernetes 배포 환경에서만 가능하며 관리자만 사용할 수 있습니다. 

## 패킷 캡처 시작 

다음 단계를 따르는 것이 권장됩니다: 

1. 대상 Pod를 검색하고 찾으십시오 **포드 목록**. 
2. 포드 상태가 실행 중인지 확인한 후, 클릭하세요 **캡처 시작**. 
3. 캡처 시간을 선택하세요: 1분, 5분 또는 30분. 
4. 캡처 파일 크기를 선택하세요: 100MB, 500MB 또는 1GB. 
5. 필요한 경우 필터 조건을 선택하거나 수동으로 tcpdump 필터 표현식을 입력하세요. 
6. 페이지에 표시된 전체 캡처 명령을 검토하세요. 
7. 클릭 **캡처 시작** 작업을 생성합니다. 

동일한 Pod에서 동시에 하나의 패킷 캡처 작업만 실행할 수 있습니다. 설정된 기간에 도달하면 작업이 자동으로 종료되거나 수동으로 중지할 수 있습니다. 

## 필터 조건 

필터 조건을 설정하면 관련 없는 트래픽과 파일 크기를 줄일 수 있습니다. 이 페이지는 다음과 같은 일반적으로 사용되는 사전 설정을 제공합니다: 

- 지정된 포트의 트래픽. 
- gRPC 트래픽. 
- 지정된 호스트와 포트. 
- HTTP POST 요청. 
- TCP 연결 수립, 재전송 또는 작은 윈도우 패킷. 

tcpdump 구문을 사용하여 수동으로 입력할 수도 있습니다. 예: 

```text
host 10.0.0.1 and port 80
```

필터 조건이 지정되지 않으면 작업이 Pod에서 많은 양의 네트워크 트래픽을 수집할 수 있습니다.

## 패킷 캡처 작업 관리

페이지에서, **패킷 캡처 작업** 페이지에서 작업 ID, Pod, 상태, 생성 시간, 실행 시간을 확인할 수 있습니다.

- **실행 중**: 작업을 수동으로 중지할 수 있습니다.
- **완료됨**: 그 PCAP 파일을 다운로드할 수 있습니다.
- **실패**: 작업 로그를 확인하여 실패 원인을 알 수 있습니다.

작업 목록은 자동으로 새로고침되거나 클릭하여 **새로 고침** 최신 상태를 수동으로 가져올 수 있습니다.

## 다운로드 및 분석

작업이 완료되면 클릭하세요 **다운로드** 하여 PCAP 파일을 얻으세요. 다운로드 기능은 시스템이 객체 저장소와 올바르게 구성되어 있어야 사용 가능합니다.

PCAP 파일에는 요청 주소, 프로토콜 데이터 또는 기타 민감한 정보가 포함될 수 있습니다. 이러한 파일은 권한 있는 인원에게만 제공하고, 사용 후 적절하게 저장하거나 삭제하세요.

## 일반 상황

- **Pod을 찾을 수 없음**: 페이지는 현재 환경에서 실행 중인 상태인 Pod만 표시합니다. Pod 상태와 배포 환경을 확인하세요.
- **패킷 캡처 시작 불가**: Pod에 진행 중인 패킷 캡처 작업이 없는지 확인하고, Kubernetes 임시 컨테이너에 대한 권한 및 지원을 확인하세요.
- **작업 실행 실패**: 작업 로그를 확인하여 필터 표현식, Pod 상태, 패킷 캡처 구성 요소가 올바르게 작동하는지 확인하세요.
- **파일 다운로드 불가**: 객체 저장소 구성과 네트워크 연결을 확인하세요.
- **패킷 캡처 파일이 너무 큽니다**: 캡처 기간을 줄이고 보다 정밀한 필터 표현식을 사용하세요.

> 패킷 캡처는 특정 네트워크, CPU및 저장소 자원을 소모합니다. 피크 시간 동안 필터 없이 장시간, 대용량 캡처를 수행하는 것은 피하십시오.
