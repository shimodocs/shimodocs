# 미들웨어 점검

[← ShimoDocs Suite 배포 문서](../../../README.md)

## 기능 개요 

미들웨어 검사는 시스템 종속적인 MySQL, Redis, Elasticsearch, S3, MongoDB, 및 Kafka 연결 가능 여부 및 읽기/쓰기 정상 여부를 확인하여 기본 서비스 이상을 적시에 감지하는 데 도움을 줍니다. 

이 페이지는 즉시 검사, 정기 검사, 최근 가용성 추세, 기록 관리, 실패 및 복구 알림을 지원합니다. 

## 페이지 진입 

관리 백엔드에 로그인한 후, **미들웨어 점검** 왼쪽 탐색에서 페이지에 들어갑니다. 

미들웨어 검사는 관리자에게만 열려 있습니다. 이 메뉴가 보이지 않는 경우, 시스템 관리자에게 계정 권한을 확인해 주십시오. 

## 즉시 검사 

페이지에서, **기본적으로 개요가 표시됩니다.** 페이지에서 클릭합니다 **즉시 검사**, 시스템은 저장된 검사 대상에 따라 검사를 수행합니다. 

검사 결과에는 다음 상태가 포함될 수 있습니다: 

- **정상**: 구성 요소 연결 및 검사 작업이 성공했습니다. 
- **실패**: 구성 요소를 연결할 수 없거나, 읽기/쓰기 실패 또는 응답이 비정상입니다. 
- **건너뜀**: 구성 요소가 현재 환경에 구성되어 있지 않거나 검사 조건을 충족하지 않습니다. 

구성 요소 결과를 클릭하면 대상 주소, 응답 시간 및 오류 세부 정보를 확인할 수 있습니다. 

## 가용성 추세 보기 

개요 페이지는 과거 검사 결과를 기반으로 각 구성 요소의 최근 가용성을 표시합니다. 지난 1시간, 6시간, 24시간, 3일, 7일, 14일 또는 30일 동안의 상태 변화를 확인할 수 있습니다. 

해당 기간 위에 마우스를 올리면 그 기간 동안의 검사 횟수, 평균 응답 시간 및 최근 오류와 같은 정보를 볼 수 있습니다. 

## 예약 검사 구성 

페이지에서, **예약 및 알림** 페이지에서는 다음을 설정할 수 있습니다: 

- **예약 검사 활성화**: 활성화하면 시스템이 설정된 간격으로 자동으로 실행됩니다. 
- **검사 간격**: 1분에서 1440분까지 지원합니다. 
- **기록 보관 일수**: 7일에서 365일까지 지원; 값을 설정하면 `0` 자동 정리가 수행되지 않습니다. 
- **검사 대상**: 검사를 수행할 미들웨어를 선택하십시오. 
- **알림 채널**: 검사 알림을 받을 채널을 선택하십시오. 
- **실패 시 알림**: 전체 상태가 정상에서 비정상으로 변경될 때 알림을 전송합니다. 
- **복구 시 알림**: 비정상 상태가 정상으로 복귀할 때 알림을 전송합니다. 

변경 사항은 클릭하여 적용해야 합니다 **저장**. 알림 채널이 없으면 먼저 **알림 채널** 페이지로 이동하여 채널을 생성하고 활성화하십시오.

## 검사 기록 보기

페이지에서, **이력** 페이지에서 검사 시간, 트리거 방법, 실행 시간, 최종 상태를 볼 수 있습니다.

트리거 방법에는 수동 검사와 예약 검사가 포함됩니다. 기록을 클릭하여 이 검사에서 각 구성 요소의 상세 결과를 확인하세요. 

## 일반 상황

- **검사 기록 없음**: 먼저 클릭할 수 있습니다 **지금 검사**, 또는 예약 검사를 활성화하십시오.
- **구성 요소 표시 건너뜀**: 시스템에서 해당 미들웨어가 구성되고 활성화되어 있는지 확인하십시오.
- **검사가 실패했습니다**: 오류 세부정보에 따라 네트워크, 계정, 연결 주소 및 미들웨어 서비스 상태를 확인하십시오.
- **알림이 수신되지 않았습니다**: 알림 채널이 선택되고 활성화되었는지 확인하고, 실패 또는 복구 알림 스위치를 확인하십시오.
- **프롬프트에 검사가 실행 중으로 표시됩니다**: 동시에 하나의 검사 작업만 실행할 수 있습니다. 현재 작업이 완료될 때까지 기다렸다가 다시 시도하십시오.

> 검사는 미들웨어에 대해 경량 연결 또는 읽기/쓰기 검사를 수행합니다. 환경 규모에 따라 적절한 검사 간격을 설정하는 것이 좋습니다.
