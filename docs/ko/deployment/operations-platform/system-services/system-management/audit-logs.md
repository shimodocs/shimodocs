# 감사 로그

[← ShimoDocs Suite 배포 문서](../../../README.md)

## 기능 개요

운영 로그는 시스템 내 사용자 관리 작업을 확인하고 추적하는 데 사용되며, 문제 해결, 보안 감사, 변경 추적에 도움이 됩니다.

이 페이지는 읽기 전용이며 로그 기록 수정 또는 삭제를 지원하지 않습니다.

## 페이지 접근 방법

관리 백엔드에 로그인한 후, **운영 로그** 페이지에 접근하세요.

## 로그 필터링

다음 조건의 조합을 사용하여 조회할 수 있습니다:

- **이벤트 소스**: 예를 들어, 제어판, 애플리케이션 구성 센터, 업데이트 관리자, Kubernetes 자원 관리 또는 사용자 관리 센터.
- **운영 유형**: 이벤트 소스를 기반으로 구성 업데이트, 버전 업그레이드, 서비스 재시작 또는 사용자 관리 작업과 같은 해당 작업을 표시합니다.
- **작업 사용자**: 특정 사용자가 생성한 기록을 필터링합니다.

이벤트 소스를 선택한 후 작업 유형 목록이 자동으로 조정됩니다. 클릭하십시오 **검색** 필터 조건을 적용하거나 재설정 버튼을 클릭하여 조건을 지우십시오.

## 로그 목록 보기

목록에는 주로 다음이 표시됩니다:

- 로그 ID.
- 이벤트 소스 및 작업 유형.
- 작업 사용자.
- 작업 대상의 유형, 이름 및 ID.
- 작업 시간. 

페이지 상단에 로그 총 수가 표시되며, 목록은 페이지네이션 및 페이지당 표시 항목 수 조정을 지원합니다. 

## 로그 세부 정보 보기 

클릭 **세부 정보** 레코드 오른쪽에서 전체 정보를 확인할 수 있습니다. 포함 정보: 

- 소스 및 작업 유형의 이름과 내부 식별자. 
- 작업 수행 사용자 및 사용자 ID. 
- 작업 시간. 
- 대상 유형, 대상 ID 및 대상 이름. 
- 이벤트 메타데이터. 

애플리케이션 구성 센터의 변경 사항에 대해, 세부 정보에는 구성 수정 사항, 릴리스 후 자동 재시작 여부, 재시작된 워크로드가 표시될 수 있습니다.

## 일반 사용 사례

- 특정 구성 변경을 실행한 사람을 확인합니다.
- 시스템 업그레이드, 서비스 재시작 또는 스케일링 작업 시간을 확인합니다.
- 객체 이름을 기준으로 관련 변경 사항을 추적합니다.
- 이벤트 메타데이터를 사용하여 구성 차이와 실행 결과를 확인합니다.
- 오작동이나 예상치 못한 관리 변경을 조사합니다.

## 일반 상황

- **기록이 없습니다**: 필터 조건을 지우거나 선택한 소스, 작업 유형 및 사용자가 일치하는지 확인하십시오.
- **작업 유형 목록이 비어 있습니다**: 먼저 이벤트 소스를 선택하거나 최신 열거를 가져오기 위해 페이지를 다시 로드하십시오.
- **객체 정보가 비어 있습니다**: 일부 시스템 이벤트는 특정 객체와 연결되지 않을 수 있으며, 이는 정상입니다.
- **메타데이터는 형식화된 콘텐츠가 아닙니다**: 일부 과거 이벤트는 일반 텍스트로 저장될 수 있으며, 페이지에 원본 내용이 표시됩니다.
- **로그 수량이 예상과 일치하지 않습니다**: 로그는 시스템에서 감사된 작업만 기록하며, 환경의 보존 정책에 따라 영향을 받을 수 있습니다.

> 작업 로그에는 사용자, 객체 식별자 및 구성 변경 정보가 포함될 수 있으며, 권한이 있는 인원만 접근할 수 있어야 합니다.
