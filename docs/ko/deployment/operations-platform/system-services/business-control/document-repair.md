# 문서 복구

[← ShimoDocs Suite 배포 문서](../../../README.md)

파일이 비정상적으로 손상된 증상에는 문서가 정상적으로 열리지 않거나, 로딩 중 오류 팝업이 나타나거나, 내용이 렌더링되지 않는 경우가 포함됩니다.

문서를 열 수 없을 때, 이 기능을 사용하여 파일을 복구하세요.

# 사용 예시

복구 방법은 2가지가 있습니다.

## 준비 사항

### 파일 유형 빠른 참조

|**파일유형**|**파일 URL 주소 기능**|**비고**|
|:----|:----|:----|
|rdoc(richdoc)|/**문서**/{fileguid}|라이트 문서|
|mosheet(modoc)|/**시트**/{fileguid}|테이블|
|modoc(modoc)|/**docx**/{fileguid}|전문 문서|

### 운영 리스크 경고

수리 실패에는 리스크가 없음

## 암호화 데이터에서 복구 중

테이블 유형 파일만 수리를 지원합니다. 다른 유형의 파일은 [히스토리 데이터에서 복구]를 선택하세요

이 방법이 권장 방법입니다. 파일을 직접 입력하여 GUID 수리를 수행할 수 있습니다. 이 GUID 은 ShimoDocs 파일 GUID.

수리 원리는 객체 스토리지에 있는 암호화 파일 데이터를 암호화되지 않은 파일 내용 데이터로 변환하는 것이며, 대부분의 시나리오에 적용 가능합니다.

이 방법으로 수리에 실패하면 다른 방법을 선택하십시오.

### 파일 GUID

1. 브라우저 개발자 도구 열기

2. 풀 리퀘스트 필터링

3. 요청에서 rp3OMYnMrdcQJZkm, 이 16자리 문자열이 guid입니다

## 히스토리 데이터에서 복원

히스토리 기록에서 복원

1. 고객 파일 ID

2. 파일 유형

   1. 전통적인 문서/스프레드시트/프레젠테이션은 modoc를 선택하세요

   2. 가벼운 문서의 경우, richdoc를 선택하세요

1. 데이터 소스 선택

### 고객 파일 ID

고객이 전체 사이트에서 ShimoDocs 사용하는 경우, 브라우저에서 문서의 파일 주소입니다. 예를 들어, 다음 m8AZMoYMrRsYbOkb

### 데이터 소스를 확인하는 방법 

svc-edit 서비스의 구성을 확인하세요 

구성 항목: history.driver 

mysql인 경우, 'Mongo 데이터 소스 사용' 스위치는 꺼져 있습니다 

mongo인 경우, 'Mongo 데이터 소스 사용' 스위치는 켜져 있습니다
