# 서비스 로그

[← ShimoDocs Suite 배포 문서](../../../README.md)

## 기능 개요 
서비스 로그 기능은 Kibana와 유사한 로그 조회 플랫폼으로, 다양한 ShimoDocs 서비스에서 Pod 로그를 수집할 수 있으며 로그 검색, 쿼리 및 비율 분석 기능을 제공합니다. 

## 입력 및 탐색
왼쪽 메뉴: 시스템 서비스 --> 서비스 운영 --> 서비스 로그

## SQL 모드
입력 상자는 ClickHouse SQL 구문 쿼리를 지원합니다. 입력 후 SQLClickHouse Raw 모드에서 쿼리를 실행할 수 있습니다.

아래 그림과 같이, 입력

``` sql
`_raw_log_` like '%access%'
```

을 사용하여 액세스를 포함하는 모든 로그를 쿼리할 수 있습니다. 

## 조건 필터링
아래 그림과 같이, '조건 추가' 버튼을 클릭하여 새로운 필터 조건을 추가합니다.

## 비율 분석
아래 그림과 같이, 행 레코드에서 필드 옆 아이콘을 클릭하면 드롭다운 메뉴가 열립니다. '상위 값'을 선택하면 현재 시간 범위 내에서 해당 필드의 비율을 오른쪽 상단에서 볼 수 있습니다.

## 필드 설명

| 내장 필드 | 설명 |
| --- | --- |
| lv | 로그의 오류 수준, info, error, warn 포함 |
| container.name | CONTAINER_NAME |
| method | 액세스 로그의 메서드; gRPC 메서드를 출력합니다 gRPC 메서드, HTTP 메서드를 출력합니다 API 경로 |
| peerIP | 피어 IP |
| peerName | 피어의 이름, 예를 들어 서비스 이름 등 |
| comp | 액세스 로그의 구성 요소, 예를 들어 server.begin |
| cost | 액세스 로그에서 소요된 시간(밀리초 단위) |
