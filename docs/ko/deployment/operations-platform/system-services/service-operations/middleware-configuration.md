# 미들웨어 구성

[← ShimoDocs Suite 배포 문서](../../../README.md)

## 1. 개요 

미들웨어 구성은 클라이언트 환경의 다양한 스토리지 및 미들웨어와 통합되며, 컴포넌트와 같은 연결 정보를 중앙에서 관리하는 MDP 운영 플랫폼의 페이지입니다 S3 객체 스토리지, Redis, 메시지 큐 Kafka, 관계형 데이터베이스 MySQL, 문서 데이터베이스 MongoDB, 및 전체 텍스트 검색 Elasticsearch. 구성 변경은 비동기 작업을 통해 클라이언트 환경에 전달되며, 변경 과정 동안 테스트 및 릴리스 진행 상황이 실시간으로 표시됩니다. 

주요 기능: 

- 각 미들웨어에 대한 연결 정보 구성 (엔드포인트, 액세스 키, USERNAMEPASSWORD등) 
- 다른 공급업체 간 전환 (S3 그리고 OSS, AWS / MinIO / 텐센트 클라우드 COS / 화웨이 클라우드 OBS, MySQL 및 DM Dameng) 
- 폼에서 변경된 값 추적; 수정된 필드만 제출됨 
- 각 구성 섹션은 독립적으로 테스트 가능; 검증 통과 후에만 게시 허용 
- 원클릭 게시: 모든 변경된 필드 구성을 일괄 제출하고 비동기 실행 

### 1.1 적용 대상 사용자 

| 역할           | 일반 작업                                     | 
| -------------- | ---------------------------------------------------- | 
| 구현 엔지니어 | 초기 배포 시 미들웨어 연결 정보를 입력하십시오 | 
| 운영 근무 | 자격 증명 교체, 엔드포인트 변경, 테스트 연결 | 
| 긴급 대응 | 백업 미들웨어로 전환하고 타임아웃 구성을 수정하십시오 |

### 1.2 이 모듈에서 권장되지 않는 작업 

벤더 전환(예: S3 → OSS)은 대규모 하위 데이터 마이그레이션이 필요한 변경 사항으로 변경 프로세스에 따라 처리해야 합니다. 여러 환경에서 연결 정보를 일괄 조정하는 것은 이 모듈에 포함되지 않으며, 각 환경에 개별적으로 들어가 페이지를 구성해야 합니다. 미들웨어 용량 계획 및 모니터링 알람은 이 페이지에 포함되지 않으므로 클러스터 관리 및 알람 구성 모듈을 사용하십시오.

## 2. 각 미들웨어 구성의 상세 설명 

### 2.1 S3 오브젝트 스토리지 

**작업 단계**: 왼쪽 메뉴에서 '미들웨어 구성'을 입력하십시오. 기본적으로 이 섹션에 위치 → 아래로 스크롤하면 세 가지 구성 섹션이 순서대로 표시됩니다: 공용 S3 인스턴스 설정, 협업 편집 S3 인스턴스 설정 및 버킷 설정. 

#### 2.1.1 공개 S3 및 협업 편집 S3

**작업 단계**: 먼저 공용 인스턴스 설정을 작성하고, 그런 다음 공동 편집을 작성하세요 S3  S3 인스턴스 설정을 입력한 후, 마지막으로 버킷 설정을 작성합니다. 필드를 수정한 후에는 아래의 "연결 테스트"를 클릭하세요.
두 섹션의 폼 필드는 일관됩니다:
| 필드               | 설명                                                              | 필수 |
| ----------------- | ---------------------------------------------------------------------- | ---- |
| 저장 유형           | 드롭다운 선택 'S3 (객체 저장소)' 또는 'OSS (알리바바 클라우드)'                             | 예   |
| 하위 유형               | 저장 유형을 기반으로 동적으로 로드됨: 경우 S3, 옵션에는 포함 AWS / 텐센트 클라우드 COS / 화웨이 클라우드 OBS / MinIO / 기타; 경우 OSS, 알리바바 클라우드만 OSS 사용 가능 | 예    |
| 액세스 키 ID     | 자격 증명 식별자                                                        | 예   |
| 액세스 키 비밀 | 자격 증명 키, 입력 상자 PASSWORD 마스킹됨 | 예 |
| 지역 | 예를 들어 `cn-north-1` | 예 |
| ForcePathStyle | 체크박스, 경로 스타일 액세스 활성화 여부 | 아니요 |
| SSL | 체크박스, 활성화 여부 HTTPS | 아니요 |
| 엔드포인트 | 내부 서비스 액세스 주소 | 예 |
| 공용 액세스 주소 | 사용자 측 액세스 주소 | 예 |
| 주소 대체 규칙 | 내부 주소를 공용 주소로 매핑하는 데 사용되는 정규식 또는 문자열 | 예 |

#### 2.1.2 버킷 설정 

**작업 단계**: 서버에서 반환된 모든 버킷은 하나씩 순서대로 렌더링되며, 필요에 따라 도메인 이름을 입력할 수 있습니다. CDN  

| 필드       | 설명                  |
| --------- | ------------------------- |
| 버킷 이름 | 버킷 이름         |
| 접두사      | 객체 저장소 경로 접두사  |
| CDN 도메인  | CDN 가속 도메인     |
| 사용 CDN 인증 | 체크박스, 활성화하면 '인증 유형'과 '인증 키' 두 항목이 추가됩니다 |

> 활성화 후 CDN 인증, 해당 인증 유형과 인증 키가 필요합니다. 

### 2.2 Redis
**단계**: 오른쪽 빠른 탐색을 사용하여 Redis 아이콘을 클릭해 이 섹션으로 스크롤 → 모드 선택 → 주소 입력 → PASSWORD → '연결 테스트' 클릭. 

필드 설명:

| 필드     | 설명                        |
| -----     | -----------------------------    |
| 모드      | Standalone 또는 Sentinel          |
| 주소   | Standalone 모드에서의 연결 주소, 예: `redis-sentinel-master-ss:6379` |
| 마스터 이름 | Sentinel 모드에서 필요, 예: `mymaster` |
| 주소 목록 | Sentinel 모드에서 여러 주소, 동적으로 추가/제거 가능 |
| PASSWORD  | 필수                          |

모드를 전환하면 주소, 마스터 이름 및 주소 목록 필드가 자동으로 재설정됩니다.

### 2.3 Kafka
**조작 단계**: 오른쪽의 빠른 탐색에서 Kafka 아이콘을 클릭하여 이 섹션으로 스크롤 → 브로커 주소를 입력 → 만약 SASL 가 활성화되어 있습니다, SASL 하위 필드를 확장 → "연결 테스트" 클릭

필드 설명:

| 필드         | 설명                                         |
| ---------- | ------------------------------------------------ |
| 브로커 주소 | 배열, 동적으로 추가/삭제 가능        |
| 토픽 접두사    | 모든 토픽에 자동으로 추가되는 접두사         |
| 사용 SASL 인증 | 스위치, 활성화하면 세 가지 SASL 구성 |
| 인증 메커니즘 | PLAIN / SCRAM-SHA-256 / SCRAM-SHA-512 (활성화 후) SASL) |
| USERNAME / PASSWORD   | SASL 자격 증명 (활성화 후 SASL)           |

### 2.4 MySQL (관계형 데이터베이스)
**작업 단계**: 오른쪽 빠른 탐색에서 RDB 아이콘을 클릭하고 이 섹션으로 스크롤 → MySQL 또는 DM 선택 Dameng → 호스트, 포트 입력 USERNAMEPASSWORD → "연결 테스트" 클릭

필드 설명:

| 필드      | 설명        |
| -------- | ---------------- |
| 데이터베이스 유형 | MySQL 또는 DM (Dameng) |
| 호스트 주소  | 예를 들어 `mysql-master` |
| 포트          | 3306           |
| USERNAME / PASSWORD | 자격 증명      |

> “RDB 오른쪽 메뉴와 페이지 제목의 '관계형 데이터베이스'는 다음과 대응합니다 MySQL 설정 섹션.

### 2.5 MongoDB
**작업 단계**: 오른쪽의 빠른 탐색에서 MongoDB 오른쪽 빠른 탐색의 아이콘을 클릭하여 이 섹션으로 스크롤 → 연결 문자열 입력 → 서버 구성에 따라 각 데이터베이스 자격 증명을 하나씩 렌더링 → '연결 테스트' 클릭.

필드 설명: 

| 필드           | 설명                       |
| ------------- | -------------------------------- |
| 연결 문자열 | 예를 들어 `mongo-master:27017` |
| 각 데이터베이스 USERNAME / PASSWORD | 서버에 설정된 데이터베이스를 하나씩 렌더링함 |

### 2.6 Elasticsearch
**단계:** 오른쪽의 빠른 탐색을 사용하여 클릭하세요 Elasticsearch 아이콘을 클릭하고 이 섹션으로 스크롤 → 호스트 주소와 포트를 입력 → 인증이 활성화되어 있으면 입력 USERNAME 그리고 PASSWORD → '연결 테스트'를 클릭합니다.

필드 설명: 

| 필드     | 설명       | 필수 |
| ----      | --------------  | ----    |
| 호스트 주소 | 예:, `elasticsearch` | 예      |
| 포트        | 9200             | 예      |
| USERNAME    | ES 자격 증명   | 아니요       |
| PASSWORD    | ES 자격 증명   | 아니요       |

## 3. 일반 작업 

### 3.1 자격 증명 업데이트(예: 액세스 키 교체) 

1. 미들웨어 구성으로 이동 
2. 공용 카드에서 액세스 키 ID와 액세스 키 비밀을 교체하십시오 S3  
3. "테스트 연결"을 클릭하고 초록색 "연결 테스트 성공" 메시지가 나타날 때까지 기다립니다 
4. 수정된 다른 섹션에 대해서도 연결 테스트를 반복합니다 
5. 하단에서 "구성 게시"를 클릭합니다 
6. 시스템에서 비동기 작업이 생성되었음을 알리고 작업 로그 탭으로 리디렉션합니다 

### 3.2 미들웨어 공급자 전환 

1. 미들웨어 구성으로 이동 
2. 해당 카드에서 "스토리지 유형 / 하위 유형"뿐만 아니라 새 공급자의 엔드포인트, 액세스 키, 주소 대체 규칙 등을 수정합니다. 
3. 수정 후, "연결 테스트"를 클릭하여 확인합니다 
4. "구성 게시"를 클릭합니다 

> 공급자 전환은 하류 서비스의 연결 풀을 다시 로딩하므로 피크 업무 시간은 피하시기 바랍니다. 전환 후에는 응용 프로그램 로그를 5~10분간 모니터링하는 것이 좋습니다. 

### 3.3 활성화 Kafka SASL 

1. 미들웨어 구성을 열고 다음 위치를 찾습니다 Kafka 섹션 
2. "사용 안 함"을 켭니다 SASL 인증 스위치, 그리고 SASL 필드가 확장됩니다 
3. 인증 메커니즘을 입력하세요, USERNAME, 및 PASSWORD 
4. "연결 테스트"를 클릭하세요 
5. 통과 후, "구성 게시"를 클릭하세요 

### 3.4 잘못된 작업에서 복구 

"구성 게시"를 클릭하기 전에, 양식 상태가 브라우저의 localStorage에 저장됩니다. 다음 방법으로 복구할 수 있습니다: 

- 하단의 "모두 재설정" 버튼을 클릭하면 모든 필드가 초기 서버 값으로 복원됩니다. 

### 3.5 비동기 작업 추적 

구성을 성공적으로 게시한 후, 시스템은 작업 진행 상황을 표시하기 위해 작업 로그 탭으로 이동합니다. 작업 시간은 미들웨어 인스턴스 수와 변경된 필드 수에 따라 길거나 짧을 수 있습니다.

## 4. 일반적인 문제 

**Q1: 클릭하면 Redis 오른쪽 상단 빠른 탐색에서 반응이 없습니다.**

오른쪽 빠른 탐색은 해당 섹션으로만 스크롤됩니다. 해당 섹션이 현재 페이지에 없으면(예: 팝업으로 가려진 경우) 페이지를 스크롤하거나 오른쪽 탐색에서 Redis 아이콘을 다시 클릭하여 위치를 다시 지정할 수 있습니다.

**Q2: 구성을 게시한 후 상태가 업데이트되지 않는 것 같습니다.**

게시 후 페이지는 자동으로 새로 고침됩니다. 브라우저가 자동으로 새로 고침되지 않으면 F5를 눌러 최신 구성을 가져올 수 있습니다.

**Q3: '수정된 N개 구성'의 숫자가 실제 수와 일치하지 않습니다.**

페이지 수는 폼의 더티 값 필드를 기준으로 계산됩니다. 특정 상황, 예를 들어 리셋 후 수정하거나 배열 항목을 동적으로 추가/제거하는 경우, 계산 불일치가 발생할 수 있습니다. '모두 초기화'를 클릭하고 항목을 다시 채울 수 있습니다.

**Q4: 버킷 설정 카드에서 추가하려는 버킷을 찾을 수 없습니다.**

페이지는 서버 측 구성에 따라 기존 버킷을 렌더링합니다. 새로운 버킷을 추가하려면 이 페이지가 아닌 기본 서버 구성 파일을 수정해야 합니다. 필요하다면 구현 엔지니어에게 문의하십시오.
