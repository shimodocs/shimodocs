# 고가용성 Kubernetes 배포

[← ShimoDocs Suite 배포 문서](../README.md)

## 1. 적용 시나리오 

> [!TIP] 
> 
> K8s 클러스터 배포는 운영 환경에 적합합니다. 단일 머신 배포와 비교하여, 클러스터 배포는 장기간 운영, 확장 및 고가용성 시나리오에 더 적합합니다. 

- 운영 환경에서는 사용을 권장합니다 `3 master   N worker`. 
- 최소한 3대의 서버를 준비하고, 모두 마스터로 설정합니다. 워커는 초기에는 마스터 노드를 재사용할 수 있으며, 나중에 규모에 따라 워커를 증가시킬 수 있습니다. 

## 2. 배포 전 준비 사항 

### 2.1 다음 정보를 준비합니다 

| 정보 | 예시 | 설명 | 
| --- | --- | --- | 
| 네트워크 환경 | 온라인 / 오프라인 | 공용 네트워크 접근이 지원되는 경우 온라인 선택; 내부 네트워크 또는 단절된 환경에서는 오프라인 선택 | 
| INSTALL_NODE_IP | `<INSTALL_NODE_IP>` | 웹 페이지를 시작할 설치 노드 1대를 선택 | 
| 비즈니스 NODE_IP | `<Node1IP>`, `<Node2IP>`, `<Node3IP>` | 최소 3대의 서버 | 
| 실행 사용자 | `root` | 설치 명령은 다음 사용자로 실행 `root` | 
| 접속 프로토콜 | HTTP / HTTPS | HTTPS 운영 환경에서는 권장 | 
| ACCESS_DOMAIN | `<ACCESS_DOMAIN>` | 사용자가 접속할 주소 ShimoDocs Suite |
| 데이터 디렉터리 | `/data` | 모든 노드에서 일관성을 유지하는 것이 권장됩니다 |
| 설치 도구 | `mdp-installer-${Arch}` | 제공된 설치 프로그램 ShimoDocs, `${Arch}` 다른 칩 아키텍처를 구분하며, x86 아키텍처의 경우 값이 amd64, arm 아키텍처의 경우 arm64일 수 있습니다 |
| 제품 설치 패키지 | ShimoDocs Suite 설치 패키지 | 실제로 제공된 파일 이름을 사용하십시오 |
| 오프라인 이미지 패키지 | `*.tar.gz` | 오프라인 설치에만 필요합니다 |
| 외부 미들웨어 | 예 / 아니오 | 외부 미들웨어가 있는 경우 주소, 포트, 계정을 미리 준비하십시오 PASSWORD 사전에 |

### 2.2 최소 서버 요구 사항

| 항목 | 요구 사항 |
| --- | --- |
| 서버 수 | 3대 이상 |
| 권장 역할 | `3 master   N worker` |
| CPU 노드당 | 16코어 이상 |
| 노드당 메모리 | 32GB 이상 |
| 시스템 디스크 | 루트 `/` 파티션 100GB 이상 |
| 데이터 디스크 | 별도 마운트 `/data`, 사용 가능한 공간 300GB 이상 |
| 오프라인 설치 | 설치 노드의 데이터 디스크에 추가로 100GB 이상을 확보하는 것이 권장됩니다 |

참고:

- 파티션하지 마십시오 `/root`, `/var`, 또는 `/tmp` 별도로 
- 데이터를 시스템 디스크에 두지 말고 모두 여기에 두십시오 `/data`. 
- 모든 노드의 시간이 동기화되어야 합니다. 
- 설치 노드는 다른 노드에 접근할 수 있어야 합니다 SSH. 

각 서버에서 실행할 수 있습니다: 

```bash
lscpu
free -g
df -h
timedatectl status
```

설치 노드에서 다른 노드에 접근할 수 있는지 확인하십시오: 

```bash
ssh root@<NODE2IP>
ssh root@<NODE3IP>
```

로그인에 실패하면 먼저 SSH, PASSWORD, 방화벽 또는 보안 그룹 설정을 확인한 후 설치를 계속하십시오.

## 3. 설치 도구 및 설치 패키지 업로드
> [!TIP]
>
> - 명령어의 파일 이름을 실제 상황에 맞게 반드시 수정하십시오. 예를 들어, x86 아키텍처 환경에서 설치 패키지 이름은 mdp-installer-amd64입니다.
> - 실제 시나리오에 따라 적절한 업로드 방법을 선택하십시오. 이 문서에서는 scp 명령어를 예로 사용하지만, 다른 그래픽 SSH 도구를 사용하여 업로드할 수도 있습니다.

설치 노드로 설치 프로그램을 전송하려면 로컬 컴퓨터에서 다음 명령어를 실행하십시오:

```bash
scp mdp-installer-amd64 root@<INSTALL_NODE_IP>:/root/
```

오프라인 설치 역시 오프라인 이미지 패키지 업로드가 필요합니다: 

```bash
scp smbase_image-amd64.tar.gz offline_app_image.tar.gz root@<INSTALL_NODE_IP>:/root/
```

설치 노드에 로그인하십시오: 

```bash
ssh root@<INSTALL_NODE_IP>
```

설치 프로그램 실행 권한을 부여하십시오:

```bash
chmod +x /root/mdp-installer-amd64
```

설치 프로그램 웹 페이지를 실행하십시오: 

```bash
nohup /root/mdp-installer-amd64 server --port 18080 &
```

브라우저 접근: 

```text
http://<INSTALL_NODE_IP>:18080
```

## 4. 웹 페이지를 통한 설치

### 4.1 제품 설치 패키지 업로드

1. 열기 `http://<INSTALL_NODE_IP>:18080`.
2. 설치 패키지 업로드 ShimoDocs Suite 설치 패키지를 업로드합니다.
3. 업로드가 완료되면 클릭하십시오 `Continue`.

### 4.2 구성 ACCESS_DOMAIN

입력하십시오 ShimoDocs Suite 접근 주소:

| 구성 항목 | 작성 방법 |
| --- | --- |
| ACCESS_DOMAIN / IP | `<ACCESS_DOMAIN>` |

### 4.3 기본 구성 확인

| 구성 항목 | 작성 방법 |
| --- | --- |
| NODE_IP | 마스터 / 워커 NODE_IP를 하나씩 작성하십시오 |
| SSH 포트 | 보통 `22` |
| SSH PASSWORD | `root` 사용자 PASSWORD |
| 노드 유형 | `master`, `worker`, 설치 노드 |
| 데이터 디렉터리 | `/data` |

운영 단계:

1. 추가 INSTALL_NODE_IP.
2. 각 마스터/워커 노드의 IP 주소를 추가하십시오.
3. 각 서버에 노드 역할을 할당하십시오.
4. 설치 노드에서 각 노드로의 연결을 테스트하십시오.
5. 데이터 카탈로그 및 컨테이너 네트워크 구간을 작성하십시오.

구성 중 확인할 핵심 포인트:

- 접근 프로토콜 및 ACCESS_DOMAIN 이 올바르게 작성되어 있는지 확인하십시오.
- Pod CIDR 및 서비스 CIDR 기존 네트워크, 사무실 네트워크, VPN, 또는 IDC 네트워크 구간과 충돌하지 않습니다.
- 데이터 디렉토리는 `/data` 또는 실제 계획된 데이터 디스크의 디렉토리를 사용합니다.
- 온라인/오프라인 설치 방식은 현재 네트워크 환경과 일치합니다.
- 오프라인 설치는 오프라인 기본 이미지 패키지 및 애플리케이션 이미지 패키지를 업로드해야 합니다. 기본값은 온라인 설치이며, 클러스터가 공용 네트워크에 접근할 수 있어야 합니다.

### 4.4 초기 배포

구성이 완료되면 ‘배포 초기화’를 클릭합니다. 페이지에 이 배포의 개요가 표시됩니다. 다음 사항에 특히 주의해 주세요:

- 제품 패키지 버전.
- 배포 NODE_IP.
- SSH 사용자 및 포트.
- ACCESS_DOMAIN 및 프로토콜.
- 데이터 디렉토리.
- 온라인 또는 오프라인 설치 모드.
- 미들웨어 선택.

오류가 없는 것을 확인한 후 계속 진행합니다.

### 4.5 시스템 환경 점검

설치 프로그램이 서버 환경을 자동으로 점검합니다.

점검이 통과하면 배포를 계속 진행합니다. 실패가 발생하면 페이지의 안내를 따라 문제를 해결한 후 다시 점검합니다. 일반적인 처리 방법은 다음과 같습니다:

- 디스크 공간 부족: 공간을 정리하거나 데이터 디스크를 확장합니다.
- 포트 사용 불가: 포트를 해제하거나 포트 사용을 조정합니다.
- SSH 연결 실패: 계정을 확인하고, PASSWORD, 개인 키, 포트 및 보안 그룹을 확인합니다.
- 시간 동기화 예외: 서버 시간을 구성 NTP 하거나 보정합니다.
- 기본 명령 누락: 시스템 배포에 따라 누락된 명령을 설치하십시오.

### 4.6 배포 시작

환경 검사가 완료되면 '배포 시작'을 클릭하십시오.

배포 과정 중 각 구성요소의 실행 로그를 확인할 수 있습니다. 설치 중에는 다음 사항을 확인하십시오: 

- 설치 프로그램 프로세스가 실행 중이어야 합니다. 
- 브라우저가 설치 노드와 네트워크를 통해 통신할 수 있어야 합니다. 
- 서버를 재시작하지 마십시오. 
- 설치 패키지, 오프라인 이미지 패키지 또는 데이터 디렉터리를 이동하거나 삭제하지 마십시오. 

### 4.7 설치 완료 대기

설치 과정에는 다소 시간이 걸리며, 정확한 시간은 서버 성능, 네트워크 환경, 이미지 다운로드 속도에 따라 달라집니다.

페이지에 모든 작업이 성공적으로 실행되었고 실패한 구성요소가 없는 경우, 배포가 완료되었음을 나타냅니다.

### 4.8 설치 결과 확인

설치가 완료되면 설치 프로그램이 배포 완료 페이지와 접속 정보를 표시합니다. 비즈니스 시스템과 운영 플랫폼에 접속하기 전에 페이지에 실패한 작업이 없는지 먼저 확인하십시오. MDP 운영 플랫폼.

비즈니스 주소 방문: 

```text
http://<ACCESS_DOMAIN>/
```

설치 중 HTTPS 가 구성된 경우, 다음을 방문하십시오: 

```text
https://<ACCESS_DOMAIN>/
```

기본 계정 또는 관리자 계정으로 로그인 후, 초기 설정을 즉시 변경하십시오. PASSWORD 즉시 변경

접속 MDP 운영 플랫폼:

```text
http://<ACCESS_DOMAIN>/mdp/
```

관리자를 수정해야 하는 경우, 배포 노드에서 다음 명령을 실행하여 수정하거나 재설정할 수 있습니다. MDP 관리자 PASSWORD다음 명령을 배포 노드에서 실행하여 수정하거나 재설정할 수 있습니다. PASSWORD.
{password}를 새로운 복잡하고 강력한 암호로 교체하십시오. PASSWORD 실제 보안 요구 사항에 따라 적용하십시오.

```bash
kubectl exec -it $(kubectl get pods -l app=mdp -o jsonpath='{.items[0].metadata.name}') -- reset-admin-password {password}
```

## 5. 설치 후 검수

### 5.1 확인 K8s 노드 상태

배포 노드에서 실행:

```bash
kubectl get node
```

노드 상태는 다음과 같아야 합니다 `Ready`. 

서비스를 계속 확인하십시오: 

```bash
kubectl get pod -A
```

정상 상태는 일반적으로 다음과 같습니다: 

- `Running`: 서비스가 실행 중입니다. 
- `Completed`: 작업이 실행을 완료했습니다. 

다음과 같은 상태가 나타나면 `CrashLoopBackOff`, `ImagePullBackOff`, `Error`, `Pending`먼저 해당 Pod 로그를 확인하고 처리하십시오. 

### 5.2 접근 항목 확인 

접속 ShimoDocs Suite 브라우저를 통한 접근: 

```text
http://<ACCESS_DOMAIN>/
```

설치 중 HTTPS 가 구성되었습니다. 방문하십시오: 

```text
https://<ACCESS_DOMAIN>/
```

로그인 페이지가 정상적으로 열리는지 확인하십시오. 

### 5.3 관리 백엔드 및 라이선스 확인 

다음 항목을 확인하십시오:

- 라이선스 페이지를 열 수 있습니다. 
- 기계 정보를 확인할 수 있습니다.

### 5.5 설치 프로그램 프로세스 중지

배포가 완료되고 승인된 후, 설치 프로그램 웹 서비스를 중지할 수 있습니다
설치 웹 페이지 중지:
설치 프로그램을 중지하는 명령: 

```bash

```

설치 프로그램이 백그라운드에서 시작된 경우 `nohup`, 로그를 확인할 수도 있습니다: 

```bash
tail -f /root/nohup.out
```

## 6. 일반 문제 처리

### 6.1 브라우저가 설치 페이지를 열 수 없음

다음을 확인하십시오:

- 설치 프로그램 프로세스가 여전히 실행 중인지 여부
- 포트 `18080` 가 방화벽 또는 보안 그룹에 의해 차단되었는지 여부
- 브라우저가 접근하는 IP가 INSTALL_NODE_IP.

서버에서 다음을 실행할 수 있습니다:

```bash
ps -ef | grep mdp-installer | grep -v grep
ss -lntp | grep 18080
```

### 6.2 환경 검사 실패

페이지의 안내에 따라 각 항목을 처리하세요. 처리 후 설치 프로그램 페이지로 돌아가 환경 검사를 다시 실행하십시오.

우선 순위 확인:

- 여부 CPU, 메모리 및 디스크가 요구 사항을 충족합니다.
- 여부 `/data` 은 독립형 데이터 디스크입니다.
- 서버 시간이 동기화되어 있는지 여부.
- 여부 SSH 사용자에게 배포 권한이 있습니다.

### 6.3 오프라인 설치 이미지 가져오기 실패

지침 확인:

- 오프라인 이미지 패키지가 배포 노드에 업로드되었는지 여부.
- 기본 오프라인 이미지 패키지와 제품 오프라인 이미지 패키지가 완전한지 여부.
- 이미지 패키지 버전이 제품 설치 패키지와 일치하는지 여부.
- 개인 이미지 저장소 주소, 계정 및 PASSWORD 이 올바르게 작성되어 있는지 확인하십시오.

### 6.4 Pod가 오랜 시간 동안 비정상 상태로 남아 있음

먼저, 비정상 Pod를 확인:

```bash
kubectl get pod -A
```

로그를 다시 확인: 

```bash
kubectl logs -n <namespace> <pod-name>
```

로그를 기반으로 이미지, 구성, 리소스 또는 종속성과 관련된 문제 처리.

## 7. 설치 후 자료 보관

배포 후 유지보수, 업그레이드 및 문제 해결을 용이하게 하기 위해 다음 자료를 보관하는 것이 좋습니다:

- INSTALL_NODE_IP, ACCESS_DOMAIN및 접근 프로토콜.
- 설치 프로그램 파일 이름과 버전.
- 제품 설치 패키지 파일 이름과 버전.
- 오프라인 이미지 패키지 파일 이름과 버전.
- 웹 페이지의 주요 구성 스크린샷.
- `kubectl get node` 체크 결과.
- `kubectl get pod -A` 체크 결과.
- 라이선스 승인 기록.
- 업무 기능 승인 기록.
- 배포 중 발생한 문제와 처리 결과.
