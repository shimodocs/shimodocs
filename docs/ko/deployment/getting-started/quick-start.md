# 빠른 시작

[← ShimoDocs Suite 배포 문서](../README.md)

> [!TIP]
>
> 이 문서에서는 `mdp-installer` 를 사용하여 새 환경을 빠르게 배포하는 방법을 소개합니다. ShimoDocs Suite.
>
> 이 문서는 **All-in-One 단일 노드, 온라인 설치** 시나리오를 위해 작성되었으며, 처음 설치, 제품 체험, 기능 검증, 배포 과정 연습에 적합합니다. 이 문서를 완료하면 ShimoDocs Suite 업무 접근 주소와 MDP 운영 플랫폼 주소를 얻을 수 있습니다.

> IP 주소, 설치 프로그램 패키지 이름, VERSION및 페이지의 디렉터리는 예시용입니다. 실제 배포 시에는 현재 환경과 전달된 자료를 참고하십시오.

## 1. 배포 과정 개요

전체 과정은 다음 7단계로 나눌 수 있습니다:

| 단계 | 완료해야 할 작업 | 완료 지표 |
| --- | --- | --- |
| 1. 서버 및 설치 자료 준비 | 서버, 설치 프로그램, 및 ShimoDocs Suite 배포 패키지가 사용 가능한지 확인 | 서버에 로그인하고 설치 파일을 찾을 수 있음 |
| 2. 설치 프로그램 시작 | 설치 노드에서 `mdp-installer` 실행 | 터미널에 설치 프로그램 접근 주소 표시 |
| 3. 배포 패키지 업로드 | 브라우저에서 ShimoDocs Suite 배포 패키지를 선택 | 페이지에 배포 패키지가 검증을 통과했음 표시 |
| 4. 배포 환경 구성 | 도메인 또는 IP, 배포 모드, 노드 로그인 정보 및 데이터 디렉토리 입력 | 노드가 성공적으로 검증되고 배포 개요 접근 가능 |
| 5. 환경 점검 | 설치 프로그램이 서버 및 배포 환경 확인 대기 | 설치를 막는 실패 없음 |
| 6. 설치 시작 | 점검 결과 확인 후 배포 실행 | 페이지에 설치 완료 표시 |
| 7. 납품 정보 저장 | 접속 주소를 저장하고 로그인, 서비스 및 기능 확인을 완료합니다 | 비즈니스 페이지 및 MDP 운영 플랫폼에 접속할 수 있습니다 |

## 2. 배포 전 준비

### 1. 설치 노드 준비

설치 노드는 설치 프로그램을 실행하는 데 사용되며, 이 올인원 단일 노드 배포의 대상 서버 역할을 합니다.

시작하기 전에 다음을 확인하십시오:

- 사용 가능한 서버가 준비되었으며 SERVER_IP 주소가 확보되었습니다.
- 서버에 다음을 통해 접속할 수 있습니다 SSH.
- 사용자는 SSH 이며 `root`배포 작업을 수행할 수 있는 필요한 권한을 가지고 있습니다.
- 서버의 CPU 아키텍처가 설치 프로그램 및 배포 패키지와 일치합니다. 예를 들어, 둘 다 `x86_64`.
- 서버가 현재 배포 사양을 충족합니다; Ubuntu 24.04 최소 설치 사용을 권장합니다 LTS.
- 루트 파티션과 데이터 공간은 현재 배포 요구 사항을 충족하며, 데이터 디렉토리가 결정되었습니다.
- 서버 시간과 시간대가 올바르며, 시간 동기화가 정상입니다.
- 브라우저가 설치 노드의 포트에 접근할 수 있습니다. `18080/TCP` 설치 노드의 포트.
- 서버가 인터넷에 접속하여 배포 패키지와 이미지 리소스를 온라인에서 다운로드할 수 있습니다.
- 비즈니스 접근에 도메인을 사용하는 경우, 도메인 이름 해석이 사전에 완료되어야 합니다(선택 사항).

최소 서버 요구 사항은 다음과 같습니다:

| 운영 체제 | 아키텍처 | CPU | 메모리 | 디스크 |
| --- | --- | --- | --- | --- |
| Ubuntu 24.04 LTS | `x86_64` | 16코어 | 32GB | 100GB SSD |

추가로 다음 사항을 확인해 주세요:

- 파티션하지 마십시오 `/root`, `/var`, `/tmp` 별도로.
- 설치 전, 설치 프로그램 검증에 영향을 줄 수 있는 Docker 등의 추가 구성 요소를 서버에 배포하지 마세요. Kubernetes 서버에서 설치 프로그램 검증에 영향을 줄 수 있는 추가 구성 요소는 배포하지 마세요.
- 포트 `22/TCP` 사용 용도: SSH, `18080/TCP` 설치 프로그램 웹 페이지에 사용됩니다, `80/TCP` 그리고 `443/TCP` 비즈니스 접근에 사용됩니다.

> 공식 배포 전, 실제 동시 접속 수, 파일 크기, 가용성 요구 사항에 따라 서버 사양을 확인하는 것이 권장됩니다; 본 문서의 단일 노드 프로세스는 신속한 배포와 검증에 적합하며, 장기간 운영이나 고가용성을 위해서는 해당 클러스터 배포 방안을 사용하세요.

### 2. 설치 자료 준비

#### 설치 프로그램 확보

에서 제공한 설치 프로그램을 확보하세요. ShimoDocs 설치 노드의 `/root/` 디렉토리에 업로드하세요. 다음 방법 중 하나를 선택할 수 있습니다:

- **방법 1: 를 통한 업로드 SSH 도구**를 사용하여 업로드하세요. `mdp-installer-amd64` 설치 노드의 `/root/` 설치 노드의 디렉토리.

#### 배포 패키지 획득

배포 패키지 준비 ShimoDocs Suite 이번 배포를 위해 배포 패키지를 준비하십시오. 배포 패키지는 웹 설치 페이지에 업로드되며, 파일 이름과 버전은 실제 전달에 따라야 합니다.

예시 파일 이름: `co1.8.20260711.3286-drive-release.tar.gz`

자재 명세는 다음과 같습니다:

| 파일 | 설명 |
| --- | --- |
| `mdp-installer` 설치 프로그램 | 서버 아키텍처에 따라 해당 파일을 선택하십시오. 예를 들어, `mdp-installer-amd64`. |
| ShimoDocs Suite 배포 패키지 | 파일 이름과 버전은 실제 전달에 따라야 합니다. 예를 들어, `co1.8.20260711.3286-drive-release.tar.gz`. |

설치 프로그램과 관련 설치 자료를 동일한 작업 디렉터리에 배치하면 이후에 보다 쉽게 검색하고 보관할 수 있습니다. 배포 패키지를 사용하기 전에 파일이 완전하고 전송 도구로 인해 손상되지 않았는지 확인하십시오.

## 3. 설치 프로그램 실행

### 1. 설치 노드에 로그인

를 통해 설치 노드에 로그인하고 설치 프로그램이 위치한 디렉터리로 이동하십시오. 예를 들어: SSH 

```bash
ssh root@<INSTALL_NODE_IP>
cd /root
```

### 2. 실행 권한 추가

설치 프로그램에 아직 실행 권한이 없는 경우, 다음을 실행하십시오:

```bash
chmod +x ./mdp-installer-amd64
```
명령어의 파일 이름은 실제 설치 프로그램 이름으로 바꿔야 합니다. 

### 3. 웹 설치 페이지 실행 

실행: 

```bash
./mdp-installer-amd64 server
```

현재 터미널 종료 후에도 설치 프로그램이 계속 실행되도록 하려면 다음을 사용할 수 있습니다: 

```bash
nohup ./mdp-installer-amd64 server > nohup.out 2>&1 &
```

성공적으로 시작되면 터미널에 두 개의 주소가 표시됩니다: 

- `Local`: 설치 노드 자체에서만 사용 
- `Network`: 동일 네트워크의 다른 컴퓨터에서 액세스 가능 

백그라운드 모드로 시작된 경우, 다음 명령어를 실행하여 설치 프로그램 출력을 확인할 수 있습니다: 

```bash
cat nohup.out
```

열기 `Network` 브라우저 터미널에 표시된 주소, 예를 들어:

```text
http://<INSTALL_NODE_IP>:18080/
```

> 설치 중에는 설치 프로그램 프로세스를 계속 실행 상태로 유지하세요. 설치 프로그램을 닫거나 현재 서비스를 중지하지 마세요.

## 4. 업로드 ShimoDocs Suite 릴리스 패키지

### 1. 릴리스 패키지 선택

설치 페이지에 들어간 후:

1. 클릭 **배포 시작** 또는 페이지에서 릴리스 패키지 선택 항목.
2. 선택 ShimoDocs Suite `.tar.gz` 이번 배포에 사용할 릴리스 패키지를 선택하세요.
3. 파일 업로드와 검증이 완료될 때까지 기다리세요.

### 2. 인증 결과 확인

검증이 통과되면 페이지에 릴리스 패키지 이름과 배포 구성 항목이 표시됩니다.

다음 정보가 정확한지 확인해 주세요:

- 패키지 이름은 이번에 전달된 버전과 일치합니다.
- 릴리스 패키지는 ShimoDocs Suite 제품에 속합니다.
- 페이지는 파일 손상, 형식 오류 또는 스키마 불일치를 나타내지 않았습니다.

확인 후 클릭하십시오 **계속** 배포 구성을 진행합니다.

검증에 실패하면, 배포 패키지가 완전한지, 파일 형식이 올바른지, 배포 패키지가 서버 아키텍처와 일치하는지 다시 확인하십시오. CPU 

## 5. 배포 환경 구성

### 1. 네트워크 주소 확인

페이지에 표시된 호스트명 또는 IP 주소를 확인하십시오. 이 주소는 사용자가 정상적으로 접근할 수 있는 설치 노드 주소여야 합니다.

입력하지 마십시오 `127.0.0.1`, 현재 컴퓨터에서만 접근할 수 있는 임시 주소는 사용하지 마십시오. 도메인 이름을 통해 접근할 때는 도메인 이름이 올바른 서비스 엔트리로 해결되었는지 확인하십시오.

### 2. 올인원 단일 노드 모드 선택

선택 **올인원 단일 노드** 배포 모드 또는 대상 환경에서 (페이지에 표시되는 실제 이름은 현재 버전에 따라 다를 수 있음).

이 모드에서 설치 노드는 해당 배포에 대해 제어 및 비즈니스 역할을 동시에 수행하므로, 제품 체험, 기능 검증 및 단일 노드 계획을 위한 경량 환경에 적합합니다.

### 3. 노드 구성 SSH

설치 프로그램은 대상 노드에 연결하여 SSH 배포 작업을 수행합니다. 다음을 작성하십시오:

- NODE_IP 주소
- SSH 사용자, 일반적으로 `root`.
- SSH 포트, 일반적으로 `22` 기본값으로.
- PASSWORD 또는 개인 키 인증 정보.

작성 후, 클릭하세요 **확인** 를 확인하기 위해 SSH 연결이 성공했습니다.

> SSH 자격 증명은 통제된 환경에서만 사용하고 저장해야 합니다. 작성하지 마세요 PASSWORD 공개 문서, 스크린샷 또는 채팅 기록에 비밀 키를 작성하지 마세요.

### 4. 데이터 디렉터리 및 기타 설정 구성

페이지 안내에 따라 다음 구성을 입력하거나 확인하십시오:

| 구성 항목 | 설명 |
| --- | --- |
| ACCESS_DOMAIN / IP | 사용자가 접속할 주소 ShimoDocs Suite; IP 사용 시 실제 접속 가능한 주소를 입력하십시오. |
| 배포 모드 | All-in-One 단일 노드 모드를 선택하십시오. |
| 노드 데이터 디렉터리 | 배포 데이터를 저장하는 데 사용됩니다. 디스크에 충분한 공간이 있고 읽기/쓰기 권한이 있는지 확인하십시오. |
| 오프라인 저장소 | 이 가이드는 온라인 설치용입니다; 페이지에서 기본값을 유지하십시오. |
| 서드파티 미들웨어 | 이 가이드는 기본 배포를 사용합니다; 외부 미들웨어가 필요한 경우 현재 전달 요구 사항에 따라 확인하십시오. |

특별한 구성 요구 사항이 없는 경우 오프라인 저장소 및 서드파티 미들웨어에 대해 기본값을 유지할 수 있습니다. 확인 후, 클릭하십시오 **배포 초기화** 페이지 하단에서.

## 6. 배포 개요 확인

배포 개요는 공식 확인 전에 설치 구성을 검증하는 데 사용됩니다.

특히 다음 사항에 주의하십시오:

- 릴리스 패키지 버전과 제품명이 올바른지 확인하십시오.
- ACCESS_DOMAIN 또는 IP가 올바른지 확인하고 올바르지 않은지 확인하십시오. `127.0.0.1`.
- 배포 모드는 올인원 단일 노드입니다.
- NODE_IP, SSH 사용자 및 포트가 정확합니다.
- 데이터 디렉터리가 정확하며 디스크 공간이 충분합니다.
- 오프라인 저장소 및 서드파티 미들웨어 구성은 현재 환경과 일치합니다.

오류가 없는 것을 확인한 후, 클릭 **계속** 하여 환경 검사를 진행합니다.

## 7. 환경 점검 수행

설치 관리자가 노드와 배포 환경을 점검합니다. 점검 과정에는 몇 분 정도 소요될 수 있으니, 페이지를 열어 둔 상태로 유지해주세요.

### 1. 노드 개요 보기

노드 개요는 다음과 같은 점검 진행 상황을 표시합니다. SSH 연결성, 시스템 및 성능, 저장소 및 디스크, 네트워크, 배포 환경.

특정 점검의 상세 결과를 보려면 해당 점검 항목이나 상세 항목을 클릭하세요.

### 2. 자세한 검사 결과 보기

자세한 결과에는 일반적으로 다음이 포함됩니다:

- SSH 연결 상태 및 실행 사용자 권한.
- 운영 체제, CPU 아키텍처 및 코어 수.
- 메모리 용량, 디스크 공간 및 디렉터리 권한.
- 시간대 및 시간 동기화 상태.
- 네트워크, 이미지 리소스 및 외부 서비스 연결 상태.
- 배포에 영향을 줄 수 있는 서버 환경 잔여물.

### 3. 검사 상태 이해하기

| 상태 | 의미 | 다음 조치 |
| --- | --- | --- |
| 성공 | 현재 검사 항목이 배포 요구 사항을 충족함 | 다른 항목 완료를 기다리기 |
| 경고 | 직접적으로 배포를 차단하지는 않지만, 현재 계획과 일치하는지 확인 필요 | 세부 사항을 열고 영향 확인 후 계속 진행 |
| 실패 | 현재 문제가 설치 또는 제품 운영에 영향을 미칠 수 있음 | 문제를 먼저 해결한 후 재검사 |
| 진행 중 | 설치 관리자가 검사를 수행 중임 | 검사가 완료될 때까지 기다리며, 반복 작업 금지 |

항목이 '진행 중' 상태로 오래 유지되면, 현재 디스크 또는 원격 검사가 완료될 때까지 기다린 후 재검사 여부 결정 가능

### 4. 경고 및 실패 처리

페이지에 경고가 표시되면:

1. 해당 검사 항목의 세부 설명 열기
2. 경고가 현재 배포 계획과 일치하는지 확인
3. 확실하지 않으면 페이지와 설치 로그를 저장한 후, 구현 또는 운영 담당자에게 확인

페이지가 표시되지 않을 경우: 

1. 지시에 따라 수정하십시오 SSH권한, 리소스, 디스크, 네트워크 또는 미들웨어 문제. 
2. 클릭 **다시 스캔**. 
3. 실패 항목이 사라졌는지 확인하십시오. 

배포를 방해하는 실패가 없고 모든 경고를 확인한 후, 클릭하십시오 **계속**. 

## 8. 설치 시작 

### 1. 설치 계획 확인 

페이지에 설치 계획과 실행될 작업이 표시됩니다. 올바른지 확인한 후 클릭하십시오 **배포 시작**. 

페이지에 "설치를 시작하도록 확인" 메시지가 나타날 수 있습니다. 시작되면 설치 작업이 예정대로 진행됩니다. 구성을 조정해야 하는 경우, 클릭하십시오 **취소** 이전 단계로 돌아가기 위해

### 2. 배포 진행 상황 확인

배포를 시작하면, 페이지에 현재 작업 상태, 실시간 로그 및 실행 시간이 표시됩니다. 단일 노드 배포는 보통 약 10분 정도 걸리며, 실제 시간은 서버 성능과 네트워크 대역폭에 따라 달라집니다.

설치 과정에서 주의 사항: 

- 설치 프로그램을 닫지 마십시오. 
- 설치 노드를 재시작하지 마십시오. 
- 설치 작업을 새로고침, 뒤로 가기 또는 다시 제출하지 마십시오. 
- 작업이 실패하면, 먼저 해당 작업 로그의 첫 번째 오류를 확인한 후, 지시에 따라 처리하십시오. 

페이지에 표시될 때 **설치 완료** 또는 **배포 전달** 페이지에 들어가면 설치 작업이 완료된 것을 나타냅니다. 

## 9. 전달 정보 저장 

설치 완료 페이지에는 이 배포에 대한 접근 정보와 점검 항목이 표시됩니다. 다음 작업을 즉시 완료해 주십시오: 

1. 사후 설치 서비스 점검을 실행하고 점검 결과를 확인하십시오. 
2. 배포 전달 페이지의 접근 정보를 사용하여 ShimoDocs Suite 업무 페이지를 열고 로그인 확인을 완료하십시오. 
3. 다음을 기록하십시오: ShimoDocs Suite 업무 접근 주소와 MDP 운영 플랫폼 주소. 
4. 초기 계정과 임시 PASSWORD, 그리고 첫 로그인 후 즉시 초기 PASSWORD 를 변경하십시오. 
5. 클러스터 노드 및 애플리케이션 상태를 확인하십시오 MDP 운영 플랫폼. 

> 배송 정보에는 접근 주소와 초기 자격 증명이 포함됩니다. 스크린샷을 찍어 배포하지 말고, 공개 지식 기반에 업로드하지 말며, 통제되지 않은 채널로 전송하지 마십시오. 

## 10. 배포 결과 확인 

설치가 완료된 후에는 다음 순서로 인수 검사를 수행하는 것이 좋습니다. 

### 1. 설치 후 서비스 확인 

설치 완료 페이지에서 설치 후 검사를 수행하여 서비스 테스트 사례가 통과했는지 또는 결과가 현재 환경의 기대에 부합하는지 확인합니다. 

검사가 실패했거나 부분적으로 통과한 경우, 다음에서 검사 작업을 다시 제출할 수 있습니다. MDP 운영 플랫폼. 

### 2. 확인 MDP 운영 플랫폼

운영 플랫폼에 로그인하고, MDP 로 이동합니다 **시스템 서비스 → 클러스터 관리**, 클러스터 노드와 애플리케이션 실행 상태가 정상인지 확인합니다.

### 3. 확인 ShimoDocs Suite 기능

운영 플랫폼에 로그인하고, ShimoDocs Suite 프론트엔드 페이지를 열고 최소한 다음 기능을 확인합니다:

- 테스트 파일 또는 테스트 스위트 생성.
- 내용 편집 및 저장.
- 파일 내보내기.
- 파일 가져오기.

위의 모든 검사가 성공적으로 완료되면, 이 빠른 배포가 완료되었음을 나타냅니다. 향후 장기 운영, 확장 또는 고가용성이 필요한 경우, 실제 규모에 따라 해당 배포 계획으로 전환하고 라이선스 및 비즈니스 구성을 완료하십시오.

## 11. 일반 질문

### 1. 브라우저에서 설치 페이지를 열 수 없음

순서대로 확인:

- 설치 프로그램 프로세스가 여전히 실행 중인지 여부
- 접근 주소가 설치 노드의 실제 IP 또는 확인 가능한 도메인 이름을 사용하는지 여부.
- 포트 `18080/TCP` 열려 있는지 여부.
- 브라우저가 있는 컴퓨터와 설치 노드 간의 네트워크가 연결되어 있는지 여부.

### 2. 배포 패키지 검증 실패

확인:

- 업로드된 파일이 완전한지 여부 `.tar.gz` 출시 패키지.
- 파일 이름과 제품 유형이 이 배송과 일치하는지 여부.
- 릴리스 패키지가 서버와 일치하는지 여부 CPU 
- 업로드 또는 전송 중 파일이 손상되었는지 여부

### 3. SSH 인증 실패

확인:

- 여부 NODE_IP 및 SSH 포트가 올바릅니다.
- 여부 SSH 사용자, PASSWORD또는 개인 키가 올바릅니다.
- 사용자가 필요한 배포 권한을 가지고 있습니까? SSH 방화벽 또는 보안 그룹이 연결을 허용하는지 여부.
- 연결. SSH 연결.

### 4. 환경 검사 경고

경고는 배포를 직접적으로 막지는 않지만, 영향을 확인하려면 세부 정보를 열어야 합니다. 디스크 성능, 시간 동기화, 구성 잔여물 또는 외부 서비스와 관련된 경우, 계속 진행할지 결정하기 전에 현재 배포 계획과 일치하는지 먼저 확인하십시오.

### 5. 환경 점검 실패

실패 항목은 먼저 수정해야 합니다. 점검을 우회하고 설치를 바로 시작하지 마십시오. 수정 후, 클릭하여 실패 항목이 통과했는지 확인하십시오. **다시 스캔** 

### 6. 설치 작업 실패

1. 실패한 작업의 실행 로그를 엽니다.
2. 처음 발생한 오류 메시지를 찾습니다.
3. 설치 프로그램 로그, 실패한 작업 이름, 발생 시간을 저장합니다.
4. 해당 네트워크, 디스크, 이미지, 미들웨어 또는 Kubernetes 문제를 해결한 후 실제 복구 방법에 따라 계속 진행합니다.
