# Kafka 구성

[← ShimoDocs Suite 배포 문서](../../README.md)

이 문서는 구현, 운영 또는 통합 담당자가 외부 메시지 미들웨어와의 통합을 완료하도록 안내하기 위한 것입니다. ShimoDocs 비동기 작업 처리, 메시지 알림, 데이터 동기화, 감사 로그 전달과 같은 시나리오를 단계별로 통합합니다. Kafka  


## 1. 사전 운영 확인 

## Kafka 인스턴스 요구 사항 


| 미들웨어 | 권장 버전 | 사용자 수 3000명 미만 | 사용자 수 3000명 이상 | 
| --- | --- | --- | --- | 
| Kafka | Kafka 3.5 | 2C 4G 300G SSD | 4C 8G 300G SSD | 


## 구성 요구 사항 
- 브로커 >= 3 
- 복제 계수: 기본 복제본 수는 3이며, 운영 환경에서는 고가용성을 보장하기 위해 ≥ 3 이상이 필수입니다 
- 메시지 보관 기간: 72시간(비즈니스 요구에 따라 조정 가능) 
- 주제별 최대 단일 메시지 크기: 10MB 
- 인증: 지원 SASL 암호화된 접근 (PLAIN, SCRAM-SHA-256, SCRAM-SHA-512) 





## 네트워크 연결 

비즈니스 클러스터에서 Kafka 인스턴스에 접근하기 위한 포트는 K8s 열려 있어야 합니다 

```js
telnet IP 9092
```



## 기타 요구 사항
- 인트라넷 RTT 지연 시간은 < 5ms가 권장되며, 데이터센터 간/지역 간은 < 20ms가 권장됩니다.
- 대역폭은 네트워크 포화로 인한 메시지 적체를 방지하기 위해 최대 처리량을 충족해야 합니다.
- 다음 사항을 보장하십시오 Kafka 브로커와 ShimoDocs 애플리케이션 서버 시간이 동기화되어 있습니다 (NTP), 시간 편차가 메시지 순서 및 TTL 계산에 영향을 줄 수 있습니다.
