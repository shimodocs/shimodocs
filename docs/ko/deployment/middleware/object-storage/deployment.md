# 객체 스토리지로 배포

[← ShimoDocs Suite 배포 문서](../../README.md)

이 문서에서는 내장된 MinIO 을 비활성화하는 방법을 설명합니다. ShimoDocs 설치 프로그램을 비활성화하고 고객의 자체 S3 서드파티 오브젝트 스토리지로서의 오브젝트 스토리지. S3 구성이 완료되면 설치 관리자가 확인합니다. S3 객체 스토리지 네트워크 연결, 인증 정보 및 버킷 읽기/쓰기 권한. 확인이 완료되면 배포를 계속할 수 있습니다. 

# 1. 구성 전 준비 
시작하기 전에 다음을 확인하십시오: 
- S3 객체 스토리지가 설치되어 정상적으로 실행 중입니다. 
- K8s 클러스터 노드는 객체 스토리지의 호스트 및 포트에 접근할 수 있습니다. S3  
- 객체 스토리지에 연결하기 위한 인증 AK/SK가 준비되었습니다. S3  
- S3 스토리지는 클라이언트 브라우저 접근을 지원해야 합니다. 
- 별도의 인스턴스를 사용하는 것이 권장됩니다. S3  
- 표준 S3 내부 및 외부 네트워크용 프로토콜 접근 주소가 제공되어야 합니다. 
- ShimoDocs 비즈니스 표준 S3 버킷은 사전에 생성되어 있어야 합니다. 
- S3 스토리지는 디스크를 사용해야 합니다. SSD

## 버킷 구성 지침
- 노출_헤더는 헤더 이름을 지정하고, * 기호를 사용하지 않는 것이 권장됩니다. 일부 공급업체는 * 기호를 지원하지 않을 수 있습니다. 예: 화웨이 클라우드 OBS, 알리바바 OSS
- 버킷 이름은 회사의 필요에 따라 접두사를 설정하여 중복을 방지할 수 있습니다

# 2. 고급 설정 입력
설치 프로그램의 '구성' 단계에서 네트워크, 대상 환경 및 노드 정보 구성을 완료한 후, 페이지 하단의 '고급 구성'을 확장합니다.

# 3. 내장 설치 취소 MinIO
'미들웨어 서비스' 영역에서 선택을 해제합니다 MinIO

선택을 해제하면 설치 관리자가 더 이상 내장된 MinIO및 외부를 설치하지 않습니다 S3 준비된 객체 스토리지는 나중에 사용됩니다. 다른 미들웨어가 내장 서비스를 사용할지는 실제 배포 계획에 따라 선택해야 합니다.

# 선택 해제
4. 타사 미들웨어 구성 열기

# 타사 미들웨어 구성 열기 S3 객체 스토리지
1. 데이터베이스S3 왼쪽의 "객체 스토리지"
2. 사용 설정MinIO "객체 스토리지"
3. 주요 서비스/편집기 상호작용의 경우 각각 AK/SK, 내부 엔드포인트, 공개 엔드포인트, 호스트, 포트, SSL및 기타 정보를 입력하세요
4. 확인 및 저장

> [!TIP]
>
> 주요 서비스: 협업 편집 이외의 서비스에 사용되는 객체 스토리지 인스턴스
> 편집기 상호작용: 협업 편집 서비스에서 사용되는 객체 스토리지 인스턴스
>
> 참고: 주요 서비스와 편집기 상호작용은 동일한 객체 스토리지 인스턴스를 사용할 수 있지만, 편집기 상호작용에 별도의 인스턴스를 제공하면 더 나은 협업 편집 성능을 얻을 수 있습니다

# 6. 검증 결과 확인
설치 프로그램은 다음을 확인합니다:
- 로그인: 계정이 정상적으로 인증될 수 있습니다
- 연결성: 배포 환경이 접근할 수 있습니다 S3 객체 스토리지
- 권한: 계정은 연결, 인증, 버킷 읽기/쓰기 등의 권한을 가지고 있습니다.

모든 점검 항목이 '성공'으로 표시되면, 구성 창을 닫고 설치 프로그램의 '구성' 페이지로 돌아갑니다.

실패한 항목이 있는 경우, 페이지 안내에 따라 확인하십시오:
- 호스트와 포트가 올바르게 입력되어 있는지
- 배포 노드와의 네트워크가 S3 오브젝트 스토리지가 연결되었습니다.
- 여부 USERNAME 그리고 PASSWORD 맞습니다. 
- 계정이 필요한 권한(연결 및 인증, 버킷 읽기/쓰기 권한 등)을 가지고 있는지 여부. 

# 7. 배포 초기화 계속 
'구성(Configuration)' 페이지로 돌아간 후에, S3 객체 스토리지가 선택되어 있지 않은지 확인한 다음 '배포 초기화'를 클릭하여 배포 개요, 확인 및 실행 단계를 계속 완료합니다. 

> [!TIP] 
> 
> 배포를 초기화하기 전에 다시 한 번 S3 객체 스토리지 구성이 저장되었고 모든 검증 항목이 통과되었습니다.
