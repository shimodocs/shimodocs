# 와 함께 배포 Redis

[← ShimoDocs Suite 배포 문서](../../README.md)

이 문서에서는 내장된 Redis 을 비활성화하는 방법을 설명합니다. ShimoDocs 설치 프로그램을 비활성화하고 고객의 자체 Redis 서드파티 캐시 데이터베이스로 사용. 구성 후 설치 프로그램은 Redis 네트워크 연결, 연결, 인증, 명령 실행, 게시/구독 권한 등을 확인합니다. 확인이 완료되면 배포를 계속할 수 있습니다. 

# 1. 구성 전 준비 
시작하기 전에 다음을 확인하십시오: 
- 사용자는 Redis 서버가 설치되어 정상적으로 실행 중인지. 
- 배포 노드는 접속할 수 있어야 합니다 Redis 서버의 호스트와 포트에 
- 인증 사용자 정보 및 PASSWORD 연결용 Redis 서버가 준비되었습니다. 

> [!TIP] 
> 
> 이 문서의 IP, 포트 및 계정은 예시입니다. 실제 환경 정보를 사용하여 구성하시고, 실제 PASSWORD를 공개 문서나 스크린샷에 기록하지 마십시오. 
> 

# 2. 고급 구성 입력 
설치 프로그램의 '구성(Configuration)' 단계에서 네트워크, 대상 환경 및 노드 정보 설정을 완료한 후, 페이지 하단의 '고급 구성(Advanced Configuration)'을 확장하십시오. 

# 3. 내장 설치 취소 Redis
'미들웨어 서비스(Middleware Services)' 섹션에서 체크 해제하십시오 Redis

선택을 해제하면 설치 관리자가 더 이상 내장된 Redis, 대신 준비된 외부 Redis 를 사용합니다. 다른 미들웨어가 내장 서비스를 사용할지는 실제 배포 계획에 따라 선택해야 합니다.

4. 타사 미들웨어 구성 열기

4. '마스터 이름(Master Name), SENTINEL PASSWORD, SENTINEL 노드(Nodes)'
5. 확인 및 저장

# 6. 검증 결과 확인
설치 프로그램은 다음을 확인합니다:
- 로그인: 계정을 정상적으로 인증할 수 있음
- 연결성: 배포 환경에서 접근할 수 있습니다. Redis
- 권한(permission): 이 계정은 연결, 인증, 명령 실행, 게시/구독 등 권한을 가지고 있습니다.

모든 확인 항목이 '성공'으로 표시되면 구성 창을 닫고 설치 프로그램의 '구성' 페이지로 돌아갑니다.

실패가 발생하면, 페이지의 안내에 따라 확인해 주십시오:
- 호스트와 포트가 올바르게 입력되어 있는지
- 배포 노드와의 네트워크가 Redis 서버가 연결되었습니다.
- 여부 USERNAME 그리고 PASSWORD 가 올바른지
- 계정이 필요한 권한(연결 및 인증, 명령 권한, 게시/구독 권한 등)을 갖추고 있는지 여부입니다.

# 7. 배포 초기화 계속
'구성' 페이지로 돌아간 후, 다음을 확인 Redis 확인이 되지 않은 채로 남아 있으면 '배포 초기화'를 클릭하여 배포 개요, 확인 및 실행 단계를 계속 진행하십시오.

> [!TIP]
>
> 배포를 초기화하기 전에, 다시 한 번 확인해 주십시오. Redis 구성이 저장되었으며 모든 검증 항목을 통과했습니다.
