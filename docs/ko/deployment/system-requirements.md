# 시스템 요구 사항

[← ShimoDocs Suite 배포 문서](README.md)

## 1. 시나리오에 따른 자원 준비

| 사용 시나리오 | 권장 배포 | 자원 준비 |
| --- | --- | --- |
| 경량 소규모 팀, PoC, 데모, 기능 검증 | 단일 서버 배포 | 서버 1대 |
| 공식 출시, 장기 운영, 높은 가용성 필요 또는 미래 확장 필요 | 고가용성 클러스터 | 서버 3대 이상 |

- 단일 서버 배포는 빠른 검증과 소규모 사용에 적합합니다.
- 클러스터 배포는 공식 출시, 장기 운영 및 미래 확장에 적합합니다.

## 2. 운영 체제 요구 사항

| 운영 체제 | 지원 버전 | 지원 아키텍처 |
| --- | --- | --- |
| Ubuntu | 22.04, 24.04 | x86 |

각 서버에서 실행:

```bash
cat /etc/os-release
uname -m
```

확인 결과: 

- 운영 체제는 Ubuntu 22.04 또는 Ubuntu 24.04입니다. 
- CPU 아키텍처는 x86입니다. 
- 설치 계정은 `root`이거나 동등한 시스템 관리 권한이 있어야 합니다. 

참고: CentOS 시스템 지원 중단 이유 
- CentOS Linux 7과 8은 지원 종료(EOL)에 도달했으며, CentOS 공식은 더 이상 CentOS 9 및 이후 버전을 제공하지 않으며, 새로운 보안 업데이트, 취약점 수정 또는 문제 패치를 받지 않습니다. 
- 기본 시스템 구성 요소는 장기적으로 보안 패치를 받을 수 없어, 수정할 수 없는 노출된 취약점이 생길 수 있으며, 이는 생산 환경 보안 요구 사항을 충족하지 못합니다. 
- CentOS 7/8의 커널, glibc, OpenSSL 및 기타 기본 구성 요소는 비교적 오래되어 새로운 런타임 및 종속성 라이브러리 요구 사항을 충족할 수 없습니다. Kubernetes  
- CentOS Stream은 기존 CentOS Linux에 비해 버전 위치와 업데이트 메커니즘이 다르며, 특별한 호환성 검증을 거치지 않은 CentOS Stream 환경 또한 공식 지원 범위에 포함되지 않습니다. 


## 3. 서버 구성 요구 사항 

### 3.1 단일 노드 배포 

- 200명 이하의 소규모 가벼운 팀에 적합합니다. 
- PoC데모 및 기능 검증 시나리오는 단일 노드 리소스에 따라 준비할 수 있습니다. 

| 프로젝트 | 요구 사항 | 
| --- | --- | 
| 서버 수 | 1 | 
| CPU | 16코어 이상 |
| 메모리 | 32GB 이상 |
| 시스템 디스크 | 루트 `/` 파티션 100GB 이상 |
| 데이터 디스크 | 독립적으로 장착 `/data`, 사용 가능한 공간 300GB 이상, 확장 지원 |

### 3.2 클러스터 배포

공식 출시, 장기 운영, 고가용성 또는 향후 확장이 필요한 시나리오의 경우 클러스터 요구 사항에 따라 리소스를 준비합니다.

| 항목 | 요구 사항 |
| --- | --- |
| 서버 수 | 3대 이상 |
| 권장 역할 | `3 master   N worker` |
| CPU 노드당 | 16코어 이상 |
| 노드당 메모리 | 32GB 이상 |
| 노드별 시스템 디스크 | 루트 `/` 파티션 100GB 이상 |
| 노드별 데이터 디스크 | 독립적으로 장착 `/data`, 사용 가능한 공간 300GB 이상, 확장 지원 |

파티션 주의 사항:

- 루트 파티션에 최소 100GB 확보 `/` 합니다.
- 통합 관리 위해 루트 파티션 아래에 배치하는 것을 권장합니다. `/root`, `/var`, `/tmp` 합니다.
- 데이터 디렉터리용으로 독립 데이터 디스크를 사용하고, 여기에 마운트합니다. `/data`.

## 4. 서버 자체 점검 명령

각 서버에서 실행: 

```bash

# 1. View CPU architecture and core information
#    - Architecture type (x86_64/aarch64)
# ============================================
lscpu

# ============================================
# 2. Display memory and swap usage in GiB
# ============================================
free -g

# ============================================
# 3. File System Disk Space Usage
# ============================================
df -h

# ============================================
# 4. Find the executable file path
# ============================================
which iptables gzip tar

# ============================================
# 5. Display system time, time zone, and NTP synchronization status
#    Distributed clusters must have strict time synchronization, otherwise it will affect authentication and log sequencing.
# ============================================
timedatectl status
```

비교 체크리스트:

| 점검 항목 | 통과 조건 |
| --- | --- |
| CPU | 16코어 이상 |
| 메모리 | 32GB 이상 |
| 시스템 디스크 | 루트 `/` 파티션 사용 가능한 공간 100GB 이상 |
| 데이터 디스크 | `/data` 마운트됨, 사용 가능한 공간 300GB 이상 |
| 기본 명령 | `iptables`, `gzip`, `tar` 찾을 수 있음 |
| 시간 동기화 | 시스템 시간 동기화 정상 |

## 7. 포트 요구 사항

배포 전에 서버, 보안 그룹, 방화벽, 로드 밸런서 및 네트워크 정책이 다음 포트를 허용했는지 확인하십시오.

| 포트 | 대상 | 목적 |
| --- | --- | --- |
| `18080/TCP` | 설치 프로그램 웹 UI | 설치 페이지 접속 |
| `80/TCP` 또는 `443/TCP` | ShimoDocs서비스_DOMAIN | 사용자 접근 항목 |
| `22/TCP` | 모든 배포 노드 | SSH 로그인 및 설치 작업 분배 |
| `3306/TCP` | MySQL | 데이터베이스 연결 |
| `6379/TCP` | Redis | 캐시 연결 |
| `27017/TCP` | MongoDB | 문서 데이터베이스 연결 |
| `9092/TCP` | Kafka | 메시지 큐 연결 |
| `9200/TCP` | Elasticsearch | 검색 서비스 연결 |
| 서비스 포트별 | S3 / OBS / OSS / COS / MinIO | 객체 저장소 연결 |

## 8. 디스크 IO 요구사항

데이터 디스크에는 SSD 사용을 권장합니다. 디스크 성능은 다음 기준을 충족해야 합니다:

| 항목 | 요구 사항 |
| --- | --- |
| 혼합 읽기/쓰기 IOPS | 5000 이상 |
| 순차 읽기/쓰기 처리량 | 150 MB/s 이상 |
| 평균 지연 시간 | 약 5 ms 이하 |

설치 후 `fio`, 다음에서 테스트를 수행할 수 있습니다 `/data`.

### 8.1 혼합 읽기/쓰기 테스트

```bash
fio --name=randrw-test \
  --filename=/data/testfile \
  --size=20G \
  --rw=randrw \
  --rwmixread=70 \
  --bs=4k \
  --ioengine=libaio \
  --direct=1 \
  --iodepth=32 \
  --numjobs=4 \
  --runtime=300 \
  --time_based \
  --group_reporting
```

결과에서 IOPS 에 주의하세요; 혼합 읽기/쓰기는 IOPS 진행을 위해 5000 이상이어야 합니다. 

### 8.2 순차 읽기 테스트

```bash
fio --name=seqread-test \
  --filename=/data/testfile \
  --size=20G \
  --rw=read \
  --bs=1M \
  --ioengine=libaio \
  --direct=1 \
  --iodepth=32 \
  --numjobs=1 \
  --runtime=300 \
  --time_based \
  --group_reporting
```

### 8.3 순차 쓰기 테스트

```bash
fio --name=seqwrite-test \
  --filename=/data/testfile \
  --size=20G \
  --rw=write \
  --bs=1M \
  --ioengine=libaio \
  --direct=1 \
  --iodepth=32 \
  --numjobs=1 \
  --runtime=300 \
  --time_based \
  --group_reporting
```

순차 읽기 및 순차 쓰기 처리량이 150 MB/s 이상이면 계속 진행할 수 있습니다. 

테스트 후 테스트 파일은 삭제할 수 있습니다: 

```bash
rm -f /data/testfile
```

## 9. 공용 네트워크 대역폭 요구사항

사용자 수를 기반으로 한 공용 네트워크 액세스 시나리오의 대역폭 추정:

```text
PUBLIC_NETWORK_BANDWIDTH = NUMBER_OF_USERS x 0.25 Mbps
```

예:

| 사용자 수 | 권장 공용 네트워크 대역폭 |
| --- | --- |
| 100명 사용자 | 25 Mbps 이상 |
| 200명 사용자 | 50 Mbps 이상 |
| 500명 사용자 | 125 Mbps 이상 |

인트라넷 액세스 시나리오의 경우에도 동일한 기준을 사용하여 송신, 수신 및 부하 분산 대역폭을 평가하는 것이 권장됩니다.

## 11. 배포 전 체크리스트

설치를 시작하기 전에 각 항목을 확인하십시오:

- 운영 체제 버전이 요구 사항을 충족하는지 확인.
- CPU메모리, 시스템 디스크 및 데이터 디스크가 요구 사항을 충족하는지 확인.
- `/data` 데이터 디스크에 마운트되어 있는지 확인.
- `iptables`, `gzip`, 및 `tar` 설치되어 있는지 확인.
- 시스템 시간 동기화가 정상인지 확인.
- 온라인 또는 오프라인 설치 방법이 결정되었는지 확인.
- 설치 프로그램 포트 `18080` 접근 가능한지 확인.
- 비즈니스 액세스 포트 `80` 또는 `443` 열려 있는지 확인.
- 외부 미들웨어를 사용하는 경우, 연결 정보가 완전히 준비되어 있습니다.
- 오브젝트 스토리지는 해당 프로토콜과 호환되며, S3 버킷 및 계정 권한이 준비되어 있습니다. 
- 데이터 디스크 IO 테스트가 요구 사항을 충족합니다. 
- 공용 또는 내부 네트워크 대역폭이 예상 사용자 수를 충족합니다.
