> [!TIP]
>
> 本文介绍如何使用 `mdp-installer` 快速部署一个新的环境。 ShimoDocs Suite.
>
> 本文针对 **All-in-One 单节点在线安装** 场景，适用于首次安装、产品体验、功能验证和部署流程练习。完成本文后，您可以获取 ShimoDocs Suite 业务访问地址以及 MDP 运维平台地址。

> 页面上的 IP 地址、安装包名称、 VERSION以及目录仅供示例。在实际部署中，请参考当前环境和交付资料。

## 1. 部署流程概览

整个流程可分为以下 7 个步骤：

| 步骤 | 需完成的操作 | 完成指示器 |
| --- | --- | --- |
| 1. 准备服务器和安装材料 | 确保服务器、安装程序和 ShimoDocs Suite 分发包可用 | 能够登录服务器并找到安装文件 |
| 2. 启动安装程序 | 在安装节点上运行 `mdp-installer`  | 终端显示安装程序访问地址 |
| 3. 上传分发包 | 在浏览器中选择 ShimoDocs Suite 分发包 | 页面显示分发包已通过验证 |
| 4. 配置部署环境 | 填写域名或IP、部署模式、节点登录信息和数据目录 | 节点验证成功，可访问部署概览 |
| 5. 环境检查 | 等待安装程序检查服务器和部署环境 | 没有阻碍安装的失败 |
| 6. 开始安装 | 确认检查结果并执行部署 | 页面显示安装已完成 |
| 7. 保存交付信息 | 保存访问地址并完成登录、服务和功能验证 | 业务页面和 MDP 运营平台可以访问 |

## 2. 部署前准备

### 1. 准备安装节点

安装节点用于运行安装程序，并作为此全功能单节点部署的目标服务器。

开始前，请确认：

- 一个可用的服务器已准备好，并且已获取 SERVER_IP地址。
- 可以通过以下方式访问服务器： SSH.
- 用户为 SSH ，或者具有执行部署任务所需的权限。 `root`服务器
- 架构与安装程序和分发包匹配，例如，两者都是 CPU 。 `x86_64`.
- 服务器符合当前部署规范；建议使用最小安装的 Ubuntu 24.04。 LTS.
- 根分区和数据空间符合当前部署要求，并已确定数据目录。
- 服务器时间和时区正确，且时间同步正常。
- 可以使用浏览器的计算机访问安装节点的 `18080/TCP` 端口。
- 服务器可以访问互联网以在线下载部署包和镜像资源。
- 如果业务访问使用域名，域名解析已提前完成（可选）。

最低服务器要求如下：

| 操作系统 | 架构 | CPU | 内存 | 磁盘 |
| --- | --- | --- | --- | --- |
| Ubuntu 24.04 LTS | `x86_64` | 16 核 | 32 GB | 100 GB SSD |

此外，请确认：

- 不要分区 `/root`, `/var`, `/tmp` 单独确认。
- 在安装前，不要在服务器上部署可能影响安装程序检查的额外组件，如 Docker 或其他。 Kubernetes 
- 端口 `22/TCP` 用于 SSH, `18080/TCP` 用于安装程序网页， `80/TCP` 以及 `443/TCP` 用于业务访问。

> 在正式部署前，建议根据实际并发、文件大小和可用性要求确认服务器规格；本文档中的单节点流程适用于快速部署和验证，如需长期运行或高可用，请使用相应的集群部署方案。

### 2. 准备安装材料

#### 获取安装程序

将提供的安装程序上传到 ShimoDocs 安装节点的 `/root/` 目录。你可以选择以下任意方法：

- **方法 1：通过 SSH 工具上传**安装节点的目录。 `mdp-installer-amd64` 安装节点的 `/root/` 上传

#### 获取分发包

为本次部署准备 ShimoDocs Suite 分发包。分发包上传至网页安装页面，文件名和版本应符合实际交付。

示例文件名： `co1.8.20260711.3286-drive-release.tar.gz`

物料清单如下：

| 文件 | 说明 |
| --- | --- |
| `mdp-installer` 安装程序 | 根据服务器架构选择相应的文件，例如， `mdp-installer-amd64`. |
| ShimoDocs Suite 分发包 | 文件名和版本应与实际交付版本一致，例如， `co1.8.20260711.3286-drive-release.tar.gz`. |

建议将安装程序及相关安装资料放置在同一工作目录中，以便后续检索和存储。在使用发行包之前，请确保文件完整且未被传输工具损坏。

## 3. 启动安装程序

### 1. 登录安装节点

通过以下方式登录安装节点 SSH 并导航到安装程序所在的目录。例如：

```bash
ssh root@<INSTALL_NODE_IP>
cd /root
```

### 2. 添加执行权限

如果安装程序尚未具有执行权限，请运行：

```bash
chmod +x ./mdp-installer-amd64
```
命令中的文件名需要替换为实际安装程序名称。 

### 3. 启动网页安装页面 

运行： 

```bash
./mdp-installer-amd64 server
```

如果需要在当前终端退出后继续运行安装程序，可以使用： 

```bash
nohup ./mdp-installer-amd64 server > nohup.out 2>&1 &
```

启动成功后，终端将显示两个地址： 

- `Local`：仅供安装节点本身使用。 
- `Network`：可由同一网络上的其他计算机访问。 

如果以后台模式启动，可以运行以下命令查看安装程序输出： 

```bash
cat nohup.out
```

打开 `Network` 在浏览器中访问终端显示的地址，例如：

```text
http://<INSTALL_NODE_IP>:18080/
```

> 安装过程中，请保持安装程序进程运行。不要关闭安装程序进程或停止当前服务。

## 4. 上传 ShimoDocs Suite 发布包

### 1. 选择发布包

进入安装页面后：

1. 点击 **开始部署** 或页面上的发布包选择入口。
2. 选择该 ShimoDocs Suite `.tar.gz` 用于此部署的发布包。
3. 等待文件上传和验证完成。

### 2. 确认验证结果

验证通过后，页面将显示发布包名称和部署配置条目。

请确认以下信息是否正确：

- 包名称与本次交付的版本一致。
- 发布包属于 ShimoDocs Suite 产品。
- 页面未提示文件损坏、格式错误或模式不匹配。

确认后，点击 **继续** 进入部署配置。

如果验证失败，请重新确认分发包是否完整、文件类型是否正确，以及分发包是否与服务器 CPU 架构匹配。

## 5. 配置部署环境

### 1. 确认网络地址

检查页面上显示的主机名或IP地址。该地址应为用户可以正常访问的安装节点地址。

不要输入 `127.0.0.1`，并且不要使用只能由当前计算机访问的临时地址。通过域名访问时，请确保域名已解析到正确的服务入口。

### 2. 选择一体化单节点模式

选择 **一体化单节点** 在部署模式或目标环境中（页面上显示的实际名称以当前版本为准）。

在此模式下，安装节点同时承担本次部署的控制和业务角色，适合用于产品体验、功能验证和单节点规划的轻量级环境。

### 3. 配置节点 SSH

安装程序通过 SSH 连接目标节点并执行部署任务。请填写：

- NODE_IP 地址
- SSH 用户，通常是 `root`.
- SSH 端口，通常为 `22` 默认值。
- PASSWORD 或私钥认证信息。

填写完成后，点击 **验证** 以确认 SSH 连接成功。

> SSH 凭据应仅在受控环境中使用和存储。不要将 PASSWORD 或私钥写入公开文档、截图或聊天记录中。

### 4. 设置数据目录及其他配置

根据页面提示填写或确认以下配置：

| 配置项 | 说明 |
| --- | --- |
| ACCESS_DOMAIN / IP | 用户访问地址 ShimoDocs Suite；使用 IP 时，请填写实际可访问地址。 |
| 部署模式 | 选择 All-in-One 单节点模式。 |
| 节点数据目录 | 用于存储部署数据，请确保磁盘空间充足并具有读写权限。 |
| 离线仓库 | 本指南为在线安装；页面上保留默认值即可。 |
| 第三方中间件 | 本指南使用默认部署；如需外部中间件，请根据当前交付需求确认。 |

如无特殊配置需求，离线仓库和第三方中间件可保留默认值。确认后，点击 **初始化部署** 在页面底部。

## 6. 确认部署概览

部署概览用于在正式检查前验证安装配置。

请特别注意以下内容：

- 确保发布包版本和产品名称正确。
- ACCESS_DOMAIN 或者 IP 地址正确且无误。 `127.0.0.1`.
- 部署模式为 All-in-One 单节点。
- NODE_IP， SSH 用户和端口正确。
- 数据目录正确且磁盘空间充足。
- 离线仓库和第三方中间件配置符合当前环境。

确认无误后，点击 **继续** 继续进行环境检查。

## 7. 执行环境检查

安装程序将检查节点和部署环境。检查过程可能需要几分钟，请保持页面打开。

### 1. 查看节点概览

节点概览显示检查进度，如 SSH 连通性、系统与性能、存储与磁盘、网络和部署环境等。

要查看特定检查的详细结果，请点击相应检查项目或详细条目。

### 2. 查看详细检查结果

详细结果通常包括：

- SSH 连通性和执行用户权限。
- 操作系统， CPU 架构及核心数。
- 内存容量、磁盘空间和目录权限。
- 时区和时间同步状态。
- 网络、镜像资源及与外部服务的连通性。
- 服务器上可能影响部署的环境残留物。

### 3. 理解检查状态

| 状态 | 含义 | 下一步操作 |
| --- | --- | --- |
| 成功 | 当前检查项符合部署要求 | 继续等待其他项完成 |
| 警告 | 不会直接阻止部署，但需要确认是否符合当前计划 | 打开详情并在确认影响后继续 |
| 失败 | 当前问题可能影响安装或产品运行 | 先修复问题，然后重新扫描 |
| 进行中 | 安装程序正在执行检查 | 等待检查完成，不要重复操作 |

如果某项长时间处于“进行中”，可以先等待当前磁盘或远程检查完成，再决定是否重新扫描。

### 4. 处理警告和失败

如果页面显示警告：

1. 打开相应检查项的详细描述。
2. 确认警告是否符合当前部署计划。
3. 如不确定，请保存页面和安装程序日志，然后联系实施或运维人员确认。

如果页面未能显示： 

1. 按照提示修复 SSH，权限、资源、磁盘、网络或中间件问题。 
2. 点击 **重新扫描**. 
3. 确认失败项已消失。 

确认没有阻止部署的失败项且所有警告已确认后，点击 **继续**. 

## 8. 开始安装 

### 1. 确认安装计划 

页面将显示安装计划和待执行的任务。确认无误后，点击 **开始部署**. 

页面可能会出现“确认开始安装”提示。一旦开始，安装任务将按计划进行；如果需要调整配置，请点击 **取消** 返回上一步。

### 2. 检查部署进度

启动部署后，页面将显示当前任务状态、实时日志和执行时间。单节点部署通常需要约10分钟，实际时间会受服务器性能和网络带宽影响。

在安装过程中，请注意： 

- 不要关闭安装程序进程。 
- 不要重启安装节点。 
- 不要刷新、返回或重新提交安装任务。 
- 如果任务失败，请先查看对应任务日志中的第一个错误，然后根据提示进行处理。 

当页面显示 **安装完成** 或进入 **部署交付** 页面时，表示安装任务已完成。 

## 9. 保存交付信息 

安装完成页面将显示本次部署的访问信息和检查入口，请立即完成以下操作： 

1. 运行安装后服务检查并确认检查结果。 
2. 使用部署交付页面上的访问信息，打开 ShimoDocs Suite 业务页面并完成登录验证。 
3. 记录 ShimoDocs Suite 业务访问地址以及 MDP 运营平台地址。 
4. 保存初始账号和临时 PASSWORD，并在首次登录后立即更改初始 PASSWORD 。 
5. 检查集群节点和应用程序状态。 MDP 运营平台。 

> 交付信息包括访问地址和初始凭据。请勿截图分发，不要上传到公共知识库，也不要通过不受控制的渠道发送。 

## 10. 检查部署结果 

完成安装后，建议按以下顺序进行验收： 

### 1. 检查安装后服务 

在安装完成页面执行安装后检查，以确认服务测试用例通过或结果符合当前环境的预期。 

如果检查失败或部分通过，您可以在 MDP 运营平台。 

### 2. 检查 MDP 运维平台

登录到 MDP 运维平台，进入 **系统服务 → 集群管理**，并确认集群节点和应用程序运行状态正常。

### 3. 验证 ShimoDocs Suite 功能

登录到 ShimoDocs Suite 前端页面并至少验证以下功能:

- 创建测试文件或套件。
- 编辑内容并保存。
- 导出文件。
- 导入文件。

在完成上述所有检查后，说明此快速部署已完成。如果将来需要长期运行、扩展或高可用性，请根据实际规模切换到相应的部署方案，并完成许可和业务配置。

## 11. 常见问题

### 1. 浏览器无法打开安装页面

按顺序检查：

- 安装程序进程是否仍在运行。
- 访问地址是否使用安装节点的实际IP或可解析的域名。
- 端口是否 `18080/TCP` 是否已开启。
- 浏览器所在计算机与安装节点之间的网络是否已连接。

### 2. 分发包验证失败

检查：

- 上传的文件是否为完整的 `.tar.gz` 发布包。
- 文件名和产品类型是否与此交付一致。
- 发布包是否与服务器匹配 CPU 架构匹配。
- 无论文件是在上传还是传输过程中损坏。

### 3. SSH 认证失败

检查：

- 是否 NODE_IP 和 SSH 端口是正确的。
- 是否 SSH 用户， PASSWORD或私钥是正确的。
- 是否 SSH 用户是否拥有部署所需的权限？
- 防火墙或安全组是否允许 SSH 连接。

### 4. 环境检查中的警告

警告不会直接阻止部署，但你需要打开详细信息以确认其影响。如果涉及磁盘性能、时间同步、配置残留或外部服务，首先确认是否符合当前部署计划，然后再决定是否继续。

### 5. 环境检查中的失败

失败项需要先修复。不要绕过检查直接开始安装。修复后，点击 **重新扫描** 确认失败项已通过。

### 6. 安装任务失败

1. 打开失败任务的执行日志。
2. 找到首次出现的错误信息。
3. 保存安装程序日志、失败任务名称和发生时间。
4. 在处理相应的网络、磁盘、镜像、中间件或 Kubernetes 问题后，根据实际恢复方法继续操作。
