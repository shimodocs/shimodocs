# 单节点 Kubernetes 部署

[← ShimoDocs Suite 部署文档](../README.md)

## 1. 适用场景
- **K8s 单节点部署**:
    - 适用于轻量化小团队、少于200人的小规模使用， PoC、演示、功能验证和短期测试。
- 只需要一台服务器，并且该服务器同时作为安装节点， K8s 主节点，以及业务工作节点。
- **注意**
    - 对于正式发布、长期运行或后续的高可用性扩展，建议使用 K8s 集群部署。

## 2. 部署流程概述

| 步骤 | 操作指南 | 完成指示器 |
| --- | --- | --- |
| 1. 检查系统环境 | 确认服务器资源、磁盘、网络、时间同步以及基本命令 | 服务器符合部署要求 |
| 2. 准备安装材料 | 获取安装程序和产品安装包；离线环境还需要准备离线镜像包 | 文件名匹配 CPU 架构 |
| 3. 上传安装材料 | 将安装程序和安装包上传到部署节点 | 文件已放置在服务器的指定目录中 |
| 4. 启动安装程序 | 启动 `mdp-installer` 网页 | 可以通过浏览器访问安装程序页面 |
| 5. 网页安装 | 选择发行包，配置节点，完成环境检查，并开始部署 | 所有安装任务成功 |
| 6. 安装后验收 | 检查集群、服务、登录、许可和业务功能 | 核心功能可以正常使用 |

## 3. 部署前准备

### 3.1 准备服务器信息

| 信息 | 示例 | 说明 |
| --- | --- | --- |
| INSTALL_NODE_IP | `<INSTALL_NODE_IP>` | 单节点 K8s 部署仅使用 1 台服务器 |
| CPU 架构 | `amd64` / `arm64` | 安装程序和安装包必须与服务器架构匹配 |
| 网络环境 | 在线 / 离线 | 如果可访问公共网络，选择在线；对于内部或隔离环境，选择离线 |
| 执行用户 | `root` 或者具有 `sudo` 权限的用户 | 安装程序需要通过执行部署任务 SSH |
| SSH 端口 | `22` | 如果 SSH 端口已更改，请填写实际端口 |
| 访问协议 | HTTP / HTTPS | HTTP 可用于测试环境； HTTPS 推荐用于生产或外部访问 |
| ACCESS_DOMAIN | `<ACCESS_DOMAIN>` 或 `<INSTALL_NODE_IP>` | 用户访问的入口地址 ShimoDocs Suite |
| 数据目录 | `/data` | 建议使用单独的数据磁盘挂载 |

### 3.2 准备安装材料

| 材料 | 示例文件名 | 说明 |
| --- | --- | --- |
| 安装程序 | `mdp-installer-amd64` | 适用示例 `amd64` 架构；其他架构请替换为实际文件名 |
| 产品安装包 | `co1.8.20260807.3639-drive-release..tar.gz` | 对于单节点 K8s 部署，选择文件名中不包含的发行包 `k3s`；文件名以实际交付为准 |
| 基础离线镜像包 | `smbase_image-amd64.tar.gz` | 仅在离线安装时需要 |
| 产品离线镜像包 | `offline_app_image.tar.gz` | 仅离线安装时需要，必须与产品安装包版本匹配 |

注意:

- 命令中的文件名需要替换为实际文件名，例如 `mdp-installer-amd64`, `co1.8.<VERSION>-drive-release.tar.gz`.
- 产品安装包、离线镜像包和服务器 CPU 架构必须一致。
- 离线安装前，建议一次性准备好基础离线镜像包和产品离线镜像包，以避免部署过程中临时添加包。

### 3.3 检查服务器资源

| 项目 | 推荐要求 |
| --- | --- |
| 服务器数量 | 1 |
| CPU | 16 核或以上 |
| 内存 | 32 GB 或以上 |
| 系统盘 | 根目录 `/` 分区 100 GB 或以上 |
| 数据盘 | 独立挂载于 `/data`，可用空间超过 300 GB |
| 离线安装 | 建议在数据盘上额外预留超过 100 GB，用于镜像包和临时解压文件 |

在服务器上执行： 

```bash
lscpu
free -g
df -h
timedatectl status
```

确认以下结果： 

- CPU，内存和磁盘满足部署规格。 
- `/data` 已挂载到独立的数据盘。 
- 系统时间同步正常。 
- 可以通过以下方式访问服务器： SSH 登录。 
- 在线安装环境可以访问公网；离线安装环境已准备好离线镜像包。 

### 3.4 检查端口 

| 端口 | 目的 | 
| --- | --- | 
| `22/TCP` | SSH 登录并执行安装任务 | 
| `18080/TCP` | 安装程序网页 | 
| `80/TCP` 或 `443/TCP` | ShimoDocs Suite 访问入口 | 

如果服务器启用了防火墙或安全组，请提前开放上述端口。 

## 4. 上传安装工具和软件包 

以下示例使用 `amd64` 架构。对于其他架构，请用实际文件名替换。 

### 4.1 上传安装程序 

在本地计算机上执行： 

```bash
scp mdp-installer-amd64 root@<INSTALL_NODE_IP>:/root/
```

### 4.2 上传离线镜像包

此步骤可在在线安装时跳过。

对于离线安装，需要将离线镜像包上传到部署节点：

```bash
scp smbase_image-amd64.tar.gz offline_app_image.tar.gz root@<INSTALL_NODE_IP>:/root/
```

### 4.3 登录服务器

```bash
ssh root@<INSTALL_NODE_IP>
```

### 4.4 给安装程序添加执行权限

```bash
chmod +x /root/mdp-installer-amd64
```

### 4.5 启动安装程序网页

在服务器上执行：

```bash
cd /root
./mdp-installer-amd64 server
```

如果希望安装程序在后台运行，可以使用： 

```bash
nohup /root/mdp-installer-amd64 server > /root/mdp-installer.log 2>&1 &
```

浏览器访问: 

```text
http://<INSTALL_NODE_IP>:18080
```

## 5. 通过网页安装

### 5.1 选择分发包

进入安装程序网页后，选择本次要部署的产品分发包。

对于 K8s 单节点部署，请选择文件名不包含 `k3s`的分发包，例如：

```text
co1.8.20260807.3639-drive-release.tar.gz
```

### 5.2 配置 SSH 连接

安装程序将通过 SSH 登录部署节点并执行安装任务。 SSH 设置支持两种认证方式：

- 私钥认证。
- PASSWORD 认证。

建议使用 `root` 用户或具有 `sudo` 权限的用户进行部署。填写信息后，可以先测试连接，以确保安装程序可以正常登录部署节点。

### 5.3 确认基本配置

选择分发包后，进行下一步操作。如果没有特殊要求，可以保持页面默认配置；如果部署环境已有明确的域名、证书、网段或中间件方案，请按实际方案填写。

配置时需确认的要点： 

- 确保访问协议和 ACCESS_DOMAIN 填写正确。 
- Pod CIDR 和服务 CIDR 不与现有网络、办公室网络、 VPN, 或 IDC 网络段。 
- 使用 `/data` 或实际规划的数据盘目录作为数据目录。 
- 线上/线下安装方式与当前网络环境一致。 

### 5.4 初始部署 

配置完成后，点击初始部署。页面将显示本次部署的概览，请重点检查： 

- 产品包版本。 
- 部署 NODE_IP。 
- SSH 用户和端口。 
- ACCESS_DOMAIN 协议。 
- 数据目录。 
- 线上或线下安装模式。 
- 中间件选择。 

确认无误后继续。 

### 5.5 检查系统环境

安装程序将自动检查服务器环境。

检查通过后继续部署。如果有失败项，请根据页面提示处理并重新检查。常见处理方向包括： 

- 磁盘空间不足：清理空间或扩展数据盘。 
- 端口不可用：释放端口或调整端口使用。 
- SSH 连接失败：请检查账号， PASSWORD、私钥、端口和安全组。 
- 时间同步异常：配置 NTP 或校准服务器时间。 
- 缺少基本命令：根据系统发行版安装缺失的命令。 

### 5.6 开始部署 

环境检查通过后，点击开始部署。 

在部署过程中，可以查看各组件的执行日志。安装期间，请确保： 

- 安装程序进程保持运行。 
- 浏览器可以连接到安装节点网络。 
- 不要重启服务器。 
- 不要移动或删除安装包、离线镜像包或数据目录。 

### 5.7 等待安装完成

安装过程需要等待一段时间，具体耗时取决于服务器性能、网络环境和镜像下载速度。

当页面显示所有任务已成功执行且没有失败组件时，即表示部署完成。

### 5.8 确认安装结果

安装完成后，安装程序将显示部署完成页面和访问入口信息。请先确认页面上没有失败任务后，再继续访问业务系统和 MDP 运维平台。

访问营业地址： 

```text
http://<ACCESS_DOMAIN>/
```

如果 HTTPS 在安装过程中已配置，请访问： 

```text
https://<ACCESS_DOMAIN>/
```

使用默认账号或管理员账号登录后，请立即更改初始 PASSWORD 。

访问 MDP 运维平台： 

```text
http://<ACCESS_DOMAIN>/mdp/
```

如果需要修改 MDP 管理员 PASSWORD，可以在部署节点执行以下命令以修改或重置 PASSWORD.
请将 {password} 替换为新的复杂强密码 PASSWORD 根据实际安全要求。

```bash
kubectl exec -it $(kubectl get pods -l app=mdp -o jsonpath='{.items[0].metadata.name}') -- reset-admin-password {password}
```

## 6. 安装后验收

### 6.1 检查 K8s 节点状态

在部署节点上执行：

```bash
kubectl get node
```

节点状态应为 `Ready`. 

继续检查服务： 

```bash
kubectl get pod -A
```

正常状态通常为： 

- `Running`：服务正在运行。 
- `Completed`：任务已执行完成。 

如果遇到如下状态 `CrashLoopBackOff`, `ImagePullBackOff`, `Error`, `Pending`，请先检查对应的 Pod 日志并进行处理。 

### 6.2 检查访问入口 

访问 ShimoDocs Suite 通过浏览器访问入口： 

```text
http://<ACCESS_DOMAIN>/
```

如果 HTTPS 已配置，请访问： 

```text
https://<ACCESS_DOMAIN>/
```

确认登录页面可以正常打开。

### 6.3 检查管理后台和许可证

确认以下项目：

- 可以访问管理后台。
- 管理员可以登录。
- 许可证页面可以打开。
- 可以查看机器信息。
- 可以根据授权流程申请或更新许可证。

### 6.4 检查业务功能

使用测试账户或管理员创建的账户登录后，至少验证：

- 可以创建文档、电子表格和幻灯片。
- 文档可以编辑和保存，刷新后内容仍然存在。
- 支持多用户协作编辑。
- 文件导入和导出正常。
- 核心功能如搜索、团队空间和联系人列表可用。

首次使用默认测试账号登录后，请更改 PASSWORD 。
账号 PASSWORD 是部署交付账号 PASSWORD!
```text
ACCOUNT:autotest@example.com
PASSWORD:xxxxx
```

### 6.5 停止安装程序进程

部署完成并验收通过后，可以停止安装程序 Web 服务：
停止安装网页：
停止安装程序的命令： 
```bash
ps -ef | grep mdp-installer | grep -v grep
kill <PID>
```

如果安装程序是使用 `nohup`在后台启动的，也可以检查日志： 

```bash
tail -f /root/nohup.out
```

## 7. 常见故障排除

### 7.1 浏览器无法打开安装程序页面

检查以下内容：

- 安装程序进程是否仍在运行。
- 端口是否 `18080` 被防火墙或安全组阻塞。
- 浏览器访问的 IP 是否 INSTALL_NODE_IP。

您可以在服务器上执行以下操作：

```bash
ps -ef | grep mdp-installer | grep -v grep
ss -lntp | grep 18080
```

### 7.2 环境检查失败

根据页面提示处理每一项。处理后，返回安装程序页面并重新运行环境检查。

优先检查项：

- 是否 CPU，内存和磁盘满足要求。
- 是否 `/data` 是独立数据盘。
- 服务器时间是否同步。
- 是否 SSH 用户是否具有部署权限。

### 7.3 离线安装镜像拉取失败

检查方向：

- 离线镜像包是否已上传到部署节点。
- 基础离线镜像包和产品离线镜像包是否完整。
- 镜像包版本是否与产品安装包匹配。
- 私有镜像仓库地址、账号及 PASSWORD 已正确填写。

### 7.4 Pod 长时间处于异常状态

首先检查异常 Pod：

```bash
kubectl get pod -A
```

再次检查日志： 

```bash
kubectl logs -n <namespace> <pod-name>
```

根据日志处理镜像、配置、资源或依赖问题。

## 8. 安装后保留材料

部署后，建议保留以下资料以便后续维护、升级和故障排除：

- INSTALL_NODE_IP， ACCESS_DOMAIN及访问协议。
- 安装程序文件名及版本。
- 产品安装包文件名及版本。
- 离线镜像包文件名及版本。
- 网页关键配置截图。
- `kubectl get node` 检查结果。
- `kubectl get pod -A` 检查结果。
- 许可证授权记录。
- 业务功能验收记录。
- 部署过程中遇到的问题及其处理结果。
