# 使用对象存储部署

[← ShimoDocs Suite 部署文档](../../README.md)

本文说明如何在安装程序中禁用内置 MinIO 在 ShimoDocs 安装程序并配置客户自己的 S3 对象存储作为第三方 S3 对象存储。一旦配置完成，安装程序将检查 S3 对象存储网络连接、认证信息，以及桶的读写权限。一旦检查通过，部署可以继续。 

# 1. 配置前的准备 
在开始之前，请确认： 
- S3 对象存储已安装并正常运行。 
- K8s 集群节点可以访问对象存储的主机和端口。 S3  
- 用于连接对象存储的认证 AK/SK 已准备好。 S3  
- S3 存储必须支持客户端浏览器访问。 
- 建议使用单独的实例。 S3  
- 标准 S3 必须提供内部和外部网络的标准协议访问地址。 
- ShimoDocs 业务标准 S3 桶应提前创建。 
- S3 存储必须使用 SSD 磁盘。

## 存储桶配置说明
- 暴露_建议在 headers 中指定头名称，而不是使用 * 符号，因为某些厂商可能不支持 * 符号，例如华为云 OBS，阿里巴巴 OSS
- 存储桶名称可以根据公司的需求配置前缀以避免重复

# 2. 进入高级设置
在安装程序的“配置”步骤中，完成网络、目标环境和节点信息配置后，展开页面底部的“高级配置”。

# 3. 取消内置安装 MinIO
在“中间件服务”区域，取消勾选 MinIO

取消勾选后，安装程序将不再安装内置 MinIO，而会使用后续准备好的外部 S3 预先准备的对象存储稍后将被使用。其他中间件是否使用内置服务应根据实际部署方案选择。

# 4. 打开第三方中间件配置
在“第三方中间件”区域，点击“配置”。

# 5. 进行配置 S3 对象存储
1. 选择 ""S3 左侧的“对象存储”。
2. 启用"MinIO 对象存储。"
3. 对于主服务/编辑器交互，分别输入：AK/SK、内部端点、公共端点、主机、端口， SSL及其他信息
4. 验证并保存

> [!TIP]
>
> 主服务：用于协作编辑之外的服务的对象存储实例
> 编辑器交互：协作编辑服务使用的对象存储实例
>
> 注意：主服务和编辑器交互可以使用同一对象存储实例，但为编辑器交互提供单独实例可以获得更好的协作编辑性能

## 存储桶命名

> [!NOTE]
>
> 当多个业务应用共享同一 S3 实例时，客户可以根据 ShimoDocs存储桶命名规则添加前缀，以帮助区分不同业务并管理存储桶

# 6. 确认验证结果
安装程序将检查以下内容：
- 登录：该账户可以正常认证
- 连接性：部署环境可以访问 S3 对象存储
- 权限：该账户拥有连接、认证、存储桶读写等权限。

当所有检查项显示“成功”后，关闭配置窗口，并返回安装程序的“配置”页面。

如果有失败项，请根据页面提示检查：
- 主机和端口是否填写正确。
- 部署节点与...之间的网络是否 S3 对象存储已连接。
- 是否 USERNAME 以及 PASSWORD 是正确的。 
- 账户是否具备所需权限（连接和认证、存储桶读写权限等）。 

# 7. 继续初始化部署 
返回“配置”页面后，确保 S3 对象存储保持未选中状态，然后点击“初始化部署”以继续完成部署概览、检查和执行步骤。 

> [!TIP] 
> 
> 在初始化部署之前，请再次确认 S3 对象存储配置已保存，且所有验证项已通过。
