# 部署与 Kafka

[← ShimoDocs Suite 部署文档](../../README.md)

本文说明如何禁用内置 Kafka 在 ShimoDocs 安装程序并配置客户自己的 Kafka 作为第三方消息队列。配置完成后，安装程序将检查 Kafka的网络连接性和创建主题的权限。检查完成后，即可进行部署。 

# 1. 配置前的准备工作 
在开始之前，请确认： 
- Kafka 服务器已安装并正常运行。 
- 部署节点可以访问 Kafka 服务器主机和端口。 
- 已准备好的认证用户信息和 PASSWORD 用于连接到 Kafka 服务器主题（如果外部 Kafka 集群已启用了安全认证）。 
- 经过认证的账户必须使用管理员用户，并具有创建、删除、授权以及读写主题的权限（如果外部 Kafka 集群已启用了安全认证）。 

> [!TIP]
>
> 本文中的 IP、端口和账户仅为示例。请使用您的实际环境信息进行配置；不要在外部 PASSWORD 文档或截图中记录真实信息。 
>

# 2. 进入高级配置 
在安装程序的“配置”步骤中，完成网络、目标环境和节点信息配置后，展开页面底部的“高级配置”部分。 

# 3. 取消内置组件安装 Kafka
在“中间件服务”区域，取消勾选 Kafka.

取消勾选后，安装程序将不再安装内置 Kafka，而会使用后续准备好的外部 Kafka 其他中间件是否使用内置服务应根据实际部署方案选择。

# 4. 打开第三方中间件配置
在“第三方中间件”区域，点击“配置”。

# 5. 进行配置 Kafka 消息中间件
## Kafka 服务器 SASL 未启用身份验证
1. 选择 ""Kafka 左侧的“消息队列”。
2. 启用“使用第三方 Kafka 消息队列”。
3. 填写 Kafka 服务器连接信息。
5. 验证并保存

## 正在启用 SASL 身份验证开启 Kafka 服务器 
如果 Kafka 服务器已 SASL 启用身份验证，需要在 Web 界面中同时启用：仅在代理要求身份验证访问时启用按钮 
1. 启用 SASL 身份验证 
2. 检查机制 
3. 输入 USERNAME 以及 PASSWORD 
4. 验证并保存 

# 6. 确认验证结果
安装程序将检查以下内容：
- 登录：账户可以正常认证（如果 SASL 已启用)。
- 连接性：部署环境可以访问 Kafka.
- 创建主题权限：该账户具有创建主题、授权以及读/写的权限。

当所有检查项显示“成功”后，关闭配置窗口并返回安装程序的“配置”页面。

如果有任何失败，请根据页面上的提示检查：
- 主机和端口是否填写正确。
- 部署节点与...之间的网络是否 Kafka 服务器已连接。
- 是否 USERNAME 以及 PASSWORD 是正确的（Kafka 服务器已启用 SASL 身份验证）。
- 账户是否具有所需权限（Kafka 服务器已 SASL 启用身份验证）。

# 7. 继续初始化部署
返回“配置”页面后，确保 Kafka 保持未选中状态，然后点击“初始化部署”以继续进行部署概述、检查和执行步骤。

> [!TIP]
>
> 在初始化部署之前，请再次确认 Kafka 配置已保存，所有验证项目均已通过。
