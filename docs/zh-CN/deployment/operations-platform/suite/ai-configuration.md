# AI 配置

[← ShimoDocs Suite 部署文档](../../README.md)

AI 配置用于连接 ShimoDocs Suite 与基础模型、图像模型、在线搜索和嵌入服务。完成配置后，功能在 ShimoDocs Suite 例如 AI 对话、内容生成、图像处理和知识检索可以访问相应的服务。 

## 1. 在配置之前了解四种能力类型 

这四种配置类型的目的不同，您不一定需要全部配置。请根据 ShimoDocs Suite 您计划启用的功能。 

| 配置类型 | 目的 | 需要配置 | 
| --- | --- | --- |
| 基础模型 | 处理对话、写作、总结、重写、问答以及其他文本或多模态任务 | 通常在使用 AI 功能时需要 |
| 图像模型 | 生成或编辑图像 | 仅在使用图像生成或编辑功能时需要 |
| 在线搜索 | 从外部搜索服务获取信息以补充模型参考 | 仅在使用在线检索功能时需要 |
| 嵌入 | 将文本转换为向量以用于知识库检索、语义搜索及类似功能 | 仅在使用知识检索或向量搜索功能时需要 |

> [!TIP]
>
> 在线搜索通常是独立的搜索服务，与基础模型内置的在线功能不同。 

## 2. 访问 AI 配置 

1. 登录到 **MDP 运维平台**. 
2. 在顶部，选择 **ShimoDocs Suite**.
3. 在左侧边栏，选择 **租户管理**.
4. 找到 **AI 配置** 卡片。
5. 点击卡片进入“AI 模型与搜索配置”页面。

## 3. 首先选择要连接的模型服务提供商

请先确认您计划使用的模型服务，然后前往相应的配置部分。

| 模型类型 | 服务提供商 |
| --- | --- |
| 基础模型 | 与 OpenAI Responses 协议兼容的提供商 |
| 图像模型 | 与 OpenAI Image 协议兼容的提供商 |
| 互联网搜索引擎模型 | 目前仅支持火山引擎 |
| 嵌入模型 | 与 OpenAI 嵌入协议兼容的提供商 |

## 4. AI 模型配置

本部分用于配置 GPT相关服务。请让工程确认是使用 OpenAI 官方服务、Azure OpenAI、代理服务或其他兼容接口，因为请求地址和模型 ID 可能因连接方式而异。

### 4.1 基础模型

基础模型用于对话、内容生成、总结、改写以及多模态理解功能。

## 5. 每个配置项的业务意义

本节对页面上每个配置项的用途进行统一说明。首次配置时，可以根据前面提到的供应商模板填写，然后返回本节确认每个字段是否符合实际业务需求。

### 5.1 基础模型提供商配置项

| 配置项 | 业务意义 | 错误输入的常见影响 | 必填 |
| --- | --- | --- | --- |
| 提供商 | 指示系统使用哪种模型适配方法。即使两个服务接口相似兼容，提供者选项也可能决定请求格式、认证方式以及结果解析方式。 | 可能保存失败、请求格式不匹配或响应无法解析。 | 是 |
| 请求 URL / 基础 URL | 入口地址 ShimoDocs Suite 在向模型服务发送请求时访问。 | 如果地址不正确，无法连接模型；如果路径级别错误，接口可能显示不存在。 | 是 |
| API 密钥 | 模型服务用于识别调用方并验证权限的凭证。 | 通常在凭证不正确、过期或权限不足时提示认证失败。 | 是 |
| 默认模型 | 业务功能未显式指定模型时，系统优先调用的模型。 | 如果未设置或设置为不可用模型，某些AI功能可能无法使用。 | 是 |

### 5.2 基本模型配置项目

| 配置项 | 业务意义 | 错误输入的常见影响 | 必填 |
| --- | --- | --- | --- |
| 状态 | 控制模型是否允许被调用。 ShimoDocs Suite关闭后，配置可以保留，但业务通常无法继续使用该模型。 | 即使模型配置正确，如果状态为关闭，业务仍可能显示其不可用。 | 是 |
| 模型 ID | 模型服务接口识别的模型名称或唯一标识符。 | 如果与服务器名称不一致，通常提示模型不存在。 | 是 |
| 模型名称 | 在运维平台上向管理员显示的名称，用于区分不同模型。 | 如果名称重复或不清晰，容易选择错误模型；是否参与实际请求由工程确认。 | 是 |
| 上下文窗口 | 模型在单次请求中可以处理的信息总量，通常会影响输入文本的长度、对话历史和输出空间。 | 设置大于模型实际容量可能导致请求失败；设置过小可能导致内容被截断或无法提交。 | 是 |
| 文本输入 | 指示模型是否可以接受文本内容。 | 如果错误地设置为关闭，文本相关功能可能无法选择或调用该模型。 | 是 |
| 图像输入 | 指示基础模型是否可以理解用户上传的图像；这是多模态输入功能，与生成图像不同。 | 对于不支持图像的模型启用此功能可能导致请求失败；若关闭，则图像理解功能不可用。 | 是 |

### 5.3 图像模型配置选项

| 配置项 | 业务意义 | 错误设置的常见影响 | 必填 |
| --- | --- | --- | --- |
| 状态 | 控制图像模型是否可以被图像生成或编辑功能调用。 | 如果状态为关闭，相关图像功能无法使用该模型。 | 是 |
| 服务提供商 | 确定图像请求使用的接口适配方式。 | 选择不当可能导致请求参数或返回格式不兼容。 | 是 |
| 模型名称 / 模型ID | 指定实际调用的图像模型。此字段是显示名称还是请求ID需由工程确认。 | 名称与服务器不一致可能表示该模型不存在。 | 是 |
| 基础 URL | 图像生成或编辑请求发送的服务地址。 | 地址或路径不正确时，无法调用图像服务。 | 是 |
| API 密钥 | 调用图像服务时使用的认证凭证。 | 错误、过期或缺乏权限将导致身份验证失败。 | 是 |
| 功能 | 声明模型支持的图像功能，如图像生成、图像编辑等。 | 如果配置了模型不支持的功能，业务入口可能可见，但调用会失败。 | 是 |

注意：目前仅支持 OpenAI 图像 API 协议

### 5.4 互联网搜索配置

| 配置项 | 业务意义 | 常见影响（如果不正确） | 必填 |
| --- | --- | --- | --- |
| 状态 | 控制是否 ShimoDocs Suite 可以调用当前搜索服务。 | 当状态为关闭时，模型可能仍可用，但无法获取互联网搜索结果。 | 无 |
| 服务提供商 | 指定使用的搜索服务类型及其接口适配方式。 | 如果选择不正确，请求和结果解析可能不兼容。 | 无 |
| 接口地址 | 发起搜索请求时访问的服务端点。 | 如果地址不正确，互联网功能可能会超时或无法连接。 | 无 |
| API 密钥 | 搜索服务使用的身份验证凭证。 | 如果不正确或权限不足，搜索请求将被拒绝。 | 无 |
| 超时设置 | 单次搜索的最大等待时间；若超出，系统将停止等待并视为失败或无结果。 | 设置过短会导致频繁超时；设置过长会增加用户等待时间。 | 无 |

### 5.5 嵌入配置

嵌入模型不一定需要启用，但如果未启用，文档内容无法向量化，从而系统无法处理与用户知识库相关的问题。

| 配置项 | 业务意义 | 填写不正确的常见后果 | 是否必填 |
| --- | --- | --- | --- |
| 基础 URL | 发送到文本向量化请求的服务地址。如果地址不正确，则无法生成或更新向量数据。否 |
| API 密钥 | 嵌入服务使用的身份验证凭证。由于错误、过期或缺乏权限，向量化失败。否 |
| 嵌入模型 | 实际负责将文本转换为向量的模型ID。当模型不存在或不匹配时，无法生成向量。否 |
| 维度 | 每行文本生成的最终向量长度必须与模型的实际输出和向量存储配置相匹配。 | 如果维度不一致，通常无法写入或检索；更改维度后，可能需要重新生成现有向量。否 |

注意：目前仅支持 OpenAI Embedding API 协议 

## 6. 推荐配置顺序 

为减少重复，建议按以下顺序进行配置： 

1. 首先，确认需要启用哪些 AI 功能 ShimoDocs Suite. 
2. 选择符合协议要求的基础模型。 
3. 配置提供商并至少添加一个基础模型。 
4. 将验证可用的模型设置为默认模型。 
5. 根据业务需求配置图像模型。 
6. 根据业务需求配置网络搜索。 
7. 如果使用知识库或语义搜索，则配置嵌入。 
8. 保存后，分别验证每项功能；不要仅根据页面上的“启用”显示来判断配置是否成功。 

## 7. 有效配置规则 
| 需要工程确认的问题 | 内容 |
| --- | --- |
| 保存配置后是否立即生效 | 不会立即生效；需要等待 1-2 分钟 |
| 您需要重启服务吗 | 无需重启服务 |
| 新配置是否在已打开的页面生效 | 您需要刷新当前页面 |
| 多模型之间的优先选择 | 不支持 |
| 默认模型不可用时会自动切换吗？ | 不支持 |

## 8. 常见问题排查 

| 现象 | 常见原因 | 排查方法 |
| --- | --- | --- |
| 连接模型服务失败 | 请求地址、网络、证书或端口配置异常 | 检查服务地址、 DNS端口、证书及防火墙策略 | 
| 提示身份验证失败 | API Key 错误、已过期或权限不足 | 确认 API Key 正确并有权访问目标模型或服务 | 
| 提示模型不存在 | 模型 ID 与服务器端名称不匹配 | 确认完整模型 ID 并检查大小写及版本后缀 | 
| 文本可用但图片不可用 | 模型不支持图片输入，或图片输入开关未启用 | 检查模型能力及输入开关 | 
| 存在图片功能入口但调用失败 | 功能与模型实际能力不一致 | 验证图像模型支持的生成和编辑能力 | 
| 在线搜索频繁超时 | 搜索服务慢、网络不稳定或超时设置过短 | 检查网络延迟、服务性能及超时设置 | 
| 嵌入写入失败 | 输出维度与向量存储配置不一致 | 验证模型实际输出维度及存储配置 | 

## 问答

1. 如何验证配置是否生效？

完成配置后，可以前往编辑器侧边栏开启 AI 会话，以验证功能是否正常运行：

- 消息应能正常回复
- 如果配置了图像模型，可以发送类似“生成一个 Xxx 图片”的命令，并观察命令是否正确执行
- 如果配置了在线搜索，可以发送类似“搜索今日北京天气”的命令，并观察结果是否符合预期

2. 是否支持 /chat/completions 接口？

目前不支持。当前只支持 OpenAI Responses API 协议。已知官方 API 如 Deepseek / 小米 Mimo 提供对该协议的支持。本地部署方案如 vLLM 和 Ollama 也支持 Responses 协议。
