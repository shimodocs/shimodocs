# 系统配置

[← ShimoDocs Suite 部署文档](../../../README.md)

## 1. 使用说明

本手册介绍“系统配置”功能， ShimoDocs Suite适用于首次使用此功能的系统管理员和实施人员。您可以按照本文档中的步骤查找配置项、修改配置、验证更改是否生效，并在需要时恢复原始设置。

> [!TIP]
>
> 如果不确定某个配置项的含义或影响，请在进行任何更改之前联系 ShimoDocs 技术支持以确认。

**最重要的范围规则** 当企业 ID 留空时，查询和修改适用于全局配置；当选择企业 ID 时，查询和修改适用于所选企业的配置。修改全局配置可能会影响多个企业，因此请在保存之前重新确认配置范围。

### 1.1 访问入口

管理员后台 > ShimoDocs Suite > 配置管理 > 系统配置

### 1.2 使用前的准备

- 确认登录账户具有查看和编辑权限 ShimoDocs Suite 系统配置。
- 首先确认目标范围是全球还是特定企业，并获取准确的企业ID。
- 根据配置需求或附录A确认配置键名称。配置键名称是唯一标识，请不要仅根据中文名称猜测。
- 在修改前记录来源、状态和生效值；对于重要配置，还需准备回滚值。
- 影响较大的全局配置应在业务低峰期进行修改，并提前通知相关人员。

## 2. 配置范围和优先级

系统配置支持全局和企业范围。在修改前，必须检查企业ID字段和页面底部的范围提示。

| **功能区域** | **全局范围** | **企业范围** | **页面识别信号** |
| --- | --- | --- | --- |
| 系统配置 | 留空企业ID | 选择企业ID | 底部提示“全球版本覆盖”或“企业最终生效结果” |

*图1 系统配置中选择企业ID的位置*

### 2.1 全局配置

- 保持企业ID未选择。
- 页面提示当前查询和修改的是“全球版本覆盖”。
- 全局值是在未设置企业覆盖时使用的基础值；修改它们可能会影响多个企业。
- 保存前，请至少再检查一次以确保企业ID字段确实为空。

### 2.2 企业级配置

- 从企业ID下拉菜单中选择目标企业。
- 页面显示将默认值与当前企业自定义配置合并后的最终生效结果。
- 企业级配置仅影响所选企业，不会直接更改其他企业的配置。
- 当相同项目存在企业级配置时，企业的最终生效值优先于全局值。

### 2.3 覆盖、继承与恢复

- 当当前企业没有覆盖时，将使用全局配置或系统默认值。
- 诸如“恢复系统默认值”或删除当前覆盖的操作通常意味着移除当前范围的覆盖并重新继承上级值。
- 页面上的提示如“系统默认”、“全局版本覆盖”和“企业最终生效结果”可用于判断当前值来源于哪一层。
- 在执行恢复或删除之前，请记录当前值并确认继承结果符合预期。

**风险提示** 在未确认企业范围前请勿直接保存。如果企业ID为空，操作可能会写入全局覆盖并影响多个企业。

## 3. 系统配置

系统配置用于查看和调整通用功能、配额和操作参数 ShimoDocs Suite.

### 3.1 搜索方法一：精确搜索

- 企业ID：留空表示全局；选择企业ID进行企业级配置。
- 搜索条件：根据需要选择类型、值类型和有效结束日期；如果不确定，请保持“全部”。
- 关键名称：输入配置键名称；每行输入一个键，或使用逗号分隔多个键。
- 点击“搜索”以在结果中确认名称、键、来源、状态和当前值。
- 点击目标行最右侧的“编辑”以打开修改弹窗。

*图2 系统配置精确搜索区域。*

*图3 配置键名称精确搜索后的单个结果。*

**范围提示。** 当页面底部显示“当未选择企业时，当前查询和修改适用于全局版本覆盖”时，表示当前作用域为全局。选择企业后，页面显示将默认值与当前企业自定义配置组合的最终生效结果。

### 3.2 第二种搜索方法：直接在列表中定位

- 保持企业范围和过滤条件正确，并使用页面滚动浏览列表。
- 通过“名称”或“键名”确认目标配置，不要仅根据当前值判断。
- 在同一行查看类型、有效结束日期、当前值、来源和状态。
- 点击最右侧的“编辑”。如果看不到操作列，请水平滚动表格到最右侧，或放大浏览器视口。

#### 3.3.1 键值类型

编辑弹窗顶部显示只读的元数据，包括键名、名称、描述、类型和有效结束日期。启用后，在如“字符串值”等输入框中填写数值并保存。如果字符串包含路径或列表，应保持原格式。 JSON, URL

*图 4 系统配置键值类型编辑弹窗*

#### 3.3.2 配额类型

配额弹出窗口通常包括状态、最小值、最大值和“无验证”开关。启用配置后，根据业务需求填写范围；开启“无验证”意味着系统不会根据输入的范围进行限制检查。数值必须与弹出窗口的单位一致，如“个”、“MB”等。

*图 5 系统配置配额类型编辑弹出窗口*

#### 3.3.3 功能类型

功能类型主要基于状态切换。开启表示配置项在当前范围内启用；关闭表示禁用或未启用。一些键具有反向语义，应根据配置项名称和描述判断。例如，名称包含“unsupport”或“disable”的键在开启时可能表示“不支持”或“禁用”。

### 3.4 保存、删除和恢复

- 保存前，请再次确认企业范围、键名、类型、单位和修改后的值。
- 保存后，再次搜索相同的配置项，以确认源、状态和生效值已发生变化。
- 当当前范围存在覆盖时，可能可以执行“删除”操作；删除覆盖后，它将恢复到上一级继承的值。
- 需要回滚时，先写回原始记录的值，或者在确认继承关系后删除当前覆盖。
- 不要将“删除”理解为删除配置项本身；页面上的删除通常只针对当前范围内的覆盖记录。

## 4. 生效性验证与回滚

### 4.1 保存后的验证

- 在系统配置页面，重新查询相同企业范围和相同配置项，以确认源、状态和生效值。
- 访问实际使用该配置的功能页面，检查功能的表现，而不仅仅是查看配置后台。
- 对于全局配置，至少应对一个没有企业级配置的公司进行抽查；企业级配置仅对目标公司进行验证。
- 对于账户、权限或缓存相关的设置，如有必要，请刷新页面、重新登录或等待缓存更新。
- 记录修改时间、操作人员、企业范围、键名、修改前后的值以及验证结果。

### 4.2 回滚

- 存在确定的原始值：重新编辑并写回原始值。
- 只需移除当前范围覆盖：使用“恢复系统默认”或删除当前覆盖。
- 回滚后，再次查询源值和生效值，并重新进入业务页面进行验证。
- 如果全局修改导致广泛异常，应优先恢复全局覆盖，然后调查各个企业之间的覆盖差异。

**重要提示** 页面上的删除通常适用于当前范围内的覆盖记录；配置项本身仍然存在。删除前有必要确认继承值是否符合预期。

## 5. 常见问题

| **问题** | **处理方法** |
| --- | --- |
| 找不到编辑或操作按钮 | 当表格很宽时，水平滚动到最右侧；也可以放大浏览器的可视区域。 |
| 精确搜索无结果 | 检查键名的大小写和下划线；确认企业ID范围；清除过于严格的类型、值类型或有效结束过滤条件。 |
| 保存后，业务页面没有变化 | 检查是否选择了错误的企业范围，源是否被企业覆盖，是否需要刷新或重新登录，并确认配置项是否适用于当前功能。 |
| 恢复系统默认按钮不可用 | 当前范围没有覆盖，当前使用继承值或系统默认值。 |
| JSON 或 URL 配置错误 | 保持有效 JSON 或 URL 格式，不要省略引号、逗号或协议；请先在测试企业中验证。 |
| 企业最终有效值与全局值不同 | 当前企业可能存在覆盖。请检查源记录和覆盖记录以确认是保留企业差异还是恢复继承。 |

## 附录 B：术语与页面字段对应关系

| **术语** | **含义** |
| --- | --- |
| 配置键 / 键名 | 配置项的唯一键，例如 batch_下载_文件数。 |
| 企业ID | 企业标识。选择后进入企业级配置范围。 |
| 全局配置 | 当企业 ID 留空时，查询和修改的默认范围。 |
| 企业级配置 | 仅对所选企业生效的覆盖。 |
| 系统默认值 | 如果当前范围内没有自定义覆盖，则使用内置默认值。 |
| 全局版本覆盖 | 当前配置项在全局级别具有自定义设置。 |
| 企业生效结果 | 合并企业默认值与企业覆盖后的实际生效结果。 |
| 键-值 | 以字符串形式存储的单值参数，可能包含文本、 URL路径，或 JSON. |
| 配额 | 包括最小值、最大值或限制切换的数值范围。 |
| 功能 | 开关或状态类型参数。 |
| 无验证 | 不根据指定的上限执行验证检查。 |
