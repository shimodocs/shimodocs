# 系统升级

[← ShimoDocs Suite 部署文档](../../../README.md)

## 功能概览

系统升级用于上传和应用新的 MDP 安装包。在正式升级之前，系统会自动检查升级包和当前环境，并显示此次升级涉及的配置和服务变更，帮助您完成版本升级或日常维护。

该页面还保留升级历史记录，使查看过去的升级记录、执行状态和相关日志变得容易。

**注意**：重大版本升级可能会更新数据库模式。升级过程涉及配置更改、服务重启和功能接口变更，可能影响用户体验。应在业务非高峰时段进行。

## 进入页面

登录管理后台后，选择 **系统升级** 在左侧导航中进入页面。

系统升级仅对管理员可用。如果您看不到此菜单，请联系系统管理员确认当前账户权限。

## 升级前准备

在开始升级之前，建议确认以下事项：

- 使用官方提供的与当前产品类型和部署方式匹配的升级包。
- 升级包为 `.tar.gz` 格式。请不要解压或修改包内文件。
- 建议在业务非高峰时段或维护窗口进行升级。
- 确认当前服务运行正常，并提前通知相关用户。
- 如果升级涉及许可证更改，请提前准备新的许可证内容。

## 升级步骤

### 1. 上传升级包

点击系统升级页面上的上传区域，或将升级包拖入上传区域。上传完成后，系统将自动解析并验证升级包。

验证主要包括：

- 安装包的格式和内容完整性。
- 安装包签名是否有效。
- 升级包的版本和升级计划。
- 产品类型和部署架构是否匹配。
- 当前许可证是否支持此次升级。

验证结果分为以下状态：

- **通过**：验证正常，可以继续。
- **更改**：此次升级存在预期的更改；请在继续前确认内容。
- **不匹配**：存在阻止升级的问题；您需要更换升级包或处理相关配置后重新上传。

### 2. 输入许可证

如果系统判断此次升级需要更新许可证，页面将提示需要更新的产品，并显示当前服务器机器码等信息。

粘贴新的许可证内容后，点击 **验证并临时保存**。仅在许可证成功验证后，升级才能继续。临时保存的许可证将在升级成功应用后自动生效。有关许可证的参考，请参见[许可证管理]。

如果页面显示许可证无需更新，则可以直接进行下一步。

### 3. 确认升级包内容

页面将显示升级包中的配置文件和服务资源。您可以选择特定文件查看其内容，并确认升级包与当前升级目标一致。

### 4. 确认更改

系统将比较当前环境与升级包，并显示本次升级中将新增、修改、删除或重启的资源。

请特别注意确认： 

- 是否有任何意外的资源删除。 
- 是否有任何重要服务需要重启。 
- 配置文件中的更改是否符合预期。 

### 5. 应用更新 

在确认上述信息正确后，点击 **确认开始更新**。系统将创建升级前快照并开始应用更新包。 

在升级过程中，页面将持续显示执行日志，包括资源更新、服务重启和运行状态检查等信息。当某些组件重启时，管理页面可能会暂时无法访问。请稍等片刻，然后重新打开页面以检查进度。 

如果执行失败，您可以根据日志处理问题，然后点击 **重新应用**. 

### 6. 完成升级 

在升级任务成功执行后，点击 **完成** 以完成此次升级过程。 

升级完成页面将显示升级包的名称和版本，并提供以下操作： 

- **查看执行日志**：查看此升级的完整过程。 
- **回滚到升级前版本**：进入升级前的快照，并按照页面提示进行回滚。 
- **返回应用更新**：返回系统升级主页。 

## 升级历史 

系统升级主页底部将显示升级历史，包括升级包名称、版本、创建时间和执行状态。 

点击升级记录以重新进入相应流程，查看升级进度或历史执行结果。

## 常见情况

- **升级包验证失败**：请确认升级包来源、文件完整性、产品类型和部署架构正确。
- **版本不匹配**：请检查当前系统版本和升级包版本，确保使用正确的升级路径。
- **需要更新许可证**：获取与目标版本和当前运行环境兼容的新许可证，进行验证，并临时保存后再继续。
- **升级流程页面暂时不可用**: 该 MDP 服务可能正在更新或重启，请稍候并刷新页面。
- **升级任务失败**：检查执行日志以确定原因；解决问题后，使用 **重新应用**.
- **升级后服务异常**：首先检查执行日志和服务状态；如果需要恢复，可以使用升级前的快照回滚。

> 系统升级将修改服务配置，可能触发服务重启。请在确认升级包和变更正确后再进行操作。
