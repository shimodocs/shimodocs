# 中间件配置

[← ShimoDocs Suite 部署文档](../../../README.md)

## 1. 概览 

中间件配置是 MDP 运营平台中的页面，用于与客户端环境中的各种存储和中间件集成，集中管理诸如以下组件的连接信息 S3 对象存储， Redis，消息队列 Kafka，关系型数据库 MySQL，文档数据库 MongoDB，以及全文本搜索 Elasticsearch。配置更改通过异步任务发送到客户端环境，在更改过程中可以实时显示测试和发布进度。 

主要功能： 

- 为每个中间件配置连接信息（端点、访问密钥， USERNAMEPASSWORD，等等） 
- 在不同供应商之间切换 (S3 以及 OSS, AWS / MinIO / 腾讯云 COS / 华为云 OBS, MySQL 和 DM Dameng) 
- 跟踪表单中的脏值；只有修改过的字段会被提交 
- 每个配置部分可以独立测试；只有在验证通过后才允许发布 
- 一键发布：批量提交所有脏字段配置并异步执行 

### 1.1 适用用户 

| 角色           | 常规操作                                     | 
| -------------- | ---------------------------------------------------- | 
| 实施工程师 | 在初次部署期间填写中间件连接信息 | 
| 运维值班 | 凭证更换、端点变更、测试连接 | 
| 应急响应 | 切换备份中间件并修改超时配置 |

### 1.2 本模块不推荐的操作 

切换供应商（例如 S3 → OSS）涉及大规模下游数据迁移的变更，应按照变更流程处理。多个环境的连接信息批量调整不在本模块涵盖范围；您需要逐个进入每个环境进行页面配置。中间件容量规划和监控告警不在此页面；请使用集群管理和告警配置模块。

## 2. 各中间件配置的详细说明 

### 2.1 S3 对象存储 

**操作步骤**：从左侧菜单进入“中间件配置”，默认在此部分 → 向下滚动即可依次看到三个配置区块：公共 S3 实例设置，协作编辑 S3 实例设置，以及存储桶设置。 

#### 2.1.1 公共 S3 与协作编辑 S3

**操作步骤**：首先填写公开信息 S3 实例设置，然后填写协作编辑 S3 实例设置，最后填写存储桶设置。修改任何字段后，点击底部的“测试连接”。
两个部分的表单字段一致：
| 字段               | 描述                                                              | 必填 |
| ----------------- | ---------------------------------------------------------------------- | ---- |
| 存储类型           | 下拉选择 'S3 （对象存储）' 或 'OSS （阿里云）'                             | 是   |
| 子类型               | 根据存储类型动态加载：对于 S3，选项包括 AWS / 腾讯云 COS / 华为云 OBS / MinIO / 其他；对于 OSS, 仅限阿里云 OSS 可用 | 是    |
| 访问密钥 ID     | 凭证标识符                                                        | 是   |
| 访问密钥密文 | 凭证密钥，输入框 PASSWORD 已隐藏 | 是 |
| 区域 | 例如 `cn-north-1` | 是 |
| 强制路径样式 | 复选框，是否启用路径样式访问 | 无 |
| SSL | 复选框，是否启用 HTTPS | 无 |
| 端点 | 内部服务访问地址 | 是 |
| 公共访问地址 | 用户侧访问地址 | 是 |
| 地址替换规则 | 用于将内部地址映射到公共地址的正则表达式或字符串 | 是 |

#### 2.1.2 存储桶设置 

**操作步骤**：服务器返回的所有存储桶将会以逐一的形式呈现，您可以根据需要填写 CDN 域名。 

| 字段       | 描述                  |
| --------- | ------------------------- |
| 桶名称 | 存储桶名称         |
| 前缀      | 对象存储路径前缀  |
| CDN 域名  | CDN 加速域名     |
| 启用 CDN 认证 | 复选框，启用后将添加两个项目“认证类型”和“认证密钥” |

> 启用后 CDN 认证，需要对应的认证类型和认证密钥。 

### 2.2 Redis
**步骤**: 使用右侧的快速导航点击 Redis 图标以滚动到此部分 → 选择一种模式 → 填写地址并 PASSWORD → 点击“测试连接”。 

字段说明：

| 字段     | 说明                        |
| -----     | -----------------------------    |
| 模式      | 独立模式或哨兵模式          |
| 地址   | 独立模式下的连接地址，例如， `redis-sentinel-master-ss:6379` |
| 主名称 | 哨兵模式下必填，例如， `mymaster` |
| 地址列表 | 哨兵模式下的多个地址，可动态添加/删除 |
| PASSWORD  | 必填                          |

切换模式将自动重置地址、主名称和地址列表字段。

### 2.3 Kafka
**操作步骤**: 点击 Kafka 右侧快速导航中的图标以滚动到此部分 → 填写 Broker 地址 → 如果 SASL 已启用，展开 SASL 子字段 → 点击“测试连接”。

字段说明：

| 字段         | 描述                                         |
| ---------- | ------------------------------------------------ |
| Broker 地址 | 数组，可动态添加/删除        |
| 主题前缀    | 自动添加到所有主题的前缀         |
| 启用 SASL 认证 | 开关，启用时添加三个 SASL 配置 |
| 认证机制 | PLAIN / SCRAM-SHA-256 / SCRAM-SHA-512（启用后） SASL) |
| USERNAME / PASSWORD   | SASL 凭证（启用后 SASL)           |

### 2.4 MySQL （关系型数据库）
**操作步骤**：在右侧快速导航中，点击 RDB 图标并滚动到此部分 → 选择 MySQL 或 DM Dameng → 填写主机、端口， USERNAMEPASSWORD → 点击“测试连接”。

字段说明：

| 字段      | 描述        |
| -------- | ---------------- |
| 数据库类型 | MySQL 或 DM（Dameng) |
| 主机地址  | 例如 `mysql-master` |
| 端口          | 3306           |
| USERNAME / PASSWORD | 凭证      |

> 右侧菜单和页面标题中的 “RDB 关系型数据库” 对应于 MySQL 配置部分。

### 2.5 MongoDB
**操作步骤**: 点击 MongoDB 右侧快速导航中的图标滚动到此部分 → 填写连接字符串 → 根据服务器配置逐一渲染每个数据库凭据 → 点击“测试连接”。

字段说明： 

| 字段           | 说明                       |
| ------------- | -------------------------------- |
| 连接字符串 | 例如 `mongo-master:27017` |
| 每个数据库 USERNAME / PASSWORD | 为服务器配置的数据库逐一呈现 |

### 2.6 Elasticsearch
**步骤：** 使用右侧快速导航点击 Elasticsearch 图标并滚动到此部分 → 填写主机地址和端口 → 如果启用身份验证，请填写 USERNAME 以及 PASSWORD → 点击“测试连接”。

字段说明： 

| 字段     | 描述       | 必填 |
| ----      | --------------  | ----    |
| 主机地址 | 例如， `elasticsearch` | 是      |
| 端口        | 9200             | 是      |
| USERNAME    | ES 凭证   | 否       |
| PASSWORD    | ES 凭证   | 否       |

## 3. 常见操作 

### 3.1 凭证更新（例如，访问密钥轮换） 

1. 转到中间件配置 
2. 在...中替换访问密钥 ID 和访问密钥 Secret S3 公共卡 
3. 点击“测试连接”，并等待绿色“连接测试成功”消息 
4. 对其他已修改的部分重复连接测试 
5. 点击底部的“发布配置” 
6. 系统提示已创建异步任务并跳转到任务日志标签 

### 3.2 切换中间件供应商 

1. 转到中间件配置 
2. 在对应卡片中修改“存储类型 / 子类型”以及新供应商的端点、访问密钥、地址替换规则等 
3. 修改后，点击“测试连接”以验证 
4. 点击“发布配置” 

> 切换供应商会涉及下游服务的连接池重新加载，请避免在业务高峰期进行；切换后建议监控应用日志 5 至 10 分钟。 

### 3.3 启用 Kafka SASL 

1. 进入中间件配置并定位到 Kafka 部分 
2. 开启“启用” SASL 身份验证”开关， SASL 字段将展开 
3. 填写认证机制， USERNAME和 PASSWORD 
4. 点击“测试连接” 
5. 通过后，点击“发布配置” 

### 3.4 从错误操作中恢复 

在点击“发布配置”之前，表单状态会保存在浏览器的 localStorage 中。可以通过以下方式恢复： 

- 点击底部的“全部重置”按钮，所有字段将恢复为初始服务器值 

### 3.5 异步任务跟踪 

成功发布配置后，系统将跳转到任务日志标签以显示任务进度。任务可能长也可能短，具体取决于中间件实例的数量和更改字段的数量。

## 4. 常见问题 

**问1：点击 Redis 右上角的快速导航没有响应。**

右侧的快速导航只会滚动到相应的部分。如果该部分不在当前页面上（例如，被弹出窗口遮挡），您可以滚动页面或者再次点击右侧导航中的 Redis 图标来重新定位。

**问2：发布配置后，状态似乎没有更新。**

发布后页面会自动刷新。如果浏览器没有自动刷新，您可以手动按F5获取最新配置。

**问3：“已修改N个配置”中的数字与实际数量不符。**

页面计数基于表单的脏值字段。在某些情况下，例如在重置后进行修改，或动态添加/删除数组项时，可能会导致计数不一致。您可以点击“全部重置”并重新填写条目。

**问：Bucket 设置卡找不到我想添加的 Bucket。**

页面根据服务器端配置渲染现有的 Bucket。添加新的 Bucket 需要修改基础的服务器配置文件，而不是通过此页面操作。如果需要添加，请联系实施工程师。

## 附录 A：术语参考

| 术语       | 解释                                                                |
| -------- | ----------------------------------------------------------------- |
| 服务器配置文件 | 平台维护的最终配置来源，由平台默认值与本页面发布的值合并形成 |
| Bucket   | 存储桶所在位置 S3 / OSS |
| 端点 | 中间件服务地址，用于内部集群访问 |
| 公网访问地址 | 用户可见的中间件地址 |
| 地址替换规则 | 将内部地址映射为公共地址的正则表达式或字符串 |
| SASL     | 简单认证和安全层，用于像以下组件的认证机制 Kafka |
| 哨兵 | 其中一个 Redis的高可用性计划 |
| DM       | Dameng 数据库（国内关系型数据库）                                             |
| 脏字段       | 表单中已修改且与初始值不同的字段          |
