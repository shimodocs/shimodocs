# RDB 工具

[← ShimoDocs Suite 部署文档](../../../README.md)

> [!TIP]
>
> RDB 用于在运维平台中查看和排查关系型数据库数据，常用于确认业务记录、配置记录、任务状态、操作日志及其他结构化数据。
>
> 使用前，请确保您的当前账户具有中间件工具权限，并选择了正确的部署环境。

> 用户为 RDB 工具可直接访问数据库数据。在查询之前，请确认表和过滤条件，以避免执行高成本查询或误操作生产数据。

## 1. 访问 RDB

1. 登录至 **MDP 运维平台**.
2. 选择 **系统服务** 在左侧导航栏中
3. 展开 **中间件工具** 在左侧导航面板中。
4. 选择 **RDB**.

页面通常包括数据库连接、表选择、 SQL 输入和查询结果区域。

## 2. 选择数据库连接

1. 在 RDB 页面上，选择您需要访问的数据库实例。
2. 确认实例名称、数据库地址或环境标识是否与当前故障排除目标匹配。
3. 选择目标数据库。
4. 展开表列表，确认目标表是否存在。

> 如果数据库实例为空或连接失败，请先检查中间件配置、账户权限和网络连接。

## 3. 查看表结构

1. 从左侧的表列表中选择目标表。
2. 查看字段名称、字段类型、主键和索引信息。
3. 根据字段含义确认后续查询条件。

建议关注以下信息：

| 信息 | 说明 |
| --- | --- |
| 主键 | 用于精确查询单条记录。 |
| 业务ID | 例如租户ID、用户ID、任务ID、文件ID。 |
| 状态字段 | 用于确认业务当前流程状态。 |
| 时间字段 | 用于限制查询的时间范围。 |
| 索引字段 | 尽可能作为查询过滤条件以减少全表扫描。 |

## 4. 使用常用功能 SQL

'常用' SQL'常用'用于快速执行预设查询，适用于证书、申请、文件和用户等高频检查场景。

1. 点击 **常用 SQL** 位于 SQL 编辑器上方。
2. 选择该 SQL 你需要从下拉列表中使用。
3. 如果需要先检查语句内容，请点击 **预览** 对应的旁边 SQL.
4. 在预览窗口中验证描述、数据库、表名和 SQL 内容。
5. 确认无误后，点击 **执行**.

常用 SQL 可能包含占位符：

| 占位符 | 参数类型 | 示例 |
| --- | --- | --- |
| `%s` | 字符串 | 应用ID、提供者文件ID、历史GUID、提供者用户ID |
| `%d` | 数字 | 内部用户ID |

如果 SQL 包含占位符，执行时会弹出一个 **填写 SQL 参数** 窗口。

1. 根据提示填写每个参数。
2. 对于字符串参数，填写完整的ID，不要加额外的引号。
3. 数值参数请填写纯数字。
4. 点击 **执行查询**.

常用的 SQL 目前主要包括以下场景：

| 场景 | 说明 |
| --- | --- |
| 证书查询 | 查询应用证书和应用ID。 |
| 按指定appid查询 | 通过应用ID查询应用详情。 |
| 按指定客户文件guid查询 | 查询文件详情 `provider_file_id`. |
| 按指定内部文件guid查询 | 查询文件详情 `history_guid`. |
| 按指定内部用户id查询 | 通过内部用户ID查询用户详情。 |
| 按指定客户用户id查询 | 查询用户详情通过 `provider_user_id`. |

> 即使在使用常用的 SQL之前，也有必要确认目标环境和参数值。常用 SQL 仅用于减少手工编写的成本，并不能保证查询结果会符合本次调查的目标。

## 5. 执行查询

1. 在 SQL 输入区域填写查询语句。
2. 优先使用 `SELECT` 查询，不要执行插入、更新或删除语句。
3. 默认查询 LIMIT 是10，可以手动调整。
4. 点击 **执行查询**.
5. 优先执行 EXPLAIN和 **确认执行** 后再开始查询。

示例：

```sql
SELECT *
FROM example_table
WHERE id = 'example-id';
```

## 6. 查看查询结果

1. 在结果区域查看返回的记录。
2. 检查关键字段是否符合预期。
3. 如果结果为空，请检查数据库、表名、查询条件和时间范围。
4. 如果结果过多，请增加更精确的筛选条件并重新查询。

## 7. 使用查询历史

“查询历史”用于查看 SQL 在当前页面执行过的语句，方便重复使用故障排查语句、验证执行结果及复制。 SQL."

> [!NOTE]
>
> 查询历史保存在当前浏览器本地，不会持久存储。每个数据库/表维度最多保留最近100条记录，目前没有自动的时间淘汰机制；清除浏览器站点数据、切换浏览器、切换设备或切换到不同数据库/表将会看到不同的历史记录。

1. 切换到 **查询历史** 在结果区域查看。
2. 查看执行状态、时间、数据库、表， SQL，返回的行数，以及历史记录中的消耗时间。
3. 要再次执行一个 SQL 语句，请点击 **插入到编辑器并执行** 在该记录的操作栏中。
4. 如果您只需要重复使用该语句，请点击 **复制 SQL**.

查询历史字段描述：

| 字段 | 说明 |
| --- | --- |
| 状态 | 是否 SQL 执行成功；如果失败，请结合错误提示排查。 |
| 时间 | 当前查询的执行时间。 |
| 数据库 | 所选的数据库在 SQL 执行。 |
| 表 | 关联的表 SQL 执行。 |
| SQL | 实际执行的查询语句。 |
| 返回行数 | 此查询返回的数据行数。 |
| 耗时 | SQL 执行所花费的时间，可用于判断是否存在慢查询风险。 |
| 操作 | 支持重新插入执行或复制 SQL. |

在排查查询历史问题时，建议重点关注： 

| 情况 | 处理建议 |
| --- | --- |
| 状态 失败 | 首先，检查是否存在 SQL 语法、数据库表是否存在，以及字段是否正确。 |
| 耗时较长 | 添加过滤条件，或先检查表结构和索引字段。 |
| 返回行数过多 | 添加'WHERE'条件和'LIMIT'. |
| 多次查询结果不一致 | 确认是否切换了数据库、表或环境。 |

> 查询历史用于辅助审核当前的故障排查过程。在重新执行历史 SQL之前，仍需确认 SQL 内容、目标数据库和当前环境。 

## 8. 常见故障排除场景

| 场景 | 操作建议 |
| --- | --- |
| 确认业务记录是否存在 | 使用业务ID进行精准查询。 |
| 检查任务状态 | 通过任务ID查询状态字段和更新时间。 |
| 排查失效配置 | 查询配置表中当前值及更新时间。 |
| 检查最近变更 | 按时间字段降序查询，并限制返回条目数量。 |
| 查询应用或证书信息 | 在“常用中”优先使用证书查询或appid查询 SQL”. |
| 复用故障排查语句 | 复制 SQL 从“查询历史”中，核对参数，然后再次执行。 |

## 9. 注意事项

1. 在生产环境中禁止对大表进行无条件查询。
2. 如果不确定影响，请先在低风险环境中验证。 SQL 
3. 除非有明确的变更计划并获得批准，否则不要通过工具直接修改业务数据。 RDB 
4. 通用参数 SQL 必须填写当前环境的实际值，以避免跨环境的错误查询。
5. SQL 查询历史中的内容可能包含敏感ID，复制或转发前请确认范围。
6. 当查询结果涉及敏感信息时，不要将完整的截图或明文数据外传。
