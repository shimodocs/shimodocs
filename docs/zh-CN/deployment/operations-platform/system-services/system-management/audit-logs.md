# 审计日志

[← ShimoDocs Suite 部署文档](../../../README.md)

## 功能概览

操作日志用于查看和跟踪系统中的用户管理操作，有助于故障排查、安全审计和变更追踪。

此页面为只读，不支持修改或删除日志记录。

## 访问页面

登录管理后台后，选择 **操作日志** 在左侧导航中访问该页面。

## 筛选日志

您可以使用以下条件组合进行查询：

- **事件来源**：例如，控制面板、应用配置中心、更新程序、 Kubernetes 资源管理或用户管理中心。
- **操作类型**：根据事件源显示相应操作，例如配置更新、版本升级、服务重启或用户管理操作。
- **操作用户**：筛选由特定用户生成的记录。

选择事件源后，操作类型列表将自动调整。点击 **搜索** 以应用筛选条件，或点击重置按钮清除条件。

## 查看日志列表

列表主要显示：

- 日志ID。
- 事件源和操作类型。
- 操作用户。
- 被操作对象的类型、名称和ID。
- 操作时间。 

日志总数将显示在页面顶部，列表支持分页和调整每页显示条目数量。 

## 查看日志详情 

点击 **详情** 在记录右侧查看完整信息，包括： 

- 源和操作类型的名称及内部标识符。 
- 执行操作的用户及用户ID。 
- 操作时间。 
- 对象类型、对象ID和对象名称。 
- 事件元数据。 

对于应用配置中心的更改，详情还可能显示配置修改内容、发布后是否自动重启，以及已重启的工作负载。

## 常见用例

- 检查谁执行了特定的配置更改。
- 确认系统升级、服务重启或扩展操作的时间。
- 根据对象名称追踪相关更改。
- 使用事件元数据验证配置差异和执行结果。
- 调查操作失误或意外的管理更改。

## 常见情况

- **未找到记录**：尝试清除筛选条件，或确认所选的来源、操作类型和用户是否匹配。
- **操作类型列表为空**：先选择事件来源，或重新加载页面以获取最新枚举。
- **对象信息为空**：某些系统事件可能未关联特定对象，这是正常的。
- **元数据不是格式化内容**：某些历史事件可能以纯文本形式存储，页面将显示原始内容。
- **日志数量与预期不符**：日志仅记录系统已审核的操作，并可能受环境保留策略的影响。

> 操作日志可能包含用户、对象标识和配置更改信息，应仅授权人员可访问。
