# 静态资源监控

[← ShimoDocs Suite 部署文档](../../../README.md)

静态资源监控用于检查网页引用的JS和 CSS 资源，帮助您了解资源的访问状态、传输协议、缓存配置以及 CDN 使用情况。

> 系统页面上的功能名称为“静态资源检测”。

## 1. 使用方法

登录管理平台，选择 **系统服务** 在顶部，然后选择 **工具集合 > 静态资源检测** 。

此功能仅对管理员可用。如果您未看到该入口，请检查您的账户权限和当前产品版本。

1. 输入完整的页面 URL，例如 `https://example.com/recent`.
2. 如果页面需要登录，展开“自定义请求头”并填写必要信息，例如 `Cookie` 以及 `Authorization`.
3. 点击“开始检测”，然后等待结果返回。

> 请求头也将用于访问页面引用的静态资源。请仅使用临时凭证，并确保跨源资源的域是可信的。页面地址、请求头以及最近的检测结果将保存在当前浏览器中。

## 2. 检测范围

系统将识别 JS 和 CSS 直接在页面中引用的 HTML，但不会检测图像、字体、内联代码或脚本执行后动态加载的资源。

- 每个域最多检测 3 个同域的 JS 和 CSS 文件；
- 一次最多可以检测 50 个跨域资源；
- 重复的 URL 只计算一次。

未检测到的同域资源将被标记为“跳过同域抽样”，这不表示资源错误。

## 3. 查看结果

检测完成后，页面将显示：

- **汇总信息**：数量 HTML 资源数，检测到的数量，问题数量，缓存使用情况， CDN和 HTTP/2;
- **页面响应**：目标页面的状态码、协议和缓存信息；
- **资源列表**: URL，状态码、协议、缓存， CDN、每个资源的问题和响应头。

资源列表支持按“已检测”、“全部”和“有问题”筛选。 

系统主要提示以下问题： 

- HTTP 4xx/5xx； 
- 未检测到有效缓存； 
- HTTP未使用 /2； 
- 跨域资源未显示 CDN 特性； 
- 请求超时或域名解析失败。 

## 4. 常见问题 

### 页面检测失败 

请检查页面 URL、网络连接， HTTPS 证书和登录状态。检测服务不会自动重用浏览器中的登录信息，因此如果需要，请提供自定义请求头。 

### 未识别的资源 

请确保页面返回正常 HTML通过脚本动态加载的资源将无法被识别。 

### CDN 显示“未检测到” 

此结果仅表示在响应中未检测到任何 CDN 特征，并不意味着该资源一定未使用 CDN。请通过 CDN 控制台和网络架构进行验证。 

## 5. 注意事项 

- 检测结果反映了管理平台在此次请求期间从网络观察到的情况，可能与实际用户体验有所不同。 
- CDN缓存和问题状态为自动确定的结果，仅用于辅助诊断。 
- “未发现问题”并不意味着页面已通过完整的性能、安全或可用性评估。 
- 页面发布后， CDN 被刷新或网络环境发生变化，建议重新测试。
