# 容器抓包

[← ShimoDocs Suite 部署文档](../../../README.md)

## 功能概览 

容器数据包捕获用于从运行中的 Pod 收集网络数据， Kubernetes 帮助您分析连接失败、请求超时、 TCP 重传和网络拥塞等问题。 

捕获完成后，您可以下载 PCAP 文件，并使用像 Wireshark 这样的网络分析工具进一步检查它。 

## 访问页面 

登录管理控制台后，选择 **容器抓包** 在左侧导航中进入该页面。 

容器数据包捕获仅适用于 Kubernetes 部署环境，并且仅对管理员可用。 

## 启动数据包捕获 

建议遵循以下步骤： 

1. 在中搜索并定位目标 Pod **Pods 列表**. 
2. 确保 Pod 状态为运行中，然后点击 **开始捕获**. 
3. 选择捕获持续时间：1分钟、5分钟或30分钟。 
4. 选择捕获文件大小：100 MB、500 MB 或 1 GB。 
5. 根据需要选择过滤条件，或者手动输入 tcpdump 过滤表达式。 
6. 查看页面上显示的完整捕获命令。 
7. 点击 **开始捕获** 以创建任务。 

同一时间在同一个 Pod 上只能运行一个数据包捕获任务。任务将在达到设定的持续时间后自动结束，也可以手动停止。 

## 过滤条件 

设置过滤条件可以减少无关流量和文件大小。页面提供了一些常用的预设，例如： 

- 指定端口的流量。 
- gRPC 流量。 
- 指定主机和端口。 
- HTTP POST 请求。 
- TCP 连接建立、重传或小窗口数据包。 

你也可以使用 tcpdump 语法手动输入，例如： 

```text
host 10.0.0.1 and port 80
```

如果未指定过滤条件，任务可能会收集 Pod 大量的网络流量。

## 管理数据包捕获任务

在 **数据包捕获任务** 在页面上，你可以查看任务 ID、Pod、状态、创建时间和运行时间。

- **运行中**：任务可以手动停止。
- **已完成**: 该 PCAP 文件可以下载。
- **失败**：你可以查看任务日志以了解失败原因。

任务列表会自动刷新，也可以点击 **刷新** 手动获取最新状态。

## 下载与分析

任务完成后，点击 **下载** 以获取 PCAP 文件。下载功能依赖于系统正确配置对象存储。

PCAP 文件可能包含请求地址、协议数据或其他敏感信息。请仅提供给授权人员，并在使用后妥善存储或删除。

## 常见情况

- **未找到 Pod**：页面仅显示当前环境中处于运行状态的 Pod。请检查 Pod 状态和部署环境。
- **无法启动抓包**：请确保 Pod 上没有正在进行的抓包任务，并检查 Kubernetes 临时容器的权限和支持情况。
- **任务执行失败**：检查任务日志以验证过滤表达式、Pod 状态，以及抓包组件是否正常工作。
- **无法下载文件**：请检查对象存储配置和网络连接。
- **抓包文件过大**：减少抓包持续时间，并使用更精确的过滤表达式。

> 数据包捕获会消耗一定的网络、 CPU和存储资源。请避免在高峰时段进行长时间、大流量且无过滤器的捕获。
