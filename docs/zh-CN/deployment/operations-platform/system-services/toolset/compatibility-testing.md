# 兼容性测试

[← ShimoDocs Suite 部署文档](../../../README.md)

## 1. 页面概览

兼容性测试页面用于检查对象存储配置、连接性、上传兼容性和上传性能。页面分为：

1. 存储配置；
2. 兼容性测试；
3. 性能测试。

## 2. 存储配置 

### 2.1 配置项说明 

| 配置项 | 功能 |
| --- | --- |
| 访问密钥 | 对象存储访问身份标识符，即 AK |
| 密钥 | 与 AK 配套的访问密钥，即 SK |
| 端点 | 对象存储服务地址 |
| 桶名称 | 待检测的目标存储桶 |
| 区域 | 存储桶所在区域 |
| 公共端点 | 浏览器访问对象存储使用的公网域名，可选 |
| 路径风格 | 使用“endpoint/bucket/object”格式访问对象，类似服务通常需要启用 MinIO  |

### 2.2 填写配置 
1. 根据需要点击“填写附件桶”或“填写内容桶”。 
2. 系统会自动根据当前环境填写 AK、SK、Endpoint、Bucket、Region 等配置。 
3. 如果不使用自动填写，也可以手动填写所有配置。 
4. 检查端点是否包含正确的协议和端口。 
5. 检查 Bucket 名称是否为本次待检测的存储桶。 
6. 检查 Region 是否与对象存储实际所在区域匹配。
7. 如果需要浏览器直接访问对象存储，请填写公共端点。
8. 根据对象存储的类型决定是否启用路径风格。

本次自动填充附件桶后：

- 桶： `shimo-attachments`;
- 端点：系统自动填充；
- 区域： `cn-north-1`;
- 公共端点：系统自动填充；
- 路径风格：已启用。

点击“填充内容桶”后，桶可以自动切换到 `file-contents`.

> 密钥是敏感信息；不要在截图、聊天或工单中以明文显示。

## 3. 兼容性测试

兼容性测试将依次检查后端上传、浏览器直接上传和分片上传。

### 3.1 开始测试

1. 完成存储配置。
2. 点击“兼容性测试”选项卡。
3. 再次确认桶、端点、区域、公共端点和路径风格配置正确。
4. 点击“开始兼容性测试”。
5. 等待页面显示“兼容性测试完成”。
6. 检查页面上的汇总状态是否为“全部通过”。
7. 分别检查三个测试的状态、持续时间和结果信息。

### 3.2 后端上传测试

该测试用于验证后端服务到对象存储的网络连接性和写入权限。

1. 后端生成一个测试文本文件。
2. 后端将文件写入目标存储桶。
3. 页面显示上传持续时间和测试对象的路径。
4. 绿色成功状态表示后端网络和写入权限正常。

当前结果：上传成功，持续时间 `157 ms`.

### 3.3 浏览器直接上传测试

该测试用于验证浏览器通过 PostPolicy 直接上传到对象存储的链接。

1. 页面从后端请求直接上传所需的 PostPolicy。
2. 浏览器使用公共端点直接向对象存储上传文件。
3. 页面检查对象存储返回的 HTTP 状态码。
4. HTTP 204 表示浏览器直接上传成功。

本次结果：浏览器直接上传成功，耗时 `61 ms`，状态码 `204`.

### 3.4 分片上传测试

此测试用于验证大文件分片上传的完整过程。

1. 初始化分片上传任务。
2. 将测试文件拆分为多个部分。
3. 依次上传每个部分。
4. 调用合并接口完成对象创建。
5. 页面显示 `multipart upload succeeded`，表示整个过程成功。

本次结果：分片上传成功，耗时 `1746 ms`.

### 3.5 测试对象说明

兼容性测试将对目标 Bucket 进行实际写入，后台测试对象的路径通常类似于：

```text
compatibility-tests/<RANDOM UUID>.txt
```

1. 在运行测试前确认目标 Bucket 是否正确。
2. 不要在错误的生产 Bucket 中随意运行测试。
3. 测试完成后，可以根据环境的清理策略检查和清理测试对象。

## 4. 性能测试

性能测试用于测量不同文件大小的上传时间和吞吐量。

### 4.1 配置性能测试

1. 点击“性能测试”选项卡。
2. 选择测试模式；页面默认“浏览器直传”。
3. 选择内容类型；您可以使用 `application/octet-stream` 默认值。
4. 选择要测试的文件大小。
5. 页面支持 1、5、8、10、12、15、20 和 25 MB。
6. 在测试环境中，可以先选择 1 MB 以快速验证。
7. 对于正式性能比较，请选择多个文件大小进行测试。

### 4.2 开始性能测试

1. 确认存储配置正确。
2. 确认已选择至少一个文件大小。
3. 点击“开始性能测试”。
4. 等待所有文件上传完成。
5. 查看平均吞吐量、最短时间和最长时间。
6. 查看每个文件大小的状态、耗时、吞吐量和错误信息。
7. 如果发生失败，首先检查浏览器网络、公共端点、跨域配置和对象存储状态。

### 4.3 本次测试结果

本测试仅使用 1 MB 文件进行轻量前端直传测试：

| 指标 | 结果 |
| --- | ---: |
| 文件大小 | 1.0 MB |
| 状态 | 成功 |
| 时间 | 874 毫秒 |
| 吞吐量 | 1.14 MB/s |
| 错误信息 | 无 |

实际结果：上传成功，页面能够正确生成耗时和吞吐量指标。

> 性能结果可能会受到浏览器网络、集群负载、代理链接和对象存储负载的影响。单次测试只能验证功能可用性；正式性能验收应在相同环境下反复测试并进行统计， P50, P95并记录失败率。

## 5. 注意事项
1. 在进行测试前确认目标存储桶，以避免将测试文件写入错误的存储桶。
2. 不要在文档或截图中以明文显示密钥。
3. 浏览器直接上传依赖公共端点和跨域配置。
4. S3兼容服务如 MinIO 通常需要启用路径风格。
5. 性能测试会生成真实的网络流量和存储写入；在测试大文件前评估环境影响。
6. 正式性能验收应进行多轮测试；单次浏览器测试结果不足以作为依据。
