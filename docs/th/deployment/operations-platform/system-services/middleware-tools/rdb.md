# RDB เครื่องมือ

[← ShimoDocs Suite เอกสารการติดตั้ง](../../../README.md)

> [!TIP]
>
> RDB ใช้เพื่อดูและแก้ไขปัญหาข้อมูลฐานข้อมูลเชิงสัมพันธ์ในแพลตฟอร์มปฏิบัติการ และมักใช้เพื่อยืนยันข้อมูลธุรกิจ ข้อมูลการกำหนดค่า สถานะงาน บันทึกการปฏิบัติการ และข้อมูลเชิงโครงสร้างอื่น ๆ
>
> ก่อนใช้งาน โปรดตรวจสอบให้แน่ใจว่าบัญชีปัจจุบันของคุณมีสิทธิ์เครื่องมือมัลติเพิลแวร์และเลือกสภาพแวดล้อมการปรับใช้อย่างถูกต้อง

> ผู้ใช้ RDB เครื่องมือนี้เข้าถึงข้อมูลฐานข้อมูลโดยตรง ก่อนการค้นหา กรุณายืนยันตารางและเงื่อนไขตัวกรองเพื่อหลีกเลี่ยงการเรียกใช้การค้นหาที่มีค่าใช้จ่ายสูงหรือการทำงานผิดพลาดของข้อมูลในระบบจริง

## 1. การเข้าถึง RDB

1. เข้าสู่ระบบที่ **MDP แพลตฟอร์มปฏิบัติการ**.
2. เลือก **บริการระบบ** ที่ด้านบน
3. ขยาย **เครื่องมือ Middleware** ในแผงนำทางด้านซ้าย
4. เลือก **RDB**.

หน้ามักรวมถึงพื้นที่สำหรับการเชื่อมต่อฐานข้อมูล การเลือกตาราง SQL การป้อนข้อมูล และผลลัพธ์การค้นหา

## 2. การเลือกการเชื่อมต่อฐานข้อมูล

1. บนหน้า RDB เลือกอินสแตนซ์ของฐานข้อมูลที่คุณต้องการเข้าถึง
2. ยืนยันว่าชื่ออินสแตนซ์ ที่อยู่ฐานข้อมูล หรือรหัสสภาพแวดล้อมตรงกับเป้าหมายการแก้ไขปัญหาปัจจุบัน
3. เลือกฐานข้อมูลเป้าหมาย
4. ขยายรายการตารางและยืนยันว่าตารางเป้าหมายมีอยู่

> หากอินสแตนซ์ฐานข้อมูลว่างหรือการเชื่อมต่อล้มเหลว โปรดตรวจสอบการตั้งค่า middleware สิทธิ์บัญชี และการเชื่อมต่อเครือข่ายก่อน

## 3. การดูโครงสร้างตาราง

1. เลือกตารางเป้าหมายจากรายการตารางทางด้านซ้าย
2. ดูชื่อฟิลด์ ประเภทฟิลด์ คีย์หลัก และข้อมูลดัชนี
3. ยืนยันเงื่อนไขการสืบค้นต่อไปตามความหมายของฟิลด์

แนะนำให้เน้นข้อมูลต่อไปนี้:

| ข้อมูล | คำอธิบาย |
| --- | --- |
| คีย์หลัก | ใช้สำหรับสืบค้นระเบียนเดียวอย่างแม่นยำ |
| รหัสธุรกิจ | เช่น Tenant ID, User ID, Task ID, File ID |
| ฟิลด์สถานะ | ใช้เพื่อยืนยันสถานะปัจจุบันของกระบวนการธุรกิจ |
| ฟิลด์เวลา | ใช้เพื่อจำกัดช่วงเวลาการสืบค้น |
| ฟิลด์ที่มีดัชนี | ควรใช้เป็นตัวกรองการสืบค้นเพื่อลดการสแกนตารางทั้งหมด |

## 4. การใช้ Common SQL

'Common' SQL'Common' ถูกใช้สำหรับการเรียกใช้คำสั่งที่ตั้งไว้ล่วงหน้าอย่างรวดเร็ว เหมาะสำหรับสถานการณ์การตรวจสอบที่มีความถี่สูง เช่น ใบรับรอง, การสมัคร, ไฟล์, และผู้ใช้

1. คลิก **Common SQL** เหนือ SQL ตัวแก้ไข
2. เลือก SQL คุณจำเป็นต้องใช้จากรายการแบบเลื่อนลง
3. ถ้าคุณจำเป็นต้องตรวจสอบเนื้อหาคำสั่งก่อน ให้คลิก **Preview** ถัดจาก SQL.
4. ตรวจสอบคำอธิบาย, ฐานข้อมูล, ชื่อตาราง, และ SQL เนื้อหาในหน้าต่างตัวอย่าง
5. หลังจากยืนยันว่าทุกอย่างถูกต้องแล้ว ให้คลิก **Execute**.

ที่ใช้บ่อย SQL อาจมีที่ว่างสำหรับใส่ข้อมูล:

| ตัวแทน | ประเภทพารามิเตอร์ | ตัวอย่าง |
| --- | --- | --- |
| `%s` | สตริง | รหัสแอป, รหัสไฟล์ผู้ให้บริการ, GUID ประวัติ, รหัสผู้ใช้ผู้ให้บริการ |
| `%d` | ตัวเลข | รหัสผู้ใช้ภายใน |

หาก SQL มีตัวแทน, จะมี **กรอก SQL พารามิเตอร์** หน้าต่างจะปรากฏขึ้นเมื่อดำเนินการ

1. กรอกแต่ละพารามิเตอร์ตามคำแนะนำ
2. สำหรับพารามิเตอร์สตริง, กรอกรหัสทั้งหมดโดยไม่ต้องเพิ่มเครื่องหมายคำพูดพิเศษ
3. กรอกพารามิเตอร์ตัวเลขด้วยตัวเลขล้วน
4. คลิก **ดำเนินการแบบสอบถาม**.

ที่ใช้กันทั่วไป SQL ปัจจุบันส่วนใหญ่รวมถึงสถานการณ์ดังต่อไปนี้:

| สถานการณ์ | คำอธิบาย |
| --- | --- |
| การสอบถามใบรับรอง | สอบถามใบรับรองแอปพลิเคชันและรหัสแอปพลิเคชัน |
| สอบถามโดยระบุ appid | สอบถามรายละเอียดแอปพลิเคชันตามรหัสแอปพลิเคชัน |
| สอบถามโดยระบุ customer file guid | สอบถามรายละเอียดไฟล์โดย `provider_file_id`. |
| สอบถามโดยระบุ internal file guid | สอบถามรายละเอียดไฟล์โดย `history_guid`. |
| สอบถามโดยระบุ internal user id | สอบถามรายละเอียดผู้ใช้ตาม internal user ID |
| สอบถามโดยระบุ customer user id | สอบถามรายละเอียดผู้ใช้โดย `provider_user_id`. |

> แม้ก่อนที่จะใช้ที่ใช้กันทั่วไป SQLจำเป็นต้องยืนยันสภาพแวดล้อมเป้าหมายและค่าพารามิเตอร์ Common SQL มีไว้เพื่อลดค่าใช้จ่ายในการเขียนด้วยตนเองเท่านั้นและไม่รับประกันว่าผลการสอบถามจะตรงกับวัตถุประสงค์ของการสอบสวนนี้

## 5. การดำเนินการสอบถาม

1. กรอกคำสั่งสอบถามใน SQL พื้นที่ป้อนข้อมูล
2. แนะนำให้ใช้ `SELECT` คำสั่งสอบถามและไม่ดำเนินการคำสั่ง insert, update, หรือ delete
3. คำสั่งสอบถามเริ่มต้น LIMIT คือ 10 และสามารถปรับได้ด้วยตนเอง
4. คลิก **ดำเนินการแบบสอบถาม**.
5. แนะนำให้ทำ EXPLAIN, และ **ยืนยันการดำเนินการ** ก่อนเริ่มการสอบถาม

ตัวอย่าง:

```sql
SELECT *
FROM example_table
WHERE id = 'example-id';
```

## 6. การดูผลลัพธ์การค้นหา

1. ดูระเบียนที่ส่งกลับในพื้นที่ผลลัพธ์
2. ตรวจสอบว่าฟิลด์หลักตรงตามที่คาดไว้หรือไม่
3. หากผลลัพธ์ว่าง ให้ตรวจสอบฐานข้อมูล ชื่อตาราง เงื่อนไขการค้นหา และช่วงเวลา
4. หากผลลัพธ์มีมากเกินไป ให้เพิ่มเงื่อนไขการกรองที่ชัดเจนมากขึ้นแล้วค้นหาอีกครั้ง

## 7. การใช้ประวัติการค้นหา

'ประวัติการค้นหา' ใช้เพื่อดู SQL คำสั่งที่ได้ถูกดำเนินการบนหน้าปัจจุบัน ทำให้สะดวกในการนำคำสั่งตรวจสอบปัญหากลับมาใช้ใหม่ ตรวจสอบผลลัพธ์การดำเนินการ และคัดลอก SQL."

> [!NOTE]
>
> ประวัติคำสั่งค้นหาจะถูกบันทึกไว้ในเครื่องท้องถิ่นบนเบราว์เซอร์ปัจจุบันและจะไม่ถูกเก็บอย่างถาวร แต่ละมิติของฐานข้อมูล/ตารางจะเก็บประวัติได้สูงสุด 100 ระเบียนล่าสุด และปัจจุบันยังไม่มีการหมดอายุอัตโนมัติตามเวลา; การล้างข้อมูลไซต์ของเบราว์เซอร์ เปลี่ยนเบราว์เซอร์ เปลี่ยนอุปกรณ์ หรือสลับไปยังฐานข้อมูล/ตารางอื่นจะทำให้เห็นประวัติที่แตกต่างกัน.

1. สลับไปยัง **ประวัติการค้นหา** ในพื้นที่ผลลัพธ์
2. ดูสถานะการดำเนินการ เวลา ฐานข้อมูล ตาราง, SQLจำนวนแถวที่ส่งกลับ และเวลาที่ใช้ไปในบันทึกประวัติ
3. ในการดำเนินการคำสั่งอีกครั้ง ให้คลิก SQL  **แทรกลงในตัวแก้ไขและดำเนินการ** ในคอลัมน์การดำเนินการของระเบียนนั้น
4. ถ้าคุณเพียงแค่ต้องการใช้คำสั่งซ้ำ คลิก **คัดลอก SQL**.

คำอธิบายฟิลด์ประวัติการสอบถาม:

| ช่องข้อมูล | คำอธิบาย |
| --- | --- |
| สถานะ | ไม่ว่า SQL ดำเนินการเสร็จสิ้นเรียบร้อยแล้ว; หากล้มเหลว ให้แก้ไขปัญหาพร้อมกับข้อความแสดงข้อผิดพลาด |
| เวลา | เวลาการประมวลผลของคำสั่งค้นหาปัจจุบัน |
| ฐานข้อมูล | ฐานข้อมูลที่เลือกในระหว่าง SQL การประมวลผล |
| ตาราง | ตารางที่เกี่ยวข้องในระหว่าง SQL การประมวลผล |
| SQL | คำสั่ง query ที่ถูกดำเนินการจริง |
| ส่งคืนจำนวนแถว | จำนวนแถวข้อมูลที่ส่งคืนโดย query นี้ |
| เวลาที่ใช้ | SQL การดำเนินการใช้เวลาและสามารถใช้เพื่อตัดสินว่ามีความเสี่ยงของ query ช้าไหม |
| การดำเนินการ | รองรับการแทรกและดำเนินการใหม่ หรือคัดลอก SQL. |

เมื่อแก้ไขปัญหาเกี่ยวกับประวัติ query แนะนำให้มุ่งเน้นที่: 

| สถานการณ์ | ข้อเสนอแนะการจัดการ |
| --- | --- |
| สถานะล้มเหลว | ก่อนอื่น ตรวจสอบว่ามี SQL ไวยากรณ์ ตารางฐานข้อมูลมีอยู่จริง และว่าฟิลด์ถูกต้องหรือไม่ |
| ใช้เวลานาน | เพิ่มเงื่อนไขตัวกรอง หรือเช็คโครงสร้างตารางและฟิลด์ดัชนีก่อน |
| ส่งคืนแถวมากเกินไป | เพิ่ม 'WHERE' เงื่อนไขและ 'LIMIT'. |
| ผลลัพธ์การค้นหาหลายรายการไม่สอดคล้องกัน | ยืนยันว่าฐานข้อมูล ตาราง หรือสภาพแวดล้อมมีการเปลี่ยนแปลงหรือไม่ |

> ประวัติการค้นหาถูกใช้เพื่อช่วยในการตรวจสอบกระบวนการแก้ไขปัญหาปัจจุบัน ก่อนที่จะรันประวัติย้อนหลัง SQLคุณยังต้องยืนยัน SQL เนื้อหา ฐานข้อมูลเป้าหมาย และสภาพแวดล้อมปัจจุบัน 

## 8. สถานการณ์การแก้ไขปัญหาที่พบบ่อย

| สถานการณ์ | ข้อแนะนำในการปฏิบัติ |
| --- | --- |
| ยืนยันว่ามีบันทึกธุรกิจอยู่หรือไม่ | ใช้ ID ธุรกิจสำหรับการค้นหาแบบแม่นยำ |
| ตรวจสอบสถานะงาน | ค้นหาฟิลด์สถานะและเวลาปรับปรุงตาม ID งาน |
| แก้ไขการตั้งค่าที่ไม่มีผล | ค้นหาค่าปัจจุบันและเวลาปรับปรุงในตารางการตั้งค่า |
| ตรวจสอบการเปลี่ยนแปลงล่าสุด | ค้นหาเรียงลำดับจากมากไปน้อยตามฟิลด์เวลาและจำกัดจำนวนรายการที่ส่งคืน |
| ค้นหาข้อมูลแอปพลิเคชันหรือใบรับรอง | แนะนำให้ใช้การค้นหาใบรับรองหรือ appid ใน “ทั่วไป SQL”. |
| ใช้ประโยคแก้ไขปัญหาเดิมซ้ำ | คัดลอก SQL จาก “ประวัติการสอบถาม”, ตรวจสอบพารามิเตอร์ และดำเนินการอีกครั้ง |

## 9. ข้อควรระวัง

1. การสอบถามโดยไม่กำหนดเงื่อนไขในตารางขนาดใหญ่ถูกห้ามในสภาพแวดล้อมการผลิต
2. หากไม่แน่ใจเกี่ยวกับ SQL ผลกระทบ ให้ตรวจสอบในสภาพแวดล้อมที่มีความเสี่ยงต่ำก่อน
3. อย่าแก้ไขข้อมูลธุรกิจโดยตรงผ่าน RDB เครื่องมือเว้นแต่มีแผนการเปลี่ยนแปลงที่ชัดเจนและได้รับอนุมัติแล้ว
4. พารามิเตอร์ทั่วไป SQL ต้องกรอกด้วยค่าจริงของสภาพแวดล้อมปัจจุบันเพื่อหลีกเลี่ยงการสอบถามผิดสภาพแวดล้อม
5. SQL ในประวัติการสอบถามอาจมี ID ที่ละเอียดอ่อน ยืนยันขอบเขตก่อนคัดลอกหรือส่งต่อ
6. เมื่อผลลัพธ์การสอบถามเกี่ยวข้องกับข้อมูลที่ละเอียดอ่อน อย่านำภาพหน้าจอเต็มหรือข้อมูลข้อความธรรมดาไปแชร์ภายนอก
