# การกำหนดค่า Middleware

[← ShimoDocs Suite เอกสารการติดตั้ง](../../../README.md)

## : 1. ภาพรวม 

การกำหนดค่า Middleware คือหน้าหนึ่งใน MDP แพลตฟอร์มปฏิบัติการที่ทำงานร่วมกับสตอเรจและมิดเดิลแวร์ต่าง ๆ ในสภาพแวดล้อมของลูกค้า โดยจัดการข้อมูลการเชื่อมต่อของส่วนประกอบต่าง ๆ เช่น S3 สตอเรจวัตถุ, Redisคิวข้อความ Kafkaฐานข้อมูลเชิงสัมพันธ์ MySQLฐานข้อมูลเอกสาร MongoDBและการค้นหาข้อความทั้งหมด Elasticsearchการเปลี่ยนแปลงการกำหนดค่าจะถูกส่งไปยังสภาพแวดล้อมของลูกค้าผ่านงานแบบอะซิงโครนัส โดยมีการแสดงผลแบบเรียลไทม์ของการทดสอบและความคืบหน้าของการปล่อยในระหว่างกระบวนการเปลี่ยนแปลง 

ความสามารถหลัก: 

- กำหนดข้อมูลการเชื่อมต่อสำหรับแต่ละมิดเดิลแวร์ (Endpoint, Access Key, USERNAMEPASSWORDเป็นต้น) 
- สลับไปมาระหว่างผู้ขายต่างๆ (S3 และ OSS, AWS / MinIO / เทนเซนต์ คลาวด์ COS / Huawei Cloud OBS, MySQL และ DM Dameng) 
- ติดตามค่าที่เปื้อนในแบบฟอร์ม; เฉพาะฟิลด์ที่มีการแก้ไขเท่านั้นที่จะถูกส่ง 
- แต่ละส่วนของการกำหนดค่าสามารถทดสอบได้อย่างอิสระ; การเผยแพร่จะอนุญาตก็ต่อเมื่อการตรวจสอบผ่าน 
- เผยแพร่ด้วยคลิกเดียว: ส่งการกำหนดค่าฟิลด์ที่มีการเปลี่ยนแปลงทั้งหมดเป็นชุดและดำเนินการแบบอะซิงโครนัส 

### 1.1 ผู้ใช้ที่เกี่ยวข้อง 

| บทบาท           | การปฏิบัติการทั่วไป                                     | 
| -------------- | ---------------------------------------------------- | 
| วิศวกรการใช้งาน | กรอกข้อมูลการเชื่อมต่อมิดเดิลแวร์ในระหว่างการปรับใช้งานครั้งแรก | 
| การดำเนินงานระหว่างเวร | การเปลี่ยนข้อมูลรับรอง, การเปลี่ยน Endpoint, การทดสอบการเชื่อมต่อ | 
| การตอบสนองฉุกเฉิน | สลับมิดเดิลแวร์สำรองและแก้ไขการตั้งค่า timeout |

### 1.2 การดำเนินงานที่ไม่แนะนำในโมดูลนี้ 

การเปลี่ยนผู้ขาย (เช่น S3 → OSS) เป็นการเปลี่ยนแปลงที่เกี่ยวข้องกับการย้ายข้อมูลลงสู่ระบบลูกค้าขนาดใหญ่และควรดำเนินการตามกระบวนการเปลี่ยนแปลง การปรับข้อมูลเชื่อมต่อแบบเป็นชุดในหลายสภาพแวดล้อมไม่ได้ครอบคลุมในโมดูลนี้; คุณต้องเข้าแต่ละสภาพแวดล้อมทีละรายการเพื่อกำหนดค่าเพจ การวางแผนความจุมิดเดิลแวร์และการแจ้งเตือนการตรวจสอบไม่ได้อยู่ในหน้านี้; กรุณาใช้โมดูลการจัดการคลัสเตอร์และการกำหนดค่าแจ้งเตือน

## 2. คำอธิบายรายละเอียดของการตั้งค่ามิดเดิลแวร์แต่ละอย่าง 

### 2.1 S3 Object Storage 

**ขั้นตอนการดำเนินงาน**: เข้า 'การตั้งค่ามิดเดิลแวร์' จากเมนูด้านซ้าย ซึ่งโดยค่าเริ่มต้นอยู่ในส่วนนี้ → เลื่อนลงเพื่อดูสามส่วนการตั้งค่าเรียงตามลำดับ: Public S3 การตั้งค่า instance, Collaborative Editing S3 การตั้งค่า instance, และการตั้งค่า Bucket 

#### 2.1.1 สาธารณะ S3 และการแก้ไขร่วมกัน S3

**ขั้นตอนการดำเนินงาน**: เริ่มต้นด้วยการกรอกข้อมูลสาธารณะ S3 การตั้งค่าตัวอย่าง จากนั้นกรอกข้อมูลการแก้ไขร่วมกัน S3 การตั้งค่าอินสแตนซ์ และท้ายที่สุดกรอกการตั้งค่า Bucket หลังจากแก้ไขช่องใด ๆ ให้คลิก "ทดสอบการเชื่อมต่อ" ที่ด้านล่าง
ช่องฟอร์มในทั้งสองส่วนมีความสอดคล้องกัน:
| ช่อง               | คำอธิบาย                                                              | จำเป็น |
| ----------------- | ---------------------------------------------------------------------- | ---- |
| ประเภทการจัดเก็บข้อมูล           | เลือกจากเมนูดรอปดาวน์ 'S3 (Object Storage)' หรือ 'OSS (Alibaba Cloud)'                             | ใช่   |
| ประเภทย่อย               | โหลดแบบไดนามิกตามประเภทการจัดเก็บ: สำหรับ S3, ตัวเลือกมี AWS / เทนเซนต์ คลาวด์ COS / Huawei Cloud OBS / MinIO / อื่น ๆ; สำหรับ OSS, ใช้ได้เฉพาะ Alibaba Cloud OSS สามารถใช้งานได้ | ใช่    |
| รหัส Access Key     | ตัวระบุข้อมูลประจำตัว                                                        | ใช่   |
| รหัสลับ Access Key | คีย์ข้อมูลประจำตัว, กล่องใส่ข้อมูล PASSWORD ซ่อนข้อมูล | ใช่ |
| ภูมิภาค | ตัวอย่างเช่น `cn-north-1` | ใช่ |
| ForcePathStyle | ช่องทำเครื่องหมาย, เปิดใช้งานการเข้าถึงแบบ path style หรือไม่ | ไม่ใช่ |
| SSL | ช่องทำเครื่องหมาย, เปิดใช้งานหรือไม่ HTTPS | ไม่ใช่ |
| ปลายทาง | ที่อยู่สำหรับเข้าถึงบริการภายใน | ใช่ |
| ที่อยู่สำหรับเข้าถึงสาธารณะ | ที่อยู่สำหรับผู้ใช้งานเข้าถึง | ใช่ |
| กฎแทนที่ที่อยู่ | Regex หรือสตริงที่ใช้แมปที่อยู่ภายในไปยังที่อยู่สาธารณะ | ใช่ |

#### 2.1.2 การตั้งค่อถัง 

**ขั้นตอนการดำเนินงาน**: ถังทั้งหมดที่ส่งกลับโดยเซิร์ฟเวอร์จะแสดงผลทีละอัน และคุณสามารถเติมชื่อโดเมน CDN ตามที่ต้องการได้ 

| ฟิลด์       | คำอธิบาย                  |
| --------- | ------------------------- |
| ชื่อบัคเก็ต | ชื่อของถัง         |
| คำนำหน้า      | คำนำหน้าของเส้นทางจัดเก็บวัตถุ  |
| CDN โดเมน  | CDN โดเมนเร่งความเร็ว     |
| เปิดใช้งาน CDN การตรวจสอบสิทธิ์ | ช่องทำเครื่องหมาย เมื่่อเปิดใช้งาน จะมีการเพิ่ม 2 รายการ คือ "ประเภทการตรวจสอบสิทธิ์" และ "คีย์การตรวจสอบสิทธิ์" |

> หลังจากเปิดใช้งาน CDN การตรวจสอบสิทธิ์ จำเป็นต้องใช้ประเภทการตรวจสอบสิทธิ์และคีย์การตรวจสอบสิทธิ์ที่เกี่ยวข้อง 

### 2.2 Redis
**ขั้นตอน**: ใช้การนำทางด่วนทางด้านขวาเพื่อคลิกที่ไอคอน Redis เพื่อเลื่อนไปยังส่วนนี้ → เลือกโหมด → กรอกที่อยู่และ PASSWORD → คลิก "ทดสอบการเชื่อมต่อ" 

คำอธิบายฟิลด์:

| ฟิลด์     | คำอธิบาย                        |
| -----     | -----------------------------    |
| โหมด      | แบบสแตนด์อโลน หรือ เซนทิเนล          |
| ที่อยู่   | ที่อยู่การเชื่อมต่อในโหมดสแตนด์อโลน เช่น `redis-sentinel-master-ss:6379` |
| ชื่อมาสเตอร์ | จำเป็นในโหมดเซนทิเนล เช่น `mymaster` |
| รายการที่อยู่ | หลายที่อยู่ในโหมดเซนทิเนล สามารถเพิ่ม/ลบอย่างไดนามิก |
| PASSWORD  | จำเป็น                          |

การสลับโหมดจะทำการรีเซ็ตช่อง Address, Master Name และ Address List โดยอัตโนมัติ

### 2.3 Kafka
**ขั้นตอนการใช้งาน**: คลิกที่ Kafka ไอคอนในเมนูนำทางด่วนทางด้านขวาเพื่อเลื่อนมาที่ส่วนนี้ → กรอกที่อยู่ของ Broker → ถ้า SASL เปิดใช้งานแล้ว ขยาย SASL ช่องย่อย → คลิก "ทดสอบการเชื่อมต่อ"

คำอธิบายฟิลด์:

| ช่อง         | คำอธิบาย                                         |
| ---------- | ------------------------------------------------ |
| ที่อยู่ของ Broker | เป็นอาร์เรย์ สามารถเพิ่ม / ลบได้แบบไดนามิก        |
| คำนำหน้าหัวข้อ (Topic Prefix)    | คำนำหน้าที่ถูกเพิ่มโดยอัตโนมัติไปยังหัวข้อทั้งหมด         |
| เปิดใช้งาน SASL การตรวจสอบสิทธิ์ | สวิตช์ หากเปิดใช้งาน จะเพิ่มการกำหนดค่าทั้งสาม SASL การกำหนดค่า |
| กลไกการตรวจสอบสิทธิ์ | PLAIN / SCRAM-SHA-256 / SCRAM-SHA-512 (หลังจากเปิดใช้งาน SASL) |
| USERNAME / PASSWORD   | SASL ข้อมูลรับรอง (หลังจากเปิดใช้งาน SASL)           |

### 2.4 MySQL (ฐานข้อมูลเชิงสัมพันธ์)
**ขั้นตอนการดำเนินงาน**: ในเมนูนำทางด่วนทางด้านขวา คลิกที่ RDB ไอคอนและเลื่อนมาที่ส่วนนี้ → เลือก MySQL หรือ DM Dameng → กรอก host, port, USERNAMEPASSWORD → คลิก "ทดสอบการเชื่อมต่อ"

คำอธิบายฟิลด์:

| ช่อง      | คำอธิบาย        |
| -------- | ---------------- |
| ประเภทฐานข้อมูล | MySQL หรือ DM (Dameng) |
| ที่อยู่โฮสต์  | ตัวอย่างเช่น `mysql-master` |
| พอร์ต          | 3306           |
| USERNAME / PASSWORD | ข้อมูลรับรอง      |

> “RDB ฐานข้อมูลเชิงสัมพันธ์” ในเมนูด้านขวาและชื่อหน้าตรงกับ MySQL 

### 2.5 MongoDB
**ขั้นตอนการดำเนินงาน**: คลิกที่ MongoDB ไอคอนในเมนูทางลัดด้านขวาเพื่อเลื่อนไปยังส่วนนี้ → กรอกสายการเชื่อมต่อ → แสดงข้อมูลประจำตัวฐานข้อมูลแต่ละรายการทีละรายการตามการตั้งค่าเซิร์ฟเวอร์ → คลิก "ทดสอบการเชื่อมต่อ"

คำอธิบายฟิลด์: 

| ฟิลด์           | คำอธิบาย                       |
| ------------- | -------------------------------- |
| สตริงการเชื่อมต่อ | ตัวอย่างเช่น `mongo-master:27017` |
| แต่ละฐานข้อมูล USERNAME / PASSWORD | แสดงผลทีละรายการสำหรับฐานข้อมูลที่ตั้งค่าในเซิร์ฟเวอร์ |

### 2.6 Elasticsearch
**ขั้นตอน:** ใช้การนำทางด่วนด้านขวาเพื่อคลิกที่ Elasticsearch ไอคอนและเลื่อนไปยังส่วนนี้ → กรอกที่อยู่โฮสต์และพอร์ต → หากเปิดใช้งานการตรวจสอบสิทธิ์ ให้กรอก USERNAME และ PASSWORD → คลิก 'ทดสอบการเชื่อมต่อ'

คำอธิบายฟิลด์: 

| ฟิลด์     | คำอธิบาย       | จำเป็น |
| ----      | --------------  | ----    |
| ที่อยู่โฮสต์ | เช่น, `elasticsearch` | ใช่      |
| พอร์ต        | 9200             | ใช่      |
| USERNAME    | ข้อมูลรับรอง ES   | ไม่       |
| PASSWORD    | ข้อมูลรับรอง ES   | ไม่       |

## 3. การดำเนินการทั่วไป 

### 3.1 การอัปเดตข้อมูลรับรอง (เช่น การหมุนรอบรหัสผ่านเข้าถึง) 

1. ไปที่การกำหนดค่า middleware 
2. แทนที่ Access Key ID และ Access Key Secret ใน S3 บัตรสาธารณะ 
3. คลิก "ทดสอบการเชื่อมต่อ" และรอข้อความสีเขียว "การทดสอบการเชื่อมต่อสำเร็จ" 
4. ทำการทดสอบการเชื่อมต่อซ้ำสำหรับส่วนอื่นที่มีการแก้ไข 
5. คลิก "เผยแพร่การกำหนดค่า" ที่ด้านล่าง 
6. ระบบจะแจ้งว่ามีการสร้างงานแบบอะซิงโครนัสและเปลี่ยนเส้นทางไปยังแท็บบันทึกงาน 

### 3.2 การสลับผู้ให้บริการมิดเดิลแวร์ 

1. ไปที่การกำหนดค่า middleware 
2. ในการ์ดที่เกี่ยวข้อง แก้ไข "ประเภท/ประเภทย่อยของที่เก็บ" รวมถึง Endpoint ของผู้จำหน่ายใหม่, Access Key, กฎการแทนที่ที่อยู่ เป็นต้น 
3. หลังการแก้ไข คลิก "ทดสอบการเชื่อมต่อ" เพื่อตรวจสอบ 
4. คลิก "เผยแพร่การกำหนดค่า" 

> การสลับผู้จำหน่ายเกี่ยวข้องกับการโหลดพูลการเชื่อมต่อใหม่สำหรับบริการที่อยู่ด้านล่าง ดังนั้นโปรดหลีกเลี่ยงช่วงเวลาที่มีธุรกิจสูงสุด; หลังการสลับ แนะนำให้ตรวจสอบบันทึกแอปพลิเคชันเป็นเวลา 5 ถึง 10 นาที 

### 3.3 เปิดใช้งาน Kafka SASL 

1. ไปที่การกำหนดค่ามิดเดิลแวร์และค้นหา Kafka ส่วน 
2. เปิดใช้งาน "เปิดใช้งาน" SASL สวิตช์ 'การตรวจสอบสิทธิ์' และ SASL ฟิลด์จะขยาย 
3. กรอกกลไกการตรวจสอบสิทธิ์, USERNAME, และ PASSWORD 
4. คลิก "ทดสอบการเชื่อมต่อ" 
5. หลังจากผ่าน คลิก "เผยแพร่การตั้งค่า" 

### 3.4 กู้คืนจากการดำเนินการผิดพลาด 

ก่อนคลิก "เผยแพร่การตั้งค่า" สถานะฟอร์มจะถูกบันทึกใน localStorage ของเบราว์เซอร์ สามารถกู้คืนได้ดังนี้: 

- คลิกปุ่ม "รีเซ็ตทั้งหมด" ที่ด้านล่าง และทุกช่องจะถูกคืนค่าเป็นค่าตั้งต้นของเซิร์ฟเวอร์ 

### 3.5 การติดตามงานแบบอะซิงโครนัส 

หลังจากเผยแพร่การตั้งค่าเรียบร้อยแล้ว ระบบจะไปยังแท็บบันทึกงานเพื่อแสดงความคืบหน้าของงาน งานสามารถใช้เวลานานหรือสั้น ขึ้นอยู่กับจำนวนอินสแตนซ์ของมิดเดิลแวร์และจำนวนช่องที่มีการเปลี่ยนแปลง

## 4. ปัญหาที่พบบ่อย 

**คำถาม 1: การคลิก Redis ในเมนูนำทางด่วนมุมบนขวาไม่มีการตอบสนอง**

เมนูนำทางด่วนด้านขวาจะเลื่อนไปยังส่วนที่สอดคล้องกันเท่านั้น หากส่วนดังกล่าวไม่อยู่ในหน้าปัจจุบัน (เช่น ถูกป๊อปอัพบัง) คุณสามารถเลื่อนหน้าหรือคลิกไอคอน Redis ในเมนูนำทางด้านขวาอีกครั้งเพื่อปรับตำแหน่ง

**คำถาม 2: หลังจากเผยแพร่การตั้งค่า สถานะดูเหมือนไม่มีการอัปเดต**

หน้าเว็บจะรีเฟรชโดยอัตโนมัติหลังจากเผยแพร่ หากเบราว์เซอร์ไม่รีเฟรชอัตโนมัติ คุณสามารถกด F5 ด้วยตนเองเพื่อดึงการตั้งค่าล่าสุดได้

**คำถาม 3: จำนวนใน 'N การตั้งค่าได้รับการแก้ไข' ไม่ตรงกับจำนวนจริง**

การนับหน้าจะขึ้นอยู่กับฟิลด์ค่าที่สกปรกของแบบฟอร์ม ในบางสถานการณ์ เช่น หลังจากรีเซ็ตแล้วมีการแก้ไข หรือการเพิ่ม/ลบรายการอาร์เรย์แบบไดนามิก ซึ่งอาจทำให้การนับมีความคลาดเคลื่อนได้ คุณสามารถคลิก 'รีเซ็ตทั้งหมด' และกรอกข้อมูลใหม่ได้

**คำถามที่ 4: การ์ดการตั้งค่า Bucket ไม่สามารถหาค่า Bucket ที่ฉันต้องการเพิ่มได้**

หน้าจะเรนเดอร์ Buckets ที่มีอยู่ตามการกำหนดค่าฝั่งเซิร์ฟเวอร์ การเพิ่ม Bucket ใหม่จำเป็นต้องแก้ไขไฟล์การกำหนดค่าฝั่งเซิร์ฟเวอร์ ไม่ใช่หน้านี้ หากมีความจำเป็น กรุณาติดต่อวิศวกรที่ดำเนินการ

## ภาคผนวก A: การอ้างอิงคำศัพท์

| คำศัพท์       | คำอธิบาย                                                                |
| -------- | ----------------------------------------------------------------- |
| ไฟล์การกำหนดค่าของเซิร์ฟเวอร์ | แหล่งกำหนดค่าขั้นสุดท้ายสำหรับการบำรุงรักษาแพลตฟอร์ม ซึ่งเกิดจากการรวมค่าตั้งต้นของแพลตฟอร์มกับค่าที่ออกในหน้านี้ |
| Bucket   | ถังเก็บข้อมูลใน S3 / OSS |
| ปลายทาง | ที่อยู่บริการ Middleware ใช้สำหรับการเข้าถึงคลัสเตอร์ภายใน |
| ที่อยู่สำหรับเข้าถึงสาธารณะ | ที่อยู่ middleware ที่ผู้ใช้สามารถเห็นได้ |
| กฎการแทนที่ที่อยู่ | แมปที่อยู่ภายในไปยัง regex หรือสตริงของที่อยู่สาธารณะ |
| SASL     | ชั้นการยืนยันตัวตนและความปลอดภัยที่เรียบง่าย, กลไกการยืนยันตัวตนสำหรับส่วนประกอบเช่น Kafka |
| Sentinel | หนึ่งใน Redisแผนความพร้อมใช้งานสูงของ |
| DM       | Dameng ฐานข้อมูล (ฐานข้อมูลเชิงสัมพันธ์ภายในประเทศ)                                             |
| ฟิลด์ที่สกปรก       | ฟิลด์ในแบบฟอร์มที่ถูกแก้ไขและแตกต่างจากค่าจุดเริ่มต้น          |
