# ช่องทางการแจ้งเตือน

[← ShimoDocs Suite เอกสารการติดตั้ง](../../../README.md)

## ภาพรวมฟังก์ชัน

ช่องทางการแจ้งเตือนใช้เพื่อจัดการศูนย์กลางวิธีการรับข้อความแจ้งเตือนของระบบ ทำให้สามารถตรวจสอบโดยมิดเดิลแวร์และฟังก์ชันอื่น ๆ ในการส่งการแจ้งเตือนข้อผิดพลาดและการกู้คืนได้

ช่องทางที่รองรับในปัจจุบันได้แก่ WeCom, DingTalk, Feishu และ Webhooks ที่กำหนดเอง

## การเข้าถึงหน้า

หลังจากเข้าสู่ระบบคอนโซลผู้ดูแลระบบ ให้เลือก **ช่องทางการแจ้งเตือน** ในเมนูนำทางด้านซ้ายเพื่อเข้าถึงหน้า

ช่องทางการแจ้งเตือนสามารถใช้งานได้เฉพาะผู้ดูแลระบบ หากคุณไม่เห็นเมนูนี้ โปรดติดต่อผู้ดูแลระบบเพื่อยืนยันสิทธิ์บัญชีของคุณ

## การสร้างช่องทางการแจ้งเตือนใหม่

คลิก **สร้างช่องทาง**, ใส่ชื่้อช่องทาง และเลือกประเภทของช่องทาง:

- **WeCom**: ใส่คีย์ Webhook ของหุ่นยนต์
- **DingTalk**: ใส่ Webhook ฉบับเต็ม URL, และสามารถใส่ Signature Secret ตามการตั้งค่าของหุ่นยนต์ได้
- **Feishu**: ใส่ Webhook ฉบับเต็ม URL, และสามารถใส่ Signature Secret ตามการตั้งค่าของหุ่นยนต์ได้
- **Custom Webhook**: ใส่วิธีการร้องขอ URL, HTTP และเทมเพลตเนื้อหา

ยืนยันว่าต้องการเปิดใช้งานช่องทางหรือไม่ จากนั้นคลิก **บันทึก**.

## Custom Webhook

เทมเพลตของ Body ของ Webhook แบบกำหนดเองรองรับตัวแปรดังต่อไปนี้: 

```text
{{title}}
{{body}}
{{level}}
```

ตัวอย่างเทมเพลตเริ่มต้น: 

```json
{"title":"{{title}}","body":"{{body}}","level":"{{level}}"}
```

เมื่อระบบส่งการแจ้งเตือน ระบบจะทำการแทนที่ตัวแปรด้วยชื่อเรื่อง เนื้อหา และระดับการเตือนจริง 

## ช่องทดสอบ 

หลังจากบันทึกแล้ว คลิก **ทดสอบ** ทางด้านขวาของช่อง ระบบจะส่งข้อความทดสอบเพื่อตรวจสอบว่าที่อยู่ Webhook ลายเซ็น และการเชื่อมต่อเครือข่ายถูกต้องหรือไม่ 

แนะนำให้ทดสอบทันทีหลังจากสร้างหรือแก้ไขช่อง ก่อนผูกเข้ากับการตรวจสอบของ middleware หรือฟังก์ชันธุรกิจอื่น ๆ 

## เปิดใช้งาน แก้ไข และลบ 

- **เปิดใช้งาน/ปิดใช้งาน**: ปรับสถานะการเปิดใช้งานเมื่อแก้ไขช่อง เมื่อปิดใช้งาน ช่องจะไม่ได้รับการแจ้งเตือนทางธุรกิจ 
- **แก้ไข**: คุณสามารถแก้ไขชื่อช่อง ประเภท และการกำหนดค่า Webhook 
- **ลบ**: ลบช่องที่ไม่ได้ใช้อีกต่อไป ช่องที่ถูกอ้างอิงโดยการตรวจสอบ middleware ต้องถูกยกเลิกการผูกก่อนจึงจะสามารถลบได้ 

## สถานการณ์ทั่วไป

- **การทดสอบการส่งล้มเหลว**: กรุณาตรวจสอบที่อยู่ Webhook, Key, Secret HTTP วิธีการ และสิทธิ์การเข้าถึงเครือข่าย
- **บันทึกล้มเหลว**: โปรดตรวจสอบให้แน่ใจว่าฟิลด์ที่จำเป็นทั้งหมดถูกกรอกครบถ้วนและรูปแบบ Webhook URL ถูกต้อง
- **ไม่ได้รับการแจ้งเตือนธุรกิจ**: โปรดยืนยันว่าช่องทางถูกเปิดใช้งานและได้ถูกเลือกบนหน้าธุรกิจที่เกี่ยวข้องแล้ว
- **ไม่สามารถลบช่องทางได้**: ช่องทางนี้อาจยังถูกใช้โดยการตรวจสอบของตัวกลาง กรุณาลบการเชื่อมโยงและบันทึกการตั้งค่าการตรวจสอบก่อน
- **รูปแบบเนื้อหาที่ได้รับจาก Custom Webhook ไม่ถูกต้อง**: กรุณาตรวจสอบว่าเทมเพลต Body ตรงตามข้อกำหนดของระบบเป้าหมายหรือไม่

> ที่อยู่ Webhook และ Secret สำหรับลายเซ็นเป็นข้อมูลที่ละเอียดอ่อน โปรดจำกัดการเข้าถึงและหลีกเลี่ยงการแชร์สาธารณะผ่านสกรีนช็อต, บันทึก หรือเครื่องมือแชท

## ตัวอย่างอินเทอร์เฟซการทำงาน

ภาพด้านล่างแสดงประเภทช่องทางและแบบฟอร์มการตั้งค่าเมื่อสร้างช่องการแจ้งเตือนใหม่
