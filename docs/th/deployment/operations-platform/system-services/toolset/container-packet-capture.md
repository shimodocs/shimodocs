# การจับแพ็กเก็ตคอนเทนเนอร์

[← ShimoDocs Suite เอกสารการติดตั้ง](../../../README.md)

## ภาพรวมคุณสมบัติ 

การดักจับแพ็กเก็ตของคอนเทนเนอร์ถูกใช้เพื่อเก็บข้อมูลเครือข่ายจาก Pods ที่กำลังทำงานใน Kubernetes สภาพแวดล้อม ช่วยให้คุณวิเคราะห์ปัญหา เช่น การเชื่อมต่อล้มเหลว การหมดเวลาของคำขอ TCP การส่งซ้ำ และความหนาแน่นของเครือข่าย 

หลังจากการบันทึกเสร็จสิ้น คุณสามารถดาวน์โหลด PCAP ไฟล์และตรวจสอบเพิ่มเติมโดยใช้เครื่องมือวิเคราะห์เครือข่ายเช่น Wireshark 

## การเข้าถึงหน้าเว็บ 

หลังจากเข้าสู่คอนโซลการจัดการ เลือก **การจับแพ็กเก็ตคอนเทนเนอร์** ในแถบนำทางด้านซ้ายเพื่อเข้าสู่หน้า 

การจับแพ็กเก็ตคอนเทนเนอร์ใช้ได้เฉพาะใน Kubernetes สภาพแวดล้อมการปรับใช้และสามารถใช้ได้เฉพาะผู้ดูแลระบบ 

## เริ่มการจับแพ็กเก็ต 

แนะนำให้ปฏิบัติตามขั้นตอนเหล่านี้: 

1. ค้นหาและระบุตำแหน่ง Pod เป้าหมายใน **รายการ Pods**. 
2. ตรวจสอบให้แน่ใจว่าสถานะของ Pod เป็นกำลังทำงาน จากนั้นคลิก **เริ่มการบันทึก**. 
3. เลือกระยะเวลาการจับภาพ: 1 นาที, 5 นาที, หรือ 30 นาที 
4. เลือกขนาดไฟล์ที่จับภาพ: 100 MB, 500 MB, หรือ 1 GB 
5. เลือกเงื่อนไขตัวกรองตามต้องการ หรือป้อนนิพจน์ตัวกรอง tcpdump ด้วยตัวเอง 
6. ตรวจสอบคำสั่งการจับภาพทั้งหมดที่แสดงบนหน้า 
7. คลิก **เริ่มการบันทึก** เพื่อสร้างงาน 

สามารถรันงานจับแพ็กเก็ตได้เพียงงานเดียวบน Pod เดียวในเวลาเดียวกัน งานจะสิ้นสุดโดยอัตโนมัติเมื่อถึงระยะเวลาที่กำหนด หรือสามารถหยุดได้ด้วยตัวเอง 

## เงื่อนไขตัวกรอง 

การตั้งค่าเงื่อนไขตัวกรองสามารถลดทราฟิกที่ไม่เกี่ยวข้องและขนาดไฟล์ หน้าจอนี้มีการตั้งค่าล่วงหน้าที่ใช้บ่อย เช่น: 

- ทราฟิกบนพอร์ตที่ระบุ 
- gRPC ทราฟิก 
- โฮสต์และพอร์ตที่ระบุ 
- HTTP POST คำขอ 
- TCP การสร้างการเชื่อมต่อ การส่งซ้ำ หรือแพ็กเก็ตหน้าต่างขนาดเล็ก 

คุณสามารถป้อนด้วยตนเองโดยใช้ไวยากรณ์ tcpdump ตัวอย่างเช่น: 

```text
host 10.0.0.1 and port 80
```

หากไม่ระบุเงื่อนไขตัวกรอง งานอาจเก็บทราฟิกเครือข่ายจำนวนมากจาก Pod

## จัดการงานจับแพ็กเก็ต

บนหน้า **งานจับแพ็กเก็ต** หน้าจอนี้ คุณสามารถดู ID งาน Pod สถานะ เวลาในการสร้าง และเวลารัน

- **กำลังรัน**: งานสามารถหยุดด้วยตนเองได้
- **เสร็จสิ้น**: การ PCAP สามารถดาวน์โหลดไฟล์ได้
- **ล้มเหลว**: คุณสามารถดูบันทึกของงานเพื่อเข้าใจสาเหตุของความล้มเหลว

รายการงานจะรีเฟรชโดยอัตโนมัติ หรือคุณสามารถคลิก **รีเฟรช** เพื่อดึงสถานะล่าสุดด้วยตนเอง

## ดาวน์โหลดและวิเคราะห์

หลังจากงานเสร็จสิ้น ให้คลิก **ดาวน์โหลด** เพื่อรับ PCAP ไฟล์ ฟังก์ชันการดาวน์โหลดขึ้นอยู่กับการกำหนดค่าระบบให้พร้อมกับการจัดเก็บวัตถุ

PCAP ไฟล์อาจมีที่อยู่คำขอ ข้อมูลโปรโตคอล หรือข้อมูลที่ละเอียดอ่อนอื่น โปรดส่งให้เฉพาะบุคคลที่ได้รับอนุญาต และจัดเก็บหรือลบออกอย่างเหมาะสมหลังการใช้งาน

## สถานการณ์ทั่วไป

- **ไม่พบ Pod**: หน้าเว็บจะแสดงเฉพาะ Pods ที่อยู่ในสถานะ Running ในสภาพแวดล้อมปัจจุบัน โปรดตรวจสอบสถานะ Pod และสภาพแวดล้อมการปรับใช้
- **ไม่สามารถเริ่มจับแพ็กเก็ตได้**: โปรดตรวจสอบให้แน่ใจว่า Pod ไม่มีงานจับแพ็กเก็ตที่กำลังดำเนินอยู่ และตรวจสอบ Kubernetes สิทธิ์และการสนับสนุนสำหรับ container ชั่วคราว
- **การดำเนินงานของงานล้มเหลว**: ตรวจสอบบันทึกของงานเพื่อตรวจสอบนิพจน์กรอง สถานะของ Pod และว่าคอมโพเนนต์การจับแพ็กเก็ตทำงานอย่างถูกต้องหรือไม่
- **ไม่สามารถดาวน์โหลดไฟล์ได้**: โปรดตรวจสอบการกำหนดค่า object storage และการเชื่อมต่อเครือข่าย
- **ไฟล์จับแพ็กเก็ตใหญ่เกินไป**: ลดระยะเวลาการจับและใช้ นิพจน์กรองที่แม่นยำมากขึ้น

> การดักจับแพ็กเก็ตใช้ทรัพยากรเครือข่าย, CPUและการจัดเก็บบางส่วน กรุณาหลีกเลี่ยงการทำการดักจับปริมาณมากเป็นเวลานานโดยไม่มีตัวกรองในช่วงเวลาที่มีการใช้งานสูง
