# การตรวจสอบทรัพยากรสถิต

[← ShimoDocs Suite เอกสารการติดตั้ง](../../../README.md)

การตรวจสอบทรัพยากรคงที่ใช้ตรวจสอบ JS และ CSS ทรัพยากรที่อ้างอิงโดยหน้าเว็บ ช่วยให้คุณเข้าใจสถานะการเข้าถึงของทรัพยากร โปรโตคอลการส่งข้อมูล การตั้งค่าแคช และ CDN การใช้งาน

> ชื่อฟังก์ชันบนหน้าระบบคือ 'ตรวจจับทรัพยากรคงที่'

## 1. วิธีการใช้งาน

เข้าสู่ระบบแพลตฟอร์มการจัดการ เลือก **บริการระบบ** ที่ด้านบน แล้วเลือก **เครื่องมือ > การตรวจจับทรัพยากรคงที่** ในแถบนำทางด้านซ้าย

ฟีเจอร์นี้สามารถใช้ได้เฉพาะผู้ดูแลระบบเท่านั้น หากคุณไม่เห็นรายการ กรุณาตรวจสอบสิทธิ์บัญชีของคุณและเวอร์ชันของผลิตภัณฑ์ปัจจุบัน

1. ป้อนหน้าที่สมบูรณ์ URLตัวอย่างเช่น `https://example.com/recent`.
2. หากหน้าต้องเข้าสู่ระบบ ให้ขยาย 'หัวข้อคำขอที่กำหนดเอง' และกรอกข้อมูลที่จำเป็น เช่น `Cookie` และ `Authorization`.
3. คลิก 'เริ่มการตรวจจับ' และรอผลลัพธ์

> หัวข้อคำขอจะถูกใช้เพื่อเข้าถึงทรัพยากรคงที่ที่ถูกอ้างอิงโดยหน้า กรุณาใช้ข้อมูลประจำตัวชั่วคราวเท่านั้น และตรวจสอบให้แน่ใจว่าชื่อโดเมนของทรัพยากรข้ามแหล่งที่มาน่าเชื่อถือ ที่อยู่หน้า, หัวข้อคำขอ, และผลการตรวจจับล่าสุดจะถูกบันทึกในเบราว์เซอร์ปัจจุบัน

## 2. ขอบเขตของการตรวจจับ

ระบบจะระบุ JS และ CSS ที่ถูกอ้างอิงโดยตรงในหน้า HTMLแต่จะไม่ตรวจจับภาพ, ฟอนต์, โค้ดที่ฝังในหน้า หรือทรัพยากรที่โหลดแบบไดนามิกหลังการทำงานของสคริปต์

- ตรวจจับไฟล์ JS และ CSS จากโดเมนเดียวกันได้สูงสุด 3 ไฟล์ต่อโดเมน;
- ตรวจพบทรัพยากรข้ามโดเมนได้สูงสุด 50 รายการต่อครั้ง;
- URL ซ้ำจะถูกนับเพียงครั้งเดียว

ทรัพยากรในโดเมนเดียวกันที่ไม่ได้ตรวจพบจะถูกระบุว่า “ข้ามการสุ่มตัวอย่างในโดเมนเดียวกัน” และนี่ไม่ได้หมายถึงข้อผิดพลาดของทรัพยากร

## 3. การดูผลลัพธ์

หลังจากการตรวจพบเสร็จสมบูรณ์ หน้าจะมีการแสดง:

- **ข้อมูลสรุป**: จำนวน HTML ทรัพยากร จำนวนที่ตรวจพบ จำนวนปัญหา การใช้แคช CDN, และ HTTP/2;
- **การตอบสนองของหน้า**: รหัสสถานะ โปรโตคอล และข้อมูลแคชของหน้าปลายทาง;
- **รายการทรัพยากร**: URL, รหัสสถานะ โปรโตคอล แคช, CDN, ปัญหา, และส่วนหัวของการตอบสนองของแต่ละทรัพยากร.

รายการทรัพยากรสนับสนุนการกรองตาม 'ตรวจพบ', 'ทั้งหมด', และ 'มีปัญหา'. 

ระบบส่วนใหญ่ระบุปัญหาต่อไปนี้: 

- HTTP 4xx/5xx; 
- ไม่พบแคชที่ถูกต้อง; 
- HTTP/2 ไม่ถูกใช้; 
- ทรัพยากรข้ามต้นทางไม่แสดง CDN ลักษณะ; 
- คำขอล้มเวลาหมดหรือการแก้ไขชื่อโดเมนล้มเหลว. 

## 4. ปัญหาที่พบบ่อย 

### การตรวจจับหน้าล้มเหลว 

โปรดตรวจสอบหน้า URL, การเชื่อมต่อเครือข่าย, HTTPS ใบรับรอง และสถานะการเข้าสู่ระบบ บริการตรวจจับไม่สามารถใช้ข้อมูลการเข้าสู่ระบบจากเบราว์เซอร์โดยอัตโนมัติได้ ดังนั้นหากจำเป็น โปรดระบุหัวข้อคำขอที่กำหนดเอง 

### ไม่รู้จักทรัพยากร 

โปรดตรวจสอบให้แน่ใจว่าหน้าคืนค่าปกติ HTML. ทรัพยากรที่ถูกโหลดแบบไดนามิกโดยสคริปต์จะไม่ถูกตรวจสอบ 

### CDN แสดง 'ไม่ตรวจพบ' 

ผลลัพธ์นี้แสดงเพียงว่าไม่มี CDN ลักษณะใดๆ ถูกตรวจพบในการตอบสนอง และไม่ได้หมายความว่าทรัพยากรนั้นไม่ได้ใช้งาน CDN. โปรดยืนยันกับ CDN คอนโซลและโครงสร้างเครือข่าย 

## 5. หมายเหตุ 

- ผลการตรวจจับสะท้อนสิ่งที่ถูกสังเกตจากเครือข่ายของแพลตฟอร์มการจัดการในระหว่างคำขอนี้ และอาจแตกต่างจากประสบการณ์ของผู้ใช้จริง 
- CDN, แคช, และสถานะปัญหาเป็นผลลัพธ์ที่กำหนดโดยอัตโนมัติ และใช้สำหรับการวินิจฉัยเสริมเท่านั้น 
- 'ไม่พบปัญหา' ไม่ได้หมายความว่าหน้านั้นผ่านการประเมินประสิทธิภาพ ความปลอดภัย หรือการใช้งานทั้งหมดแล้ว 
- หลังจากหน้าถูกเผยแพร่ CDN ถูกรีเฟรช หรือสภาพแวดล้อมเครือข่ายเปลี่ยนแปลง แนะนำให้ทดสอบใหม่
