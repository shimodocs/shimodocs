# การทดสอบความเข้ากันได้

[← ShimoDocs Suite เอกสารการติดตั้ง](../../../README.md)

## 1. ภาพรวมหน้าเพจ

หน้าการทดสอบความเข้ากันได้ใช้เพื่อตรวจสอบการกำหนดค่าโครงสร้างเก็บวัตถุ การเชื่อมต่อ ความเข้ากันได้ในการอัปโหลด และประสิทธิภาพการอัปโหลด หน้าเพจแบ่งออกเป็น:

1. การกำหนดค่า Storage;
2. การทดสอบความเข้ากันได้;
3. การทดสอบประสิทธิภาพ

## 2. การกำหนดค่า Storage 

### 2.1 คำอธิบายรายการการกำหนดค่า 

| รายการการกำหนดค่า | ฟังก์ชัน |
| --- | --- |
| Access Key | ตัวระบุเอกลักษณ์การเข้าถึงที่เก็บวัตถุ หรือที่เรียกว่า AK |
| รหัสลับ | คีย์การเข้าถึงที่มาพร้อมกับ AK คือ SK |
| ปลายทาง | ที่อยู่บริการที่เก็บวัตถุ |
| ชื่อบัคเก็ต | ถังเป้าหมายที่จะตรวจสอบ |
| ภูมิภาค | พื้นที่ที่ตั้งของถังเก็บข้อมูล |
| จุดเชื่อมต่อสาธารณะ | โดเมนสาธารณะที่ใช้โดยเบราว์เซอร์เพื่อเข้าถึงที่เก็บวัตถุ เป็นทางเลือก |
| รูปแบบเส้นทาง | การใช้รูปแบบ 'endpoint/bucket/object' เพื่อเข้าถึงวัตถุ บริการเช่น MinIO มักต้องเปิดใช้งาน |

### 2.2 กรอกการตั้งค่า 
1. คลิก "กรอกถังไฟล์แนบ" หรือ "กรอกถังเนื้อหา" ตามที่ต้องการ 
2. ระบบจะกรอกการตั้งค่าเช่น AK, SK, Endpoint, Bucket, Region เป็นต้น โดยอัตโนมัติตามสภาพแวดล้อมปัจจุบัน 
3. หากไม่ใช้การกรอกอัตโนมัติ คุณสามารถกรอกการตั้งค่าทั้งหมดด้วยตนเองได้เช่นกัน 
4. ตรวจสอบว่าจุดเชื่อมต่อมีโปรโตคอลและพอร์ตที่ถูกต้องหรือไม่ 
5. ตรวจสอบว่าชื่อถังเป็นถังที่ต้องตรวจสอบในครั้งนี้หรือไม่ 
6. ตรวจสอบว่าภูมิภาคตรงกับภูมิภาคที่แท้จริงของที่เก็บวัตถุหรือไม่
7. หากคุณต้องการให้เบราว์เซอร์เข้าถึงที่เก็บวัตถุโดยตรง ให้กรอก Public Endpoint
8. ตัดสินใจว่าจะเปิดใช้งาน Path Style หรือไม่ ขึ้นอยู่กับประเภทของการจัดเก็บวัตถุ

หลังจากระบบกรอกข้อมูลถังแนบให้อัตโนมัติในครั้งนี้:

- ถัง: `shimo-attachments`;
- Endpoint: กรอกโดยอัตโนมัติโดยระบบ;
- Region: `cn-north-1`;
- Public Endpoint: กรอกโดยอัตโนมัติโดยระบบ;
- Path Style: เปิดใช้งานแล้ว

หลังจากคลิก "Fill Contents bucket" ถังสามารถสลับอัตโนมัติไปยัง `file-contents`.

> Secret Key เป็นข้อมูลที่ละเอียดอ่อน; อย่าแสดงในรูปแบบข้อความปกติในภาพหน้าจอ การสนทนา หรือบันทึกตั๋ว

## 3. การทดสอบความเข้ากันได้

การทดสอบความเข้ากันได้จะตรวจสอบการอัปโหลดของแบ็กเอนด์, การอัปโหลดโดยตรงจากเบราว์เซอร์ และการอัปโหลดแบบหลายส่วนตามลำดับ

### 3.1 เริ่มการทดสอบ

1. ทำการกำหนดค่าที่จัดเก็บให้สมบูรณ์
2. คลิกแท็บ "การทดสอบความเข้ากันได้"
3. ยืนยันอีกครั้งว่าการกำหนดค่า Bucket, Endpoint, Region, Public Endpoint และ Path Style ถูกต้อง
4. คลิก "เริ่มการทดสอบความเข้ากันได้"
5. รอให้หน้าระบุว่า "การทดสอบความเข้ากันได้เสร็จสมบูรณ์"
6. ตรวจสอบว่าสถานะสรุปบนหน้าเป็น "ผ่านทั้งหมด" หรือไม่
7. ตรวจสอบสถานะ ระยะเวลา และข้อมูลผลลัพธ์ของการทดสอบทั้งสามอย่างแยกกัน

### 3.2 การทดสอบการอัปโหลด Backend

การทดสอบนี้ใช้เพื่อตรวจสอบการเชื่อมต่อเครือข่ายและสิทธิ์การเขียนจากบริการแบ็กเอนด์ไปยังการเก็บข้อมูลออบเจ็กต์

1. แบ็กเอนด์สร้างไฟล์ข้อความทดสอบ
2. ระบบหลังบ้านบันทึกไฟล์ไปยัง Bucket เป้าหมาย
3. หน้าจอแสดงระยะเวลาในการอัปโหลดและเส้นทางของวัตถุทดสอบ
4. สถานะความสำเร็จสีเขียวแสดงว่าเครือข่ายและสิทธิ์การเขียนของระบบหลังบ้านเป็นปกติ

ผลลัพธ์ปัจจุบัน: อัปโหลดสำเร็จ, ระยะเวลา `157 ms`.

### 3.3 การทดสอบการอัปโหลดโดยตรงผ่านเบราว์เซอร์

การทดสอบนี้ใช้เพื่อตรวจสอบลิงก์สำหรับเบราว์เซอร์ในการอัปโหลดไปยังพื้นที่เก็บวัตถุโดยตรงผ่าน PostPolicy

1. หน้าจะร้องขอ PostPolicy ที่จำเป็นสำหรับการอัปโหลดโดยตรงจากแบ็กเอนด์
2. เบราว์เซอร์ใช้ Public Endpoint เพื่ออัปโหลดไฟล์ไปยังพื้นที่เก็บวัตถุโดยตรง
3. หน้าจะตรวจสอบ HTTP รหัสสถานะที่ส่งกลับโดยพื้นที่เก็บวัตถุ
4. HTTP 204 หมายถึงการอัปโหลดโดยตรงผ่านเบราว์เซอร์สำเร็จ

ผลลัพธ์ครั้งนี้: การอัปโหลดโดยตรงผ่านเบราว์เซอร์สำเร็จ ใช้เวลา `61 ms`, รหัสสถานะ `204`.

### 3.4 การทดสอบการอัปโหลดแบบ Multipart

การทดสอบนี้ใช้เพื่อตรวจสอบกระบวนการทั้งหมดของการอัปโหลดไฟล์ขนาดใหญ่แบบ multipart

1. เริ่มต้นงานอัปโหลดแบบ multipart
2. แยกไฟล์ทดสอบออกเป็นหลายส่วน
3. อัปโหลดแต่ละส่วนตามลำดับ
4. เรียกใช้อินเทอร์เฟซการรวมเพื่อตั้งค่าอ็อบเจ็กต์ให้สมบูรณ์
5. หน้าจอจะแสดง `multipart upload succeeded`, ซึ่งบ่งบอกว่ากระบวนการทั้งหมดสำเร็จ

ผลลัพธ์ครั้งนี้: การอัปโหลดแบบ multipart สำเร็จ ใช้เวลา `1746 ms`.

### 3.5 คำอธิบายของอ็อบเจ็กต์ทดสอบ

การทดสอบความเข้ากันได้จะทำการเขียนจริงไปยัง Bucket เป้าหมาย และเส้นทางของอ็อบเจ็กต์ทดสอบเบื้องหลังมักคล้ายกับ:

```text
compatibility-tests/<RANDOM UUID>.txt
```

1. ยืนยันว่า Bucket เป้าหมายถูกต้องก่อนทำการทดสอบ
2. ไม่ควรทำการทดสอบโดยไม่ระมัดระวังใน Bucket ผลิตจริงที่ผิด
3. หลังจากการทดสอบ คุณสามารถตรวจสอบและลบอ็อบเจ็กต์ทดสอบตามนโยบายการทำความสะอาดของสภาพแวดล้อม

## 4. การทดสอบประสิทธิภาพ

การทดสอบประสิทธิภาพใช้วัดเวลาการอัปโหลดและอัตราการส่งผ่านของไฟล์ขนาดต่าง ๆ

### 4.1 การกำหนดค่าการทดสอบประสิทธิภาพ

1. คลิกที่แท็บ "การทดสอบประสิทธิภาพ"
2. เลือกโหมดทดสอบ; หน้าเพจตั้งค่าเริ่มต้นเป็น "Browser Direct"
3. เลือกประเภทเนื้อหา (Content-Type); คุณสามารถใช้ `application/octet-stream` เป็นค่าตั้งต้น
4. เลือกขนาดไฟล์ที่คุณต้องการทดสอบ
5. หน้าผลลัพธ์รองรับ 1, 5, 8, 10, 12, 15, 20 และ 25 MB
6. ในสภาพแวดล้อมทดสอบ คุณสามารถเลือก 1 MB ก่อนเพื่อการตรวจสอบอย่างรวดเร็ว
7. สำหรับการเปรียบเทียบประสิทธิภาพอย่างเป็นทางการ ให้เลือกหลายขนาดไฟล์เพื่อทดสอบ

### 4.2 เริ่มการทดสอบประสิทธิภาพ

1. ยืนยันว่าการกำหนดค่าที่จัดเก็บถูกต้อง
2. ยืนยันว่ามีการเลือกอย่างน้อยหนึ่งขนาดไฟล์
3. คลิก 'เริ่มการทดสอบประสิทธิภาพ'
4. รอให้การอัปโหลดไฟล์ทั้งหมดเสร็จสิ้น
5. ตรวจสอบอัตราการถ่ายโอนเฉลี่ย เวลาที่สั้นที่สุด และเวลาที่ยาวที่สุด
6. ตรวจสอบสถานะ เวลาในการดำเนินการ อัตราการถ่ายโอน และข้อความข้อผิดพลาดสำหรับแต่ละขนาดไฟล์
7. หากเกิดความล้มเหลว ให้ตรวจสอบเครือข่ายเบราว์เซอร์, Public Endpoint, การกำหนดค่า cross-origin และสถานะการจัดเก็บออบเจ็กต์ก่อน

### 4.3 ผลการทดสอบนี้

การทดสอบนี้ใช้ไฟล์ขนาด 1 MB เท่านั้นเพื่อทำการทดสอบการอัปโหลดโดยตรงแบบ frontend ที่เบา

| ตัวชี้วัด | ผลลัพธ์ |
| --- | ---: |
| ขนาดไฟล์ | 1.0 MB |
| สถานะ | สำเร็จ |
| เวลา | 874 ms |
| อัตราการถ่ายโอน | 1.14 MB/s |
| ข้อความผิดพลาด | ไม่มี |

ผลลัพธ์จริง: การอัปโหลดสำเร็จ และหน้าเว็บสามารถสร้างค่าตัวชี้วัดเวลาที่ใช้และอัตราผลผลิตได้อย่างถูกต้อง

> ผลประสิทธิภาพอาจได้รับผลกระทบจากเครือข่ายของเบราว์เซอร์, โหลดของคลัสเตอร์, ลิงก์พร็อกซี, และโหลดของการจัดเก็บวัตถุ การทดสอบเพียงครั้งเดียวสามารถตรวจสอบความพร้อมใช้งานของฟังก์ชันเท่านั้น การยอมรับประสิทธิภาพอย่างเป็นทางการควรทำการทดสอบซ้ำหลายครั้งในสภาพแวดล้อมเดียวกันและเก็บสถิติ P50, P95และอัตราความล้มเหลวควรถูกบันทึกไว้

## 5. ข้อควรระวัง
1. ยืนยัน Bucket เป้าหมายก่อนทำการทดสอบเพื่อหลีกเลี่ยงการเขียนไฟล์ทดสอบไปยัง bucket ที่ไม่ถูกต้อง
2. อย่าแสดง Secret Key ในข้อความธรรมดาในเอกสารหรือภาพหน้าจอ
3. การอัปโหลดตรงผ่านเบราว์เซอร์ขึ้นอยู่กับ Public Endpoint และการกำหนดค่าข้ามแหล่งกำเนิด
4. S3บริการที่เข้ากันได้กับ - เช่น MinIO มักจะต้องเปิดใช้งาน Path Style
5. การทดสอบประสิทธิภาพสร้างการจราจรเครือข่ายจริงและการเขียนลง storage; ประเมินผลกระทบของสภาพแวดล้อมก่อนทดสอบไฟล์ขนาดใหญ่
6. การยอมรับประสิทธิภาพอย่างเป็นทางการควรทำในหลายรอบ; ผลการทดสอบเบราว์เซอร์เพียงครั้งเดียวไม่เพียงพอ
