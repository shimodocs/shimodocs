# Kafka การกำหนดค่า

[← ShimoDocs Suite เอกสารการติดตั้ง](../../README.md)

เอกสารฉบับนี้มีวัตถุประสงค์เพื่อแนะนำเจ้าหน้าที่ด้านการนำไปใช้งาน การปฏิบัติ หรือการบูรณาการให้สามารถทำ ShimoDocs การบูรณาการกับซอฟต์แวร์ตัวกลางสำหรับข้อความภายนอก Kafka ทีละขั้นตอน สำหรับสภาวะเช่น การประมวลผลงานที่ไม่ซิงโครนัส การแจ้งเตือนข้อความ การซิงโครไนซ์ข้อมูล และการส่งมอบบันทึกการตรวจสอบ 


## 1. การยืนยันก่อนการปฏิบัติการ 

## Kafka ข้อกำหนดของอินสแตนซ์ 


| ซอฟต์แวร์ตัวกลาง | เวอร์ชันที่แนะนำ | สำหรับผู้ใช้น้อยกว่า 3000 คน | สำหรับผู้ใช้งานมากกว่า 3000 คน | 
| --- | --- | --- | --- | 
| Kafka | Kafka 3.5 | 2C 4G 300G SSD | 4C 8G 300G SSD | 


## ความต้องการในการกำหนดค่า 
- Broker >= 3 
- Replication factor: จำนวนสำเนาเริ่มต้นคือ 3 ในสภาพแวดล้อมการผลิต จำเป็นต้องมี ≥ 3 เพื่อความพร้อมใช้งานสูง 
- การเก็บข้อความ: 72 ชั่วโมง (สามารถปรับตามความต้องการทางธุรกิจ) 
- ขนาดข้อความเดี่ยวสูงสุดต่อหัวข้อ: 10 MB 
- การตรวจสอบสิทธิ์: รองรับ SASL การเข้าถึงแบบเข้ารหัส (PLAIN, SCRAM-SHA-256, SCRAM-SHA-512) 





## การเชื่อมต่อเครือข่าย 

พอร์ตสำหรับการเข้าถึง Kafka อินสแตนซ์จาก K8s คลัสเตอร์ธุรกิจต้องเปิดอยู่ 

```js
telnet IP 9092
```



## ความต้องการอื่น ๆ
- อินทราเน็ต RTT แนะนำให้ < 5ms; ข้ามดาต้าเซ็นเตอร์/ข้ามภูมิภาคแนะนำให้ < 20ms
- แบนด์วิดธ์ต้องตอบสนองต่ออัตราการผ่านสูงสุดเพื่อหลีกเลี่ยงข้อความค้างเกิดจากการอิ่มตัวของเครือข่าย
- ตรวจสอบให้แน่ใจว่า Kafka โบรกเกอร์และ ShimoDocs เซิร์ฟเวอร์แอปพลิเคชันถูกซิงโครไนซ์เวลา (NTP) เนื่องจากความเบี่ยงเบนของเวลาสามารถส่งผลต่อการเรียงลำดับข้อความและ TTL การคำนวณ
