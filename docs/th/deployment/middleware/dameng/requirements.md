# Dameng V8 ข้อกำหนด

[← ShimoDocs Suite เอกสารการติดตั้ง](../../README.md)

เอกสารนี้มีวัตถุประสงค์เพื่อเป็นแนวทางสำหรับบุคลากรที่กำลังดำเนินการ ดูแลรักษา หรือบูรณาการ Dameng ฐานข้อมูลเป็นครั้งแรก เพื่อทำให้สมบูรณ์ Dameng DM8 การเริ่มต้นฐานข้อมูล, MySQL การกำหนดค่าโหมดความเข้ากันได้, การเริ่มต้นบริการ, และการตรวจสอบการเชื่อมต่อทีละขั้นตอน.

ตัวอย่างในเอกสารนี้ใช้การวางแผนดังต่อไปนี้:

| รายการ | ค่าตัวอย่าง |
| --- | --- |
| ไดเรกทอรีติดตั้งฐานข้อมูล | `/opt/dmdbms` |
| ไดเรกทอรีจัดเก็บฐานข้อมูล | `/dmdata/data` |
| DATABASE_NAME | `DMTEST` |
| ชื่ออินสแตนซ์ | `DBSERVER` |
| พอร์ตฐานข้อมูล | `5236` |
| บัญชีผู้ดูแลระบบ | `SYSDBA` |
| ผู้ดูแลระบบ PASSWORD | `<SYSDBA_PASSWORD>` |

> หมายเหตุ: `<SYSDBA_PASSWORD>` และ `<SYSAUDITOR_PASSWORD>` ในเอกสารเป็นตัวแทนชั่วคราว ในระหว่างการปฏิบัติการจริง โปรดแทนที่ด้วยรหัสผ่านจริงที่ตรงตาม PASSWORD ข้อกำหนดความซับซ้อน

## 1. การยืนยันก่อนการปฏิบัติการ

### 1. ยืนยันว่า Dameng ได้ถูกติดตั้งแล้ว

ดำเนินการบนเซิร์ฟเวอร์:

```bash
ls /opt/dmdbms/bin
```

หากคุณสามารถเห็นไฟล์เช่น `dminit`, `dmserver`, `disql`ซึ่งบ่งชี้ว่า Dameng ซอฟต์แวร์ได้ถูกติดตั้งเรียบร้อยแล้ว

คุณสามารถตรวจสอบเวอร์ชันได้ด้วย:

```bash
/opt/dmdbms/bin/dmserver
```

เนื้อหาแบบนี้สามารถปรากฏในเอาต์พุตได้:

```text
dmserver V8
version: 03134284194-20240920-243574-20108
```

### 2. ยืนยันผู้ใช้ของระบบ

Dameng โดยปกติจะรันฐานข้อมูลโดยใช้ `dmdba` ผู้ใช้ ตรวจสอบว่าผู้ใช้มีอยู่หรือไม่:

```bash
id dmdba
```

หากไม่มีอยู่ สามารถสร้างได้โดยผู้ใช้ `root` :

```bash
groupadd dinstall
useradd -g dinstall -m -d /home/dmdba -s /bin/bash dmdba
passwd dmdba
```

### 3. เตรียมไดเรกทอรีข้อมูล

ดำเนินการโดยใช้ `root` :

```bash
mkdir -p /dmdata/data
chown -R dmdba:dinstall /dmdata
chmod -R 775 /dmdata
```

วัตถุประสงค์ของขั้นตอนนี้คือเพื่อสร้างไดเรกทอรีสำหรับเก็บไฟล์ฐานข้อมูลและมอบสิทธิ์ให้กับผู้ใช้ `dmdba` .

## 2. เริ่มต้นฐานข้อมูล

สลับไปยัง `dmdba` :

```bash
su - dmdba
```

ดำเนินการคำสั่งเริ่มต้น: 

```bash
/opt/dmdbms/bin/dminit \
  PATH=/dmdata/data \
  PAGE_SIZE=32 \
  EXTENT_SIZE=32 \
  CASE_SENSITIVE=0 \
  UNICODE_FLAG=1 \
  DB_NAME=DMTEST \
  INSTANCE_NAME=DBSERVER \
  PORT_NUM=5236 \
  SYSDBA_PWD=<SYSDBA_PASSWORD> \
  SYSAUDITOR_PWD=<SYSAUDITOR_PASSWORD>
```

หากการเริ่มต้นสำเร็จ คุณจะเห็นเอาต์พุตคล้ายกับ: 

```text
create dm database success
```
หลังจากเริ่มต้นสำเร็จ จะมีการสร้างไดเรกทอรีฐานข้อมูล: 

```text
/dmdata/data/DMTEST
```

ไฟล์การกำหนดค่าที่สำคัญในนั้นคือ:

```text
/dmdata/data/DMTEST/dm.ini
```

## 3. แก้ไข MySQL การกำหนดค่าความเข้ากันได้

แก้ไขไฟล์การกำหนดค่าด้วย `root` หรือ `dmdba` :

```bash
vi /dmdata/data/DMTEST/dm.ini
```

ค้นหาและแก้ไขการกำหนดค่าทั้งสองนี้: 

```ini
COMPATIBLE_MODE = 4
ORDER_BY_NULLS_FLAG = 0
```

หากไฟล์มีการกำหนดค่าทั้งสองนี้แล้ว คุณสามารถแก้ไขบรรทัดที่มีอยู่โดยตรง

อย่าเพิ่มการกำหนดค่าอื่นที่มีชื่อเดียวกันไว้ท้ายไฟล์ มิฉะนั้นอาจเกิดการกำหนดค่าซ้ำ ทำให้ค่าจริงที่มีผลแตกต่างจากค่าที่คาดไว้

หลังจากแก้ไขเสร็จแล้ว คุณสามารถตรวจสอบโดยใช้คำสั่งดังต่อไปนี้:

```bash
grep -Ein 'COMPATIBLE_MODE|ORDER_BY_NULLS_FLAG' /dmdata/data/DMTEST/dm.ini
```

คาดว่าจะเห็น:

```text
COMPATIBLE_MODE = 4
ORDER_BY_NULLS_FLAG = 0
```

## 4. ลงทะเบียนบริการฐานข้อมูล

สลับกลับไปที่ `root` :

```bash
exit
```

ลงทะเบียนบริการฐานข้อมูล: 

```bash
/opt/dmdbms/script/root/dm_service_installer.sh \
  -t dmserver \
  -p DBSERVER \
  -dm_ini /dmdata/data/DMTEST/dm.ini
```

หลังจากการลงทะเบียนสำเร็จ ชื่อบริการปกติจะเป็น:

```text
DmServiceDBSERVER.service
```

ตั้งค่าให้เริ่มต้นเมื่อบูตและเริ่มบริการ: 

```bash
systemctl daemon-reload
systemctl enable DmServiceDBSERVER.service
systemctl start DmServiceDBSERVER.service
```

ตรวจสอบสถานะบริการ: 

```bash
systemctl status DmServiceDBSERVER.service --no-pager
```

หากคุณเห็น: 

```text
Active: active (running)
```

แสดงว่าบริการฐานข้อมูลได้เริ่มทำงานแล้ว 

## 5. ตรวจสอบว่าฐานข้อมูลพร้อมใช้งานหรือไม่ 

### 1. ตรวจสอบพอร์ต 

เรียกใช้: 

```bash
ss -lntp | grep ':5236'
```

หากคุณเห็น `dmserver` กำลังฟังที่ `5236`แสดงว่าพอร์ตฐานข้อมูลปกติ

### 2. ทดสอบการเข้าสู่ระบบภายในเครื่อง

สลับไปยัง `dmdba` :

```bash
su - dmdba
```

เข้าสู่ระบบฐานข้อมูล: 

```bash
/opt/dmdbms/bin/disql SYSDBA/<SYSDBA_PASSWORD>@127.0.0.1:5236
```

เรียกใช้หลังจากเข้าสู่ระบบสำเร็จ:

```sql
select 1 as OK;
```

หากคืนค่า: 

```text
OK
-----------
1
```

แสดงว่าการเชื่อมต่อฐานข้อมูลเป็นปกติ 

### 3. ตรวจสอบว่ามี MySQL โหมดความเข้ากันได้

เรียกใช้ใน `disql`: 

```sql
select para_name, para_value
from v$dm_ini
where para_name in (
  'COMPATIBLE_MODE',
  'ORDER_BY_NULLS_FLAG',
  'INSTANCE_NAME',
  'PORT_NUM'
);
```

ผลลัพธ์ที่คาดหวัง: 

```text
INSTANCE_NAME        DBSERVER
PORT_NUM             5236
COMPATIBLE_MODE      4
ORDER_BY_NULLS_FLAG  0
```

ในนั้น:

```text
COMPATIBLE_MODE = 4
```

แสดงว่าสถานะการทำงานปัจจุบันของฐานข้อมูลได้เปิดใช้งาน MySQL โหมดความเข้ากันได้แล้ว 



## ภาคผนวก 1, คำอธิบายรายละเอียดของรายการการกำหนดค่า 

### 1. `PATH` 

ตัวอย่าง: 

```text
PATH=/dmdata/data
```

ความหมาย: 

`PATH` คือไดเรกทอรีรากของไฟล์ฐานข้อมูล ในระหว่างการเริ่มต้น Dameng จะสร้างไดเรกทอรีฐานข้อมูลภายใต้ไดเรกทอรีนี้

ถ้า `DB_NAME=DMTEST`, ไดเรกทอรีสุดท้ายมักจะเป็น: 

```text
/dmdata/data/DMTEST
```

ไดเรกทอรีนี้จะเก็บไฟล์ข้อมูล ไฟล์ล็อก ไฟล์ควบคุม และไฟล์ `dm.ini` การกำหนดค่า

คำแนะนำ:

- แนะนำให้วางบนดิสก์ข้อมูลที่มีความจุเพียงพอและมีประสิทธิภาพเสถียรในสภาพแวดล้อมการผลิต
- ไม่แนะนำให้วางในไดเรกทอรีชั่วคราว เช่น `/tmp`.
- อย่าย้ายไดเรกทอรีโดยไม่ระมัดระวังหลังจากการเริ่มต้นใช้งาน

### 2. `DB_NAME`

ตัวอย่าง:

```text
DB_NAME=DMTEST
```

ความหมาย: 

`DB_NAME` คือชื่อของ DATABASE_NAME. มันจะมีผลต่อชื่อไดเรกทอรีฐานข้อมูล, ชื่อไฟล์บันทึก, เป็นต้น 

ตัวอย่างเช่น, เมื่อ `DB_NAME=DMTEST`, มันมักจะสร้าง: 

```text
/dmdata/data/DMTEST
/dmdata/data/DMTEST/DMTEST01.log
/dmdata/data/DMTEST/DMTEST02.log
```

คำแนะนำ:

- ใช้รูปแบบเดียวที่ชัดเจน DATABASE_NAME ตลอดทั้งโครงการ.
- ไม่แนะนำให้เปลี่ยนหลังจากการเริ่มต้น.

### 3. `INSTANCE_NAME`

ตัวอย่าง:

```text
INSTANCE_NAME=DBSERVER
```

ความหมาย: 

`INSTANCE_NAME` คือชื่ออินสแตนซ์ของฐานข้อมูล. มันมักจะถูกใช้เพื่อสร้างชื่อเซอร์วิสเมื่อทำการลงทะเบียนเซอร์วิส.

ตัวอย่างเช่น: 

```text
INSTANCE_NAME=DBSERVER
```

ชื่อบริการหลังจากการลงทะเบียนปกติคือ:

```text
DmServiceDBSERVER.service
```

คำแนะนำ: 

- สำหรับเครื่องเดียวที่มีอินสแตนซ์เดียว คุณสามารถใช้ `DBSERVER`.
- เมื่อปรับใช้หลายอินสแตนซ์บนเครื่องเดียว แต่ละชื่ออินสแตนซ์ต้องไม่เหมือนกัน

### 4. `PORT_NUM`

ตัวอย่าง: 

```text
PORT_NUM=5236
```

ความหมาย: 

`PORT_NUM` เป็นพอร์ตที่ฐานข้อมูลใช้ฟัง แอปพลิเคชันต้องเข้าถึงพอร์ตนี้เมื่อเชื่อมต่อกับฐานข้อมูล 

พอร์ตที่ป้อนในหน้าของโปรแกรมต้องสอดคล้องกับพอร์ตนี้: 

```text
HOST:172.17.9.84
PORT:5236
```

คำแนะนำ: 

- พอร์ตเริ่มต้นสำหรับ Dameng ปกติคือ `5236`. 
- หากมีหลาย Dameng อินสแตนซ์บนเครื่องเดียว พอร์ตจะไม่สามารถซ้ำกันได้ 
- หลังจากเปลี่ยนพอร์ต บริการฐานข้อมูลต้องถูกรีสตาร์ท 

### 5. `PAGE_SIZE` 

ตัวอย่าง: 

```text
PAGE_SIZE=32
```

ความหมาย: 

`PAGE_SIZE` เป็นขนาดหน้าของฐานข้อมูล เป็นหน่วย KB เมื่อฐานข้อมูลอ่านและเขียนข้อมูล จะจัดระเบียบข้อมูลตามหน้า 

`PAGE_SIZE=32` หมายความว่าหนึ่งหน้าข้อมูลมีขนาด 32KB 

ผลกระทบ: 

- มันมีผลต่อการจัดเก็บข้อมูล การจัดทำดัชนี และพฤติกรรม IO 
- ไม่แนะนำให้แก้ไขหลังจากการเริ่มต้นใช้งาน 
- หากจำเป็นต้องปรับค่า มักจะต้องทำการเริ่มต้นฐานข้อมูลใหม่และย้ายข้อมูล 

คำแนะนำ: 

- หากมี SOP สำหรับสถานการณ์นั้น ให้กำหนดค่าตาม SOP. 
- เมื่อไม่มีข้อกำหนดพิเศษ ไม่ควรเปลี่ยนแปลงตามอำเภอใจ 

### 6. `EXTENT_SIZE` 

ตัวอย่าง: 

```text
EXTENT_SIZE=32
```

ความหมาย: 

`EXTENT_SIZE` คือขนาดคลัสเตอร์ วัดเป็นจำนวนหน้า สามารถเข้าใจได้ว่าเป็นหน่วยพื้นฐานของการจัดสรรพื้นที่ที่ฐานข้อมูลใช้ในครั้งเดียว

ถ้า: 

```text
PAGE_SIZE=32
EXTENT_SIZE=32
```

ดังนั้นคลัสเตอร์หนึ่งจะประมาณ: 

```text
32KB * 32 = 1024KB
```

ประมาณ 1MB 

ผลกระทบ: 

- จะส่งผลต่อความละเอียดของการจัดสรรพื้นที่ไฟล์ข้อมูล 
- ไม่แนะนำให้แก้ไขหลังจากการเริ่มต้นใช้งาน 

### 7. `CASE_SENSITIVE` 

ตัวอย่าง: 

```text
CASE_SENSITIVE=0
```

ความหมาย: 

`CASE_SENSITIVE` ระบุว่าชื่อวัตถุในฐานข้อมูลมีความไวต่อขนาดตัวอักษรหรือไม่

ค่าที่พบบ่อย: 

```text
0:CASE_INSENSITIVE
1:CASE_SENSITIVE
```

ตัวอย่างเช่น เมื่อไม่ไวต่อขนาดตัวอักษร ชื่อตารางสองชื่อต่อไปนี้สามารถถือว่าเป็นวัตถุเดียวกัน:

```text
user
USER
```

ผลกระทบ: 

- จะส่งผลต่อการจดจำชื่อตาราง ชื่อฟิลด์ และชื่อวัตถุ 
- สำหรับ MySQL การย้ายข้อมูลหรือ MySQL-สถานการณ์ที่เข้ากันได้ มักนิยมตั้งค่าเป็น `0`. 
- ไม่แนะนำให้แก้ไขหลังจากการเริ่มต้นใช้งาน 

### 8. `UNICODE_FLAG` 

ตัวอย่าง: 

```text
UNICODE_FLAG=1
```

ความหมาย: 

`UNICODE_FLAG` คือการตั้งค่าชุดอักขระ

ค่าที่พบบ่อย: 

```text
0:GB18030
1:UTF-8
2:EUC-KR
```

`UNICODE_FLAG=1` ระบุว่าฐานข้อมูลใช้ชุดอักขระ UTF-8

คำแนะนำ:

- แนะนำให้ใช้ UTF-8 สำหรับระบบใหม่
- เข้ากันได้ดีกับตัวอักษรจีน อังกฤษ และหลายภาษา
- ไม่แนะนำให้แก้ไขหลังจากการเริ่มต้น

### 9. `SYSDBA_PWD`

ตัวอย่าง:

```text
SYSDBA_PWD=<SYSDBA_PASSWORD>
```

ความหมาย: 

`SYSDBA_PWD` คือ PASSWORD สำหรับ `SYSDBA` บัญชีผู้ดูแลระบบ

`SYSDBA` คล้ายกับผู้ดูแลระบบสูงสุดของฐานข้อมูลและมีสิทธิพิเศษระดับสูง

คำแนะนำ: 

- ใช้ PASSWORD.
- อย่าใช้รหัสผ่านง่ายๆ เช่น `SYSDBA`, `123456`, `password`.
- PASSWORD แนะนำให้มีความยาวอย่างน้อย 8 ตัวอักษร และรวมตัวอักษรและตัวเลข
- อย่าบันทึก PASSWORD จริงลงในเอกสารภายนอก

### 10. `SYSAUDITOR_PWD`

ตัวอย่าง: 

```text
SYSAUDITOR_PWD=<SYSAUDITOR_PASSWORD>
```

ความหมาย: 

`SYSAUDITOR_PWD` คือ PASSWORD ของ `SYSAUDITOR` บัญชีผู้ดูแลระบบตรวจสอบ

`SYSAUDITOR` ใช้สำหรับความสามารถในการจัดการที่เกี่ยวข้องกับการตรวจสอบเป็นหลัก

คำแนะนำ:

- ใช้ PASSWORD ที่แตกต่างจาก `SYSDBA`.
- ใช้ PASSWORD ที่ตรงตามข้อกำหนดความซับซ้อน

### 11. `COMPATIBLE_MODE`

ตัวอย่าง:

```text
COMPATIBLE_MODE = 4
```

ความหมาย: 

`COMPATIBLE_MODE` คือการกำหนดค่าโหมดความเข้ากันได้ของ Dameng ฐานข้อมูล ใช้เพื่อควบคุมว่าฐานข้อมูลเข้ากันได้กับฐานข้อมูลประเภทใดในแง่ของ SQL ไวยากรณ์ ฟังก์ชัน และพฤติกรรมบางประการ

ความหมายทั่วไปของค่า: 

```text
0:DEFAULT_MODE
1:SQL92
2:Oracle
3:MS SQL Server
4:MySQL
5:DM6
6:Teradata
7:PostgreSQL
8:DB2
```

ข้อความนี้ถูกกำหนดค่าเป็น: 

```text
COMPATIBLE_MODE = 4
```

ระบุว่าการเปิดใช้งาน MySQL โหมดความเข้ากันได้แล้ว 

ฟังก์ชัน: 

- ปรับปรุงความเข้ากันได้ของ MySQL SQL ไวยากรณ์ใน Dameng. 
- ลดค่าใช้จ่ายในการแปลงเมื่อย้ายจาก MySQL หรือปรับตัวให้เข้ากับ Dameng. 

หมายเหตุ: 

- การกำหนดค่านี้ไม่ได้หมายความว่า Dameng รองรับ MySQL โปรโตคอล 
- โปรแกรมยังคงต้องใช้ Dameng ไดรเวอร์ภายใน; หากไม่มีตัวเลือกการกำหนดค่าไดรเวอร์บนหน้า ผู้ใช้ไม่จำเป็นต้องกรอกแยกต่างหาก 
- จำเป็นต้องรีสตาร์ทบริการฐานข้อมูลหลังจากการแก้ไข 
- ว่าจะมีผลในที่สุดหรือไม่นั้นควรขึ้นอยู่กับ `v$dm_ini` ผลลัพธ์การค้นหา 

### 12. `ORDER_BY_NULLS_FLAG` 

ตัวอย่าง: 

```text
ORDER_BY_NULLS_FLAG = 0
```

ความหมาย: 

`ORDER_BY_NULLS_FLAG` ถูกใช้เพื่อควบคุมว่า NULL ปรากฏที่ต้นหรือท้ายเมื่อเรียงลำดับด้วย `ORDER BY`. 

เหตุผลที่สำคัญ: 

ฐานข้อมูลต่าง ๆ อาจมีพฤติกรรมเริ่มต้นที่แตกต่างกันสำหรับการเรียง NULLs เมื่อย้ายแอปพลิเคชันจาก MySQL ถึง Dameng, หากผลการจัดเรียงขึ้นอยู่กับตำแหน่งของ NULLs พารามิเตอร์นี้อาจมีผลต่อคำสั่งลำดับของผลลัพธ์การค้นหา 

บทความนี้ถูกตั้งค่าเป็น: 

```text
ORDER_BY_NULLS_FLAG = 0
```

จุดประสงค์คือเพื่อทำให้พฤติกรรมการจัดเรียงใกล้เคียงกับ MySQL นิสัยการใช้งานมากขึ้น

หมายเหตุ:

- ต้องรีสตาร์ทบริการฐานข้อมูลหลังจากปรับเปลี่ยน
- หากธุรกิจ SQL ได้ระบุอย่างชัดเจนแล้ว `NULLS FIRST` หรือ `NULLS LAST`พฤติกรรมที่ระบุใน SQL ควรมีความสำคัญเหนือกว่า

## ภาคผนวก 2 คำถามที่พบบ่อย

### 1. ทำไมฉันถึงไม่สามารถเชื่อมต่อโดยใช้ MySQL แม้หลังจากตั้งโหมดความเข้ากันได้ MySQL แล้ว?

เพราะว่า MySQL โหมดความเข้ากันได้ส่งผลกระทบเฉพาะ SQL ไวยากรณ์และพฤติกรรมบางอย่างของฐานข้อมูล ไม่ได้เปลี่ยนแปลง Damengโปรโตคอลเครือข่ายของ

เมื่อโปรแกรมประยุกต์หรือเครื่องมือต่อเข้ากับ Dameng, ยังคงต้องใช้ Dameng ไดรเวอร์:

```text
dm.jdbc.driver.DmDriver
jdbc:dm://<host>:5236
```

ไม่สามารถใช้: 

```text
com.mysql.cj.jdbc.Driver
jdbc:mysql://<host>:5236
```

### 2. วิธีตรวจสอบว่าการตั้งค่ามีผลจริงหรือไม่?

อย่ามองแค่ `dm.ini` ไฟล์; แนะนำให้เข้าสู่ระบบฐานข้อมูลเพื่อตรวจสอบสถานะการทำงาน:

```sql
select para_name, para_value
from v$dm_ini
where para_name in ('COMPATIBLE_MODE', 'ORDER_BY_NULLS_FLAG');
```

สถานะการทำงานจะมีผลเพียงเมื่อเห็นผลลัพธ์ดังต่อไปนี้: 

```text
COMPATIBLE_MODE      4
ORDER_BY_NULLS_FLAG  0
```

### 3. ทำไมถึงไม่มีผลหลังจากแก้ไข `dm.ini`?

สาเหตุที่พบบ่อย:

- บริการฐานข้อมูลไม่ได้ถูกรีสตาร์ทหลังจากการแก้ไข
- มีรายการการกำหนดค่าซ้ำในไฟล์
- ไฟล์ที่แก้ไขแล้วไม่ใช่ `dm.ini` กำลังถูกใช้งานโดยอินสแตนซ์

คุณสามารถยืนยันไฟล์การกำหนดค่าที่อินสแตนซ์ปัจจุบันกำลังใช้ผ่านคำสั่งเริ่มบริการ:

```bash
systemctl status DmServiceDBSERVER.service --no-pager
```

โดยทั่วไปคุณจะเห็นบางอย่างคล้ายกับสิ่งต่อไปนี้ในผลลัพธ์:

```text
dmserver path=/dmdata/data/DMTEST/dm.ini -noconsole
```

### 4. ฉันควรทำอย่างไรหาก PASSWORD ในระหว่างการเริ่มต้นใช้งานหรือไม่?

ระบุว่า PASSWORD นั้นง่ายเกินไป กรุณาเปลี่ยนเป็น PASSWORDตัวอย่าง:

```text
AT_LEAST 8 POSITION
CONTAINS_LETTERS_AND_NUMBERS
AVOID_USING_THE_ACCOUNT_NAME_ITSELF
```

### ที่ซับซ้อนมากขึ้น 5 พารามิเตอร์เหล่านี้สามารถเปลี่ยนแปลงภายหลังได้หรือไม่? 

ไม่ได้ 

โดยทั่วไปไม่แนะนำให้เปลี่ยนแปลงพารามิเตอร์เริ่มต้นภายหลัง ตัวอย่างเช่น: 
- 'PAGE_SIZE'
- 'EXTENT_SIZE'
- 'CASE_SENSITIVE'
- 'UNICODE_FLAG'
- 'DB_NAME'
- 'INSTANCE_NAME'

หากพารามิเตอร์เหล่านี้ถูกตั้งค่าไม่ถูกต้อง โดยปกติจะแนะนำให้เริ่มฐานข้อมูลใหม่และย้ายข้อมูลอีกครั้ง พารามิเตอร์ 

'dm.ini' สามารถปรับเปลี่ยนได้ภายหลัง ตัวอย่างเช่น: 

- 'COMPATIBLE_MODE'
- 'ORDER_BY_NULLS_FLAG'
- 'PORT_NUM'

อย่างไรก็ตาม หลังจากมีการแก้ไข บริการฐานข้อมูลโดยทั่วไปจะต้องถูกรีสตาร์ท 

## ภาคผนวก 3: รายการตรวจสอบสุดท้าย
