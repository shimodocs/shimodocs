# การกำหนดค่า Object Storage

[← ShimoDocs Suite เอกสารการติดตั้ง](../../README.md)

เอกสารฉบับนี้มีวัตถุประสงค์เพื่อชี้แนะแก่บุคลากรที่เกี่ยวข้องกับการดำเนินการ การปฏิบัติงาน หรือการบูรณาการให้สามารถดำเนินการให้เสร็จสมบูรณ์ ShimoDocs การเชื่อมต่อกับที่เก็บวัตถุจากบุคคลที่สามภายนอก S3 ทีละขั้นตอน


# 1. การยืนยันก่อนการดำเนินงาน

## S3 ข้อกำหนดการจัดเก็บวัตถุ

`Only object storage fully compatible with the S3 protocol is supported. Huawei Cloud OBS, Alibaba Cloud OSS, Tencent Cloud COS, and AWS S3 are recommended. For local deployment, MinIO can be considered.`



> [!TIP]
>
> แนะนำคลาวด์สาธารณะ ต้องสนับสนุน HTTPS การเข้าถึงจากภายนอก



## การเชื่อมต่อเครือข่าย

พอร์ตสำหรับ K8s เครือข่ายคลัสเตอร์ธุรกิจที่จะเชื่อมต่อกับอินสแตนซ์การจัดเก็บวัตถุต้องเปิดอยู่

```js
telnet IP 9000
```
## การควบคุมการเข้าถึงและสิทธิ์
- ให้ข้อมูลการรับรองความถูกต้อง AK/SK อย่างครบถ้วน
- ต้องสนับสนุนอินเทอร์เฟซหลักอย่างเต็มที่ เช่น PutObject, GetObject, DeleteObject, ListObjects, CopyObject, InitiateMultipartUpload



# S3 คำอธิบายข้อกำหนดการจัดเก็บ
- ข้อกำหนดความหน่วง: ในสภาพแวดล้อมเครือข่ายภายใน เวลาในการตอบสนองเฉลี่ยของการเก็บข้อมูล API แนะนำให้ < 50ms; ในสภาพแวดล้อมเครือข่ายสาธารณะ แนะนำให้ < 200ms ความหน่วงสูงจะส่งผลโดยตรงต่อความเร็วในการเปิดเอกสารและประสบการณ์การอัปโหลดไฟล์แนบ
- ความสามารถในการทำงานพร้อมกัน: ต้องรองรับจุดสูงสุดที่ประมาณการขององค์กร QPS. ShimoDocs จะสร้างการจราจรแบบระเบิดในระหว่างการทำงานร่วมกันของผู้ใช้หลายคนและการนำเข้/ส่งออกเป็นชุด ดังนั้นด้านการจัดเก็บข้อมูลต้องไม่มีนโยบายจำกัดอัตราที่เข้มงวดเกินไป
- ความพร้อมใช้งาน SLA: แนะนำให้ความพร้อมใช้งานของการจัดเก็บข้อมูลในสภาพแวดล้อมการผลิต ≥ 99.9%
- การสื่อสารการจัดเก็บข้อมูลผ่านเครือข่ายสาธารณะต้องดำเนินการผ่าน HTTPS/TLS ช่องทางเข้ารหัส
- การซิงโครไนซ์เวลา: S3 บริการจัดเก็บข้อมูลและ ShimoDocs เซิร์ฟเวอร์แอปพลิเคชันต้องซิงโครไนซ์ผ่าน NTPมิฉะนั้น S3 การตรวจสอบลายเซ็นจะล้มเหลว
