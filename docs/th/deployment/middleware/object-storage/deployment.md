# การปรับใช้ด้วย Object Storage

[← ShimoDocs Suite เอกสารการติดตั้ง](../../README.md)

บทความนี้อธิบายวิธีปิดการใช้งานในตัว MinIO ใน ShimoDocs และกำหนดค่า S3 การจัดเก็บวัตถุเป็นการจัดเก็บวัตถุบุคคลที่สาม S3 เมื่อการตั้งค่าเสร็จสมบูรณ์ ตัวติดตั้งจะตรวจสอบ S3 การเชื่อมต่อเครือข่ายที่จัดเก็บวัตถุ ข้อมูลการรับรอง และสิทธิ์ในการอ่าน/เขียนบัคเก็ต เมื่อการตรวจสอบผ่าน การปรับใช้สามารถดำเนินต่อไปได้ 

# 1. การเตรียมความพร้อมก่อนการกำหนดค่า 
ก่อนเริ่มโปรดยืนยันว่า: 
- S3 การจัดเก็บวัตถุติดตั้งและทำงานได้ตามปกติ 
- K8s โหนดของคลัสเตอร์สามารถเข้าถึงโฮสต์และพอร์ตของ S3 การจัดเก็บวัตถุ 
- การรับรอง AK/SK สำหรับการเชื่อมต่อกับ S3 การจัดเก็บวัตถุพร้อมใช้งาน 
- S3 ที่จัดเก็บต้องสนับสนุนการเข้าถึงผ่านเบราว์เซอร์ของลูกค้า 
- แนะนำให้ใช้ S3 อินสแตนซ์แยกต่างหาก 
- มาตรฐาน S3 ที่อยู่การเข้าถึงโปรโตคอลสำหรับเครือข่ายภายในและภายนอกต้องถูกจัดเตรียม 
- ShimoDocs ธุรกิจ-มาตรฐาน S3 บัคเก็ตควรถูกสร้างล่วงหน้า 
- S3 ที่จัดเก็บต้องใช้ SSD ดิสก์

## คำแนะนำการกำหนดค่าบัคเก็ต
- เผย_แนะนำให้ระบุชื่อหัวเรื่อง ไม่ใช้สัญลักษณ์ * เพราะผู้ขายบางรายอาจไม่รองรับ * สัญลักษณ์ เช่น Huawei Cloud OBS, Alibaba OSS
- ชื่อบัคเก็ตสามารถกำหนดค่าโดยมีคำนำหน้าตามความต้องการของบริษัทเพื่อหลีกเลี่ยงการซ้ำกัน

# 2. เข้าสู่การตั้งค่าขั้นสูง
ในขั้นตอน 'การกำหนดค่า' ของตัวติดตั้ง หลังจากตั้งค่าเครือข่าย, สภาพแวดล้อมเป้าหมาย และข้อมูลโหนดเรียบร้อยแล้ว ให้ขยาย 'การตั้งค่าขั้นสูง' ที่ด้านล่างของหน้า

# 3. ยกเลิกการติดตั้ง MinIO
ในพื้นที่ 'Middleware Services' ยกเลิกการเลือก MinIO

หลังจากยกเลิกการเลือก ตัวติดตั้งจะไม่ติดตั้ง MinIOในตัวอีกต่อไป และจะเป็นภายนอก S3 จะใช้ object storage ที่เตรียมไว้ก่อนหน้านี้ในภายหลัง ไม่ว่าจะเป็น middleware อื่นใช้บริการที่มีอยู่แล้วหรือไม่ควรเลือกตามแผนการปรับใช้จริง

# 4. เปิดการตั้งค่า Middleware ของบุคคลที่สาม
ในพื้นที่ 'Third-Party Middleware' คลิก 'Configure'

# 5. กำหนดค่า S3 Object Storage
1. เลือก "S3 Object Storage" ทางด้านซ้าย
2. เปิดใช้งาน "MinIO Object Storage."
3. สำหรับการโต้ตอบ Main Service/Editor ให้กรอกตามลำดับ: AK/SK, internal endpoint, public endpoint, host, port, SSLและข้อมูลอื่น ๆ
4. ตรวจสอบและบันทึก

> [!TIP]
>
> Main Service: อินสแตนซ์ object storage ที่ใช้สำหรับบริการอื่นที่ไม่ใช่การแก้ไขร่วมกัน
> Editor Interaction: อินสแตนซ์ object storage ที่ใช้โดยบริการการแก้ไขร่วมกัน
>
> หมายเหตุ: Main Service และ Editor Interaction สามารถใช้ object storage อินสแตนซ์เดียวกันได้ แต่การให้ instance แยกสำหรับ Editor Interaction จะช่วยให้ประสิทธิภาพการแก้ไขร่วมกันดีกว่า

## การตั้งชื่อบัคเก็ต

> [!NOTE]
>
> เมื่อหลายแอปพลิเคชันทางธุรกิจแชร์อินสแตนซ์เดียวกัน S3 ลูกค้าสามารถเพิ่มคำนำหน้าตาม ShimoDocsกฎการตั้งชื่อบัคเก็ตเพื่อช่วยแยกแยะธุรกิจที่แตกต่างกันและจัดการบัคเก็ต

# 6. ยืนยันผลการตรวจสอบ
โปรแกรมติดตั้งจะตรวจสอบสิ่งต่อไปนี้:
- เข้าสู่ระบบ: บัญชีสามารถตรวจสอบสิทธิ์ได้ตามปกติ
- การเชื่อมต่อ: สภาพแวดล้อมการปรับใช้สามารถเข้าถึง S3 การจัดเก็บวัตถุ
- สิทธิ์: บัญชีมีสิทธิ์ในการเชื่อมต่อ ตรวจสอบสิทธิ์ การอ่าน/เขียนถัง ฯลฯ

หลังจากรายการตรวจสอบทั้งหมดแสดง 'สำเร็จ' ปิดหน้าต่างการกำหนดค่าและกลับไปยังหน้าการ 'กำหนดค่า' ของโปรแกรมติดตั้ง

หากมีรายการใดล้มเหลว โปรดตรวจสอบตามคำแนะนำบนหน้า:
- ตรวจสอบว่ากรอกโฮสต์และพอร์ตถูกต้องหรือไม่
- เครือข่ายระหว่างโหนดการปรับใช้งานและ S3 การจัดเก็บวัตถุถูกเชื่อมต่อแล้ว
- ว่า USERNAME และ PASSWORD ถูกต้อง 
- ว่าบัญชีมีสิทธิ์ที่จำเป็น (การเชื่อมต่อและตรวจสอบสิทธิ์ สิทธิ์การอ่าน/เขียนถัง ฯลฯ) หรือไม่ 

# 7. ดำเนินการเริ่มต้นการปรับใช้ต่อ 
หลังจากกลับไปยังหน้าการ 'กำหนดค่า' ให้ตรวจสอบว่า S3 การจัดเก็บวัตถุยังไม่ได้ถูกเลือก จากนั้นคลิก 'เริ่มต้นการปรับใช้' เพื่อดำเนินการสรุปการปรับใช้ การตรวจสอบ และขั้นตอนการดำเนินการต่อ 

> [!TIP] 
> 
> ก่อนเริ่มต้นการปรับใช้งาน โปรดยืนยันอีกครั้งว่า S3 การกำหนดค่าการจัดเก็บวัตถุถูกบันทึกและรายการตรวจสอบทั้งหมดผ่านแล้ว
