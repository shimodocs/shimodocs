# ความพร้อมใช้งานสูง Kubernetes การปรับใช้

[← ShimoDocs Suite เอกสารการติดตั้ง](../README.md)

## 1. สถานการณ์ที่ใช้ได้ 

> [!TIP] 
> 
> K8s การติดตั้งแบบคลัสเตอร์เหมาะสำหรับสภาพแวดล้อมการผลิต เมื่อเทียบกับการติดตั้งเครื่องเดียว การติดตั้งแบบคลัสเตอร์เหมาะสมกว่าสำหรับการดำเนินงานระยะยาว การปรับขนาด และสถานการณ์พร้อมใช้งานสูง 

- สำหรับสภาพแวดล้อมการผลิต แนะนำให้ใช้ `3 master   N worker`. 
- อย่างน้อยเตรียมเครื่องเซิร์ฟเวอร์ 3 เครื่อง ทั้ง 3 เป็นมาสเตอร์ พนักงานสามารถใช้โหนดมาสเตอร์ซ้ำได้ในตอนแรก และสามารถเพิ่มพนักงานภายหลังตามขนาด 

## 2. การเตรียมตัวก่อนการติดตั้ง 

### 2.1 เตรียมข้อมูลดังต่อไปนี้ 

| ข้อมูล | ตัวอย่าง | คำอธิบาย | 
| --- | --- | --- | 
| สภาพแวดล้อมเครือข่าย | ออนไลน์ / ออฟไลน์ | เลือกออนไลน์หากสนับสนุนการเข้าถึงเครือข่ายสาธารณะ; เลือกออฟไลน์สำหรับเครือข่ายภายในหรือสภาพแวดล้อมที่ไม่เชื่อมต่อ | 
| INSTALL_NODE_IP | `<INSTALL_NODE_IP>` | เลือกเครื่อง 1 เครื่องเป็นโหนดการติดตั้งเพื่อเริ่มหน้าเว็บ | 
| ธุรกิจ NODE_IP | `<Node1IP>`, `<Node2IP>`, `<Node3IP>` | อย่างน้อย 3 เซิร์ฟเวอร์ | 
| ผู้ใช้สำหรับการดำเนินการ | `root` | คำสั่งติดตั้งควรดำเนินการด้วย `root` | 
| โปรโตคอลการเข้าถึง | HTTP / HTTPS | HTTPS แนะนำสำหรับสภาพแวดล้อมการผลิต | 
| ACCESS_DOMAIN | `<ACCESS_DOMAIN>` | ที่อยู่สำหรับผู้ใช้เข้าถึง ShimoDocs Suite |
| ไดเรกทอรีข้อมูล | `/data` | แนะนำให้เก็บให้สอดคล้องกันในทุกโหนด |
| เครื่องมือการติดตั้ง | `mdp-installer-${Arch}` | ตัวติดตั้งที่จัดทำโดย ShimoDocs, `${Arch}` แยกความแตกต่างของสถาปัตยกรรมชิปที่ต่างกัน ค่าของมันอาจเป็น amd64 สำหรับสถาปัตยกรรม x86 หรือ arm64 สำหรับสถาปัตยกรรม arm |
| แพ็กเกจการติดตั้งผลิตภัณฑ์ | ShimoDocs Suite แพ็กเกจการติดตั้ง | ใช้ชื่อไฟล์จริงที่ส่งมา |
| แพ็กเกจอิมเมจออฟไลน์ | `*.tar.gz` | จำเป็นเฉพาะสำหรับการติดตั้งออฟไลน์ |
| ซอฟต์แวร์กลางภายนอก | ใช่ / ไม่ใช่ | หากมีซอฟต์แวร์กลางภายนอก ให้เตรียมที่อยู่, พอร์ต, บัญชี PASSWORD ล่วงหน้า |

### 2.2 ข้อกำหนดขั้นต่ำของเซิร์ฟเวอร์

| รายการ | ข้อกำหนด |
| --- | --- |
| จำนวนเซิร์ฟเวอร์ | 3 เครื่องขึ้นไป |
| บทบาทที่แนะนำ | `3 master   N worker` |
| CPU ต่อโหนด | 16 คอร์ขึ้นไป |
| หน่วยความจำต่อโหนด | 32 GB ขึ้นไป |
| ดิสก์ระบบ | รูท `/` พาร์ติชัน 100 GB ขึ้นไป |
| ดิสก์ข้อมูล | เมานต์แยก `/data`, พื้นที่ว่าง 300 GB ขึ้นไป |
| การติดตั้งออฟไลน์ | แนะนำให้สำรองเพิ่มอีก 100 GB ขึ้นไปในดิสก์ข้อมูลของโหนดติดตั้ง |

หมายเหตุ:

- อย่าแบ่งพาร์ติชัน `/root`, `/var`, หรือ `/tmp` แยกต่างหาก 
- อย่าวางข้อมูลบนดิสก์ระบบ ให้วางทั้งหมดใน `/data`. 
- เวลาของทุกโหนดต้องซิงโครไนซ์กัน 
- โหนดติดตั้งต้องสามารถเข้าถึงโหนดอื่นผ่าน SSH. 

สามารถดำเนินการบนแต่ละเซิร์ฟเวอร์: 

```bash
lscpu
free -g
df -h
timedatectl status
```

ยืนยันว่าโหนดอื่นสามารถเข้าถึงจากโหนดติดตั้งได้: 

```bash
ssh root@<NODE2IP>
ssh root@<NODE3IP>
```

หากเข้าสู่ระบบล้มเหลว ให้ตรวจสอบ SSH, PASSWORD, การตั้งค่าไฟร์วอลล์ หรือกลุ่มความปลอดภัยก่อนติดตั้งต่อ

## 3. อัปโหลดเครื่องมือการติดตั้งและแพ็กเกจการติดตั้ง
> [!TIP]
>
> - ตรวจสอบให้แน่ใจว่าได้แก้ไขชื่อไฟล์ในคำสั่งให้ตรงกับสถานการณ์จริง ตัวอย่างเช่น ชื่อแพ็กเกจติดตั้งในสภาพแวดล้อมสถาปัตยกรรม x86 คือ mdp-installer-amd64
> - เลือกวิธีการอัปโหลดที่เหมาะสมตามสถานการณ์จริง ในบทความนี้ใช้คำสั่ง scp เป็นตัวอย่าง แต่เครื่องมือกราฟิกอื่น ๆ SSH ก็สามารถใช้ในการอัปโหลดได้เช่นกัน

เรียกใช้คำสั่งต่อไปนี้บนคอมพิวเตอร์เครื่องท้องถิ่นของคุณเพื่อย้ายตัวติดตั้งไปยังโหนดติดตั้ง:

```bash
scp mdp-installer-amd64 root@<INSTALL_NODE_IP>:/root/
```

การติดตั้งแบบออฟไลน์ยังคงต้องอัปโหลดแพ็กเกจภาพออฟไลน์: 

```bash
scp smbase_image-amd64.tar.gz offline_app_image.tar.gz root@<INSTALL_NODE_IP>:/root/
```

เข้าสู่ระบบโหนดติดตั้ง: 

```bash
ssh root@<INSTALL_NODE_IP>
```

ให้สิทธิ์ในการเรียกใช้ตัวติดตั้ง:

```bash
chmod +x /root/mdp-installer-amd64
```

เปิดหน้าติดตั้งตัวติดตั้งบนเว็บ: 

```bash
nohup /root/mdp-installer-amd64 server --port 18080 &
```

เข้าถึงผ่านเบราว์เซอร์: 

```text
http://<INSTALL_NODE_IP>:18080
```

## 4. การติดตั้งผ่านหน้าเว็บ

### 4.1 การอัปโหลดแพ็กเกจติดตั้งผลิตภัณฑ์

1. เปิด `http://<INSTALL_NODE_IP>:18080`.
2. อัปโหลด ShimoDocs Suite แพ็กเกจติดตั้ง
3. หลังจากอัปโหลดเสร็จแล้ว คลิก `Continue`.

### 4.2 กำหนดค่า ACCESS_DOMAIN

ป้อน ShimoDocs Suite ที่อยู่เข้าถึง:

| รายการการกำหนดค่า | วิธีการกรอก |
| --- | --- |
| ACCESS_DOMAIN / IP | `<ACCESS_DOMAIN>` |

### 4.3 ยืนยันการกำหนดค่าพื้นฐาน

| รายการการกำหนดค่า | วิธีการกรอก |
| --- | --- |
| NODE_IP | กรอก IP ของ master / worker NODE_ทีละตัว |
| SSH พอร์ต | โดยปกติ `22` |
| SSH PASSWORD | `root` ผู้ใช้ PASSWORD |
| ประเภทโหนด | `master`, `worker`, โหนดติดตั้ง |
| ไดเรกทอรีข้อมูล | `/data` |

ขั้นตอนการปฏิบัติการ:

1. เพิ่ม INSTALL_NODE_IP
2. เพิ่มที่อยู่ IP ของโหนด master/worker แต่ละโหนด
3. กำหนดบทบาทโหนดให้แต่ละเครื่องเซิร์ฟเวอร์
4. ทดสอบการเชื่อมต่อจากโหนดติดตั้งไปแต่ละโหนด
5. กรอกแคตาล็อกข้อมูลและช่วงเครือข่ายของคอนเทนเนอร์

จุดสำคัญที่ต้องยืนยันระหว่างการกำหนดค่า:

- โปรโตคอลการเข้าถึงและ ACCESS_DOMAIN ถูกกรอกอย่างถูกต้อง
- Pod CIDR และบริการ CIDR ไม่ทำให้เกิดความขัดแย้งกับเครือข่ายที่มีอยู่ เครือข่ายสำนักงาน, VPN, หรือ IDC ส่วนของเครือข่าย
- ไดเรกทอรีข้อมูลใช้ `/data` หรือไดเรกทอรีของดิสก์ข้อมูลที่วางแผนไว้จริง
- วิธีติดตั้งออนไลน์/ออฟไลน์สอดคล้องกับสภาพแวดล้อมเครือข่ายปัจจุบัน
- การติดตั้งออฟไลน์ต้องอัปโหลดแพ็กเกจภาพฐานออฟไลน์และแพ็กเกจภาพแอปพลิเคชัน โดยค่าเริ่มต้นจะเป็นการติดตั้งแบบออนไลน์ และต้องมั่นใจว่าคลัสเตอร์สามารถเข้าถึงเครือข่ายสาธารณะได้

### 4.4 การปรับใช้เริ่มต้น

หลังจากการตั้งค่าเสร็จสิ้น คลิก การปรับใช้เริ่มต้น หน้าเว็บจะแสดงภาพรวมของการปรับใช้นี้ โปรดให้ความสนใจเป็นพิเศษกับ:

- เวอร์ชันแพ็กเกจผลิตภัณฑ์
- ปรับใช้ NODE_IP
- SSH ผู้ใช้และพอร์ต
- ACCESS_DOMAIN และโปรโตคอล
- ไดเรกทอรีข้อมูล
- โหมดการติดตั้งออนไลน์หรือออฟไลน์
- การเลือกมิดเดิลแวร์

ดำเนินการต่อหลังจากยืนยันว่าไม่มีข้อผิดพลาด

### 4.5 ตรวจสอบสภาพแวดล้อมระบบ

ตัวติดตั้งจะตรวจสอบสภาพแวดล้อมเซิร์ฟเวอร์โดยอัตโนมัติ

ดำเนินการปรับใช้ต่อหลังจากการตรวจสอบผ่าน หากเกิดความล้มเหลวใด ๆ โปรดทำตามคำแนะนำบนหน้าเว็บเพื่อแก้ไขแล้วตรวจสอบอีกครั้ง ทิศทางการจัดการทั่วไป ได้แก่:

- พื้นที่ดิสก์ไม่เพียงพอ: ทำความสะอาดพื้นที่หรือขยายดิสก์ข้อมูล
- พอร์ตไม่พร้อมใช้งาน: ปล่อยพอร์ตหรือปรับการใช้พอร์ต
- SSH การเชื่อมต่อล้มเหลว: ตรวจสอบบัญชี, PASSWORD, คีย์ส่วนตัว, พอร์ต และกลุ่มความปลอดภัย
- ข้อยกเว้นการซิงโครไนซ์เวลา: กำหนดค่า NTP หรือตั้งเวลาเซิร์ฟเวอร์
- คำสั่งพื้นฐานหายไป: ติดตั้งคำสั่งที่หายไปตามการแจกแจงระบบ

### 4.6 เริ่มการปรับใช้

หลังจากการตรวจสอบสภาพแวดล้อมผ่านแล้ว คลิกเริ่มการปรับใช้

คุณสามารถดูบันทึกการดำเนินงานของแต่ละองค์ประกอบในกระบวนการปรับใช้ ในระหว่างการติดตั้ง กรุณาแน่ใจว่า: 

- กระบวนการติดตั้งยังคงทำงานอยู่ 
- เบราว์เซอร์สามารถสื่อสารกับโหนดติดตั้งผ่านเครือข่ายได้ 
- เซิร์ฟเวอร์ไม่ได้รีสตาร์ท 
- อย่าย้ายหรือลบแพ็กเกจติดตั้ง แพ็กเกจภาพออฟไลน์ หรือไดเรกทอรีข้อมูล 

### 4.7 รอการติดตั้งเสร็จสิ้น

กระบวนการติดตั้งต้องใช้เวลารอ และเวลาที่แน่นอนขึ้นอยู่กับประสิทธิภาพของเซิร์ฟเวอร์ สภาพแวดล้อมเครือข่าย และความเร็วในการดาวน์โหลดภาพ

เมื่อหน้าจอแสดงว่าทุกงานถูกดำเนินการเรียบร้อยและไม่มีองค์ประกอบที่ล้มเหลว นั่นหมายความว่าการปรับใช้เสร็จสมบูรณ์

### 4.8 ยืนยันผลการติดตั้ง

หลังจากการติดตั้งเสร็จสิ้น โปรแกรมติดตั้งจะแสดงหน้าการเสร็จสิ้นการปรับใช้และข้อมูลทางเข้า กรุณายืนยันก่อนว่าไม่มีงานที่ล้มเหลวบนหน้า แล้วจึงเข้าถึงระบบธุรกิจและ MDP แพลตฟอร์มปฏิบัติการ

เข้าชมที่อยู่ธุรกิจ: 

```text
http://<ACCESS_DOMAIN>/
```

ถ้า HTTPS ถูกกำหนดค่าในระหว่างการติดตั้ง กรุณาเข้าชม: 

```text
https://<ACCESS_DOMAIN>/
```

หลังจากเข้าสู่ระบบด้วยบัญชีเริ่มต้นหรือบัญชีผู้ดูแลระบบ กรุณาเปลี่ยนค่าเริ่มต้น PASSWORD ทันที

เข้าถึง MDP แพลตฟอร์มปฏิบัติการ:

```text
http://<ACCESS_DOMAIN>/mdp/
```

หากคุณต้องการแก้ไข MDP ผู้ดูแลระบบ PASSWORDคุณสามารถรันคำสั่งต่อไปนี้บนโหนดการติดตั้งเพื่อแก้ไขหรือรีเซ็ต PASSWORD.
โปรดแทนที่ {password} ด้วยรหัสผ่านใหม่ที่ซับซ้อนและแข็งแรง PASSWORD ตามข้อกำหนดด้านความปลอดภัยจริง

```bash
kubectl exec -it $(kubectl get pods -l app=mdp -o jsonpath='{.items[0].metadata.name}') -- reset-admin-password {password}
```

## 5. การตรวจรับหลังการติดตั้ง

### 5.1 ตรวจสอบ K8s สถานะโหนด

รันคำสั่งบนโหนดการติดตั้ง:

```bash
kubectl get node
```

สถานะของโหนดควรเป็น `Ready`. 

ทำการตรวจสอบบริการต่อไป: 

```bash
kubectl get pod -A
```

สถานะปกติส่วนใหญ่คือ: 

- `Running`: บริการกำลังทำงาน 
- `Completed`: งานได้ทำการรันเสร็จสิ้นแล้ว 

หากคุณพบสถานะเช่น `CrashLoopBackOff`, `ImagePullBackOff`, `Error`, `Pending`โปรดตรวจสอบบันทึกของ Pod ที่เกี่ยวข้องก่อนและดำเนินการจัดการ 

### 5.2 ตรวจสอบการเข้าถึง 

เข้าถึง ShimoDocs Suite เข้าผ่านเบราว์เซอร์: 

```text
http://<ACCESS_DOMAIN>/
```

ถ้า HTTPS ได้รับการกำหนดค่าแล้ว โปรดไปที่: 

```text
https://<ACCESS_DOMAIN>/
```

ยืนยันว่าหน้าเข้าสู่ระบบสามารถเปิดได้ตามปกติ 

### 5.3 ตรวจสอบระบบหลังบ้านการจัดการและใบอนุญาต 

ยืนยันรายการดังต่อไปนี้: 

- สามารถเข้าถึงระบบหลังบ้านการจัดการได้ 
- ผู้ดูแลระบบสามารถเข้าสู่ระบบได้ 
- สามารถเปิดหน้าการใช้งานใบอนุญาตได้ 
- สามารถดูข้อมูลเครื่องได้ 
- สามารถขอใบอนุญาตหรืออัปเดตตามกระบวนการอนุญาต 

### 5.4 ตรวจสอบฟังก์ชันธุรกิจ 

หลังจากเข้าสู่ระบบด้วยบัญชีทดสอบหรือบัญชีที่สร้างโดยผู้ดูแลระบบ อย่างน้อยให้ตรวจสอบว่า: 

- สามารถสร้างเอกสาร สเปรดชีต สไลด์ 
- สามารถแก้ไข เอกสาร บันทึก หรือรีเฟรชได้และเนื้อหายังคงอยู่ 
- สามารถแก้ไขร่วมกันหลายผู้ใช้ได้ 
- การนำเข้าและส่งออกไฟล์เป็นไปตามปกติ 
- ฟังก์ชันหลักเช่น การค้นหา พื้นที่ทีม รายชื่อผู้ติดต่อ เป็นต้น สามารถใช้งานได้ 

หลังจากเข้าสู่ระบบด้วยบัญชีทดสอบเริ่มต้นครั้งแรก โปรดอัปเดตของคุณ PASSWORD ทันที 
บัญชี PASSWORD คือบัญชีการปรับใช้และการส่งมอบ PASSWORD! 

```text
ACCOUNT:autotest@example.com
PASSWORD:xxxxxxx
```

### 5.5 หยุดกระบวนการติดตั้ง

หลังจากการปรับใช้เสร็จสิ้นและได้รับการยอมรับแล้ว สามารถหยุดบริการเว็บติดตั้งได้
หยุดหน้าเว็บติดตั้ง:
คำสั่งเพื่อหยุดตัวติดตั้ง: 

```bash
ps -ef | grep mdp-installer | grep -v grep
kill <PID>
```

หากตัวติดตั้งเริ่มทำงานในพื้นหลังโดยใช้ `nohup`คุณยังสามารถตรวจสอบบันทึกได้ด้วย: 

```bash
tail -f /root/nohup.out
```

## 6. การจัดการปัญหาทั่วไป

### 6.1 เบราว์เซอร์ไม่สามารถเปิดหน้าติดตั้งได้

ตรวจสอบดังต่อไปนี้:

- ว่ากระบวนการติดตั้งยังทำงานอยู่หรือไม่
- ว่าพอร์ต `18080` ถูกบล็อกโดยไฟร์วอลล์หรือกลุ่มความปลอดภัยหรือไม่
- ว่าที่อยู่ IP ที่เข้าถึงโดยเบราว์เซอร์คือ INSTALL_NODE_IP

คุณสามารถสั่งรันบนเซิร์ฟเวอร์ได้:

```bash
ps -ef | grep mdp-installer | grep -v grep
ss -lntp | grep 18080
```

### 6.2 การตรวจสอบสภาพแวดล้อมล้มเหลว

จัดการแต่ละรายการตามข้อความแจ้งบนหน้า หลังจากจัดการแล้ว กลับไปที่หน้าติดตั้งและรันการตรวจสอบสภาพแวดล้อมอีกครั้ง

การตรวจสอบความสำคัญ:

- ว่าหน่วยความจำ, และดิสก์ตรงตามข้อกำหนดหรือไม่ CPUว่าหน่วยความจำและดิสก์ตรงตามข้อกำหนดหรือไม่
- ว่า `/data` เป็นดิสก์ข้อมูลอิสระหรือไม่
- เวลาของเซิร์ฟเวอร์ถูกซิงโครไนซ์แล้วหรือไม่
- ว่าหน่วยความจำ, และดิสก์ตรงตามข้อกำหนดหรือไม่ SSH ผู้ใช้มีสิทธิ์ในการติดตั้งหรือไม่

### 6.3 การดึงภาพติดตั้งแบบออฟไลน์ล้มเหลว

ทิศทางการตรวจสอบ:

- ว่าชุดภาพออฟไลน์ถูกอัปโหลดไปยังโนดติดตั้งแล้วหรือไม่
- ว่าชุดภาพออฟไลน์พื้นฐานและชุดภาพออฟไลน์ผลิตภัณฑ์สมบูรณ์หรือไม่
- ว่ารุ่นของชุดภาพตรงกับชุดติดตั้งผลิตภัณฑ์หรือไม่
- ว่าที่อยู่บัญชีและ PASSWORD ถูกกรอกอย่างถูกต้อง

### 6.4 Pod ยังคงอยู่ในสถานะผิดปกติเป็นเวลานาน

ก่อนอื่นให้ตรวจสอบ Pod ที่ผิดปกติ:

```bash
kubectl get pod -A
```

ตรวจสอบบันทึกอีกครั้ง: 

```bash
kubectl logs -n <namespace> <pod-name>
```

จัดการปัญหาเกี่ยวกับภาพ, การตั้งค่า, ทรัพยากร, หรือการพึ่งพาตามบันทึก

## 7. การเก็บรักษาวัสดุหลังการติดตั้ง

หลังการติดตั้ง แนะนำให้เก็บวัสดุต่อไปนี้ไว้เพื่ออำนวยความสะดวกในการบำรุงรักษา การอัปเกรด และการแก้ไขปัญหาในภายหลัง:

- INSTALL_NODE_IP, ACCESS_DOMAINและโปรโตคอลการเข้าถึง
- ชื่อไฟล์ติดตั้งและเวอร์ชัน
- ชื่อไฟล์แพ็กเกจติดตั้งผลิตภัณฑ์และเวอร์ชัน
- ชื่อไฟล์แพ็กเกจอิมเมจออฟไลน์และเวอร์ชัน
- ภาพหน้าจอการกำหนดค่าคีย์ของเว็บเพจ
- `kubectl get node` ตรวจสอบผลลัพธ์
- `kubectl get pod -A` ตรวจสอบผลลัพธ์
- บันทึกการอนุญาตใบอนุญาต
- บันทึกการยอมรับฟังก์ชันธุรกิจ
- ปัญหาที่พบระหว่างการปรับใช้และผลการจัดการ
