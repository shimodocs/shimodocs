# เริ่มต้นอย่างรวดเร็ว

[← ShimoDocs Suite เอกสารการติดตั้ง](../README.md)

> [!TIP]
>
> บทความนี้แนะนำวิธีการใช้ `mdp-installer` เพื่อปรับใช้สภาพแวดล้อมใหม่ของ ShimoDocs Suite.
>
> บทความนี้เขียนขึ้นสำหรับ **All-in-One โหนดเดียว การติดตั้งออนไลน์** สถานการณ์ เหมาะสำหรับการติดตั้งครั้งแรก การทดลองใช้งานผลิตภัณฑ์ การตรวจสอบฟังก์ชัน และการฝึกปฏิบัติขั้นตอนการปรับใช้งาน หลังจากอ่านบทความนี้ คุณสามารถรับ ShimoDocs Suite ที่อยู่สำหรับเข้าธุรกิจ และ MDP ที่อยู่แพลตฟอร์มปฏิบัติการ

> ที่อยู่ IP ชื่อแพ็กเกจติดตั้ง VERSIONและไดเรกทอรีบนหน้าหน้าเป็นเพียงตัวอย่าง ในการปรับใช้จริง โปรดอ้างอิงตามสภาพแวดล้อมปัจจุบันและวัสดุที่ส่งมอบ

## 1. ภาพรวมกระบวนการปรับใช้

ทั้งกระบวนการสามารถแบ่งออกเป็น 7 ขั้นตอนดังนี้

| ขั้นตอน | การดำเนินการให้เสร็จสมบูรณ์ | ตัวบ่งชี้การเสร็จสมบูรณ์ |
| --- | --- | --- |
| 1. เตรียมเซิร์ฟเวอร์และวัสดุติดตั้ง | ตรวจสอบให้แน่ใจว่าเซิร์ฟเวอร์ ตัวติดตั้ง และ ShimoDocs Suite แพ็กเกจแจกจ่ายพร้อมใช้งาน | สามารถเข้าสู่ระบบเซิร์ฟเวอร์และค้นหาไฟล์ติดตั้งได้ |
| 2. เริ่มตัวติดตั้ง | เรียกใช้ `mdp-installer` บนโหนดการติดตั้ง | เทอร์มินัลแสดงที่อยู่การเข้าถึงของตัวติดตั้ง |
| 3. อัปโหลดแพ็กเกจการแจกจ่าย | เลือก ShimoDocs Suite แพ็กเกจการแจกจ่ายในเบราว์เซอร์ | หน้าจอแสดงว่าแพ็กเกจการแจกจ่ายผ่านการตรวจสอบแล้ว |
| 4. กำหนดค่าสภาพแวดล้อมการปรับใช้ | กรอกโดเมนหรือ IP, โหมดการปรับใช้, ข้อมูลการเข้าสู่ระบบของโหนด และไดเรกทอรีข้อมูล | โหนดถูกตรวจสอบเรียบร้อยแล้วและสามารถเข้าถึงภาพรวมการปรับใช้ได้ |
| 5. ตรวจสอบสภาพแวดล้อม | รอตัวติดตั้งตรวจสอบเซิร์ฟเวอร์และสภาพแวดล้อมการปรับใช้ | ไม่มีความล้มเหลวที่ขัดขวางการติดตั้ง |
| 6. เริ่มการติดตั้ง | ยืนยันผลการตรวจสอบแล้วดำเนินการปรับใช้ | หน้าจอแสดงว่าการติดตั้งเสร็จสมบูรณ์ |
| 7. บันทึกข้อมูลการส่งมอบ | บันทึกที่อยู่การเข้าถึงและทำการยืนยันการเข้าสู่ระบบ บริการ และฟีเจอร์ต่าง ๆ เสร็จสิ้น | สามารถเข้าถึงหน้าเว็บธุรกิจและ MDP แพลตฟอร์มปฏิบัติการได้ |

## 2. การเตรียมก่อนการปรับใช้

### 1. เตรียมโหนดติดตั้ง

โหนดติดตั้งใช้เพื่อรันตัวติดตั้งและทำหน้าที่เป็นเซิร์ฟเวอร์เป้าหมายสำหรับการปรับใช้แบบโหนดเดียว All-in-One

ก่อนเริ่ม โปรดยืนยันว่า:

- เตรียมเซิร์ฟเวอร์ที่สามารถใช้งานได้และ SERVER_ได้รับที่อยู่ IP แล้ว
- สามารถเข้าถึงเซิร์ฟเวอร์ผ่าน SSH.
- ผู้ใช้ SSH คือ `root`หรือมีสิทธิ์ที่จำเป็นในการดำเนินงานการปรับใช้
- สถาปัตยกรรมของเซิร์ฟเวอร์ CPU ตรงกับตัวติดตั้งและแพ็กเกจการแจกจ่าย เช่น ทั้งคู่เป็น `x86_64`.
- เซิร์ฟเวอร์เป็นไปตามข้อกำหนดการปรับใช้ปัจจุบัน แนะนำให้ใช้การติดตั้ง Ubuntu 24.04 แบบขั้นต่ำ LTS.
- พาร์ติชันรากและพื้นที่ข้อมูลตรงตามข้อกำหนดการปรับใช้ปัจจุบัน และได้กำหนดไดเรกทอรีข้อมูลเรียบร้อยแล้ว
- เวลาของเซิร์ฟเวอร์และเขตเวลาถูกต้อง และการซิงโครไนซ์เวลาเป็นปกติ
- คอมพิวเตอร์ที่ใช้เบราว์เซอร์สามารถเข้าถึงพอร์ต `18080/TCP` ของโหนดการติดตั้งได้
- เซิร์ฟเวอร์สามารถเข้าถึงอินเทอร์เน็ตเพื่อดาวน์โหลดแพ็กเกจการปรับใช้และทรัพยากรอิมเมจออนไลน์
- หากการเข้าถึงธุรกิจใช้ชื่อโดเมน การแก้ไขชื่อโดเมนได้เสร็จสิ้นล่วงหน้าแล้ว (ไม่บังคับ)

ข้อกำหนดขั้นต่ำของเซิร์ฟเวอร์มีดังนี้:

| ระบบปฏิบัติการ | สถาปัตยกรรม | CPU | หน่วยความจำ | ดิสก์ |
| --- | --- | --- | --- | --- |
| Ubuntu 24.04 LTS | `x86_64` | 16 คอร์ | 32 GB | 100 GB SSD |

นอกจากนี้ โปรดยืนยัน:

- อย่าแบ่งพาร์ติชัน `/root`, `/var`, `/tmp` แยกกัน
- ก่อนการติดตั้ง อย่านำส่วนประกอบเพิ่มเติมเช่น Docker หรือ Kubernetes ไปติดตั้งบนเซิร์ฟเวอร์ที่อาจส่งผลต่อการตรวจสอบของตัวติดตั้ง
- พอร์ต `22/TCP` ถูกใช้สำหรับ SSH, `18080/TCP` ถูกใช้สำหรับหน้าเว็บของตัวติดตั้ง `80/TCP` และ `443/TCP` ถูกใช้สำหรับการเข้าถึงธุรกิจ

> ก่อนการติดตั้งอย่างเป็นทางการ แนะนำให้ตรวจสอบสเปกของเซิร์ฟเวอร์ตามความพร้อมใช้งาน จำนวนการใช้งานพร้อมกันจริง และขนาดไฟล์; กระบวนการแบบโหนดเดี่ยวในเอกสารนี้เหมาะสำหรับการติดตั้งและตรวจสอบอย่างรวดเร็ว สำหรับการใช้งานระยะยาวหรือการใช้งานที่มีความพร้อมใช้งานสูง กรุณาใช้แผนการติดตั้งแบบคลัสเตอร์ที่สอดคล้องกัน

### 2. เตรียมวัสดุติดตั้ง

#### รับตัวติดตั้ง

อัปโหลดตัวติดตั้งที่จัดเตรียมโดย ShimoDocs ไปยังไดเรกทอรี `/root/` ของโหนดติดตั้ง คุณสามารถเลือกใช้วิธีใดก็ได้ดังต่อไปนี้:

- **วิธีที่ 1: อัปโหลดผ่าน SSH เครื่องมือ**. อัปโหลด `mdp-installer-amd64` ไปยังไดเรกทอรี `/root/` ไดเรกทอรีของโหนดติดตั้ง

#### รับแพ็กเกจแจกจ่าย

เตรียม ShimoDocs Suite แพ็กเกจแจกจ่ายสำหรับการติดตั้งนี้ แพ็กเกจแจกจ่ายจะถูกอัปโหลดบนหน้าเว็บติดตั้ง และชื่อไฟล์และเวอร์ชันควรเป็นไปตามการส่งมอบจริง

ตัวอย่างชื่อไฟล์: `co1.8.20260711.3286-drive-release.tar.gz`

รายการวัสดุมีดังนี้:

| ไฟล์ | คำอธิบาย |
| --- | --- |
| `mdp-installer` ตัวติดตั้ง | เลือกไฟล์ที่ตรงกับสถาปัตยกรรมของเซิร์ฟเวอร์ เช่น `mdp-installer-amd64`. |
| ShimoDocs Suite แพ็กเกจแจกจ่าย | ชื่อไฟล์และเวอร์ชันควรเป็นไปตามการส่งมอบจริง เช่น `co1.8.20260711.3286-drive-release.tar.gz`. |

แนะนำให้นำตัวติดตั้งและวัสดุติดตั้งที่เกี่ยวข้องไปวางในไดเรกทอรีงานเดียวกันเพื่อให้การเรียกใช้งานและจัดเก็บในภายหลังง่ายขึ้น ก่อนใช้งานแพ็กเกจแจกจ่าย โปรดตรวจสอบว่าไฟล์สมบูรณ์และไม่เสียหายจากเครื่องมือถ่ายโอน

## 3. เปิดตัวติดตั้ง

### 1. ลงชื่อเข้าใช้โหนดติดตั้ง

ลงชื่อเข้าใช้โหนดติดตั้งผ่าน SSH และไปที่ไดเรกทอรีที่ตัวติดตั้งอยู่ เช่น:

```bash
ssh root@<INSTALL_NODE_IP>
cd /root
```

### 2. เพิ่มสิทธิ์การทำงาน

หากตัวติดตั้งยังไม่มีสิทธิ์ในการทำงาน ให้รัน:

```bash
chmod +x ./mdp-installer-amd64
```
ชื่อไฟล์ในคำสั่งต้องถูกแทนด้วยชื่อตัวติดตั้งจริง 

### 3. เปิดหน้าเว็บติดตั้ง 

รัน: 

```bash
./mdp-installer-amd64 server
```

หากคุณต้องการให้ตัวติดตั้งยังทำงานต่อหลังจากเทอร์มินัลปัจจุบันปิด คุณสามารถใช้: 

```bash
nohup ./mdp-installer-amd64 server > nohup.out 2>&1 &
```

หลังจากเริ่มต้นสำเร็จ เทอร์มินัลจะแสดงสองที่อยู่: 

- `Local`: สำหรับใช้โดยโหนดติดตั้งเองเท่านั้น 
- `Network`: สามารถเข้าถึงโดยคอมพิวเตอร์อื่นบนเครือข่ายเดียวกัน 

หากเริ่มในโหมดแบ็กกราวด์ คุณสามารถรันคำสั่งต่อไปนี้เพื่อดูผลลัพธ์ของตัวติดตั้ง: 

```bash
cat nohup.out
```

เปิด `Network` ที่อยู่ที่แสดงในเทอร์มินัลในเบราว์เซอร์ ตัวอย่างเช่น:

```text
http://<INSTALL_NODE_IP>:18080/
```

> ในระหว่างการติดตั้ง กรุณาให้กระบวนการติดตั้งทำงานต่อไป อย่าปิดกระบวนการติดตั้งหรือหยุดบริการปัจจุบัน

## 4. อัปโหลด ShimoDocs Suite แพ็กเกจเวอร์ชั่น

### 1. เลือกแพ็กเกจเวอร์ชั่น

หลังจากเข้าสู่หน้าติดตั้ง:

1. คลิก **เริ่มการปรับใช้** หรือทางเข้าการเลือกแพ็กเกจเวอร์ชั่นบนหน้า
2. เลือก ShimoDocs Suite `.tar.gz` แพ็กเกจเวอร์ชั่นที่จะใช้สำหรับการปรับใช้ครั้งนี้
3. รอให้การอัปโหลดและการตรวจสอบไฟล์เสร็จสิ้น

### 2. ยืนยันผลการตรวจสอบ

หลังจากการตรวจสอบผ่านแล้ว หน้าจะปรากฏชื่อของแพ็กเกจการปล่อยและรายการการกำหนดค่าการปรับใช้

โปรดยืนยันว่าข้อมูลต่อไปนี้ถูกต้อง:

- ชื่อแพ็กเกจสอดคล้องกับเวอร์ชันที่ส่งมอบในครั้งนี้
- แพ็กเกจการปล่อยเป็นของ ShimoDocs Suite ผลิตภัณฑ์
- หน้าดังกล่าวไม่ได้ระบุถึงไฟล์ที่เสียหาย ข้อผิดพลาดของรูปแบบ หรือความไม่ตรงกันของสกีมา

หลังจากยืนยัน คลิก **ดำเนินการต่อ** ไปยังการกำหนดค่าการปรับใช้

หากการตรวจสอบล้มเหลว กรุณายืนยันอีกครั้งว่าชุดการแจกจ่ายสมบูรณ์ ประเภทไฟล์ถูกต้อง และชุดการแจกจ่ายตรงกับสถาปัตยกรรมเซิร์ฟเวอร์หรือไม่ CPU 

## 5. การกำหนดค่าสภาพแวดล้อมการปรับใช้

### 1. ยืนยันที่อยู่เครือข่าย

ตรวจสอบชื่อโฮสต์หรือที่อยู่ IP ที่ระบุบนหน้า ที่อยู่นี้ควรเป็นที่อยู่โหนดติดตั้งที่ผู้ใช้สามารถเข้าถึงได้ตามปกติ

ห้ามป้อน `127.0.0.1`และอย่าใช้ที่อยู่ชั่วคราวที่สามารถเข้าถึงได้เฉพาะคอมพิวเตอร์ปัจจุบันเท่านั้น เมื่อเข้าถึงผ่านชื่อโดเมน โปรดตรวจสอบให้แน่ใจว่าชื่อโดเมนนั้นได้รับการแก้ไขไปยังรายการบริการที่ถูกต้องแล้ว

### 2. เลือกโหมด All-in-One Single Node

เลือก **All-in-One Single Node** ในโหมดการปรับใช้หรือสภาพแวดล้อมเป้าหมาย (ชื่อจริงที่แสดงบนหน้าจะขึ้นอยู่กับเวอร์ชันปัจจุบัน)

ในโหมดนี้ โหนดติดตั้งจะทำหน้าที่ทั้งควบคุมและธุรกิจสำหรับการปรับใช้ครั้งนี้พร้อมกัน ทำให้เหมาะสำหรับสภาพแวดล้อมที่เบาสำหรับการทดลองใช้ผลิตภัณฑ์ การตรวจสอบฟีเจอร์ และการวางแผนแบบโหนดเดียว

### 3. กำหนดค่าโหนด SSH

ตัวติดตั้งเชื่อมต่อกับโหนดเป้าหมายผ่าน SSH และดำเนินงานภารกิจการปรับใช้ กรุณากรอก:

- NODE_ที่อยู่ IP
- SSH ผู้ใช้ โดยปกติ `root`.
- SSH พอร์ต โดยปกติ `22` เป็นค่าตั้งต้น
- PASSWORD หรือข้อมูลการตรวจสอบสิทธิ์ด้วยคีย์ส่วนตัว

หลังจากกรอกข้อมูลแล้ว คลิก **ยืนยัน** เพื่อยืนยันว่า SSH การเชื่อมต่อสำเร็จ

> SSH ข้อมูลประจำตัวควรถูกใช้และเก็บไว้ในสภาพแวดล้อมที่ควบคุมได้เท่านั้น อย่าเขียน PASSWORD หรือคีย์ส่วนตัวลงในเอกสารสาธารณะ, ภาพหน้าจอ, หรือบันทึกแชท

| ACCESS_DOMAIN / IP | ที่อยู่สำหรับผู้ใช้เข้าถึง ShimoDocs Suite; เมื่อใช้ IP ให้กรอกที่อยู่จริงที่สามารถเข้าถึงได้ |
| โหมดการปรับใช้งาน | เลือกโหมดโหนดเดี่ยวแบบ All-in-One |
| ไดเรกทอรีข้อมูลโหนด | ใช้เก็บข้อมูลการปรับใช้งาน กรุณาให้แน่ใจว่าดิสก์มีพื้นที่เพียงพอและมีสิทธิ์อ่าน/เขียน |
| คลังแบบออฟไลน์ | คู่มือนี้สำหรับการติดตั้งออนไลน์; เก็บค่าดีฟอลต์บนหน้าเพจ |
| ซอฟต์แวร์ตัวกลางจากบุคคลที่สาม | คู่มือนี้ใช้การปรับใช้งานตามค่าดีฟอลต์; ยืนยันตามข้อกำหนดการจัดส่งปัจจุบันหากจำเป็นต้องมีซอฟต์แวร์ตัวกลางภายนอก |

หากไม่มีข้อกำหนดการตั้งค่าเฉพาะ สามารถเก็บค่าดีฟอลต์สำหรับแหล่งเก็บข้อมูลออฟไลน์และซอฟต์แวร์ตัวกลางจากบุคคลที่สาม หลังจากตรวจสอบแล้ว คลิก **เริ่มต้นการปรับใช้งาน** ที่ด้านล่างของหน้า

## 6. ยืนยันภาพรวมการปรับใช้งาน

ภาพรวมการปรับใช้งานใช้เพื่อยืนยันการตั้งค่าการติดตั้งก่อนการตรวจสอบอย่างเป็นทางการ

กรุณาให้ความสนใจเป็นพิเศษกับสิ่งต่อไปนี้:

- ตรวจสอบให้แน่ใจว่ารุ่นแพ็กเกจและชื่อผลิตภัณฑ์ถูกต้อง
- ACCESS_DOMAIN หรือ IP ถูกต้องและไม่ใช่ `127.0.0.1`.
- โหมดการปรับใช้งานเป็น All-in-One โหนดเดียว
- NODE_IP, SSH ผู้ใช้และพอร์ตถูกต้อง
- ไดเรกทอรีข้อมูลถูกต้องและพื้นที่ดิสก์เพียงพอ
- แหล่งเก็บข้อมูลออฟไลน์และการตั้งค่าซอฟต์แวร์ตัวกลางจากบุคคลที่สามสอดคล้องกับสภาพแวดล้อมปัจจุบัน

หลังจากยืนยันว่าไม่มีข้อผิดพลาด คลิก **ดำเนินการต่อ** เพื่อไปยังการตรวจสอบสภาพแวดล้อม

## 7. ดำเนินการตรวจสอบสภาพแวดล้อม

โปรแกรมติดตั้งจะตรวจสอบโหนดและสภาพแวดล้อมการปรับใช้งาน กระบวนการตรวจสอบอาจใช้เวลาสักครู่ กรุณาเปิดหน้าจอไว้

### 1. ดูภาพรวมโหนด

ภาพรวมโหนดแสดงความคืบหน้าการตรวจสอบ เช่น SSH การเชื่อมต่อ ระบบและประสิทธิภาพ การจัดเก็บและดิสก์ เครือข่าย และสภาพแวดล้อมการปรับใช้งาน

เพื่อดูผลลัพธ์โดยละเอียดของการตรวจสอบเฉพาะ ให้คลิกที่รายการตรวจสอบหรือรายการรายละเอียดที่เกี่ยวข้อง

### 2. ดูผลการตรวจสอบโดยละเอียด

ผลลัพธ์โดยละเอียดมักจะรวมถึง:

- SSH การเชื่อมต่อและสิทธิ์ผู้ใช้ในการดำเนินการ
- ระบบปฏิบัติการ, CPU สถาปัตยกรรม และจำนวนคอร์
- ความจุหน่วยความจำ พื้นที่ดิสก์ และสิทธิ์ของไดเรกทอรี
- เขตเวลา และสถานะการซิงโครไนซ์เวลา
- เครือข่าย แหล่งภาพ และการเชื่อมต่อไปยังบริการภายนอก
- สารตกค้างในสิ่งแวดล้อมบนเซิร์ฟเวอร์ที่อาจส่งผลต่อการปรับใช้

### 3. การตรวจสอบสถานะความเข้าใจ

| สถานะ | ความหมาย | การดำเนินการต่อไป |
| --- | --- | --- |
| สำเร็จ | รายการตรวจสอบปัจจุบันตรงตามข้อกำหนดการปรับใช้ | รอต่อไปเพื่อให้รายการอื่น ๆ เสร็จสมบูรณ์ |
| คำเตือน | จะไม่บล็อกการปรับใช้โดยตรง แต่ต้องยืนยันว่าตรงกับแผนปัจจุบันหรือไม่ | เปิดรายละเอียดและดำเนินการต่อหลังจากยืนยันผลกระทบ |
| ล้มเหลว | ปัญหาปัจจุบันอาจส่งผลต่อการติดตั้งหรือการทำงานของผลิตภัณฑ์ | แก้ไขปัญหาก่อน จากนั้นตรวจสอบซ้ำ |
| กำลังดำเนินการ | โปรแกรมติดตั้งกำลังดำเนินการตรวจสอบ | รอให้การตรวจสอบเสร็จสิ้น อย่าดำเนินการซ้ำ |

หากรายการใดอยู่ใน 'กำลังดำเนินการ' เป็นเวลานาน คุณสามารถรอให้การตรวจสอบดิสก์หรือการตรวจสอบระยะไกลปัจจุบันเสร็จสิ้นก่อนตัดสินใจว่าจะตรวจสอบซ้ำหรือไม่

### 4. การจัดการคำเตือนและความล้มเหลว

หากหน้าจอแสดงคำเตือน:

1. เปิดคำอธิบายรายละเอียดของรายการตรวจสอบที่เกี่ยวข้อง
2. ยืนยันว่าคำเตือนตรงกับแผนการปรับใช้ปัจจุบันหรือไม่
3. หากไม่แน่ใจ บันทึกหน้าจอและบันทึกโปรแกรมติดตั้ง แล้วติดต่อเจ้าหน้าที่ดำเนินงานหรือบุคลากรที่เกี่ยวข้องเพื่อยืนยัน

หากหน้าจอไม่สามารถแสดงผล: 

1. ทำตามคำแนะนำเพื่อแก้ไข SSHปัญหาเกี่ยวกับสิทธิ์, ทรัพยากร, ดิสก์, เครือข่าย หรือมิดเดิลแวร์ 
2. คลิก **สแกนซ้ำ**. 
3. ยืนยันว่าส่วนที่ล้มเหลวได้หายไปแล้ว 

หลังจากตรวจสอบว่าไม่มีความล้มเหลวใด ๆ ขัดขวางการติดตั้งและยืนยันคำเตือนทั้งหมดแล้ว คลิก **ดำเนินการต่อ**. 

## 8. เริ่มการติดตั้ง 

### 1. ยืนยันแผนการติดตั้ง 

หน้าจอจะแสดงแผนการติดตั้งและงานที่จะดำเนินการ หลังจากยืนยันว่าถูกต้องแล้ว ให้คลิก **เริ่มการปรับใช้**. 

บนหน้าจออาจแสดงคำเตือน "ยืนยันเพื่อเริ่มการติดตั้ง" เมื่อเริ่มการติดตั้ง งานติดตั้งจะดำเนินไปตามกำหนดเวลา; หากต้องการปรับการกำหนดค่า กรุณาคลิก **ยกเลิก** เพื่อกลับไปยังขั้นตอนก่อนหน้า

### 2. ตรวจสอบความคืบหน้าการติดตั้ง

หลังจากเริ่มการติดตั้ง หน้าจอจะแสดงสถานะงานปัจจุบัน, บันทึกแบบเรียลไทม์ และเวลาการดำเนินการ การติดตั้งแบบโหนดเดี่ยวมักใช้เวลาประมาณ 10 นาที และเวลาแท้จริงจะขึ้นอยู่กับประสิทธิภาพเซิร์ฟเวอร์และแบนด์วิดธ์เครือข่าย

ระหว่างกระบวนการติดตั้งโปรดทราบ: 

- อย่าปิดกระบวนการติดตั้ง 
- ห้ามรีสตาร์ทโหนดการติดตั้ง 
- อย่ากดรีเฟรช, กลับ หรือส่งงานติดตั้งซ้ำ 
- หากงานล้มเหลว ให้ตรวจสอบข้อผิดพลาดแรกในบันทึกงานที่เกี่ยวข้อง แล้วดำเนินการตามคำแนะนำ 

เมื่อหน้าจอแสดงว่า **การติดตั้งเสร็จสิ้น** หรือเข้าสู่ **หน้าการส่งมอบการติดตั้ง** แสดงว่างานติดตั้งเสร็จเรียบร้อยแล้ว 

## 9. บันทึกข้อมูลการส่งมอบ 

หน้าการติดตั้งเสร็จสมบูรณ์จะแสดงข้อมูลการเข้าถึงและการตรวจสอบสำหรับการติดตั้งนี้ กรุณาทำงานต่อไปนี้ทันที: 

1. เรียกใช้การตรวจสอบบริการหลังการติดตั้งและยืนยันผลการตรวจสอบ 
2. ใช้ข้อมูลการเข้าถึงบนหน้าการส่งมอบการติดตั้ง เปิด ShimoDocs Suite หน้าธุรกิจและทำการยืนยันการเข้าสู่ระบบ 
3. บันทึก ShimoDocs Suite ที่อยู่สำหรับเข้าธุรกิจ และ MDP ที่อยู่แพลตฟอร์มปฏิบัติการ 
4. บันทึกบัญชีเริ่มต้นและรหัสชั่วคราว PASSWORDและเปลี่ยน PASSWORD ทันทีหลังจากเข้าสู่ระบบครั้งแรก 
5. ตรวจสอบโหนดคลัสเตอร์และสถานะแอปพลิเคชันใน MDP แพลตฟอร์มปฏิบัติการ 

> ข้อมูลการจัดส่งรวมถึงที่อยู่การเข้าถึงและข้อมูลรับรองเริ่มต้น ห้ามถ่ายภาพหน้าจอและแจกจ่าย ห้ามอัปโหลดไปยังฐานความรู้สาธารณะ และห้ามส่งผ่านช่องทางที่ไม่ควบคุม 

## 10. ตรวจสอบผลการปรับใช้งาน 

หลังจากเสร็จสิ้นการติดตั้ง แนะนำให้ทำการยอมรับตามลำดับดังต่อไปนี้: 

### 1. ตรวจสอบบริการหลังการติดตั้ง 

ทำการตรวจสอบหลังการติดตั้งบนหน้าการติดตั้งเสร็จสิ้นเพื่อยืนยันว่ากรณีทดสอบบริการผ่านหรือผลลัพธ์ตรงกับความคาดหวังของสภาพแวดล้อมปัจจุบัน 

หากการตรวจสอบล้มเหลวหรือผ่านบางส่วน คุณสามารถส่งงานตรวจสอบใหม่ได้ใน MDP แพลตฟอร์มปฏิบัติการ 

### 2. ตรวจสอบ MDP แพลตฟอร์มปฏิบัติการ

เข้าสู่ระบบไปยัง MDP แพลตฟอร์มปฏิบัติการ ไปที่ **บริการระบบ → การจัดการคลัสเตอร์**และยืนยันว่าสถานะของโหนดคลัสเตอร์และการทำงานของแอปพลิเคชันเป็นปกติ

### 3. ตรวจสอบ ShimoDocs Suite ฟังก์ชัน

เข้าสู่ระบบไปยัง ShimoDocs Suite หน้าฟรอนต์เอนด์และตรวจสอบอย่างน้อยฟังก์ชันต่อไปนี้:

- สร้างไฟล์ทดสอบหรือชุดทดสอบ
- แก้ไขเนื้อหาและบันทึก
- ส่งออกไฟล์
- นำเข้าไฟล์

หลังจากตรวจสอบทั้งหมดข้างต้นเรียบร้อยแล้ว แสดงว่าการปรับใช้ด่วนนี้เสร็จสมบูรณ์ หากต้องการการทำงานระยะยาว การปรับขยาย หรือต้องการความพร้อมใช้งานสูงในอนาคต โปรดเปลี่ยนไปใช้แผนการปรับใช้ที่สอดคล้องกับขนาดที่แท้จริง และทำการติดตั้งใบอนุญาตและการตั้งค่าธุรกิจให้ครบถ้วน

## 11. คำถามที่พบบ่อย

### 1. เบราว์เซอร์ไม่สามารถเปิดหน้าการติดตั้งได้

ตรวจสอบตามลำดับ:

- ว่ากระบวนการติดตั้งยังทำงานอยู่หรือไม่
- ว่า ที่อยู่การเข้าถึงใช้ IP จริงของโหนดติดตั้งหรือชื่อโดเมนที่สามารถแก้ไขได้
- ว่าพอร์ต `18080/TCP` ได้ถูกเปิดแล้วหรือไม่
- ว่า เครือข่ายระหว่างคอมพิวเตอร์ที่ใช้เบราว์เซอร์กับโหนดติดตั้งเชื่อมต่อกันหรือไม่

### 2. การตรวจสอบแพ็กเกจแจกจ่ายล้มเหลว

ตรวจสอบ:

- ว่าไฟล์ที่อัปโหลดเป็นไฟล์สมบูรณ์หรือไม่ `.tar.gz` แพ็กเกจการปล่อย.
- ตรวจสอบว่าชื่อไฟล์และประเภทผลิตภัณฑ์สอดคล้องกับการจัดส่งนี้หรือไม่.
- ว่าชุดปล่อยตรงกับเซิร์ฟเวอร์หรือไม่ CPU 
- ว่ามีไฟล์เสียหายระหว่างการอัปโหลดหรือการโอนย้ายหรือไม่

### 3. SSH การยืนยันตัวตนล้มเหลว

ตรวจสอบ:

- ว่าหน่วยความจำ, และดิสก์ตรงตามข้อกำหนดหรือไม่ NODE_IP และ SSH พอร์ตถูกต้อง
- ว่าหน่วยความจำ, และดิสก์ตรงตามข้อกำหนดหรือไม่ SSH ผู้ใช้, PASSWORD, หรือกุญแจส่วนตัวถูกต้อง
- ทำไม SSH ผู้ใช้มีสิทธิ์ที่ต้องการสำหรับการปรับใช้หรือไม่?
- ว่ากำแพงไฟหรือกลุ่มความปลอดภัยอนุญาต SSH การเชื่อมต่อหรือไม่

### 4. คำเตือนในการตรวจสอบสภาพแวดล้อม

คำเตือนจะไม่ป้องกันการปรับใช้โดยตรง แต่คุณจำเป็นต้องเปิดรายละเอียดเพื่อยืนยันผลกระทบ หากเกี่ยวข้องกับประสิทธิภาพของดิสก์ การซิงโครไนซ์เวลา การตั้งค่าเหลือค้าง หรือบริการภายนอก ให้ยืนยันก่อนว่าสอดคล้องกับแผนการปรับใช้งานปัจจุบันหรือไม่ ก่อนตัดสินใจว่าจะดำเนินการต่อหรือไม่

### 5. ความล้มเหลวในการตรวจสอบสภาพแวดล้อม

รายการที่ล้มเหลวจำเป็นต้องได้รับการแก้ไขก่อน ไม่ควรข้ามการตรวจสอบแล้วเริ่มการติดตั้งโดยตรง หลังจากแก้ไขแล้ว คลิก **สแกนซ้ำ** เพื่อยืนยันว่ารายการที่ล้มเหลวผ่านแล้ว

### 6. ความล้มเหลวของงานติดตั้ง

1. เปิดบันทึกการทำงานของงานที่ล้มเหลว
2. ค้นหาข้อความแสดงข้อผิดพลาดแรกที่ปรากฏ
3. บันทึกบันทึกการติดตั้ง ชื่อของงานที่ล้มเหลว และเวลาที่เกิดขึ้น
4. หลังจากแก้ไขปัญหาเครือข่าย ดิสก์ รูปภาพ มิดเดิลแวร์ หรือปัญหาที่เกี่ยวข้องแล้ว ให้ดำเนินการต่อไปตามวิธีการกู้คืนที่แท้จริง Kubernetes
