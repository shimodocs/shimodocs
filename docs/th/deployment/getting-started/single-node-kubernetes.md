# โหนดเดียว Kubernetes การปรับใช้

[← ShimoDocs Suite เอกสารการติดตั้ง](../README.md)

## 1. สถานการณ์ที่ใช้ได้
- **K8s การติดตั้งแบบโหนดเดี่ยว**:
    - เหมาะสำหรับทีมขนาดเล็กที่เบา การใช้งานขนาดเล็กที่มีคนน้อยกว่า 200 คน PoC, การสาธิต การตรวจสอบฟีเจอร์ และการทดสอบระยะสั้น
- จำเป็นต้องใช้เซิร์ฟเวอร์เพียง 1 เครื่อง โดยเซิร์ฟเวอร์ทำหน้าที่เป็นโหนดติดตั้ง K8s โหนดหลัก และโหนดผู้ปฏิบัติงานธุรกิจพร้อมกัน
- **หมายเหตุ**
    - สำหรับการเปิดตัวอย่างเป็นทางการ การดำเนินงานระยะยาว หรือการปรับขยายความพร้อมใช้งานสูงในอนาคต แนะนำให้ใช้ K8s การปรับใช้แบบคลัสเตอร์

## 2. ภาพรวมของกระบวนการปรับใช้

| ขั้นตอน | สิ่งที่ต้องทำ | ตัวบ่งชี้การเสร็จสมบูรณ์ |
| --- | --- | --- |
| 1. ตรวจสอบสภาพแวดล้อมของระบบ | ยืนยันทรัพยากรเซิร์ฟเวอร์, ดิสก์, เครือข่าย, การซิงโครไนซ์เวลา และคำสั่งพื้นฐาน | เซิร์ฟเวอร์ตรงตามข้อกำหนดการปรับใช้ |
| 2. เตรียมวัสดุติดตั้ง | รับตัวติดตั้งและแพ็กเกจติดตั้งผลิตภัณฑ์; ในสภาพแวดล้อมออฟไลน์ยังต้องเตรียมแพ็กเกจอิมเมจออฟไลน์ | ชื่อไฟล์ตรงกับ CPU สถาปัตยกรรม |
| 3. อัปโหลดวัสดุติดตั้ง | อัปโหลดตัวติดตั้งและแพ็กเกจติดตั้งไปยังโหนดการปรับใช้ | ไฟล์ถูกวางในไดเร็กทอรีที่กำหนดบนเซิร์ฟเวอร์แล้ว |
| 4. เริ่มตัวติดตั้ง | เปิด `mdp-installer` หน้าเว็บ | หน้าติดตั้งสามารถเข้าถึงได้ผ่านเบราว์เซอร์ |
| 5. การติดตั้งผ่านเว็บเพจ | เลือกแพ็กเกจการแจกจ่าย, กำหนดค่าหน่วย, ตรวจสอบสภาพแวดล้อม, และเริ่มการปรับใช้ | งานติดตั้งทั้งหมดสำเร็จ |
| 6. การตรวจสอบหลังการติดตั้ง | ตรวจสอบคลัสเตอร์, บริการ, การเข้าสู่ระบบ, ใบอนุญาต, และฟังก์ชันธุรกิจ | ฟังก์ชันหลักสามารถใช้งานได้ตามปกติ |

## 3. การเตรียมความพร้อมก่อนการปรับใช้

### 3.1 เตรียมข้อมูลเซิร์ฟเวอร์

| ข้อมูล | ตัวอย่าง | คำอธิบาย |
| --- | --- | --- |
| INSTALL_NODE_IP | `<INSTALL_NODE_IP>` | โหนดเดียว K8s การปรับใช้ใช้เซิร์ฟเวอร์เพียง 1 เครื่อง |
| CPU สถาปัตยกรรม | `amd64` / `arm64` | ตัวติดตั้งและแพ็กเกจติดตั้งต้องตรงกับสถาปัตยกรรมของเซิร์ฟเวอร์ |
| สภาพแวดล้อมเครือข่าย | ออนไลน์ / ออฟไลน์ | เลือกออนไลน์หากสามารถเข้าถึงเครือข่ายสาธารณะได้; เลือกออฟไลน์สำหรับสภาพแวดล้อมภายในหรือแยกตัว |
| ผู้ใช้ที่ดำเนินการ | `root` หรือผู้ใช้ที่มี `sudo` สิทธิพิเศษ | ตัวติดตั้งต้องดำเนินการงานปรับใช้ผ่าน SSH |
| SSH พอร์ต | `22` | หาก SSH พอร์ตได้ถูกเปลี่ยน แนะนำให้กรอกพอร์ตจริง |
| โปรโตคอลการเข้าถึง | HTTP / HTTPS | HTTP สามารถใช้สำหรับสภาพแวดล้อมการทดสอบ; HTTPS แนะนำสำหรับการใช้งานจริงหรือการเข้าถึงจากภายนอก |
| ACCESS_DOMAIN | `<ACCESS_DOMAIN>` หรือ `<INSTALL_NODE_IP>` | ที่อยู่สำหรับผู้ใช้ในการเข้าถึง ShimoDocs Suite |
| ไดเรกทอรีข้อมูล | `/data` | แนะนำให้ใช้การติดตั้งดิสก์ข้อมูลแยกต่างหาก |

### 3.2 เตรียมวัสดุติดตั้ง

| วัสดุ | ตัวอย่างชื่อไฟล์ | คำอธิบาย |
| --- | --- | --- |
| ตัวติดตั้ง | `mdp-installer-amd64` | ตัวอย่างสำหรับ `amd64` สถาปัตยกรรม; แทนที่ด้วยชื่อไฟล์จริงสำหรับสถาปัตยกรรมอื่น |
| แพ็กเกจติดตั้งผลิตภัณฑ์ | `co1.8.20260807.3639-drive-release..tar.gz` | สำหรับการติดตั้งแบบโหนดเดียว K8s เลือกแพ็กเกจที่ไฟล์ชื่อไม่รวม `k3s`; ชื่อไฟล์ขึ้นอยู่กับการส่งมอบจริง |
| แพ็กเกจภาพออฟไลน์ฐาน | `smbase_image-amd64.tar.gz` | จำเป็นเฉพาะสำหรับการติดตั้งออฟไลน์ |
| แพ็กเกจภาพออฟไลน์ผลิตภัณฑ์ | `offline_app_image.tar.gz` | จำเป็นเฉพาะสำหรับการติดตั้งแบบออฟไลน์ ต้องตรงกับเวอร์ชันของแพ็กเกจติดตั้งผลิตภัณฑ์ |

หมายเหตุ:

- ชื่อไฟล์ในคำสั่งต้องแทนที่ด้วยชื่อไฟล์จริง เช่น `mdp-installer-amd64`, `co1.8.<VERSION>-drive-release.tar.gz`.
- แพ็กเกจติดตั้งผลิตภัณฑ์ แพ็กเกจภาพออฟไลน์ และเซิร์ฟเวอร์ CPU สถาปัตยกรรมต้องสอดคล้องกัน
- ก่อนการติดตั้งแบบออฟไลน์ แนะนำให้เตรียมแพ็กเกจภาพออฟไลน์ฐานและแพ็กเกจภาพออฟไลน์ผลิตภัณฑ์พร้อมกันเพื่อหลีกเลี่ยงการต้องเพิ่มแพ็กเกจชั่วคราวระหว่างการติดตั้ง

### 3.3 ตรวจสอบทรัพยากรเซิร์ฟเวอร์

| รายการ | ข้อกำหนดที่แนะนำ |
| --- | --- |
| จำนวนเซิร์ฟเวอร์ | 1 |
| CPU | 16 คอร์หรือมากกว่า |
| หน่วยความจำ | 32 GB หรือมากกว่า |
| ดิสก์ระบบ | รูท `/` พาร์ติชัน 100 GB หรือมากกว่า |
| ดิสก์ข้อมูล | ติดตั้งแยกที่ `/data`, พื้นที่ว่างมากกว่า 300 GB |
| การติดตั้งออฟไลน์ | แนะนำให้สำรองพื้นที่เพิ่มอีกกว่า 100 GB บนดิสก์ข้อมูลสำหรับแพ็กเกจภาพและไฟล์ชั่วคราว |

เรียกใช้บนเซิร์ฟเวอร์: 

```bash
lscpu
free -g
df -h
timedatectl status
```

ยืนยันผลลัพธ์ต่อไปนี้: 

- CPU, หน่วยความจำ และดิสก์เป็นไปตามข้อกำหนดการติดตั้ง. 
- `/data` ถูกติดตั้งเข้ากับดิสก์ข้อมูลแยกต่างหาก 
- การซิงโครไนซ์เวลาของระบบเป็นปกติ 
- สามารถเข้าถึงเซิร์ฟเวอร์ผ่าน SSH เข้าสู่ระบบ 
- สภาพแวดล้อมการติดตั้งออนไลน์สามารถเข้าถึงเครือข่ายสาธารณะได้; สภาพแวดล้อมการติดตั้งออฟไลน์มีแพ็กเกจภาพออฟไลน์พร้อมใช้งาน 

### 3.4 ตรวจสอบพอร์ต 

| พอร์ต | วัตถุประสงค์ | 
| --- | --- | 
| `22/TCP` | SSH เข้าสู่ระบบและดำเนินการงานติดตั้ง | 
| `18080/TCP` | หน้าเว็บของตัวติดตั้ง | 
| `80/TCP` หรือ `443/TCP` | ShimoDocs Suite ทางเข้าในการเข้าถึง | 

หากเซิร์ฟเวอร์เปิดใช้งานไฟร์วอลล์หรือกลุ่มรักษาความปลอดภัย โปรดเปิดพอร์ตข้างต้นล่วงหน้า 

## 4. อัปโหลดเครื่องมือและแพ็กเกจการติดตั้ง 

ตัวอย่างต่อไปนี้ใช้สถาปัตยกรรม `amd64` สำหรับสถาปัตยกรรมอื่น โปรดแทนที่ด้วยชื่อไฟล์จริง 

### 4.1 อัปโหลดตัวติดตั้ง 

ดำเนินการบนคอมพิวเตอร์เครื่องท้องถิ่น: 

```bash
scp mdp-installer-amd64 root@<INSTALL_NODE_IP>:/root/
```

### 4.2 อัปโหลดแพ็กเกจภาพออฟไลน์

ขั้นตอนนี้สามารถข้ามได้สำหรับการติดตั้งออนไลน์

สำหรับการติดตั้งออฟไลน์ แพ็กเกจภาพออฟไลน์จำเป็นต้องอัปโหลดไปยังโหนดการปรับใช้:

```bash
scp smbase_image-amd64.tar.gz offline_app_image.tar.gz root@<INSTALL_NODE_IP>:/root/
```

### 4.3 เข้าสู่ระบบเซิร์ฟเวอร์

```bash
ssh root@<INSTALL_NODE_IP>
```

### 4.4 เพิ่มสิทธิ์ในการดำเนินการให้กับตัวติดตั้ง

```bash
chmod +x /root/mdp-installer-amd64
```

### 4.5 เปิดหน้าเว็บตัวติดตั้ง

ดำเนินการบนเซิร์ฟเวอร์:

```bash
cd /root
./mdp-installer-amd64 server
```

หากคุณต้องการให้ตัวติดตั้งทำงานในพื้นหลัง คุณสามารถใช้: 

```bash
nohup /root/mdp-installer-amd64 server > /root/mdp-installer.log 2>&1 &
```

เข้าถึงผ่านเบราว์เซอร์: 

```text
http://<INSTALL_NODE_IP>:18080
```

## 5. การติดตั้งผ่านหน้าเว็บ

### 5.1 การเลือกแพ็กเกจการแจกจ่าย

หลังจากเข้าสู่หน้าเว็บตัวติดตั้ง เลือกแพ็กเกจการแจกจ่ายของผลิตภัณฑ์ที่จะปรับใช้งานครั้งนี้

สำหรับ K8s สำหรับการปรับใช้แบบโหนดเดียว กรุณาเลือกแพ็กเกจการแจกจ่ายซึ่งชื่อไฟล์ไม่ประกอบด้วย `k3s`ตัวอย่าง:

```text
co1.8.20260807.3639-drive-release.tar.gz
```

### 5.2 การกำหนดค่า SSH การเชื่อมต่อ

ตัวติดตั้งจะเข้าสู่ระบบโหนดการปรับใช้ผ่าน SSH และดำเนินการงานติดตั้ง SSH การตั้งค่ารองรับวิธีการตรวจสอบตัวตนสองวิธี:

- การตรวจสอบตัวตนด้วยกุญแจส่วนตัว
- PASSWORD การตรวจสอบตัวตน

แนะนำให้ใช้ `root` ผู้ใช้หรือผู้ใช้ที่มี `sudo` สิทธิ์ในการดำเนินการปรับใช้ หลังจากกรอกข้อมูลแล้ว คุณสามารถทดสอบการเชื่อมต่อก่อนเพื่อให้แน่ใจว่าตัวติดตั้งสามารถเข้าสู่โหนดการปรับใช้ได้ตามปกติ

### 5.3 ยืนยันการตั้งค่าพื้นฐาน

หลังจากเลือกแพ็คเกจการแจกจ่ายแล้ว ให้ไปยังขั้นตอนถัดไป หากไม่มีข้อกำหนดพิเศษ คุณสามารถคงการตั้งค่าเริ่มต้นของหน้าต่างไว้ได้ หากสภาพแวดล้อมการปรับใช้มีแผนชัดเจนเกี่ยวกับชื่อโดเมน ใบรับรอง ส่วนของเครือข่าย หรือซอฟต์แวร์กลาง ให้กรอกตามแผนจริง

จุดสำคัญที่ต้องยืนยันในระหว่างการตั้งค่า: 

- ตรวจสอบให้แน่ใจว่าโปรโตคอลการเข้าถึงและ ACCESS_DOMAIN ถูกกรอกอย่างถูกต้อง 
- Pod CIDR และบริการ CIDR ไม่ทำให้เกิดความขัดแย้งกับเครือข่ายที่มีอยู่ เครือข่ายสำนักงาน, VPN, หรือ IDC ส่วนของเครือข่าย 
- ใช้ `/data` หรือไดเรกทอรีดิสก์ข้อมูลตามแผนจริงสำหรับไดเรกทอรีข้อมูล 
- วิธีการติดตั้งออนไลน์/ออฟไลน์สอดคล้องกับสภาพแวดล้อมเครือข่ายปัจจุบัน 

### 5.4 การปรับใช้เบื้องต้น 

หลังจากการตั้งค่าเสร็จสิ้น ให้คลิก การปรับใช้เบื้องต้น หน้าจะปรากฏภาพรวมของการปรับใช้นี้ โปรดตรวจสอบ: 

- เวอร์ชันของแพ็คเกจผลิตภัณฑ์ 
- การปรับใช้ NODE_IP 
- SSH ผู้ใช้และพอร์ต 
- ACCESS_DOMAIN และโปรโตคอล 
- ไดเรกทอรีข้อมูล 
- โหมดการติดตั้งออนไลน์หรือออฟไลน์ 
- การเลือกซอฟต์แวร์กลาง 

ดำเนินการต่อหลังจากยืนยันว่าทุกอย่างถูกต้อง 

### 5.5 ตรวจสอบสภาพแวดล้อมของระบบ

ตัวติดตั้งจะตรวจสอบสภาพแวดล้อมเซิร์ฟเวอร์โดยอัตโนมัติ

ดำเนินการติดตั้งต่อหลังจากผ่านการตรวจสอบ หากมีรายการที่ล้มเหลว โปรดจัดการตามคำแนะนำบนหน้าและตรวจสอบอีกครั้ง ทิศทางการจัดการทั่วไป ได้แก่: 

- พื้นที่ดิสก์ไม่เพียงพอ: ทำความสะอาดพื้นที่หรือขยายดิสก์ข้อมูล 
- พอร์ตไม่พร้อมใช้งาน: ปล่อยพอร์ตหรือปรับการใช้งานพอร์ต 
- SSH การเชื่อมต่อล้มเหลว: ตรวจสอบบัญชี, PASSWORD, คีย์ส่วนตัว, พอร์ต และกลุ่มความปลอดภัย 
- การซิงโครไนซ์เวลาผิดปกติ: กำหนดค่า NTP หรือปรับเวลาเซิร์ฟเวอร์ 
- คำสั่งพื้นฐานหายไป: ติดตั้งคำสั่งที่หายไปตามการแจกแจงของระบบ 

### 5.6 เริ่มการติดตั้ง 

หลังจากตรวจสอบสภาพแวดล้อมผ่านแล้ว คลิกเพื่อเริ่มการติดตั้ง 

ระหว่างกระบวนการติดตั้ง คุณสามารถดูบันทึกการดำเนินการของแต่ละส่วนประกอบได้ ในระหว่างการติดตั้ง โปรดตรวจสอบว่า: 

- กระบวนการติดตั้งยังคงทำงานอยู่ 
- เบราว์เซอร์สามารถเชื่อมต่อกับเครือข่ายของโหนดติดตั้งได้ 
- อย่ารีสตาร์ทเซิร์ฟเวอร์ 
- อย่าย้ายหรือลบแพ็กเกจติดตั้ง แพ็กเกจภาพออฟไลน์ หรือไดเรกทอรีข้อมูล 

### 5.7 รอการติดตั้งให้เสร็จสิ้น

กระบวนการติดตั้งต้องใช้เวลารอระยะหนึ่ง ระยะเวลาที่แน่นอนขึ้นอยู่กับประสิทธิภาพเซิร์ฟเวอร์, สภาพแวดล้อมเครือข่าย และความเร็วในการดาวน์โหลดอิมเมจ

เมื่อหน้าจอแสดงว่าทุกงานถูกดำเนินการเรียบร้อยและไม่มีองค์ประกอบที่ล้มเหลว นั่นหมายความว่าการปรับใช้เสร็จสมบูรณ์

### 5.8 ยืนยันผลการติดตั้ง

หลังจากการติดตั้งเสร็จสิ้น ตัวติดตั้งจะแสดงหน้าการติดตั้งเสร็จสิ้นและข้อมูลการเข้าถึง โปรดยืนยันก่อนว่าบนหน้าไม่มีงานที่ล้มเหลวก่อนที่จะดำเนินการเข้าถึงระบบธุรกิจและ MDP แพลตฟอร์มปฏิบัติการ

เข้าชมที่อยู่ธุรกิจ: 

```text
http://<ACCESS_DOMAIN>/
```

ถ้า HTTPS ถูกกำหนดค่าในระหว่างการติดตั้ง กรุณาเข้าชม: 

```text
https://<ACCESS_DOMAIN>/
```

หลังจากเข้าสู่ระบบด้วยบัญชีเริ่มต้นหรือบัญชีผู้ดูแลระบบ กรุณาเปลี่ยนค่าเริ่มต้น PASSWORD ทันที

เข้าถึง MDP แพลตฟอร์มการดำเนินงาน: 

```text
http://<ACCESS_DOMAIN>/mdp/
```

หากคุณต้องการแก้ไข MDP ผู้ดูแลระบบ PASSWORDคุณสามารถรันคำสั่งต่อไปนี้บนโหนดการติดตั้งเพื่อแก้ไขหรือรีเซ็ต PASSWORD.
โปรดแทนที่ {password} ด้วยรหัสผ่านใหม่ที่ซับซ้อนและแข็งแรง PASSWORD ตามข้อกำหนดด้านความปลอดภัยจริง

```bash
kubectl exec -it $(kubectl get pods -l app=mdp -o jsonpath='{.items[0].metadata.name}') -- reset-admin-password {password}
```

## 6. การตรวจรับหลังการติดตั้ง

### 6.1 ตรวจสอบ K8s สถานะโหนด

รันคำสั่งบนโหนดการติดตั้ง:

```bash
kubectl get node
```

สถานะของโหนดควรเป็น `Ready`. 

ทำการตรวจสอบบริการต่อไป: 

```bash
kubectl get pod -A
```

สถานะปกติส่วนใหญ่คือ: 

- `Running`: บริการกำลังทำงาน 
- `Completed`: งานได้ทำการรันเสร็จสิ้นแล้ว 

หากคุณพบสถานะเช่น `CrashLoopBackOff`, `ImagePullBackOff`, `Error`, `Pending`โปรดตรวจสอบบันทึกของ Pod ที่เกี่ยวข้องก่อนและดำเนินการจัดการ 

### 6.2 ตรวจสอบทางเข้าการเข้าถึง 

เข้าถึง ShimoDocs Suite เข้าผ่านเบราว์เซอร์: 

```text
http://<ACCESS_DOMAIN>/
```

ถ้า HTTPS ได้รับการกำหนดค่าแล้ว โปรดไปที่: 

```text
https://<ACCESS_DOMAIN>/
```

ยืนยันว่าหน้าเข้าสู่ระบบสามารถเปิดได้ตามปกติ

### 6.3 ตรวจสอบการจัดการแบ็คเอนด์และใบอนุญาต

ยืนยันรายการต่อไปนี้:

- สามารถเข้าถึงแบ็คเอนด์ของผู้ดูแลระบบได้
- ผู้ดูแลระบบสามารถเข้าสู่ระบบได้
- สามารถเปิดหน้าของใบอนุญาตได้
- สามารถดูข้อมูลเครื่องได้
- สามารถขอหรืออัปเดตใบอนุญาตตามกระบวนการอนุมัติได้

### 6.4 ตรวจสอบฟังก์ชันธุรกิจ

หลังจากเข้าสู่ระบบด้วยบัญชีทดสอบหรือบัญชีที่ผู้ดูแลสร้างขึ้น อย่างน้อยควรตรวจสอบ:

- สามารถสร้างเอกสาร สเปรดชีต และสไลด์ได้
- เอกสารถูกแก้ไขและบันทึกได้ และเนื้อหายังคงอยู่หลังการรีเฟรช
- สามารถแก้ไขร่วมกันแบบหลายผู้ใช้ได้
- การนำเข้าและส่งออกไฟล์เป็นไปตามปกติ
- ฟีเจอร์หลัก เช่น การค้นหา พื้นที่ทีม และรายชื่อผู้ติดต่อ ใช้งานได้

หลังจากเข้าสู่ระบบด้วยบัญชีทดสอบเริ่มต้นครั้งแรก กรุณาเปลี่ยน PASSWORD ทันที
บัญชี PASSWORD เป็นบัญชีส่งมอบการติดตั้ง PASSWORD!
```text
ACCOUNT:autotest@example.com
PASSWORD:xxxxx
```

### 6.5 หยุดกระบวนการติดตั้ง

หลังจากการติดตั้งเสร็จสมบูรณ์และการยอมรับผ่านแล้ว สามารถหยุดบริการเว็บของตัวติดตั้งได้
หยุดหน้าเว็บติดตั้ง:
คำสั่งเพื่อหยุดตัวติดตั้ง: 
```bash
ps -ef | grep mdp-installer | grep -v grep
kill <PID>
```

หากตัวติดตั้งเริ่มทำงานในพื้นหลังโดยใช้ `nohup`คุณยังสามารถตรวจสอบบันทึกได้ด้วย: 

```bash
tail -f /root/nohup.out
```

## 7. การแก้ไขปัญหาโดยทั่วไป

### 7.1 เบราว์เซอร์ไม่สามารถเปิดหน้าติดตั้งได้

ตรวจสอบดังต่อไปนี้:

- ว่ากระบวนการติดตั้งยังทำงานอยู่หรือไม่
- ว่าพอร์ต `18080` ถูกบล็อกโดยไฟร์วอลล์หรือกลุ่มความปลอดภัยหรือไม่
- ว่าที่อยู่ IP ที่เข้าถึงโดยเบราว์เซอร์คือ INSTALL_NODE_IP

สามารถดำเนินการดังต่อไปนี้บนเซิร์ฟเวอร์:

```bash
ps -ef | grep mdp-installer | grep -v grep
ss -lntp | grep 18080
```

### 7.2 การตรวจสอบสภาพแวดล้อมล้มเหลว

จัดการแต่ละรายการตามข้อความแจ้งบนหน้า หลังจากจัดการแล้ว กลับไปที่หน้าติดตั้งและรันการตรวจสอบสภาพแวดล้อมอีกครั้ง

การตรวจสอบความสำคัญ:

- ว่าหน่วยความจำ, และดิสก์ตรงตามข้อกำหนดหรือไม่ CPUว่าหน่วยความจำและดิสก์ตรงตามข้อกำหนดหรือไม่
- ว่า `/data` เป็นดิสก์ข้อมูลอิสระหรือไม่
- เวลาของเซิร์ฟเวอร์ถูกซิงโครไนซ์แล้วหรือไม่
- ว่าหน่วยความจำ, และดิสก์ตรงตามข้อกำหนดหรือไม่ SSH ผู้ใช้มีสิทธิ์ในการติดตั้งหรือไม่

### 7.3 การดึงภาพติดตั้งออฟไลน์ล้มเหลว

ทิศทางการตรวจสอบ:

- ว่าชุดภาพออฟไลน์ถูกอัปโหลดไปยังโนดติดตั้งแล้วหรือไม่
- ว่าชุดภาพออฟไลน์พื้นฐานและชุดภาพออฟไลน์ผลิตภัณฑ์สมบูรณ์หรือไม่
- ว่ารุ่นของชุดภาพตรงกับชุดติดตั้งผลิตภัณฑ์หรือไม่
- ว่าที่อยู่บัญชีและ PASSWORD ถูกกรอกอย่างถูกต้อง

### 7.4 Pod อยู่ในสถานะผิดปกติเป็นเวลานาน

ก่อนอื่นให้ตรวจสอบ Pod ที่ผิดปกติ:

```bash
kubectl get pod -A
```

ตรวจสอบบันทึกอีกครั้ง: 

```bash
kubectl logs -n <namespace> <pod-name>
```

จัดการปัญหาเกี่ยวกับภาพ, การตั้งค่า, ทรัพยากร, หรือการพึ่งพาตามบันทึก

## 8. เก็บวัสดุหลังการติดตั้ง

หลังการติดตั้ง แนะนำให้เก็บวัสดุต่อไปนี้ไว้เพื่ออำนวยความสะดวกในการบำรุงรักษา การอัปเกรด และการแก้ไขปัญหาในภายหลัง:

- INSTALL_NODE_IP, ACCESS_DOMAINและโปรโตคอลการเข้าถึง
- ชื่อไฟล์ติดตั้งและเวอร์ชัน
- ชื่อไฟล์แพ็กเกจติดตั้งผลิตภัณฑ์และเวอร์ชัน
- ชื่อไฟล์แพ็กเกจอิมเมจออฟไลน์และเวอร์ชัน
- ภาพหน้าจอการกำหนดค่าคีย์ของเว็บเพจ
- `kubectl get node` ตรวจสอบผลลัพธ์
- `kubectl get pod -A` ตรวจสอบผลลัพธ์
- บันทึกการอนุญาตใบอนุญาต
- บันทึกการยอมรับฟังก์ชันธุรกิจ
- ปัญหาที่พบระหว่างการปรับใช้และผลการจัดการ
