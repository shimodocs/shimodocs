## 1. เตรียมทรัพยากรตามสถานการณ์

| สถานการณ์การใช้งาน | การจัดการที่แนะนำ | การเตรียมทรัพยากร |
| --- | --- | --- |
| ทีมขนาดเล็ก น้ำหนักเบา, PoC, การสาธิต, การตรวจสอบฟีเจอร์ | การติดตั้งแบบเซิร์ฟเวอร์เดียว | 1 เซิร์ฟเวอร์ |
| การเปิดตัวอย่างเป็นทางการ, การดำเนินงานระยะยาว, ต้องการการใช้งานสูง หรือการขยายในอนาคต | คลัสเตอร์ความพร้อมใช้งานสูง | 3 เซิร์ฟเวอร์ขึ้นไป |

- การติดตั้งแบบเซิร์ฟเวอร์เดียวเหมาะสำหรับการตรวจสอบอย่างรวดเร็วและการใช้งานขนาดเล็ก
- การติดตั้งแบบคลัสเตอร์เหมาะสำหรับการเปิดตัวอย่างเป็นทางการ, การดำเนินงานระยะยาว และการขยายในอนาคต

## 2. ข้อกำหนดระบบปฏิบัติการ

| ระบบปฏิบัติการ | เวอร์ชันที่รองรับ | สถาปัตยกรรมที่รองรับ |
| --- | --- | --- |
| Ubuntu | 22.04, 24.04 | x86 |

ดำเนินการบนแต่ละเซิร์ฟเวอร์:

```bash
cat /etc/os-release
uname -m
```

ผลลัพธ์การยืนยัน: 

- ระบบปฏิบัติการคือ Ubuntu 22.04 หรือ Ubuntu 24.04 
- CPU สถาปัตยกรรมคือ x86 
- บัญชีติดตั้งคือ `root`, หรือมีสิทธิ์ผู้ดูแลระบบเทียบเท่า 

หมายเหตุ: เหตุผลที่ไม่รองรับระบบ CentOS อีกต่อไป 
- CentOS Linux 7 และ 8 ได้สิ้นสุดวงจรชีวิตแล้ว ทาง CentOS ทางการไม่จัดหา CentOS 9 และรุ่นถัดไปอีกต่อไป และไม่รับการอัปเดตความปลอดภัยใหม่ การแก้ไขช่องโหว่ หรือแพตช์ปัญหาใด ๆ 
- ส่วนประกอบระบบพื้นฐานไม่สามารถรับแพตช์ความปลอดภัยระยะยาวได้ ซึ่งอาจทำให้เกิดช่องโหว่ที่เปิดเผยแต่ไม่สามารถแก้ไขได้ ซึ่งไม่ตรงตามข้อกำหนดความปลอดภัยของสภาพแวดล้อมการผลิต 
- Kernel, glibc, OpenSSL และส่วนประกอบพื้นฐานอื่น ๆ ใน CentOS 7/8 มีอายุกว่าค่อนข้างเก่าและไม่สามารถตอบสนองความต้องการของ Kubernetes ไลบรารี runtime และ dependency ใหม่ได้ 
- CentOS Stream มีตำแหน่งและกลไกการอัปเดตรุ่นที่แตกต่างจาก CentOS Linux แบบดั้งเดิม และสภาพแวดล้อม CentOS Stream ที่ไม่ได้ผ่านการตรวจสอบความเข้ากันได้พิเศษก็ไม่ได้อยู่ภายใต้การสนับสนุนอย่างเป็นทางการเช่นกัน 


## 3. ข้อกำหนดการกำหนดค่าของเซิร์ฟเวอร์ 

### 3.1 การติดตั้งแบบโหนดเดี่ยว 

- เหมาะสำหรับทีมขนาดเล็กน้ำหนักเบา ไม่เกิน 200 คน 
- PoC, การแสดงตัวอย่าง และสถานการณ์การตรวจสอบฟังก์ชันสามารถจัดเตรียมตามทรัพยากรของโหนดเดี่ยว 

| โครงการ | ข้อกำหนด | 
| --- | --- | 
| จำนวนเซิร์ฟเวอร์ | 1 | 
| CPU | 16 คอร์หรือมากกว่า |
| หน่วยความจำ | 32 GB ขึ้นไป |
| ดิสก์ระบบ | รูท `/` พาร์ติชัน 100 GB ขึ้นไป |
| ดิสก์ข้อมูล | ติดตั้งแบบอิสระ `/data`, พื้นที่ว่าง 300 GB หรือมากกว่า รองรับการขยาย |

### การติดตั้งแบบคลัสเตอร์ 3.2

สำหรับสถานการณ์ที่ต้องการเปิดตัวอย่างเป็นทางการ การใช้งานระยะยาว การให้บริการที่สูง หรือขยายในอนาคต ให้เตรียมทรัพยากรตามข้อกำหนดของคลัสเตอร์

| รายการ | ข้อกำหนด |
| --- | --- |
| จำนวนเซิร์ฟเวอร์ | 3 เครื่องขึ้นไป |
| บทบาทที่แนะนำ | `3 master   N worker` |
| CPU ต่อโหนด | 16 คอร์หรือมากกว่า |
| หน่วยความจำต่อโหนด | 32 GB ขึ้นไป |
| ดิสก์ระบบต่อโหนด | รูท `/` พาร์ติชัน 100 GB ขึ้นไป |
| ดิสก์ข้อมูลต่อโหนด | ติดตั้งแบบอิสระ `/data`, พื้นที่ว่าง 300 GB หรือมากกว่า รองรับการขยาย |

บันทึกการแบ่งพาร์ติชัน:

- เก็บอย่างน้อย 100 GB สำหรับพาร์ติชันรูท `/` 
- แนะนำให้วาง `/root`, `/var`, `/tmp` ไว้ใต้พาร์ติชันรูทเพื่อการจัดการแบบรวมศูนย์
- ใช้ดิสก์ข้อมูลอิสระสำหรับไดเรกทอรีข้อมูล ติดตั้งที่ `/data`.

## 4. คำสั่งตรวจสอบตนเองของเซิร์ฟเวอร์

รันบนแต่ละเซิร์ฟเวอร์: 

```bash
# ============================================
# 1. View CPU architecture and core information
#    - Architecture type (x86_64/aarch64)
# ============================================
lscpu

# ============================================
# 2. Display memory and swap usage in GiB
# ============================================
free -g

# ============================================
# 3. File System Disk Space Usage
# ============================================
df -h

# ============================================
# 4. Find the executable file path
# ============================================
which iptables gzip tar

# ============================================
# 5. Display system time, time zone, and NTP synchronization status
#    Distributed clusters must have strict time synchronization, otherwise it will affect authentication and log sequencing.
# ============================================
timedatectl status
```

รายการตรวจสอบเปรียบเทียบ:

| รายการตรวจสอบ | เงื่อนไขผ่าน |
| --- | --- |
| CPU | 16 คอร์หรือมากกว่า |
| หน่วยความจำ | 32 GB หรือมากกว่า |
| ดิสก์ระบบ | รูท `/` พาร์ติชันมีพื้นที่ว่าง 100 GB หรือมากกว่า |
| ดิสก์ข้อมูล | `/data` ติดตั้งแล้ว มีพื้นที่ใช้งาน 300 GB หรือมากกว่า |
| คำสั่งพื้นฐาน | `iptables`, `gzip`, `tar` พบได้ |
| การซิงโครไนซ์เวลา | การซิงโครไนซ์เวลาของระบบเป็นปกติ |

## 7. ข้อกำหนดของพอร์ต

ก่อนการติดตั้ง ตรวจสอบให้แน่ใจว่าเซิร์ฟเวอร์ กลุ่มความปลอดภัย ไฟร์วอลล์ ตัวถ่วงสมดุลโหลด และนโยบายเครือข่ายได้อนุญาตพอร์ตดังต่อไปนี้

| พอร์ต | เป้าหมาย | วัตถุประสงค์ |
| --- | --- | --- |
| `18080/TCP` | Installer Web UI | เข้าถึงหน้าการติดตั้ง |
| `80/TCP` หรือ `443/TCP` | ShimoDocsSERVICE_DOMAIN | การเข้าถึงของผู้ใช้ |
| `22/TCP` | โหนดการปรับใช้ทั้งหมด | SSH การเข้าสู่ระบบและการกระจายงานการติดตั้ง |
| `3306/TCP` | MySQL | การเชื่อมต่อฐานข้อมูล |
| `6379/TCP` | Redis | การเชื่อมต่อแคช |
| `27017/TCP` | MongoDB | การเชื่อมต่อฐานข้อมูลเอกสาร |
| `9092/TCP` | Kafka | การเชื่อมต่อคิวข้อความ |
| `9200/TCP` | Elasticsearch | การเชื่อมต่อบริการค้นหา |
| ตามพอร์ตของบริการ | S3 / OBS / OSS / COS / MinIO | การเชื่อมต่อพื้นที่เก็บวัตถุ |

## 8. ข้อกำหนดเกี่ยวกับ Disk IO

แนะนำให้ใช้ SSD สำหรับดิสก์ข้อมูล ประสิทธิภาพดิสก์ควรเป็นไปตามมาตรฐานต่อไปนี้:

| รายการ | ข้อกำหนด |
| --- | --- |
| การอ่าน/เขียนผสม IOPS | มากกว่า 5000 |
| อัตราการอ่าน/เขียนต่อเนื่อง | มากกว่า 150 MB/s |
| ความหน่วงโดยเฉลี่ย | ประมาณ 5 ms หรือต่ำกว่า |

หลังจากติดตั้ง `fio`, สามารถทำการทดสอบได้บน `/data`.

### 8.1 การทดสอบการอ่าน/เขียนผสม

```bash
fio --name=randrw-test \
  --filename=/data/testfile \
  --size=20G \
  --rw=randrw \
  --rwmixread=70 \
  --bs=4k \
  --ioengine=libaio \
  --direct=1 \
  --iodepth=32 \
  --numjobs=4 \
  --runtime=300 \
  --time_based \
  --group_reporting
```

ให้สังเกต IOPS ในผลลัพธ์; การอ่าน/เขียนผสม IOPS ควรถึงมากกว่า 5000 เพื่อดำเนินการต่อ 

### 8.2 การทดสอบการอ่านต่อเนื่อง

```bash
fio --name=seqread-test \
  --filename=/data/testfile \
  --size=20G \
  --rw=read \
  --bs=1M \
  --ioengine=libaio \
  --direct=1 \
  --iodepth=32 \
  --numjobs=1 \
  --runtime=300 \
  --time_based \
  --group_reporting
```

### 8.3 การทดสอบการเขียนต่อเนื่อง

```bash
fio --name=seqwrite-test \
  --filename=/data/testfile \
  --size=20G \
  --rw=write \
  --bs=1M \
  --ioengine=libaio \
  --direct=1 \
  --iodepth=32 \
  --numjobs=1 \
  --runtime=300 \
  --time_based \
  --group_reporting
```

อัตราการอ่านต่อเนื่องและการเขียนต่อเนื่องที่มากกว่า 150 MB/s สามารถดำเนินการต่อได้ 

ไฟล์ทดสอบสามารถลบหลังจากการทดสอบ 

```bash
rm -f /data/testfile
```

## 9. ข้อกำหนดความกว้างแถบของเครือข่ายสาธารณะ

ประมาณแบนด์วิธสำหรับสถานการณ์การเข้าถึงเครือข่ายสาธารณะโดยอิงจากจำนวนผู้ใช้:

```text
PUBLIC_NETWORK_BANDWIDTH = NUMBER_OF_USERS x 0.25 Mbps
```

ตัวอย่าง:

| จำนวนผู้ใช้ | แบนด์วิธเครือข่ายสาธารณะที่แนะนำ |
| --- | --- |
| 100 ผู้ใช้ | มากกว่า 25 Mbps |
| 200 ผู้ใช้ | มากกว่า 50 Mbps |
| 500 ผู้ใช้ | มากกว่า 125 Mbps |

สำหรับสถานการณ์การเข้าถึงอินทราเน็ต แนะนำให้ประเมินแบนด์วิธขาออก ขาเข้า และการปรับสมดุลโหลดโดยใช้เกณฑ์เดียวกัน

## 10. คำแนะนำเวอร์ชันเบราว์เซอร์สำหรับผู้ติดตั้งและแพลตฟอร์มปฏิบัติการ

แนะนำให้ใช้ Google Chrome เวอร์ชัน 111 หรือสูงกว่า โดยควรเป็นเวอร์ชันเสถียรล่าสุด

## 11. รายการตรวจสอบก่อนการติดตั้ง

ก่อนเริ่มการติดตั้ง ให้ยืนยันแต่ละรายการ:

- เวอร์ชันของระบบปฏิบัติการเป็นไปตามข้อกำหนด
- CPUหน่วยความจำ ดิสก์ระบบ และดิสก์ข้อมูลเป็นไปตามข้อกำหนด
- `/data` ติดตั้งบนดิสก์ข้อมูลแยกต่างหาก
- `iptables`, `gzip`, และ `tar` ได้ติดตั้ง
- การซิงโครไนซ์เวลาระบบเป็นปกติ
- วิธีการติดตั้งออนไลน์หรือออฟไลน์ได้รับการกำหนดแล้ว
- พอร์ตของผู้ติดตั้ง `18080` เข้าถึงได้
- พอร์ตการเข้าถึงธุรกิจ `80` หรือ `443` เปิดใช้งานแล้ว
- หากใช้ซอฟต์แวร์ตัวกลางภายนอก ข้อมูลการเชื่อมต่อพร้อมใช้งานครบถ้วน
- ที่เก็บวัตถุรองรับกับ S3 โปรโตคอล และสิทธิ์ของบัคเก็ตและบัญชีพร้อมใช้งาน 
- การทดสอบ IO ของดิสก์ข้อมูลตรงตามข้อกำหนด 
- แบนด์วิดท์เครือข่ายสาธารณะหรือภายในตรงตามจำนวนผู้ใช้ที่คาดหวัง
